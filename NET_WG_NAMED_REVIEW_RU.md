# Именованный WireGuard: сохранённая ревизия и свежий отзыв

Этот checkpoint связывает обычный WG executor с принятым контрактом DEFAULT
`WireGuardProfileRevision` / `FrozenWireGuardProfileRevision`.
Он не добавляет назначение сервиса: producer и обычный HTTP CAS принадлежат CORE.

Для `wireguard:<id>` все выбранные маршруты должны содержать одну каноническую
ревизию именно этого профиля. WG читает `Get` у уже зарегистрированного `Profiles`;
новое хранилище, поиск каталогов или переназначение актуальной версии отсутствуют.
`main`, WARP и AWG сохраняют прежние способы выбора своего профиля.

Snapshot, Stage, Validate, Canary, Activate, Health, Commit, Reconcile и Refresh
проверяют ревизию перед входом и перед возвратом результата. Для проверки команды
используется копия маршрутов из review, а не изменяемый slice вызывающей стороны.
Командный runner проверяет тот же Store до команды и после её завершения;
legacy common policy addition также проходит через этот runner. Проверка перед
публикацией WG reference/transaction marker и staged/runtime bytes не позволяет
подменить сохранённую ревизию содержимым, появившимся позднее в каталоге.

Проверки не обещают атомарность внешнего writer и ядра. Если смена ревизии замечена
после команды, её результат не объявляется успешным; common receipt удерживает
неподтверждённую операцию по своим обычным правилам. Проверка каталога сама по себе
не даёт права удалить ресурс или восстановить runtime.

Deactivate, Rollback и cleanup сохраняют исходное право из полной immutable
квитанции и snapshot. Их локальный context снимает только проверку текущего
каталога, сохраняя cancellation и authority остальных owners. Это позволяет
убрать уже принадлежащий кандидату интерфейс после отзыва review; неподтверждённая
квитанция по-прежнему блокирует предположительное удаление.

Модели покрывают пустую/неверную ревизию, конфликт имени, две ревизии, изменение
перед каждой фазой, изменение во время команды и успешного probe, отсутствие
следующего forward effect, очистку кандидата и независимость frozen маршрутов.
Модельные результаты не являются Linux native, router/HIL или готовностью D05/D07.
