# HEV через пакетный дескриптор

Изолированный Linux-тест передаёт пакеты из штатного TUN в HEV по `AF_UNIX/SOCK_DGRAM`. Библиотека отвечает в тот же сокет. Адаптер передаёт ответ в исходный, открытый им файловый дескриптор TUN. Дескрипторы, процесс HEV и время жизни интерфейса принадлежат одному прогону. Тест принимает только полные IPv4-пакеты длиной до 1500 байт и отбрасывает служебные сообщения IPv6 от lwIP.

Локальный HTTP-сервис в отдельном пространстве имён проверяет адрес вызывающего клиента. Клиент из виртуальной LAN скачивает и отправляет по 256 КиБ напрямую, через SOCKS/VLESS и после остановки. Счётчик на входе независимого WAN-интерфейса видит обычные пакеты выбранного клиента к сервису, включая FIN и ACK. Сначала требуется ноль, затем положительное значение после возврата того же клиента на WAN.

Для сборки используйте проверенный архив исходников HEV 2.17.1. Его SHA-256 и хеш результата проектного исправления проверяет `build-relay.sh`. Нужны C-компилятор, make, patch, заголовки Linux и sha256sum. Для запуска нужны root в одноразовой Linux VM, TUN, unshare, iproute2, nftables и совместимый Linux Xray. Все адреса и ключ тестовой сессии создаются внутри приватных пространств имён. Команды выполняются из корня репозитория.

```sh
fixture="$PWD/scripts/diagnostics/hev-packet-fd"
sh "$fixture/build-relay.sh" /lab/hev-socks5-tunnel-2.17.1.tar.xz /lab/fd-build "$PWD/scripts/fixtures/hev-runtime-altstack.patch"
CGO_ENABLED=0 go build -o /lab/origin scripts/testdata/home-egress/origin.go
RAZVILKA_XRAY_NATIVE=/lab/xray RAZVILKA_FIXTURE_ORIGIN=/lab/origin RAZVILKA_HEV_RELAY=/lab/fd-build/relay sh "$fixture/scenario.sh"
```

При наличии заголовков libmnl и libnetfilter_queue можно собрать отдельный источник пакетов. Библиотека HEV получает полные IPv4-дейтаграммы из очереди через сокет. При таком режиме контроллер использует свой TUN только для записи ответа. Для повторного запуска сборки укажите новый каталог.

```sh
RAZVILKA_BUILD_NFQUEUE=1 sh "$fixture/build-relay.sh" /lab/hev-socks5-tunnel-2.17.1.tar.xz /lab/queue-build "$PWD/scripts/fixtures/hev-runtime-altstack.patch"
export RAZVILKA_XRAY_NATIVE=/lab/xray RAZVILKA_FIXTURE_ORIGIN=/lab/origin
export RAZVILKA_HEV_RELAY=/lab/queue-build/relay RAZVILKA_QUEUE_SOURCE=/lab/queue-build/queue-source
sh "$fixture/scenario.sh"
RAZVILKA_TEST_NFQUEUE_EGRESS=1 sh scripts/test-xray-home-egress-native.sh
sh "$fixture/queue-capacity.sh"
RAZVILKA_TEST_NFQUEUE_EGRESS=1 RAZVILKA_TEST_NFT_RETENTION=1 sh scripts/test-xray-home-egress-native.sh
```

Первый сценарий прокладывает статический маршрут к одному /32 через TUN. Второй использует штатный WAN, добавляет SNAT и проверяет позднее правило firewall, native VPN, исключения MAC/CIDR, DNAT и возврат обычного пути после Stop. Источник пакетов принимает IPv4-адреса клиентов одной приватной тестовой подсети и один адрес и порт назначения. В полном сценарии выбор физического входа и выхода, исходного и текущего назначения и исключения остаются за предшествующим селектором. Новый клиент со своим MAC и адресом .41 проверяется двусторонней передачей 256 КиБ. Независимый счётчик на внешнем WAN измеряет прямую утечку к сервису во время выбранных запросов и имеет положительный контроль после снятия правила. Вся топология и порядок обработчиков принадлежат одному запуску. Третий сценарий посылает четыре ICMP-пакета по loopback при вместимости очереди в один пакет. Он проверяет отсутствие доставки при переполнении и при завершении слушателя и положительный контроль после снятия правила.

При переносе на заводской NC-1812 остаются отдельные вопросы о доступности классификатора, порядке правил, существующих соединениях при переключении, строгой обратной фильтрации, аппаратном ускорении и восстановлении при остановке процесса между отправкой дейтаграммы и сетевым вердиктом. Четвёртый сценарий проверяет тот же TCP-сокет после 121 секунды простоя и отказ при заполнении nft-набора размером в одну запись. Набор удерживается до снятия селектора; закрытые соединения занимают место до Stop. Защита от повторного использования комбинации адресов и портов, внешней потери сохранённых сессий и освобождение слотов по доказанному завершению остаются требованиями к рабочему маршрутизатору. Для большого перенаправленного потока в тесте со штатным WAN проверялся режим rp_filter=0. Результаты и контрольные суммы приведены в [отчёте](../../../docs/XLATE_HOME_POSTROUTE_LAB_20261126.md).
