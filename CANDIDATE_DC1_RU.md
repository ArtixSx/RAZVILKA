# RAZVILKA DC1 — проверка состояния и начало DNS/Community-интеграции

Дата: 2026-09-13. База: AWG31-WARP, commit `64af021bbc5f367f8968a6e56b925df7f700d00f`, VERSION `0.18.2-dev`.

**Это новая редакция исходников, не установочный релиз.** В ней есть производственная разметка и API-код сравнения DNS, а также изолированная библиотека рекомендаций. Компиляция всего изменённого приложения не подтверждена: Go 1.26.5 не получен из-за сетевой ошибки окружения. Архив не содержит новых бинарников и не переименовывает старые бинарники в DC1.

## Что выяснила перепроверка

В начале этой попытки активного процесса сборки не было. Последний полный AWG31-WARP архив существует и прошёл ZIP CRC-проверку; из его Git bundle восстановлена рабочая копия с известным HEAD. Это подтверждает сохранность исходной точки, но не объясняет внутреннюю причину прерывания прежнего ответа.

Найдена важная граница: существующий DNS Apply для несистемных профилей возвращает `DNS_LIVE_ADAPTER_UNAVAILABLE`. DC1 не удаляет этот предохранитель. Нельзя реализовать автоматическое DNS-переключение только кнопкой сайта.

## Внесено

1. Метаданные DNS-провайдеров: роль, доверие/источник, дата проверки документации, отдельно неподтверждённые hints сервиса. Добавлены Malw и Comss DoH/DoT; Xbox классифицирован как Smart DNS. GeoHide и Control D Redirect — только ненастроенные шаблоны, без угаданных endpoint или аккаунтного API.
2. `POST /api/v1/dns/service-compare`: ручное сравнение A/AAAA для домена HTTPS-сценария существующего сервиса. До трёх профилей, один DoH endpoint на профиль, последовательные запросы, общий дедлайн 32 секунды. Вся партия проверяется до первого внешнего запроса. DNS-файл и маршруты не изменяются.
3. Точное ограничение результата: `service_verified=false`, `route_verified=false`, `eligible_for_apply=false`. Получение адреса не является TLS/сервисной проверкой. Путь DNS-запроса — системный, пока без доказательства фактической маршрутизации. Результат не сохраняется как PASS и не запускает WARP-регистрацию.
4. Участие в существующем operation gate, проверка авторизации/редакции, отмена через context. Политика сервиса без прямого резерва блокирует этот начальный системный путь. Не создаются отдельные таймеры.
5. В существующую вкладку DNS встроены выбор сервиса, провайдеров, отдельное согласие на DNS-запросы, результат по семействам и отмена. Сохраняются Главная-мониторинг, Сервисы-сетка, AI-группа и редакторы.
6. `internal/recipehints`: проверка подписи Ed25519 подписанного каталога, границы размера/схемы/времени/версии, нормализованный hash рецепта, отзыв, локальные allowlists и ограниченный рейтинг Wilson + давность + соответствие группе. Рецепт содержит ссылки на существующие локальные стратегии, а не shell/исполняемый Lua.

**Библиотека recipehints пока не подключена к runtime планировщику.** Нет сетевого скачивания каталога, фоновой отправки, сервера сбора, production-ключей, автоматической публикации в GitHub или изменений onboarding consent. Проверка библиотеки — не проверка развернутого облака.

## Что проверено в этой попытке

- 26 JavaScript regression-скриптов: код 0; новые 31 проверки входят в этот набор.
- Синтаксис 21 производственного JS-файла, один воспроизводимый CSS bundle, сохранённые DOM/nav/view contracts.
- 29 браузерных утверждений в Chromium на полном однофайловом preview: фиктивный API, consent/ошибки/отмена/logout, 360/768/1440 px, две темы. Это не браузер с настоящим новым Go-сервером.
- 54 Go-теста/подтеста **только recipehints**, с `-race`, плюс `go vet` этого пакета: код 0. Запуск с установленным Go 1.23.2 в `GO111MODULE=off`; пакет использует только стандартную библиотеку. Оригинальные go.mod/go.sum не менялись. Эти результаты не подтверждают компиляцию app/dnscontrol.
- Написаны дополнительные Go-тесты dnscontrol и HTTP guards app. Они **не запускались** на требуемом Go 1.26.5.
- `go version` в корне проекта и `go test -count=1 ./...` остановились на загрузке Go 1.26.5. Причина и коды есть в логах.
- Новые туннели, регистрация Cloudflare, реальная DNS-матрица, HIL и установка на роутер не выполнялись.

Полные команды и stdout/stderr сохранены рядом с исходниками в комплекте. Старые validation-файлы в source относятся только к своим прежним ревизиям.
