# С чего начать: RAZVILKA repair.2

Это единый тестовый кандидат от точной rc.6, а не очередной макет.

**Рабочую установку не обновлять вслепую.** Перед аппаратной приёмкой нужны
приватная резервная копия средствами проекта, копия прежнего установочного пакета,
доступ к роутеру вне управляемого VPN и возможность отката. Не выкладывать backup,
VLESS URI, WARP/AWG ключи, пароль, cookies либо токены в публичные issue.

## Для Codex

Использовать полный SOURCE.zip или git.bundle из этого комплекта.
Сначала прочитать `docs/REPAIR2_STATUS_RU.md` и `docs/CODEX_REPAIR2_RU.md`.
Проверить HEAD и незакоммиченные изменения. Не заменять более новую работу владельца
этими файлами целиком. Патч `FROM_RC6` применим к
`cea4b6fec8a3fc807556a045c1c6446fa8932c9d`, а не к main rc.4 или rc.5.

## Для просмотра сайта

Standalone PREVIEW.html использует искусственные snapshots и блокирует записи.
Для настоящего импорта/установки/сохранения нужен новый бинарник со встроенным сайтом.
В нём нет preview fetch. Копирование одного HTML поверх rc.5 не обновляет backend.

## Для тестового роутера

Прилагавшийся Entware-архив (если присутствует в поставке) содержит скрипты
штатного установщика и четыре тестовых ELF из этой исходной ревизии.
Это не релиз из стабильного канала. Сначала сверить SHA256SUMS, модель, архитектуру,
версию ядра и условия установщика, затем использовать его на отдельном стенде.
Самостоятельную подстановку непроверенного kernel-модуля этот комплект не выполняет.
`install-entware.sh`, `upgrade-entware.sh` и rollback уже входят в проект;
сначала изучить их параметры и readme, не вызывать bootstrap/latest для получения
этого локального кандидата — в GitHub он не опубликован.

Первый запуск нового каталога содержит только шесть NFQWS2-групп. В мастере выбрать
область устройств, подтвердить состав и отдельно импортированные дополнения.
Сохранение мастера — разрешение на последующую проверку, не доказательство доступа.
При обновлении ранее настроенного роутера каталог и выбранные сервисы сохраняются.
