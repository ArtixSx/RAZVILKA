# PR-NFQ1 — честное состояние NFQWS2 в интерфейсе

PR-NFQ1 меняет только представление состояния сервиса и не меняет firewall,
NFQUEUE, конфигурацию NFQWS2, процессы или поведение маршрутизации.

## Что реализовано

- API раздельно возвращает выбранное, рассчитанное, применённое и фактически
  подтверждённое состояние маршрута.
- Старые поля API сохранены для совместимости существующих клиентов.
- В простом режиме обычному пользователю доступны AUTO и DIRECT. Уже выбранный
  принудительный маршрут не подменяется: интерфейс показывает его и предлагает
  перейти в расширенный режим.
- Результат AUTO через NFQWS2 стал кликабельным. Боковая панель показывает
  движок, профиль, стратегию, evidence и владельца, а неизвестные данные честно
  обозначает как неизвестные.
- Для выключенного сервиса рассчитанный маршрут подписан как рекомендация, а не
  как работающий обход.
- Внешний владелец z2k показывается отдельно и не выдаётся за управляемый
  RAZVILKA NFQWS2.

## Что намеренно не входит в PR-NFQ1

Следующий PR-NFQ2 должен быть только read-only этапом ownership/inventory:

1. единый снимок процессов, init-скриптов, NFQUEUE, firewall-правил, assets и
   владельца без захвата чужого runtime;
2. явные состояния `native-managed`, `external-z2k`, `external-unknown`,
   `collision` и `missing`;
3. provenance для обнаруженных аргументов, списков и правил;
4. API и Pro-интерфейс инвентаризации без установки, остановки, миграции или
   изменения конфигурации;
5. тесты конфликтов, stale inventory и отсутствия runtime-зависимости от z2k.

В PR-NFQ2 запрещены автоподбор, применение стратегии, управление daemon,
изменение NFQUEUE/firewall и автоматическая миграция z2k. Эти операции относятся
к последующим отдельным этапам и требуют аппаратной проверки.

## Отдельный аппаратный долг USQUE

На эталонном роутере Telegram через существующий интерфейс USQUE `opkgtun0`
ответил `HTTP 200`. Ошибка выбора в RAZVILKA возникала до service canary:
унаследованный каталог staging USQUE имел права `0755`, тогда как приватный
конфигуратор обоснованно принимает только `0700`.

Совместимость исправлена ограниченной нормализацией прав только известных
каталогов RAZVILKA. Это не доказывает успешный managed apply: его ещё нужно
повторить на роутере с разрешённым применением и подтвердить exact Telegram
canary, rollback и сохранение обычного интернета.
