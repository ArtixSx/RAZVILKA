# N1.3 — точная проверка отдельного узла

Статус: локально реализовано в цикле `0.18.1-dev`, без публикации и без
аппаратного подтверждения. Проверка не назначает узел сервису и не изменяет
рабочие маршруты.

## Что проверяется

Одна операция принимает только сохранённый приватный узел и контрольный сценарий
из каталога RAZVILKA. Она последовательно выполняет:

1. строгий разбор единственного outbound без `detour`, selector и пользовательских
   правил;
2. DNS и запрет локальных, частных, loopback и link-local адресов;
3. дешёвую транспортную проверку, которая никогда не считается доказательством
   рабочего ключа;
4. создание изолированной конфигурации и запуск временного Sing-box SOCKS только
   на `127.0.0.1:19181`;
5. проверку PID, запуска, конфигурации и владельца локального порта через route
   passport;
6. получение IP через точный outbound и сравнение с независимым прямым запросом;
7. сервисный canary с теми же строгими HTTP-условиями, что использует Test Lab.

DNS-адрес удалённого узла закрепляется в временной конфигурации. Исходное имя
сохраняется для TLS SNI и HTTP/WebSocket Host, чтобы повторное DNS-разрешение не
могло незаметно направить проверку в локальную сеть.

## Результат и срок действия

NodeStore schema 3 хранит не более 20 безопасных результатов на узел. В записи
есть узел, сервис, обезличенный профиль текущей сети, уровень проверки, verdict,
IP выхода через узел, HTTP-статус, задержка и срок действия. Endpoint, UUID,
пароль, прямой IP и сырые ошибки процесса не сохраняются и не возвращаются UI.

Положительный результат требует `service-confirmed`, точного route ID и
несовпадения с прямым IP. Он становится `stale` после TTL или при смене сети.
Отключённый узел нельзя повысить результатом проверки, которая началась раньше.
Повторный ProbeID и устаревшая запись отклоняются.

## Очистка и отказ

Проверки сериализованы: одновременно работает не более одного временного
процесса. Конфигурация, PID, паспорт запуска и журнал удаляются после любого
исхода. Ошибка очистки снимает положительный verdict и блокирует доверие к
результату. При запуске RAZVILKA выполняется recovery временного runtime.

Открытый TCP-порт, успешный локальный запуск, HTTP-ответ через DIRECT или ответ
не того сервиса не делают узел доступным. UI показывает одну кнопку «Проверить»,
четыре понятных этапа и последний подтверждённый IP выхода.

## Автоматические проверки

- успешный точный путь и сервисный ответ;
- эквивалентная IPv6-запись прямого IP как direct leak;
- открытый TCP-порт при нерабочем протоколе/ключе;
- заблокированный сервис и отказ cleanup;
- запрет chained, WireGuard и локальных outbound;
- сериализация параллельных запусков;
- bounded history, TTL, schema migration и запрет promotion отключённого узла;
- HTTP API не меняет рабочие маршруты и принимает только catalog-owned probe.

До него `selectable=0` намеренно сохраняется. Перед публикацией нужны Linux
