# Безопасный точечный ремонт `ndmc` для USQUE

## Что исправляется

Некоторые старые init-скрипты USQUE запускают системный `/bin/ndmc` из окружения
Entware. Библиотеки из `/opt` могут затенить библиотеки Keenetic, из-за чего
`ndmc` не отвечает, хотя та же команда работает с
`LD_LIBRARY_PATH=/lib:/usr/lib`.

RAZVILKA не задаёт этот путь глобально. Она добавляет окружение только перед
конкретным вызовом `/bin/ndmc`.

## Предохранители

1. Doctor сначала проверяет обычный и изолированный вызов без записи.
2. Ремонт доступен только после явного подтверждения пользователя.
3. Принимаются только две однозначные формы поддерживаемого init-скрипта:
   отдельная команда `/bin/ndmc …` и такая же команда внутри `$()`.
4. Переменные, `echo`, shell control flow, несколько вызовов в строке,
   глобальный или нестандартный `LD_LIBRARY_PATH` блокируют ремонт.
5. До изменения создаётся точная закрытая копия с правами `0600`.
6. Before/after записываются в постоянный журнал до первой записи.
7. После атомарной замены выполняются `sh -n` и read-only `ndmc -c show version`
   с системными библиотеками.
8. При любой ошибке исходный файл возвращается. После аварийного завершения
   журнал восстанавливается до открытия API и запуска фоновых задач.
9. Ремонт не запускает и не останавливает USQUE, не меняет DNS, `session.conf`,
   маршруты или рабочий dataplane.

## Что видит пользователь

В «Диагностика → Проверка USQUE» отображается один из итогов:

- изменение не требуется;
- доступен безопасный точечный ремонт;
- ремонт заблокирован с понятной причиной.

После успешного ремонта Doctor запускается повторно. Перезапуск USQUE остаётся
отдельным осознанным действием: успешный `ndmc` ещё не доказывает WARP, egress
или доступность Telegram.

## Проверки

- успешное изменение и повторный запуск без дополнительных правок;
- точная резервная копия и права `0600`;
- искусственная ошибка проверки с byte-for-byte rollback;
- повреждённый журнал блокирует запись и сохраняется для разбора;
- recovery не создаёт каталог на системах, где ремонт никогда не использовался;
- неоднозначные shell-строки отклоняются;
- API требует подтверждение и использует эксклюзивный operation gate.

На ARM64-роутере текущий upstream init проверен без записи: оба его вызова
`ndmc` уже используют локальное системное окружение. Кнопка ремонта там не
нужна и не должна появляться.

Изолированный ARM64 test binary затем выполнен на том же роутере. Пройдены
успешный patch, идемпотентность, rollback после искусственной ошибки,
повреждённый журнал, чистая история после удаления пакета и все отрицательные
варианты shell-строк. Тест работал только во временных каталогах, после проверки
удалён; установленная RAZVILKA осталась `0.18.0` и healthy.
