# Отдельная аппаратная приёмка RAZVILKA

Этот сценарий подготовлен для выделенного стенда. Он не выполнялся на физическом
роутере и не разрешает изменение действующего устройства. Перед запуском нужны
явная авторизация владельца, отдельный LAN-клиент и восстановление вне панели.
Обычный startup должен сам допустить точный профиль из
[RUNTIME_SUPPORT_RU.md](RUNTIME_SUPPORT_RU.md); fixture tags и подмена профиля на
роутере не используются. Неподдержанный профиль фиксируется как отказ, не обходится.

## Что предоставить для продолжения

- Выделенный роутер: точная модель, прошивка, архитектура, ядро и состав Entware.
- Отдельный LAN-клиент, тестовый WAN и управляемый TLS-сервис с двумя доменами
  на одном IP; один домен выбран, второй служит отрицательным контролем.
- Тестовые VLESS/WG/AWG/Mihomo credentials через штатный защищённый импорт.
  Секреты и полный приватный backup не публикуются в CI/issue.
- Разрешение на установку конкретного SHA и отдельное разрешение на reboot,
  WAN change и отключение питания именно этого стенда.
- Доступ к восстановлению вне панели и проверенная копия исходной совместимой пары.

## Исходные данные

Зафиксировать SHA контроллера и компонентов, версии reader capabilities, время,
профиль WAN, scope списка/устройства/сервиса, исключения и исходный маршрут клиента.
Снять ограниченные диагностические данные процессов, интерфейсов, обеих семейств
правил и очередей штатными средствами диагностики. Эти данные служат сравнением,
а не разрешением запускать или удалять чужие ресурсы.

## Сценарии и критерии

| Сценарий | Действия на выделенном стенде | Требуемое наблюдение |
| --- | --- | --- |
| Пара binary + StrategyLab | Создать историю и manual выбор, экспортировать encrypted backup; выполнить поддержанное обновление и восстановление через штатный механизм | Восстановлены совместимые версии и точные данные истории/manual intent; после рестарта старый PASS не становится текущим runtime evidence; панель доступна |
| Неизвестное завершение | Воспроизвести предусмотренный сбой update/restore, затем штатное recovery | unknown/finalizing сохраняют запрет, пока исходный журнал/владелец не подтвердит завершение; чужие файлы не перезаписываются |
| Managed NFQWS2 | Native compatibility → scoped HTTPS probe → выбор → поддержанный Apply → health → Stop/recovery | Реальная сервисная семантика, правильные очередь/socket/scope; после Stop отсутствуют именно принадлежащие процесс/правила/очередь; поздний результат не публикуется |
| Сервис на общем IP | Одновременно запросить выбранный домен и соседний домен с того же клиента | Выбранный поток использует назначенный путь; соседний сохраняет исходный IP/порт/маршрут согласно baseline |
| Устройство и исключения | Повторить запрос с выбранного и другого LAN-устройства; включить точное исключение сервиса/домена/адреса | Изменяется только разрешённый scope; исключение проверяется до эффекта и перед публикацией результата |
| DNS и долгоживущий cache | Получить ответ до переключения/Stop и использовать его после завершения capture | Старый synthetic address не указывает на чужой сервис; baseline/retirement сохраняются до подтверждённого безопасного завершения |
| VLESS full latency | Не менее12 повторов single/selected/all; записать enqueue/start/cleanup/HTTP return, CPU/RSS и browser paint отдельно | Полное время включает очередь и cleanup; сравнение одинаковых scope/сервиса/WAN, ошибки не смешиваются с успешными измерениями |
| Компоненты | Установка/поддержанное обновление/отказ при активном старом процессе/rollback; отдельные native проверки HEV и Mihomo | Точные pinned bytes и receipts; исходный живой процесс блокирует замену; пакетный успех не подменяет сервисную готовность |
| Mihomo live post-boot | После отдельно разрешённого настоящего reboot сохранить исходные plan/digest/config/state/component пути; при остановленной панели выполнить штатный offline retirement с `-retire-mihomo-live-after-boot-plan` и парным `-retire-mihomo-live-after-boot-digest` | Все пять private leases удерживаются до closing наблюдений; текущие процессы/socket/kernel отсутствуют; архив и обе терминальные записи подтверждены; повтор безопасен; config/manual selection не меняются и не получают health |
| Reboot/WAN/power-loss | Только после отдельного разрешения, на предусмотренных фазах и с внешним способом восстановления | Холодная панель доступна; неподтверждённая история не даёт новой authority; исходные чужие маршруты и исключения сохранены |

Для неподдержанного в обычном startup сценария результат — «не допущен», с точным
причинным кодом. Его нельзя отмечать PASS по одной работе панели, компиляции или
модельному тесту. Часовая стабильность Telegram/VLESS — отдельный последний этап
после прохождения точного scope и очистки, с фиксацией обрывов и восстановления.

## Воспроизводимый программный стенд до аппаратной проверки

Использовать workflows точного SHA и их закреплённые зависимости:

- `scripts/test-managed-probe-native.sh`: реальная NFQUEUE/TLS/sole Wait/cleanup;
  режимы production и race имеют раздельные результаты.
- `scripts/test-domain-original-native.sh`: реальные LAN/WAN namespace peers,
  selected TLS, mismatch/opaque и сохранение source ports; диагностическое окно30с
  не заменяет обычную проверку12с.
- `scripts/check-node-native-performance.sh`: полные Check и App queue измерения.
- `scripts/test-mihomo-cold-native.sh`: actual parent death, cold CLI, restored panel.
- `.github/workflows/mihomo-cold-validation.yml`: persistent-route post-boot metadata
  и настоящий CLI; старый boot в программном fixture моделируется, текущие native
  наблюдения реальны. Включает `RAZVILKA_MIHOMO_COLD_SOURCE_NATIVE=1` для
  `scripts/test-managed-probe-native.sh`, пять original leases и повтор retirement.
- `.github/workflows/mihomo-health-validation.yml`: реальные исходные файлы/Gate,
  частичная публикация и повтор архива; terminal service rows моделируются.
- `scripts/test-mihomo-live-native.sh`: реальный Apply/health/Stop/repeat и
  ограниченный CPU profile; пока неуспешный health не считается готовностью.
- `scripts/test-mihomo-main-native.sh`: обычный Main, отказ неподдержанного профиля.
- `scripts/test-mihomo-main-bound-native.sh`: tagged classification для полного
  factory registry с настоящими tool/namespace источниками; это не роутерный допуск.

Изолированные native scripts запускаются только в предусмотренном disposable Linux
CI окружении; они не являются командами установки на роутер.

## Отчёт стенда

На каждый сценарий: SHA, версии/профиль, исходные условия, точные действия,
ожидаемый результат, actual result, длительность, ограниченные диагностические
артефакты, состояние очистки и оставшийся fence. До/после сравнивать одинаковую
нагрузку; не выдавать timeout→PASS за ускорение двух завершённых прогонов.
Статусы software CI, isolated native и physical router хранить отдельно.
