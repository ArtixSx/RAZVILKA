# RAZVILKA · Autonomy A1 — интегрированный кандидат в исходниках

> Исторический документ конкретного этапа. Версии, команды и состояние функций
> ниже относятся к тому этапу. Сейчас используйте [план](ROADMAP.md),
> [текущий статус](CURRENT_STATUS_RU.md) и [установку](INSTALL_RU.md).

Дата: 8 сентября 2026. База: v0.18.1-rc.2, commit c6859b07316d07de3dc1fa243484a96078c5782b.
Рабочая версия исходников: 0.18.2-dev. A1 — имя этого локального этапа, не новый опубликованный релиз.

**Не готовый установочный пакет. Полный backend не скомпилирован и не испытан на роутере.**
Не подменяйте этими файлами рабочую установку. Исходники предназначены для проверки,
сборки и аппаратной приёмки на отдельном стенде. Старые бинарники rc.2 не входят в кандидат.
Репозиторий GitHub, сайт на роутере и действующий релиз не изменялись.

## Что действительно изменено в исходниках

1. Добавлен пакет `internal/autonomy`: валидируемая общая политика, явная область устройств,
   разрешённые источники и четыре протокола, расписания с IANA/timezone/DST, ограниченная
   выборка кандидатов, подтверждение отказа и часовой бюджет переключений.
2. Добавлены API `GET/PUT /api/v1/autonomy`, `POST /api/v1/autonomy/services`,
   `DELETE /api/v1/autonomy/services/{id}`. Настройки сохраняются на роутере через
   существующий CAS-механизм файловых журналов, не в localStorage.
3. Очередь встроена в существующий Go-reconciler, в обработку события `feeds`.
   Формат старого reconciler-журнала с пятью типами задач не расширен. Браузер не запускает
   сетевой цикл и не является условием работы. Обработка одного сервиса за проход,
   общая admission-блокировка, отмена при ручном действии и дедлайн сохраняются.
4. Произвольный пользовательский сервис наследует подтверждённые defaults при явном
   создании/включении, а не при загрузке старых черновиков, backup или подписки.
5. Автоподбор использует существующий exact-checker и NodeStore. Проверяются разрешённые
   origin/protocol, актуальная сеть и свежий service proof. Новая ссылка из разрешённого
   источника может автоматически стать кандидатом в резерв. Результат одного сервиса не
   даёт PASS другому. Активный успешный путь не заменяется ради низкого ping.
6. Подбор уже готовых NFQWS2/USQUE/WARP и последующий узел проходят обычный dataplane
   Plan/Snapshot/Stage/Validate/Canary/Activate/Health/Commit/Rollback. Область устройств и
   чужие черновики не берутся из новой общей формы неявно. Наследованный/ручной fallback
   не управляет одновременно тем же сервисом. Это реализация пути в коде, не HIL PASS.
7. Удаление управляемого сервиса сначала записывает намерение, затем снимает его маршрут
   общей транзакцией, после чего удаляет пользовательское описание. HTTP 202 означает
   очередь, не готовое удаление. Пауза, ручной режим и Safe Mode могут задержать действие.
8. Сохраняются отдельные окна приложения и компонентов. В окне приложения выполняется
   проверка либо вызов штатной подготовки архива. В окне компонентов — чтение актуального
   каталога пакетов. Пропущенное окно не запускает обслуживание днём. После сбоя попытки
   в текущем окне повтор не выполняется до следующего окна. Никакого `opkg upgrade`.
9. В реальный встроенный UI добавлен `autonomy.html`: обзор, четыре шага мастера,
   управляемые сервисы, подписки. Стартовая страница и навигация старой панели связаны с ним.
   Старые разделы настройки обходов сохранены. Это не полная замена всех страниц макета v3.1.
10. Интерфейс использует реальные API. В production-файлах нет искусственного PASS,
    тестового fetch-transport или выполнения будущих таймеров браузером. После сохранения
    private URL очищается из формы; секреты не записываются в постоянное хранилище браузера.

## Важные границы состояния

Новый файл согласия: `<AutomationStatePath>.autonomy.json`, owner `razvilka-autonomy-v1`,
отдельная схема 1, максимум 256 KiB. Исходная конфигурация и старый журнал не получают новой схемы.
Файл не содержит ключей, содержимого HTTP-ответов и профилей; только разрешения и ссылки на ID.
Публичные имена сервисов и адреса устройств всё равно являются локальными пользовательскими данными.

При старте сбрасываются доказательства здоровья/кворум отказа, сохраняются бюджет и ссылки резерва.
История из этого файла никогда не заменяет свежий NodeStore proof. Замена файла на диске,
повреждение или неуспешная запись блокируют новые автономные изменения.

Сбой между успешным config commit и записью sidecar receipt приводит к review, не к слепому
повтору Apply. Согласие пока не включено в общий зашифрованный backup: восстановление профилей
не должно незаметно приносить новое разрешение на автоматическое управление.

Пауза сервиса/общей автоматики не равна остановке маршрутов. Снятие Safe Mode доступно только
отдельным явным подтверждением мастера. Глобальный Stop не снимается самим мастером.

## Проверки в этом окружении

- **74 теста и подтеста пакета `internal/autonomy` прошли с настоящим `-race`.**
  Запущен Go 1.23.2 с отдельным минимальным modfile только для stdlib-пакета; исходный
  go.mod/go.sum не менялись. Это не компиляция интеграции с приложением.
- **2 проверки `internal/projectmeta` прошли с `-race`** тем же способом.
- **45 чистых JavaScript-проверок** новой модели формы прошли.
- **51 браузерная проверка** новых экранов прошла с подставным fetch/API, в том числе
  конфликты редакций, явное согласие, ошибки источников, Safe Mode, очередь удаления,
  отсутствие искусственного результата при добавлении и ширины 390/768 px.
- **22 JavaScript test scripts** (21 прежний и новый autonomy) прошли; число скриптов
  не складывается с числом отдельных assertions как «новые тесты».
- **29 синтаксических проверок JS/shell** прошли. Go parser разобрал **395 Go-файлов**,
  ошибок синтаксиса нет. Синтаксический разбор не проверяет типы/линковку.
- Полные `go test ./...`, integration/race/vet и четыре бинарные сборки НЕ выполнены.
  `go test ./...` остановился до компиляции: go.mod requires go >= 1.26.0.
- Новые тесты `internal/app/autonomy_api_test.go` и `internal/config/autonomy_route_test.go`
  написаны, но НЕ запускались в этом окружении. CI GitHub этого кандидата не запускался.
- Нет HIL, подключения к роутеру, реальных VLESS-тестов, установки пакетов и проверки WAN/reboot.

Первичные результаты находятся в `reports/`. Статусы не переносятся со старого rc.2 на A1.
Навигация HTTP/file в браузере окружения запрещена административной политикой; UI проверялся
через локальную передачу HTML в Chromium (`set_content`) с подставным API. Политику браузера
не меняли. Поэтому это проверка рендеринга/поведения, не проверка HTTP-раздачи Go-сервером.

## Как проверить следующий этап

Работайте с копией исходников на Linux-стенде с Go 1.26.5, C-компилятором и Node.js.
Сначала выполните штатный `sh scripts/check.sh`, затем интеграционные проверки новых API
и полную аппаратную матрицу. Не выдавайте сборку за stable до этих результатов.

Полезные команды на подготовленном стенде:

```sh
go version
go test ./...
go test -race ./...
go vet ./...
node scripts/test-autonomy-ui.mjs
sh scripts/check.sh
```

Все файлы сайта встраиваются Go-сборкой из `cmd/razvilka/web`. Одной заменой HTML в старом
бинарнике rc.2 новые API не появятся. После корректной сборки мастер открывается по
`/autonomy.html`, ссылка есть в обычной панели. Код требует полноценной проверки типов.

Для патча применяйте его к чистому дереву указанного rc.2; сначала `git apply --check`.
Исходный ZIP позволяет избежать наложения на более новую ветку пользователя.

## Предпросмотр

`RAZVILKA_AUTONOMY_A1_PREVIEW.html` — самостоятельное локальное демо нового интерфейса.
Жёлтая полоса явно сообщает об искусственных данных. Fetch заменён только в этом preview,
не в production-исходниках. Изменения исчезают после перезагрузки и не затрагивают роутер.
Preview показывает структуру API/форм, не запускает алгоритм реального обхода.
`preview/preview-transport.js` нельзя включать в рабочую сборку.
