# Cloudflare Provider — пассивная основа PR-1.1

31 августа 2026 года · локальная разработка, без публикации и установки.

После PR-0.3/0.4 начат следующий пункт master-plan. Добавлен самостоятельный
пакет `internal/cloudflareprovider`; он ещё не подключён к API, UI, автопилоту
или прежнему WARP Configurator. Пользовательские профили не мигрируют при
старте приложения и новая регистрация не выполняется.

## Реализовано

- Публичная модель аккаунта с собственным ID, непрозрачной ссылкой на секреты,
  происхождением копии, датами и честным состоянием `imported-unverified`.
- Пассивный импорт обычного WireGuard-профиля и JSON-сессии USQUE из переданных
  байтов. Импортёр не принимает URL/путь и не читает исходные файлы самостоятельно.
- WireGuard: строгая структура, запрет дубликатов, hooks и неизвестных полей,
  проверка ключей, адресов, порта и MTU; fingerprint локально производного
  публичного ключа. Проверка не подтверждает принадлежность профиля Cloudflare.
- USQUE: ограниченный JSON, обязательные непустые поля и отсутствие дубликатов.
  Неизвестные compatibility-поля остаются только в приватной копии. Формат ключа,
  API version и endpoint/assigned-address schema не угадываются: это предмет
  отдельного типизированного адаптера и golden fixtures.
- Приватное хранилище ограничено 32 копиями, каждая до 256 КиБ. Вся запись
  фиксируется атомарно; одинаковый вход возвращает прежний ID, изменённый — новый.
  Исходная конфигурация, активная сессия и runtime не перезаписываются.
- POSIX-каталог должен иметь приватные права, файл создаётся с `0600`.
  Секреты не шифруются от владельца диска/root: это локальное файловое хранилище,
  не обещание защищённого аппаратного vault. Windows требует защиты ACL вне
  этого POSIX-механизма и используется здесь только для разработки/тестов.
- Отдельный публичный DTO и защищённое форматирование импортируемых данных:
  JSON и обычные форматированные сообщения не раскрывают приватный input.
- Хранилище отказывает при повреждении, нарушении прав, symlink и неизвестной
  версии. Повреждённые данные не обнуляются автоматически.
- `.import.lock` исключает одновременную запись несколькими экземплярами.
  После аварийного завершения lock остаётся для явного восстановления: код
  не удаляет чужую блокировку по предположению, что процесс уже завершился.

## Проверки

Прошли unit-тесты импорта, redaction, повторного импорта, перезапуска, ограничения
побочных эффектов, отмены, неизвестного writer, повреждения и symlink. Покрытие
этого первого блока: 83,3% до последнего уточнения redaction-маркеров.
Fuzz-проверка двух форматов: 1 197 969 выполнений за 16 секунд, без падений.
Это локальные тесты на Windows; POSIX-права и Linux/race ещё требуют CI.
После финальных правок прошли полный Go test/vet и кросс-компиляция всех пакетов
и provider tests для Linux arm64/mips/mipsle. Последнее не является запуском
этих тестов на Linux.

## Не завершено в PR-1.1

Продолжение: [адаптеры старых форматов и зашифрованный backup](CLOUDFLARE_LEGACY_IMPORT_RU.md)
реализованы локально. Список ниже уточнён после этого блока.

1. Подключение типизированных USQUE/wgcf adapters к явной миграции старых файлов
   (без удаления или передачи владения исходниками). Внутренние адаптеры готовы.
2. Модель transport candidates, registration API/DNS evidence и secret access
   contract для будущего регистратора/экспортёров.
3. Интеграция внутреннего encrypted backup/merge restore в общий recovery;
   восстановление interrupted import с доказанным владением блокировкой.
4. Аутентифицированные preview/import/list API и понятный UI; не добавлять
   секреты в обычный status, diagnostics, audit или публичный export.
5. Linux/race, тесты POSIX-прав и аппаратный gate перед подключением к живым
   профилям. PR-1.2 начинается с локальных ключей/mock API, не live registration.

Текущий WARP/USQUE lifecycle сознательно сохранён. Новый модуль пока не является
«исправленным WARP» и не доказывает доступность Telegram через туннель.
