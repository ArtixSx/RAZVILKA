# Политика сервиса и общая очередь автоматики

8 сентября 2026. AUTO0 и основа AUTO1 реализованы локально. Этот документ
описывает контракт кода, не аппаратную приёмку и не готовность полной
автоматизации из раздела 55 пользовательского плана.

Для применённой резервной группы Sing-box сервер самостоятельно проверяет
текущий узел и фактический маршрут, а после подтверждённого отказа проверяет
разрешённых участников и применяет подходящий резерв через существующую
транзакцию. Открытый браузер не нужен. Получение новых участников из подписки
с последующей автоматической проверкой и включением в резерв пока не реализовано.

## Правило и ручные изменения

`config.json` использует schema 2; поле `service_policies` имеет собственную
schema 1. Старый конфиг читается без изменения применённых маршрутов. При
первой обработке уже применённой fallback-группы фиксируются её участники,
источники, классы доверия и точная область устройств с `legacy_opt_in=true`.
Новые записи подписок или новые участники группы не расширяют это разрешение.

Политика содержит режим auto/manual/paused, разрешённые движки, идентификаторы
узлов и источников, классы доверия, закреплённый узел, допустимость его резерва,
сценарий, интервал проверки, паузу между переключениями и часовой лимит замен.
Пустая область устройств обозначает всю LAN и должна явно показываться в UI.
Сохранение политики не изменяет область устройств и не применяет маршрут.

Ручное изменение сервиса или применение конкретного узла отзывает прежнее
автоматическое намерение: policy revision повышается, режим становится ручным.
Остальные сервисы сохраняют свои правила. Пауза не удаляет применённый маршрут.
Восстановление идентичного ранее применённого runtime после запуска остаётся
отдельной операцией восстановления; оно не выбирает новые узлы.

## API

- `GET /api/v1/service-policies`: config revision, policies по service ID,
  признаки persisted/state/reason, capabilities и состояние очереди. Чтение
  предлагает значения для ненастроенных сервисов без сохранения или запуска.
- `PUT /api/v1/service-policies/{id}`: `config_revision`, `expected_revision`,
  объект `policy` и `confirm: SAVE_SERVICE_POLICY`. Сверяются обе версии и
  текущая применённая область устройств. Ответ `live_applied:false` относится
  к сохранению настройки, а не к будущему разрешённому действию worker.

Поддержанный автоматический выбор сейчас ограничен применённой fallback-группой
Sing-box и веб-проверкой. Требования UDP, IPv6, региона выхода, других сценариев
и terminal actions DIRECT/block дают `blocked-by-capability`. Единственное
реализованное действие при исчерпании резерва — сохранить существующий маршрут,
показать отсутствие подтверждённого резерва и повторить ограниченную проверку.
Разрешение выпуска credential само по себе не запускает регистрацию.
Общий междвижковый AUTO не получает право обходить эти ограничения через
прежний SmartRoute timer.

## Очередь и запуск

Один app reconciler планирует существующие node recovery, group fallback,
обслуживание применённого runtime, события обновления источников и
[проверки выбранных сервисов по таймеру](SERVICE_CONTROL_RU.md). У подписок
остаётся один ограниченный исполнитель; ручной refresh и scheduled refresh
используют одну очередь. Отдельные старые Start-методы сохранены для совместимых
тестовых вызовов, production main их таймеры не запускает.

Рядом с конфигом хранится `<имя-конфига>.automation.json`: не более пяти
записей текущих типов операций и 128 checkpoint сервисов. Там находятся ID,
версии config/policy/nodes, fingerprint сети, deadline/attempts/next_run,
состояние последнего раунда и лимит переключений. Это метаданные, не разрешение
повторить сохранённый apply. Credentials и ответы сетевых проб не сохраняются.

Перед работой записывается намерение; до переключения резервируется часовой
лимит. После перезапуска требуется свежая проверка, cached Healthy/PASS не
восстанавливается. Hold-down и потраченный лимит сохраняются. Сначала действует
уже существующее восстановление transaction journal и owned checker cleanup.
Повреждение или внешняя подмена журнала блокирует автоматику без перезаписи
чужого файла. Отмена не освобождает operation lease до окончания cleanup/rollback.

## Оставшаяся приёмка

Локальные тесты проверяют policy CAS, сохранность scope, pause/pin/trust,
нерасширение legacy opt-in, отзыв права при ручном изменении, автоматический
цикл двух узлов, сохранение лимита после запуска и fail-closed журнал.
Есть проверки с Windows race detector. Нужен новый объединённый ARM64 HIL:
два узла, закрытый браузер, отмена/ручное вмешательство, восстановление после
запуска и отрицательный LAN-контроль. Реальный reboot/WAN и 24–72 часа
непрерывной автоматической работы остаются самостоятельными gates.
