# Единый план развития RAZVILKA

Актуально для цикла `v0.17.0-dev` на 28 августа 2026 года. Этот документ заменяет разрозненные списки из
старых прототипов. Пункт считается завершённым только после теста на реальном
роутере и фиксации результата; наличие кнопки в UI не считается готовой
функцией.

Актуальный подтверждённый срез и порядок ближайших изменений находятся в
[ARCHITECTURE_GAP_2026-08-28.md](ARCHITECTURE_GAP_2026-08-28.md). Порядок по
умолчанию: release hygiene и build provenance → исправления DNS-каталога →
Evidence v2 → read-only USQUE Doctor v2. Repair USQUE, live DNS и AutoPilot не
реализуются раньше этих ворот.

## Цель продукта

Пользователь устанавливает локальный Web UI одной командой, выбирает нужный
сервис, а RAZVILKA проверяет доступные обходы, выбирает подтверждённый вариант,
применяет его транзакционно и объясняет результат простым языком. Экспертный
режим остаётся доступен, но не требуется для обычной работы.

## P0 — правда, безопасность и восстановление

- [x] Транзакции `plan → snapshot → stage → validate → apply → health → commit`
  с обратным rollback и объектами только под ownership RAZVILKA.
- [x] При переходе на DIRECT, другой обход или выключенное состояние прежний
  неиспользуемый адаптер входит в тот же snapshot/rollback-контракт и не может
  остаться скрыто активным после сохранения нового состояния.
- [x] Единые уровни доказательности: каталог, конфигурация, runtime,
  подтверждённый маршрут, подтверждённый сервис через маршрут.
- [x] Evidence v2 сохраняет структурированный факт с probe ID, временем,
  route path, outcome, HTTP-кодом, latency, confidence, source и error code.
  Совместимый линейный уровень остаётся в API, но 403/451, TLS/content mismatch
  и unsuitable edge больше не могут стать `service-confirmed`; интерфейс
  показывает источник, возраст и устаревание факта.
- [x] Уровень доказательности показан в карточках сервисов, обзоре, Apply и
  диагностическом отчёте. Desired/planned state никогда его не повышает;
  подтверждение восстанавливается только из совпадающего committed-плана.
- [x] Добавить контрольные отрицательные проверки, чтобы отличать результат
  обхода от обычного доступа, DNS-кэша или постороннего туннеля.
- [x] Отказ подключения к локальному SOCKS не считается подтверждением
  маршрута. Официальный USQUE `nativetun` проверяется отдельно через адрес
  `opkgtun0` и совпадающий kernel route; Sing-box не заявляется его зависимостью.
- [x] Контекстно отменяемая сериализация конфликтующих dataplane-операций;
  rollback получает отдельный ограниченный контекст даже после отмены Apply.
- [x] Ограничения времени для Apply, сетевых тестов, загрузок и операций
  компонентов; UI-запрос может отменить ожидание, не лишая rollback времени.
- [x] Детектор конфликтов портов, интерфейсов и NFQUEUE включён в реальный план
  Apply, а не только в диагностический экран.
- [x] До изменения системы проверяются порты, интерфейсы, NFQUEUE, владелец DNS
  `:53`, зарезервированные policy priorities и таблицы маршрутизации. Чужие
  правила становятся блокером выбранного адаптера и никогда не удаляются.
- [x] Журнал действий с понятным итогом, причиной, длительностью и ссылкой на
  технические данные без секретов.
- [x] Recovery Safe Mode и boot-loop guard после неудачного восстановления:
  RAZVILKA удаляет только свои runtime-объекты и требует нового подтверждения.
- [ ] Canary Apply через отдельный контракт адаптеров до замены рабочего
  процесса/списков; текущий pre-commit health остаётся обязательным.
  - [x] Нейтральный adapter-scoped контракт, canary до `activate` и обязательный
    rollback при его ошибке; sing-box, Xray и USQUE/MASQUE проверяются временным
    loopback SOCKS-кандидатом без TUN и policy routing.
  - [ ] Отдельные canary для NFQWS2, WARP WireGuard и AmneziaWG с аппаратным
    подтверждением до признания общего пункта завершённым.
    - [x] WARP WireGuard: временный интерфейс, source-only policy, Cloudflare
      trace, handshake по UDP `2408/500/1701/4500` и сервисная проба выполняются
      до Activate. На ARM64 подтверждены отказ handshake у текущего провайдера,
      полное удаление интерфейса/rule/table и сохранение рабочего маршрута.
      Отрицательный результат считается успешной проверкой безопасности, но не
      доказательством работоспособности самого WARP.
- [ ] Нейтральный RoutePlan IR, чтобы адаптеры не меняли глобальное состояние
  вне общего транзакционного контракта.
  - [x] Первый срез IR передаёт canary только маршруты, действия и resource
    claims конкретного адаптера; legacy-фазы будут мигрировать поэтапно.
- [ ] Разделить черновики по областям: **Сервисы**, **Настройка обходов**,
  **Устройства**, **DNS** и **Источники**. На каждой вкладке должны быть свои
  `Сохранить / Проверить / Применить / Отменить`; общий экран показывает сводку
  и позволяет применить только выбранные совместимые области одной транзакцией.
  - [x] **Сервисы** применяют только `enabled/route`, **Устройства** — только
    `sources`, а **Настройка обходов** — выбранный движок. Каждая вкладка имеет
    независимые Apply/Discard и отдельный индикатор черновика.
  - [x] Адаптер может прочитать staged-конфиг движка только при явном
    `engine/file` в RoutePlan; device-only применение не захватывает чужой
    черновик Sing-box, NFQWS2, WARP или AmneziaWG.
  - [x] DNS имеет собственный persistent-черновик, индикатор, проверку,
    Apply/Discard и не блокирует применение Сервисов или Устройств. Пока нет
    платформенного live-адаптера, кнопка заранее отключена с точной причиной.
  - [x] Источники имеют persistent desired/applied выбор, независимые
    Save/Discard и отдельное обновление только подтверждённых списков.
  - [x] Добавить совместимый multi-scope preview перед общим Apply: он явно
    разделяет включённые и отложенные области, называет проверки, откат и
    блокирующие причины до подтверждения.
- [x] Черновик одной области не должен блокировать несвязанную вкладку. Если
  зависимость действительно есть, интерфейс обязан назвать её: например,
  «профиль WARP создан, но ещё не назначен ни одному включённому сервису», и
  предложить две явные кнопки — **Назначить сервис** или **Удалить этот черновик**.
- [x] Недоступный обход нельзя сохранить как желаемый маршрут: неустановленные
  варианты показываются отдельно с действием **Установить**, а устаревшее
  назначение автоматически переводится в понятное состояние «требуется
  действие», не выдавая его за рабочий маршрут.
- [x] В карточке каждого сервиса есть понятное действие **Списки**: оно
  показывает домены, IPv4/IPv6 CIDR, подключённые источники и время их
  последнего обновления. Каталожный список явно отделён от доказательства
  реальной доступности маршрута.

## P1 — локальные обходы и полный блок

- [x] Профили сети/WAN/провайдера: отдельная память результатов для разных
  подключений вместо переноса старого «рабочего» решения.
- [x] Память NFQWS2-стратегий по сервису, TCP/QUIC и IPv4/IPv6: старые evidence
  теряют вес каждые 12 часов, пригодность требует три свежих подтверждения, а
  незакреплённый выбор после трёх последовательных изолированных отказов
  возвращается к свежему подтверждённому кандидату. Рабочий NFQWS2 из
  Strategy Lab напрямую не переключается.
- [x] Безопасный глубокий подбор NFQWS2: последовательные пробы, лимит 15 секунд,
  остановка при нехватке RAM или высокой системной нагрузке.
- [x] Read-only контроль FastNAT/offload: состояние читается из доступного kernel
  sysctl, выводится в RoutePlan и не меняется без явного действия пользователя.
- [ ] Управляемый autohostlist: базовые `MODE_AUTO`, `auto.list` и исключения уже
  доступны в настройке NFQWS2; ещё нужна подтверждённая детекция блокировки с
  защитой от ложных добавлений и отдельным откатом списка.
- [ ] Telegram: официальные IPv4/IPv6 CIDR и обязательные независимые проверки
  сайта, Web-клиента и Core/API готовы. Ещё нужны MTProto/media/voice и
  контроль DNS/IPv6 с реального клиента.
- [ ] Подключить ByeDPI и специализированный YouTube-адаптер только после
  реализации общего ownership/rollback/evidence-контракта.

## P2 — туннели, прокси и провайдеры

- [x] В установке, обзоре и настройке прямо объясняется назначение sing-box:
  это универсальный клиент VLESS/Reality, Hysteria2, TUIC и Shadowsocks для
  удалённого узла; одна установка доступ не создаёт.
- [ ] Provider/subscription manager:
  - [x] одиночные URI VLESS/Reality, Hysteria2, TUIC и Shadowsocks;
  - [x] многоузловые текстовые и Base64-подписки, JSON-массивы и JSON sing-box;
  - [x] безопасный предпросмотр без UUID/паролей/ключей и нормализация без чужих inbounds/routes/API;
  - [x] YAML Clash/Mihomo: импортируются только поддерживаемые proxies, а чужие
    DNS, rules, группы, providers, scripts и external controller отбрасываются;
  - [x] явный выбор начального узла перед созданием черновика;
  - [ ] локальный реестр провайдеров и ручное обновление подписок;
  - [ ] тест handshake/egress/сервиса, срок действия и причины отказа без
    показа секретов.
- [ ] Generic Tunnel для уже существующего интерфейса, Tailscale/Headscale и
  SSH SOCKS — только при явном подтверждении маршрута.
- [ ] Единый Cloudflare Provider для WARP WireGuard и MASQUE: endpoint scan,
  IPv4/IPv6, MTU, handshake, egress и service probes. WARP остаётся best-effort.
- [ ] Мастер восстановления **WARP · MASQUE / USQUE**. Подробный контракт:
  [USQUE_RECOVERY_PLAN_RU.md](USQUE_RECOVERY_PLAN_RU.md). Кратко:
  - отдельно диагностировать DNS регистрации, доступ к Cloudflare API,
    регистрацию/ключ, endpoint, QUIC/UDP, HTTP/2/TCP и прохождение сервиса;
  - разрешить эксперимент с Quad9 только как ограниченную candidate-транзакцию;
    не оставлять глобальный `/etc/resolv.conf` изменённым после операции;
  - старый `session.conf` сохранять до подтверждения новой сессии, никогда не
    удалять первым действием;
  - новый профиль запускать на отдельном локальном SOCKS-порту, подтвердить
    `warp=on`, egress и Telegram, затем выполнить canary/commit либо rollback;
  - учитывать rate limit Cloudflare, cooldown и явное принятие условий;
  - не обещать смену страны/POP: DNS может помочь регистрации, но локация WARP
    преимущественно определяется сетью Cloudflare и маршрутом провайдера.
  - [x] До восстановления сессии проверять текущий профиль отдельным SOCKS-
    кандидатом: наследовать безопасный SNI, последовательно пробовать QUIC и
    HTTP/2, требовать реальный ответ выбранного сервиса и запоминать только
    подтверждённый транспорт.
  - [x] Добавить read-only **USQUE Doctor**: пакет/feed/архитектура, безопасные
    поля `usque.conf`, наличие обязательных полей сессии без их значений,
    init/TUN, обычный и clean-env `ndmc`, Cloudflare API, публичные endpoints,
    маршрут до endpoint и предупреждение об IPv6.
    - [x] Первая безопасная версия: архитектура и дубликаты официального feed,
      binary/config/session без значений секретов, init/TUN, обычный и clean-env
      `ndmc`, Cloudflare API и интерфейс маршрута до публичного endpoint.
    - [x] Добавить отдельную IPv6-матрицу и `warp=on/colo/loc` через
      изолированный candidate. Результат сохраняется только после отдельного
      ответа назначенного сервиса; технический WARP и сервисное доказательство
      показаны раздельно.
    - [x] Отсутствующие init/IFACE/ip prerequisites больше не пропускаются
      молча: зависимые проверки получают `SKIPPED` с причиной, а API/UI сохраняют
      совместимые `ok/state` и дополнительно показывают итог
      `READY/DEGRADED/BLOCKED/UNKNOWN`.
    - [x] Doctor v2 показывает версии пакета/ядра/конфига раздельно, безопасное
      окружение, заявленный интерфейс и степень подтверждения владельца TUN.
      Endpoint Cloudflare через собственный TUN определяется как routing loop;
      отдельный тест подтверждает, что Doctor не меняет файлы и вызывает только
      фиксированные read-only команды. Для конфигурации, сессии, бинарника и
      init показываются только безопасные метаданные (права, UID, дата, размер,
      SHA-256), отдельно — последняя найденная резервная копия без содержимого.
  - [ ] Добавить безопасный ремонт `ndmc` только как preview → backup → точечный
    patch init-скрипта → проверка → rollback; глобальный `LD_LIBRARY_PATH`
    запрещён.
    - [x] Read-only preview считает вызовы `ndmc`, отличает уже изолированные
      команды от глобального `LD_LIBRARY_PATH`, показывает будущие шаги и
      блокеры без возврата содержимого init-скрипта. Backup/patch/rollback
      остаются отдельным следующим этапом и пока не выполняются.
  - [ ] Проверять bootstrap-домены Cloudflare и выбранный SNI через NFQWS2,
    не добавляя списки и не перезапуская обход без подтверждения пользователя.
  - [x] Показывать `warp=on`, `colo`, `loc` и egress отдельно от доказательства
    Telegram: исправный WARP-туннель не равен решённой блокировке сервиса.
  - [ ] Chained transport: направлять только публичный MASQUE endpoint через
    внешний WireGuard/VLESS-профиль с защитой от routing loop. Не включать
    `0.0.0.0/0` и не применять автоматически.
- [ ] Не преобразовывать WARP в AmneziaWG: это разные протоколы и серверная
  сторона Cloudflare не поддерживает AWG-обфускацию.

## P3 — DNS и сетевой dataplane

- [ ] Отдельная вкладка **DNS**: простой режим, независимо отслеживаемый
  безопасный черновик и контекстные Apply/Discard готовы; экспертный режим и
  live-применение ещё не включены.
- [x] Готовые профили: автоматически, без рекламы, защита от вредоносных
  доменов, семейный, приватный и без фильтрации.
- [x] Встроенные провайдеры: системный/Keenetic, Cloudflare, Google, Quad9,
  AdGuard DNS, Control D Unfiltered/Uncensored, Xbox DNS, UncensoredDNS,
  FlashStart и персональный NextDNS с проверяемым локальным ID профиля.
  UncensoredDNS работает только через DoH/DoT и больше не предлагает
  отключённый оператором port 53. FlashStart помечен как лабораторный
  negative-control и запрещён для USQUE/AutoPilot из-за риска подменённого
  API-ответа и TLS-сертификата.
- [x] Произвольный DNS-провайдер: до четырёх обычных DNS endpoint, HTTPS-only
  DoH и DoT; ввод нормализуется, проверяется и остаётся локальным черновиком.
  Локальные/частные адреса закрыты по умолчанию и требуют явного режима
  «мой DNS в LAN»; адрес проверяется повторно перед соединением.
- [x] Read-only проверка UDP/TCP, DoH и DoT выполняется отдельно и показывает
  результат по каждому typed endpoint. Конкурентность ограничена, DoH допускает
  не более двух HTTPS redirect в пределах исходного origin, TLS verification
  никогда не отключается.
- [ ] Live-транспорты UDP/TCP, DoH, DoT, DoQ и DoH3; bootstrap DNS задаётся
  отдельно, чтобы исключить циклы разрешения.
- [ ] Раздельные роли: DNS роутера, DNS через обход, bootstrap и DNS конкретного
  сервиса. Persistent-привязка DNS к сервису и понятный UI уже готовы как
  безопасный черновик; live-диспетчер, правила устройств/групп и hardware
  rollback test ещё не реализованы.
- [x] DNSSEC read-only evidence: запрос отправляется с EDNS DO, а интерфейс
  честно показывает только факт `resolver-reported AD`; локальную
  криптографическую валидацию это не имитирует.

## P4 — AutoPilot и понятный интерфейс

- [ ] Мастер первого запуска: пароль, режим безопасности, сервисы, доступные
  обходы, первая проверка, Apply и понятный итог.
- [ ] Одна основная рекомендация на экран; технический JSON только в раскрываемом
  блоке. Ошибка всегда содержит причину и безопасное следующее действие.
- [ ] AutoPilot последовательно проверяет дешёвые варианты, учитывает ресурсы
  роутера, сохраняет подтверждённый выбор и не переключается без достаточной
  разницы или отказа текущего маршрута.
- [ ] Repair Wizard для DNS, времени/TLS, offload, NFQUEUE, TUN, MTU, WARP и
  конфликтующих VPN с preview перед исправлением.
- [ ] Импорт/экспорт публичных профилей без секретов и зашифрованных приватных
  резервных копий с версией схемы и миграцией.
- [ ] В простом режиме заменить глобальное «Применить всё» на контекстное
  сохранение текущей вкладки. Перед финальным Apply показывать короткий diff:
  что изменится, какие сервисы затронуты, какой обход будет установлен/запущен,
  какая проверка обязательна и как будет выполнен откат.
- [x] Контекстные Apply/Discard в **Сервисы**, **Устройства**, **DNS** и
  **Источники** действительно независимы; глобальная панель остаётся сводкой.
- [x] Исправить UX ошибки «черновик есть, но кнопка ничего не делает»: кнопка
  всегда либо запускает действие с прогрессом, либо заранее disabled и рядом
  написана одна конкретная причина и следующее действие. Технический JSON —
  только в раскрываемом блоке.
