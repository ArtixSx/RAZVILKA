# N1.1 — основа приватного хранилища узлов

Локальная разработка, 4 сентября 2026. Это библиотека и тесты, не подключённая
страница UI, не загрузчик подписок и не новый рабочий маршрут.

## Реализовано

- `internal/nodestore`: модели Source, Node, Origin, внутренний SecretRef и
  безопасная сводка Health. На этом этапе Health всегда `not_checked`;
  источники не могут присвоить PASS, available или selectable.
- Явный импорт через строгий `providerprofile`. Частичный импорт требует
  `acceptPartial`; полностью ошибочный пакет не меняет сохранённые данные.
  Для нового хранилища дополнительно запрещён TLS insecure у всех принимаемых
  протоколов; это не меняет прежний отдельный путь импорта в Sing-box.
- Имя узла генерируется, адрес замаскирован. Сводка не содержит UUID, пароля,
  исходного alias, SNI, URI, private material или ссылки на secret storage.
  Source содержит только внутренний ID и тип, без URL/token подписки.
- Идентичность — HMAC-SHA256 нормализованного outbound без имени. Ключ HMAC
  хранится только в приватном документе: ID стабилен после перезапуска/смены
  alias, но меняется при смене credentials/endpoint/transport. Это локальная
  идентичность хранилища, не публичный глобальный fingerprint.
- Одинаковый узел из разных источников сохраняет несколько Origin с received/
  expires. Источник нельзя незаметно переименовать из community в manual.
  Удаление из очередного списка пока не удаляет сохранённые узлы.
- До canary узел остаётся `quarantined`; после истечения всех Origin — `expired`.
  Обновление TTL не даёт здоровья. Community/subscription всегда `untrusted`;
  ручные и legacy — только `user-supplied`, не «доверенные».
- Ограничения: 512 узлов, 64 источника, 4 МиБ приватного документа, TTL до 30 дней.
  Лимиты входного импортера сохраняются. Ошибка лимита не меняет старое состояние.

## Запись и сбои

`nodes.private.json`, schema 1, содержит метаданные и отдельный массив секретов
**в одном атомарном документе**. SecretRef не является путём. Нет двух независимо
записываемых файлов, которые могут разойтись при сбое. Нормализованные узлы,
ссылки, origins, ID и schema перепроверяются при чтении. Неизвестная schema,
повторные/лишние JSON-поля, повреждение или подмена материала блокируют открытие;
повреждённый файл не заменяется пустым.

Используется существующий `restorejournal.FileTarget`: постоянный marker,
OS lease до Close, bounded descriptor-anchored read, CAS и atomic rename,
fsync файла и каталога там, где это поддерживается. Если результат записи
неопределён, экземпляр блокирует дальнейшие чтения/записи до закрытия и проверки
сохранённого образа. Параллельный второй writer не допускается; смерть процесса
освобождает kernel lock без удаления чужих lock-файлов.

Каталог заранее создаёт доверенный вызывающий код с POSIX 0700, файл — 0600.
Open создаёт только служебный marker, не файл узлов или каталог. Права не являются
шифрованием против root/доступа к диску. На Windows POSIX ACL не доказывается.
Legacy/root writers и aliases вне протокола FileTarget не считаются защищёнными.

## Copy-only миграция

`CopyLegacyMain` получает явно переданное содержимое `sing-box/main`. Принимает
только полный поддерживаемый импорт и копирует узлы; DNS, маршруты, listeners,
чужие selector/urltest и прочие настройки не становятся node material.
Повтор той же копии с тем же временем не создаёт дубликаты и новую revision.

Существующий live/staged файл и его rollback остаются у вызывающего кода.
**Автоматическое чтение файлов, startup migration и перевод service bindings
ещё не подключены.** Это подготовительная copy-only операция, не завершённый
переход приложения на NodeStore.

## Проверки и следующие gates

- Полный `go test ./...` и `go vet ./...` прошли на Windows; после расширения
  сценариев повторно выполнены тесты нового пакета и vet.
- Локальные тесты: перезапуск, private snapshot, несколько Origin, TTL,
  changed credentials/transport, лимиты, отмена, частичный отказ, lease,
  конкурентные импорты, неизвестная schema, forged health, повреждённые ссылки.
- VLESS, HY2, TUIC, SS проходят хранение и повторное чтение.
- Fault injection до/после записи: нет ложного успеха; после повторного открытия
  виден только целый прежний либо новый образ, без повышения здоровья.
- Дочерний процесс убит с открытым lease после commit: копия сохраняется,
  следующий процесс может открыть store. Это process-crash тест, не power-loss.
- Тестовый бинарник собирается для Linux ARM64, MIPS и MIPSel (softfloat).
  Это компиляция, **не** аппаратное выполнение и не поддержка новой платформы.

Подготовлено [типизированное зашифрованное резервное копирование и
транзакционное восстановление](NODESTORE_BACKUP_RESTORE_RU.md), включая общий
journal rollback и process-crash recovery. Перед подключением к приложению всё
ещё нужны Linux test/vet/race, аппаратный gate и явная миграция старого journal
scope. Затем N1.2 — startup wiring, явный legacy preview/copy, API/UI узлов; N1.3 — exact-node
health evidence с TTL и привязкой к сети/сервису. Reveal/delete/disable,
subscription credentials и постоянный retry quarantine пока отсутствуют.

Роутер не изменялся. Публичные feeds не загружались этим блоком; автоматические
подписки и переключение маршрутов остаются в [плане](PUBLIC_PROVIDER_SOURCES_RU.md).
