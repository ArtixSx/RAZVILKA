# План RAZVILKA после проверки EXT5

Обновлено 20 сентября 2026 года. **0.18.5 в разработке; публикации и аппаратной
приёмки пока нет.** Исторически проверенные ревизии: локальная **c7ea788**,
точные GitHub-файлы 0.18.4 — **5fceff8**.
[Текущий статус](CURRENT_STATUS_RU.md) отделяет
программные проверки, локальную ARM64-сборку и итоговые файлы GitHub Release.

## Завершённый этап c7ea788

- Полный Go/JavaScript/Linux/race gate и кросс-сборки.
- Установка локальной ARM64-сборки штатным установщиком с сохранением данных.
- Два из пяти узлов подтвердили Discord по имени и всем пяти IPv4 CDN.
- Подтверждены маршрут одного ПК, ручное переключение A/B и перезапуск приложения.
- Остановка собственных маршрутов с Safe Mode восстановила исходные правила сети.
- Синтетическая проверка источника вне области прошла; физического второго клиента не было.

## Ближайшая приёмка

Attestation, все SHA256, штатная установка и ручное A/B итоговых файлов `5fceff8`
проверены. Два из шести узлов подтвердили сервис. Первая попытка A откатилась
при сбросе наблюдателя с восстановлением исходной сети; повторное A/B прошло.
Последующий перезапуск 0.18.4 не прошёл из-за старого backoff узла B;
публикация остановлена. Финальная очистка подтвердила исходную сеть и Safe Mode.

1. Выполнить общий CI 0.18.5: исправления backoff, сброса/пробуждения восстановления,
   диагностика наблюдателя и bounded retry netlink dump готовы, целевые тесты прошли.
   Причина прежних сбросов не установлена. После CI проверить точные файлы:
   установку, A/B, перезапуск и очистку.
   Результаты 0.18.4 не подменяют аппаратную приёмку новой версии.
2. Проверить автоматическое переключение при намеренном отказе, очистку и откат.
3. Расследовать прерывистый сброс наблюдателя (локальная и итоговая сборки;
   причина не установлена); повторить WAN reconnect/reboot,
   физический второй клиент и восстановление после сетевых событий.
4. Публиковать точную проверенную сборку с кратким описанием добавлений и исправлений.

## Следующие системные задачи

- Устойчивость: возобновление очередей после рестарта, ограничение памяти/процессов,
  паузы и ротация больших подписок, 24–72 часа работы с закрытым браузером.
- Адреса/DNS: TTL по доменам, обновление endpoint без переноса старого подтверждения,
  общий тест DNS + маршрут + сервис и область клиентов.
- Обновления: подписанные совместимые комплекты и зависимости, полная предыдущая
  версия и откат без запуска новой панели.
- Mihomo/HEV: закреплённые ядра, доставка, нативная проверка, существующий каталог
  и транзакция, реальные TCP/UDP и измерения ресурсов.
- Стратегии: совместимость NFQWS/Lua/blobs, сохранение рабочего варианта,
  подписанный каталог и защита версии при восстановлении копий.
- Аппаратная матрица: IPv6/UDP, MIPS/MIPSel и ограниченная память.
