# План развития RAZVILKA

Обновлено 20 сентября 2026 года. Основа — актуальные исходники 0.18.9.
[Подробное задание и 104 сценария](plans/automation-2026-09-20/README.md)

Добавлено [задание по устойчивому каталогу сервисов](plans/catalog-resilience-2026-09-20/README.md):

запланированных сценариев. Оно учитывает уже выполненные исправления 0.18.9.

## Ближайший результат

Автопилот должен восстановить выбранный сервис при отказе подключения,
проверить новый клиентский запрос и пополнить резерв при закрытом браузере.
Здоровое соединение сохраняется. Ручное переключение и перезапуск приложения,
проверенные раньше, не заменяют этот сценарий.

Исправлены загрузка каталога сервисов и переход к следующему резерву после
подтверждённого отказа кандидата. Продолжение после ошибки применения ещё требует
проверенного отката. Далее — сохранённый снимок подписки и продвижение по нему: рабочий
33-й узел должен быть найден даже при лимите партии 32 и ответе источника 304.

## Порядок дальнейшей работы

| Этап | Что получает пользователь | Как подтверждать |
| --- | --- | --- |
| Восстановление VLESS | Проверка следующего резерва и объяснимая причина остановки | Отказ A; B не проходит применение; подтверждённый откат; C работает; новый запрос клиента проходит через C |
| Устойчивый каталог сервисов | Каталог открывается без внешней сети; отказ обновления не стирает принятый состав | Домены получены, CIDR недоступен; перезапуск; повреждённый кэш; импорт именно просмотренной редакции; точное зеркало и расширение охвата различаются |
| Очередь и подписки | Проверки продолжаются после перезапуска, источник просматривается целиком небольшими партиями | 33-й узел, 304, изменение выдачи, паузы источника и защита действующих профилей |
| Зависимости и обновления | Приложение знает, какие компоненты нужны выбранному обходу | Одинаковые зависимости в карточке, установке, проверке и запуске; независимый откат при неудачном обновлении |
| NFQWS2 | Раздельные настройки охвата сайтов и автоматического подбора стратегии | Проверки выбранного сервиса и сохранение личных списков/стратегий |
| DNS | Ошибка одного домена не замораживает адреса остальных | Учёт TTL по доменам; исходный SNI/Host; проверка именно выбранного IP; ограниченный срок старых адресов |
| WARP, USQUE, AmneziaWG | Согласованные профиль, процесс, зависимости и проверка сервиса | Настоящие ядра и маршруты; отсутствие лишних регистраций при отказе отдельного сайта |
| Mihomo и HEV | Проверенные дополнительные исполнители | Нативная проверка, запуск, TCP/UDP, откат и сравнение нагрузки; генератора конфига недостаточно |
| Стратегии сообщества | Получение проверяемых пакетов без потери личных настроек | Подпись, совместимость, локальная проверка; отправка результатов — отдельная функция |
| Интерфейс | Видны текущая задача, причина ожидания, резерв и следующая попытка | Данные сервера сохраняются после закрытия браузера; нет ложного статуса «работает» |
| Общая приёмка | Предсказуемая работа на поддерживаемых роутерах | Точные файлы выпуска, ARM64/MIPS/MIPSel, второй клиент, перезагрузка, IPv6/UDP, длительное наблюдение |

Если откат, владение сетевыми правилами или состояние общего компонента
не подтверждены, перебор останавливается: следующий узел не исправляет эти ошибки.
Ограниченный срок проверки и предел числа попыток сохраняются.

## Уже сделано и границы проверки

Установка, обновление, откат и удаление 0.18.9 проверены на ARM64; настройки и
подключения сохраняются. Все три архитектуры Entware собираются. Физические
испытания MIPS/MIPSel и полный автоматический аварийный сценарий остаются открытыми.
Переключатель и лог проверены на роутере. Потеря непрерывности наблюдения сети
на этапе `event-drain` остаётся отдельной задачей диагностики и восстановления;
её нельзя скрывать ложным подтверждением работающего маршрута.
Подробности и ревизии — в [текущем статусе](CURRENT_STATUS_RU.md).

OpenWrt — отдельное будущее направление: пакет, procd, UCI и firewall4/nftables.
Текущий установщик предназначен для Keenetic/Netcraze с Entware.
