# План RAZVILKA

Обновлено 20 сентября 2026 года. **0.18.5 в разработке, не опубликована
и не прошла аппаратную приёмку.** [Статус](CURRENT_STATUS_RU.md) и
[аудит](EXT5_REVIEW_2026-09-19_RU.md) разделяют проверки исходной ревизии,
локального бинарника и итоговых файлов GitHub Release.

## Подтверждено для c7ea788

Полный CI; штатная установка локальной ARM64-сборки с сохранением настроек;
сервисная проверка двух VLESS-узлов; маршрут одного ПК; ручное A/B;
перезапуск приложения; остановка собственных ресурсов с восстановлением
исходных правил сети. Перезагрузки роутера и аварийного автофейловера не было.

## Следующие шаги

Происхождение, все SHA256, установка и A/B точного GitHub-бинарника `5fceff8`
подтверждены отдельно; два из шести узлов получили сервисный PASS.
Последующий перезапуск 0.18.4 не принят из-за старого backoff восстановления;
черновик не публикуется. Финальная очистка прошла, Safe Mode включён.

1. Выполнить общий CI готовых исправлений backoff, сброса/пробуждения node-recovery
   и диагностики наблюдателя с ограниченным повтором netlink dump.
   Целевые тесты прошли; причина прежних сбросов ещё не установлена.
   Затем повторить установку, A/B, перезапуск и очистку точной 0.18.5.
2. Проверить автоматическое восстановление при намеренном отказе основного узла,
   WAN reconnect/reboot и настоящий второй LAN-клиент.
3. Расследовать прерывистый сброс наблюдателя на локальной и итоговой сборках:
   откат с восстановлением исходной сети подтверждён, причина сброса неизвестна.
   Повторить проверку устойчивости
   на 24–72 часах, IPv6/UDP и малопамятных MIPS/MIPSel.
4. Завершить адресный DNS с TTL по доменам, проверкой DNS + маршрут + сервис
   и применением только к выбранным клиентам.
5. Подписанные совместимые обновления приложения и зависимостей с полным откатом;
   нативная интеграция Mihomo/HEV; онлайн-обновления проверенных стратегий.
