## Шесть логических ролей

| Роль | Владение | Ограничение |
|---|---|---|
| INTEGRATOR (координатор) | Общие контракты, scheduler, application wiring, очередь PR | Только он принимает изменения общих файлов worker/store; не объявляет чужие тесты пройденными |
| UI | web assets, UI tests, понятные flows, performance | Не меняет серверные полномочия ради клика; клиентский getter не делает mutate |
| VLESS | profile/compiler/checker/ranking/feed pipeline | Не портит source/node reputation из-за локальных ошибок; не ослабляет TLS/path proof |
| NET | WG/AWG/NFQWS2, network/DNS executor | Один владелец сети, exact scope/cleanup, no foreign takeover |
| OPS | packages/updates/snapshots/bootstrap, WARP/USQUE lifecycle | Не повторяет unknown side effects и не удаляет LKG преждевременно |
| QA | Независимые native/HTTP/fault/HIL проверки | Не использует одно поддельное API как доказательство настоящего runtime |

Роли — не заявление о реально запущенных здесь агентах. Координатор проверяет инструменты делегирования, выделяет worktree/ветку и файл-owner. Общий роутер/namespace/порты не изолируются git-worktree: live-окно только одно. При недоступном делегировании — последовательная работа по тем же ролям. В отчёте указывать настоящий task-id только если его создал инструмент.

Каждое задание: входной commit, цель, owned files, запреты, tests, Definition of Done, deadline/budget, отчёт diff+commands+rc+unverified. Не закрывать следующий PR только потому, что unit прошёл. Новый runtime может быть implemented без HIL, но не production-ready.

### D07 — Единый исполнитель обхода по активному списку

Владелец: **INTEGRATOR**. Зависимости: D03, D05. Статус: **not_run / remaining**.

Единый исполнитель list-based bypass: активный список сервисов/доменов/IP-правил действует на выбранные домашние сети, кроме исключённых устройств и сервисов. Приоритет: устройство вне области или в исключениях → базовая политика; ручное либо действующее автоматическое российское исключение ресурса → базовая политика; совпадение с активным правилом в области данного клиента → разрешённый назначенный или автоматически выбранный обход; отсутствие совпадения → базовая политика. Исключение сильнее любого положительного списка, индивидуального назначения и ручного закрепления обхода. Для его отмены требуется отдельное явное изменение исключения, а не более приоритетное положительное правило. При несовпадении индивидуальной области проверить другие применимые активные правила; если их нет — базовая политика. Удаление/отключение записи также возвращает базовую политику, если не осталось другого применимого активного правила. Общее подключение допустимо только для совпавшего трафика активного списка. All-LAN — область устройств, не catch-all VPN. Существующие транзакции, журнал, очередь, capability checks и защитные барьеры сохранить.

### D08 — Единые исключения устройств и сервисов, LAN/DNS

Владелец: **NET**. Зависимости: D07. Статус: **not_run / remaining**.

Реализовать три раздельные сущности: активный список обхода, исключения устройств, исключения сервисов/сайтов. Последний объединяет ручные исключения и отдельно хранимый обновляемый каталог российских ресурсов; поддержать идентификатор сервиса, точный домен, явно обозначенный домен с поддоменами, точный IP и проверенный CIDR. Действующее исключение применяется до любого положительного маршрута во всех управляемых исполнителях, NFQWS2, связанных с обходом DNS-перенаправлениях и Smart DNS. Не включает ресурс автоматически, не предлагает его снова и не запускает его автоматические обходные пробы. Ручные записи сохраняются при обновлении каталога, перезапуске и восстановлении. Отказ источника не очищает последний принятый список. Исключённый клиент сохраняет базовую политику и обычную DNS-обработку роутера. Список российских ресурсов не сводить к автоматически придуманным TLD/ASN/CDN-диапазонам. Сохранять Guest opt-in, bootstrap DAG, IPv6/UDP policy, TTL/CNAME, контроль общих CDN и область существующих соединений. Если выбранный механизм не способен соблюсти доменное исключение на общем IP, не устанавливать спорное расширение и показать конфликт; не отправлять исключённый ресурс в обход и не менять весь чужой трафик. DNS, маршруты и ревизия исключений применяются согласованно. Не очищать conntrack всей сети.

### D10 — Холодный first-usable и справедливый refill

## Неизменяемые инварианты

Рабочий LKG не менять ради меньшего ping. Активный список определяет, какой пользовательский трафик разрешено обрабатывать обходами; исключения устройств и ресурсов всегда ограничивают это разрешение. Российские и ручные исключения — не рекомендации и не пометка интерфейса. Пока исключение действует, автопилот, импорт, положительное ручное назначение, failover и восстановление не могут включить этот ресурс в обход. Исключения не означают блокировку интернета: действует обычная политика роутера. Каталог и активация его записей различаются; обновление источника не расширяет полномочия на обход или внешний провайдер. Пустой список/нет совпадения → базовая политика. При подтверждённом отказе выбранного обхода fallback или scoped block применяются только к разрешённому списочному трафику согласно ранее выбранной политике. Любая модификация исключений отменяет устаревшее разрешение Apply и требует повторного согласования плана; восстановление не возвращает уже запрещённый обход. Сохранять независимость панели, Stop, вход, CSRF, ownership, TLS и проверенный откат.

Никакого нового Autopilot2, отдельного DNS-scheduler, установки z2k/D2k/Podkop/VPNpool как второго owner, замены ядра неподписанным fork или выдуманного HIL. Открытие UI никогда не считается правом обновить ядро/перезагрузить устройство.
