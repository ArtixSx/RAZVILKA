# Что действительно изменено в полной копии

Дата: 03.10.2026. Статус: **исходники изменены; frontend и отдельные Go-модули проверены; полный Go CI/native/HIL не выполнены**.

## 1. Новый интерфейс

- Восемь основных разделов: Главная, Автопилот, Сервисы, Подключения, Обходы, Устройства, События, Настройки. Старые внутренние маршруты/ID остаются для совместимости, но не размножают основное меню.
- Главная: понятный статус автоматики, число сервисов, число подтверждённых сценариев, карточки обходов с количеством **применённых** назначений и отдельно проверенных сервисов. Черновики в applied-счётчик не включаются. Процесс запущен ≠ сервис работает.
- Отдельная страница Автопилот: состояние, резерв, сервисы, обслуживание; четыре частых числовых настройки редактируются тут же. Область/источники/доверие остаются отдельным осознанным сценарием.
- Дублирующий route-stack и маркетинговая схема на странице автопилота скрыты; расширенное ручное управление и лаборатория свёрнуты. Не заявляется удаление всех старых контроллеров: это потребует отдельного совместимого этапа.
- Новая форма сохраняет полную политику через существующий API/CAS, изменяя только четыре поля. Новая ревизия не стирает набранный текст. При неизвестном ответе записи нет слепого повторения PUT: сначала readback. На открытии страницы PUT/POST не отправляются.
- Убрана отдельная видимая галочка «release Safe Mode» в мастере. Если запуск разрешается явным сохранением выбранных условий, используется основное подтверждение нового согласия. Заблокированный журнал самопроизвольно не освобождается. Обычная форма интервалов не выключает Safe Mode.
- Установка по кнопке обхода больше не требует второго одинакового confirm после готового серверного плана. Проверка плана/ревизий/прав остаётся; удаление/опасные обновления не превращены в безусловный POST.
- Generic WireGuard добавлен в основной набор карточек. Отсутствие загруженных метаданных Sing-box-узла не подписывается «подключение недоступно».
- CSS остаётся локальным, без библиотек шрифтов/внешнего CDN. Desktop и 390px mobile просмотрены на синтетических данных.

## 2. Загрузка и перерисовка

Главный `loadPanelSnapshot` запрашивает только данные текущего раздела. Для Главной — 6 групп вместо прежних 23; это **не** общее число HTTP-запросов всей страницы: auth, availability, read-model автоматики и jobs имеют отдельные механизмы. Предел параллельных чтений — четыре.

Переходы отменяют старые запросы, поздние ответы ограждаются generation/epoch. Ошибка скрытого раздела не должна заставлять главную снова читать этот раздел. Убраны повторные render скрытых engineconfig/strategy/testlab/DNS-форм при независимых ответах services; введены active-view зависимости. Открытая форма сохраняет черновик.

Это кодовое сокращение работы и стендовая проверка, **не замер скорости или CPU на Keenetic**. Старые фоновые сборщики и некоторые legacy-обновления ещё остаются; профилирование и дальнейшее устранение дубликатов — задача UI.

## 3. VLESS: включён предыдущий пакет IM

Эти изменения были подготовлены ранее; теперь они перенесены в полную копию:
- prefilter возвращает фактически успешный IP, временный клиент использует именно его;
- раздельные TCPConnectMS, ProxyResponseMS и TotalCheckMS; отсутствие значения не равно нулю;
- bounded process-local cache привязан к node/service/network/route/probe/revision-time/expiry;
- результат общего checkAndRecordNode доступен UI и для автоматики, не только кнопки «Пинг»;
- общий цикл времени не называется сетевой задержкой и не используется как прежний показатель скорости;
- локальные ошибки checker не превращаются в отрицательную репутацию всех узлов; дубли probe/source не удваивают вес;
- ошибка вторичного node-autofallback не отбрасывает успешно прочитанный node-checks; 401 остаётся ошибкой аутентификации;
- когда DIRECT-контроль недоступен, разрешена только ограниченная диагностическая сервисная проба. Available=false/INCONCLUSIVE сохраняются, авторизация Apply не появляется.

**Новые timings пока не переживают restart.** Схема приватного NodeStore не переписывалась. Не реализованы exact-node Xray/XHTTP и полноценный альтернативный path proof без DIRECT-oracle.

## 4. Автопилот: более быстрый тёплый failover

Добавлена узкая функция `refillBeforeApply`. Когда замена уже разрешена состоянием автопилота и в каталоге есть свежий пригодный резерв, фоновое пополнение больше не ставится перед существующей пред-Apply проверкой этого узла. При пропуске пополнения cursor не продвигается.

Сохранены fresh recheck, switch budget, guard, общий transaction и существующий путь B→rollback→C. Неизвестность сама не разрешает замену. Холодный поиск без готового резерва всё ещё обрабатывает исходную малую партию: не заявляется законченный cold first-usable или приёмка worker на настоящем туннеле.

## 5. Прежний H00 тоже включён один раз

Единый routekind, WG/AWG initiating probe и Sources без удаления scope, typed исходы обслуживания, остановка unknown, pending/install receipts, checkpoint Geo-Aggregator/singleflight, DNS-cancellation, MemFree fallback старого ядра.

При переносе обнаружена неоднозначность старого manifest: одна и та же строка rankAutonomyNodes встречалась дважды. Обе нужные точки изменены после проверки исходных файлов; special-case записан в журнал интеграции. Новые файлы и тесты находятся в обычном дереве проекта, повторный сборщик патчей не нужен.

## 6. Чего НЕ сделали

Не отключены auth/CSRF, TLS/pinning, владение ресурсами, Stop, recovery fence, ревизии и транзакции. Не выполнены установка/перезапуск роутера, публичные проверки VLESS, регистрация WARP/relay, перепрошивка или публикация на GitHub. Не заявлены рабочие Xray/WG/AWG/all-LAN, unattended безопасное обновление при потере питания, голос/медиа и MIPS HIL.

VERSION=0.19.3 сохранён только как исходная версия. Это невыпущенная рабочая копия, а не замена официального бинарника.
