## Конкретный первый D07/D08 путь

Предлагаю расширить существующий owned sing-box TUN builder (`internal/dataplane/proxy.go:1715`), сохранив единый lifecycle/ownership executor. Первый bounded slice: один допущенный LAN-клиент, IPv4 TCP80/443; остальные capabilities остаются явно неподтверждёнными. Не вводить второй менеджер правил.

1. CORE/NET проверяет exact ingress+MAC перед capture. Исключённое устройство не входит ни в owned TUN/NFQUEUE, ни в service DNS. Guest только opt-in. Допущенный all-except scope перехватывает публичные назначения целиком: DNS-IP списки не определяют доменное решение.
2. В TUN router добавить non-final `sniff` с явными `sniffer:["http","tls"]` и bounded timeout, затем доменные terminal rules. Официальный TUN передаёт исходные Source/Destination; router читает первые bytes до вызова outbound и возвращает прочитанный buffer соединению. Это разбор HTTP Host/открытого TLS SNI без завершения клиентского TLS на роутере. [TUN source](https://github.com/SagerNet/sing-box/blob/2dcb86941f5db01bbe296acae555a3b1f38c0441/protocol/tun/inbound.go), [route source](https://github.com/SagerNet/sing-box/blob/2dcb86941f5db01bbe296acae555a3b1f38c0441/route/route.go), [sniff action](https://sing-box.sagernet.org/configuration/route/rule_action/#sniff).
3. `dns.reverse_mapping=false`, FakeIP выключен; никаких resolve/override-address или destination sniff override. Имя — только из этого потока; соединение сохраняет первоначальный IP. В проверенном DNS source disabled reverse map возвращает false. [DNS source](https://github.com/SagerNet/sing-box/blob/2dcb86941f5db01bbe296acae555a3b1f38c0441/dns/router.go).
4. Порядок решений: обязательная проверка видимости имени → доменные исключения → scoped service override → явный default. `domain` означает exact name; `domain_suffix` только для явно заданного suffix. Known miss, scope mismatch, удалённый override и прямой IP сохраняют default при допустимой visibility policy. [Правила](https://sing-box.sagernet.org/configuration/route/rule/).
5. **Stock config недостаточен для обязательных доменных исключений.** Нужен узкий typed NameState guard перед terminal outbound: visible/absent/ambiguous/ECH/timeout. Официальный TLS parser возвращает ServerName без доказательства inner ECH; отсутствие имени, ECH, opaque UDP и неоднозначность при обязательных исключениях уходят в доказанный baseline либо block. Обычный direct socket ещё не доказывает baseline LAN path. Пока guard/baseline capability не реализованы и не приняты native, соответствующий режим fenced. [TLS parser](https://github.com/SagerNet/sing-box/blob/2dcb86941f5db01bbe296acae555a3b1f38c0441/common/sniff/tls.go), [официальная граница ECH](https://xtls.github.io/en/config/inbound.html#sniffingobject).

Версию/schema необходимо проверить явно: ссылочный sing-box v1.12.0 (`2dcb869…`) не является свидетельством установленной версии. Записанный локальный minimum1.8 не разрешает молча применять новые actions.

Для Xray можно оставить тот же TUN frontend и выбирать путь **до общего SOCKS**, чтобы не потерять LAN identity. Альтернатива sniff внутри dedicated Xray inbound: `enabled:true`, `metadataOnly:false`, `destOverride:["http","tls"]`, `routeOnly:true`; routing `domainStrategy:"AsIs"`, exact `full:` и explicit default. `routeOnly` сохраняет target IP; `domainsExcluded` лишь исключает destination override, не реализует DIRECT policy. Общий loopback SOCKS сам по себе не сохраняет клиентский MAC/source scope. [Официальный контракт](https://xtls.github.io/en/config/inbound.html#sniffingobject), [dispatcher v25.9.11](https://github.com/XTLS/Xray-core/blob/3edfb0e33557330ac721862adb2e4be89ee7412a/app/dispatcher/default.go), [routing](https://xtls.github.io/en/config/routing.html#ruleobject).

Финальная native приёмка slice: два имени на одном IP получают разные решения; исключённый MAC нигде не captured; known miss/removed override/прямой IP соблюдают default; ECH/timeout/opaque UDP при обязательных исключениях fenced; Start/Stop/restart/sidecar death сохраняют ownership/LKG. Sniffed имя относится к соединению и не доказывает имена последующих encrypted HTTP2/3 запросов. IPv6/UDP и DNS bootstrap требуют отдельных D08 capabilities. До этого `NETWORK_POLICY_EXECUTOR_REQUIRED` остаётся.
