## Контракт для CORE

`NewSupervisedCompatibilityProvider(manager *strategylab.Manager, approval strategylab.CompatibilityApproval) (*strategylab.SupervisedCompatibilityProvider, error)` принимает explicit owner review. Approval: `BinaryPath`, `BinarySHA256`, ordered `Assets []CompatibilityApprovedAsset{Path,SHA256}`, exact `BaseArguments`, `ControlPath`, `InstallationID`, `Sequence`. Digests предоставляет trusted OPS/component producer или отдельная reviewed fixture; локальный hash не выдаёт provenance. Будущий managed descriptor преобразуется trusted Go wiring. Нет допуска по basename и нет argv/path/approval DTO через HTTP. `rzv-nfqws2` допустим после точного review его bytes.

CORE устанавливает этому же Manager `CompatibleValidator{Binary: approval.BinaryPath, BaseArguments: approval.BaseArguments, TrustedAssets:true, Provider:provider}`. Constructor требует уже существующий private parent StrategyLab file и готовую independent control authority. Production defaults согласованы: `/opt/var/lib/razvilka/strategy-lab.json` и `/opt/var/lib/razvilka/self-update-stop`; override только из existing trusted startup settings. Provider/helper не создают и не очищают control authority, не adopt-ят stock Entware.

Fixed early CLI dispatch до daemon startup: `nfqws-compatibility-supervisor <invocationID>` → `strategylab.RunCompatibilitySupervisor(invocationID, trustedStrategyLabStatePath, trustedControlPath) int`. Единственный CLI operand — 32-digit lowercase hex nonce. Paths берутся из existing trusted flags/env `RAZVILKA_STRATEGY_LAB_STATE` и `RAZVILKA_SELF_UPDATE_CONTROL_STATE`. Parent запускает собственный protected executable с private setsid; helper verifies frozen control path. Return 0 означает durable terminal receipt, а не native PASS. Non-Linux unavailable.

Actual parent helper Start и actual NFQWS child Start проходят `operationgate.WithSelfUpdateEffectAdmission` с sealed InstallationID+Sequence. Callback содержит только Cmd.Start. StopCheck/readback не допускают запуск. Environment фиксирован: PATH `/opt/bin:/opt/sbin:/usr/bin:/bin`, LANG=C, TZ=UTC, плюс только два trusted path setting для helper. Нет LD_PRELOAD, shell, caller Env, init hooks или opkg.

## Schema 3 и lifecycle

StrategyLab читает history schema 1/2/3. Schema 2 остаётся unknown. Schema 3 содержит одну `compatibility_session` (nested schema 1), immutable binary/assets SHA256+size, exact base/argv, boot/PID/birth/deadline, session/invocation nonces, canonical command digest и отдельные dry-run/Lua-init receipts. Receipt lifecycle: intent → armed → running → reaped либо not-started. Parent ACK хранится вместе с receipt. JSON strict: unknown fields, duplicate case-folded keys и invalid raw UTF-8 отклоняются. Output sanitizes UTF-8, сохраняет максимум 8192 bytes tail.

Дополнительно `compatibility_finalizing=true` сохраняется **до spawn** в том же State. ACK фаз не снимает marker. Только Manager.Validate, когда внешний CompatibleValidator уже вернул known result именно этого provider/session/argv, проверяет live context и Stop authority и одним CAS публикует candidate validation + снимает marker. Если ACK fsync задержался после deadline, timeout/late completion или crash не очищают durable fence. Даже оба ACK с finalizing=true при reload означают unknown. Никакого второго ledger, recovery по PID absence или resume pending invocation нет.

Helper держит existing FileTarget per-file kernel lease от intent read до terminal CAS+directory fsync. Parent intent/ACK/final publication используют тот же descriptor CAS. Ordinary writers не могут удалить/переимпортировать pending session или обновить старый image; missing/mismatched receipt, helper crash, foreign boot/birth/epoch, unACK, finalizing marker, invalid schema или uncertain CAS сохраняют fence. Новый provider/Manager не снимает его.

Closed command допускает только `--dry-run --intercept=0 <exact reviewed base> <data-only candidate>` и затем `--intercept=0 <same base/candidate> --lua-init=<exact generated assertions>`. No runtime options/custom Lua. Per command ≤32768 argv bytes, ≤114 argv entries. Binary ≤64 MiB; ≤16 deduplicated ordered assets по ≤4 MiB. Linux protected ancestry исключает symlinks, foreign ownership и group/other write. Writable sticky `/tmp` разрешён только с полностью private descendants. Это ownership boundary: root/euid остаётся доверенным. Bytes перепроверяются после armed fsync непосредственно перед child admission; CORE должен исключить замену approved generation на весь session или предоставить immutable managed generation.

Subreaper запускается только в отдельном helper. NFQWS-owned bridge reuse-ит private OPS primitives в том же components package; existing OPS code не меняется. Единственный reap owner — Wait4(-1, WNOHANG|WALL), EINTR retry; exact ECHILD после direct-child accounting. Нет Cmd.Wait в helper, PID namespace и /proc/task/children. Cleanup PPID/birth scan применяется только к own unreaped children; пустой scan не является proof. Loop следит за parent birth, deadline и Stop; forced cleanup остаётся exit125/cancelled даже если direct child успел exit0. Cleanup/pipe join bounded; missing proof означает unknown. Parent Wait относится только к owned helper и проверяет его точный boot/PID/group/birth против receipt.
