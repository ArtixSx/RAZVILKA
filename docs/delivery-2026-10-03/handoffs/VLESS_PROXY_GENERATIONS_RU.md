# Proxy wiring общего addition receipt

04.10.2026. Зависимости: общий модуль `0d49f3e`, stricter promotion retry `7253153`, CORE primitive `b3bc486`. Изменены только proxy/node runtime health и связанные fixtures; policy mutation/kernel/forwarding, manager, app и production version/dependencies не менялись.

Activate сохраняет adapter phase prepared → unknown до первой компенсации прежней policy. После owned forwarding installation общий module записывает каждый RPDB/default intent/added. Aggregate complete допустим только после полного success и совпадающего boot. Повторный Stage не перезаписывает существующий aggregate; canonical/checksummed private metadata. Failed candidate Rollback использует только shared added tuples; unknown/missing/corrupt/mismatch не переводится в broad staged cleanup, и дальнейшие stop/interface/restoration прекращаются. Unknown selector сохраняет defaults. Retry из durable restoring описан в `VLESS_ROLLBACK_RETRY_RU.md`: до начала A можно повторить раннее восстановление; полностью acknowledged A завершается без teardown; uncertain A остаётся fenced.

Commit сначала требует complete candidate receipt и forwarding readback. При promotion trusted adapter создаёт private `StateRoot/policy-generations/<validated random ID>`, сохраняет receiver ID в transaction, переносит shared cleanup grant, затем сохраняет private `policy-generation.json`. Только после этого меняет global draft/committed policy. Source не остаётся cleanup owner. Outer Commit failure использует receiver из transaction; удаление source transaction receipt не ломает committed cleanup. Повторный Commit проверяет active/fully added receiver; consumed destination отвергается уже shared API.

В policy.json добавлен только private scalar `addition_receipt_version:1`, без path/command source. Он запрещает legacy fallback для нового committed state с missing binding. Private reference содержит engine/full-state hash, generation ID, shared receipt ID и pending/active/removed; paths заново конструируются адаптером, DTO не управляет ими. Snapshot сохраняет prior tracked flag/reference, сами поколения retained. Snapshot-only история не становится active runtime authority.

Reconcile, RefreshPolicy и same-boot restoration A создают новые private generation roots. Pending reference сохраняется до попытки add; неизвестный результат остаётся с exact `policy-state.json` для trusted reconciliation. Полностью consumed receipt не оживляется. При verified восстановлении A остаются removed receipts A/B и новый active receipt A. Health/CommittedNodeHealth/VerifyRollback проверяют соответствующие exact receipts read-only. Deactivate прекращается до stop/interface mutation, если tracked cleanup не подтверждён. Existing legacy committed history сохраняет прежнюю отдельную ownership границу; новая activation всегда tracked.

Уточнение доступности: unavailable/missing addition receipt после pre-add forwarding failure, unknown add/delete и interrupted restoration оставляют fence и private материалы. Автоматическое восстановление поверх такого состояния не добавлено. Старый boot также требует отдельного trusted reconciliation CORE, а не принятия старой команды по absence. Garbage collection retained generations после verified settlement не реализован; прежние receipts намеренно сохранены.
