# Сохранение policy default при внешней зависимости — VLESS → CORE/NET

Schema 1 receipt consumer использует CORE `AssertPolicyDefaultUnreferenced` из принятого checkpoint `89966b3` и его зависимости `5454c3a`/`788ea34`/`7745a0b`. После удаления своих ACKed selectors cleanup проверяет **обе** семьи перед settlement отсутствующего default либо durable cleanup-intent и повторно после intent непосредственно перед delete. Внешний или неизвестный selector любой семьи удерживает оба defaults. Обработка уже отсутствующего default в outer cleanup также требует этой проверки, чтобы Stop не сообщил settled cleanup под внешним lookup.

CORE helper — только отрицательная read-only проверка зависимостей. Он не даёт delete authority, не удаляет чужие selectors и не заменяет receipt. Читает bounded numeric RPDB через существующие reader/parser; unsupported `-N`, aliases, неизвестная grammar, ambiguous/read-failed состояние дают отказ. WG endpoint selector допускается только при совпадении immutable NET descriptor и fresh exact host-pin/rule readback. LAN goto/nop без отдельной подтверждённой grammar остаются unknown.

VLESS wrapper объединяет ошибку с `ErrPolicyAdditionUnknown`. Отказ до intent сохраняет ACKed defaults. Если повторная dependency check в той же живой функции достоверно отказала **до вызова delete**, wrapper durably возвращает строку в `added`, сохраняя первоначальный add ACK. После независимого исчезновения зависимости retry может удалить exact owned default. Ошибка этого save, отмена, crash после intent либо неопределённый вызов delete оставляют durable `cleanup-intent` и запрет readback adoption. Общий schema 1 known-subset contract, bytes/checksum, boot/root identity и promotion остаются прежними. Ни lookup совпадение, ни свежий kernel readback не разрешают усыновить или удалить чужое правило.

Новые consumer tests проверяют foreign lookup каждой семьи, unknown/alias/unsupported/failed numeric read, зависимость после durable intent, отсутствующий первый/оба defaults, безопасный selector другой таблицы и rollback после durable IPv6 default ACK. Common parser и test fixtures остаются у CORE. Local tests/compile не являются native доказательством Stop или cleanup на firmware; actual kernel acceptance выполняет координатор.

После обычных merge принятых NET `8837583`, CORE `b6f4f21` и CLOUD `34074f5` обязательный общий прогон `WGPolicyReceipt|PolicyAdditionReceipt|PolicyAdditionDefaultDependencies|PolicyEffectsReceipt|ProxyPolicyGeneration|ProxyCandidatePolicy|ProxyRollbackRetry` прошёл: PASS, 39.089s. Отдельная новая consumer matrix также прошла, включая независимый coordinator count=2. Windows vet и Linux compile/vet новых consumer изменений: RC0. Это локальная проверка кода; native acceptance не заявляется.

После coordinator P2 дополнена live known-not-invoked restoration и regressions: dependency исчезает, retry успешно использует original ACK; failed restoration save сохраняет unknown IPv6 intent, при этом schema1 known-subset cleanup других ACKed строк остаётся прежним. Повтор обязательного общего прогона: PASS, 41.189s. Crash между durable intent и проверкой по-прежнему не даёт restoration authority.
