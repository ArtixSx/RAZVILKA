## Ограниченная реализация

Меняется только runtime внутри `NFQWSScopedBinding.Remove` и новый private helper/tests. Общий `prepare`, VerifyInactive/settlement, Apply, common receipt, DEFAULT/LAN/producer/CORE и caps 15/5 не меняются этим commit.

- Remove-local `Guard` вызывает свежий original CleanupGuard с exact frozen effect и исходным ctx; common Guard calls остаются. Это retained cleanup authority, не повтор live Apply/LAN admission после Stop.
- Common initial grant scan и оба per-delete ExactPresence по-прежнему используют полный `b.inspect`: обе family, все десять таблиц, opening/closing other-backend/physical checks, unknown/foreign/duplicate/body predicates. Common durable intent/hasUnsettledChild/whole-generation fence остаются единственным источником ownership; новый helper не открывает receipt и не синтезирует ACK.
- BeforeDelete объединяет прежние повторные инспекции в одну `cleanupBoundary`: SAME inactive/ECHILD/ACK + whole-empty queue до/после, один full rules image, pure cardinality/dependencies и отсутствие body/любых references при удалении chain. Image наружу не возвращается. Следующий common ExactPresence остаётся full, включая absent-target settlement без RPC.
- Private Remove runner принимает только однозначный exact trusted tool + frozen compiler Delete. После final common Guard он повторяет original CleanupGuard и `cleanupBoundary`, затем использует corrected `readFinalRules`: whole backend bracket, discarded pre-closing image, callback-free fresh all-ten classic facts. Pure reverse-prefix `j<=i:1; j>i:0` + dependency/reference checks выполняются только на последнем image после closing process/queue/backend predicates. Missing earlier ACK или reinserted later exact tuple отказывает actual Delete; matching rows не становятся authority.
- Last `-X` требует exact declaration=1, zero body и отсутствие ссылок во всех table/family в этой fresh boundary. CORE admission по-прежнему принадлежит actual base Runner Cmd.Start; executable/delete argv остаются detached compiler copies.
- После successful actual Delete свежий target family/mangle `-S` проверяет target=0 и exact local reverse prefix, bounded syntax и foreign conflicts. Это только observation SAME cleanup-intent. Failed RPC (в том числе after mutation), still-present/duplicate/unknown/malformed/read error/cancel возвращают error; common cleanup-intent/Unknown остаются. Далее common fault(delete), full post ExactPresence, removed save и final strict VerifyInactive идут прежним протоколом. Следующий эффект не получает cached image.
- Initial inactive/full cleanup readback, финальный VerifyInactive и отдельный SettleRemoved остаются строгими. Этот commit не ослабляет существующий отсутствующий target settlement, не повторяет Unknown RPC и не очищает fence по одному bare-chain/receipt/process snapshot.
