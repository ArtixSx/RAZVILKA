Переданные ROOT факты: ARM64/Linux4.9-ndm-5, три actual Entware1.4.21 digests совпали с reviewed official files; `/opt` — EXT4 `/dev/sda1`, UID/GID1001,0755, `/` и `/opt/lib` root-owned. **Вывод:** минимальная подготовка — сменить только UID самого inode `/opt` на0, сохранив GID1001/0755 и все descendants, после проверки mount aliases и effective SMB permissions. Полнота backend требует отдельного registered-table inventory и положительного nft результата либо точного build/config absence proof. В `3e94a67` `RegisteredTablesComplete=false` намеренно сохраняется; ни один вывод ниже не разрешает переключить его или объявить native PASS.

## 1. Доверенный `/opt` с сохранением SMB данных

Официальная [инструкция Entware Netcraze](https://support.netcraze.ru/giga/nc-1012/ru/20980-installing-the-entware-repository-on-a-usb-drive.html) показывает один раздел, доступный через `/tmp/mnt/<volume>` и `/opt`. Следовательно, owner change может затронуть корень диска под обеими aliases, а не отдельный каталог Entware. Точный target inode ещё нужен от ROOT.

Минимальная отдельно принимаемая platform preparation:

1. До записи зафиксировать effective UID, реальные ancestors, mountinfo и tuple `/opt`: canonical path, directory type, device/inode, mount identity, UID/GID, mode и доступные ACL metadata. Сохранить исходное состояние в доверенном месте вне изменяемого USB namespace. Зафиксировать отсутствие/наличие protected payload и связанных receipts/runtime.
2. Открыть и удерживать descriptor именно подтверждённого directory inode; отказать при symlink, смене mount/tuple, неожиданных permissions или недоказанном ancestor. Сменить только UID1001→0 через этот descriptor, сохранив GID и mode. Не выполнять recursive chown, chmod, remount, migration или обработку остальных foreign ancestors. Проверить результат и durability принятой платформенной процедурой; затем повторить существующий strict guard и identities инструментов/зависимостей.
3. Сохранить владельцев, права и содержимое data subdirectories. UID1001 потеряет создание/удаление/rename объектов **в корне диска**; обещать прежнюю top-level запись нельзя. Вложенная запись зависит от прежних permissions и SMB impersonation/ACL, а не только UID `/opt`.

[Netcraze folder permissions](https://support.netcraze.ru/giga/nc-1012/ru/18485-folder-permission-control-on-a-usb-drive.html) прямо поддерживает схему: чтение корня/предков, запись выбранных папок, запрет остальных; для разграничения требуется folder-control component и отключение anonymous access. Это проверяемый способ оставить запись в существующих media folders, исключив Entware/protected paths из SMB write scope. [SMB manual](https://support.netcraze.ru/giga/nc-1012/ru/19084-smb-server--shared-access-to-files-and-printers-.html) описывает anonymous access как default. Это сведения о платформе, **не** установленные настройки данного роутера. UI ACL не доказывает POSIX UID mapping; root-privileged SMB writer может обходить обычные UID/mode. Нужны actual share paths, aliases, accounts/anonymous policy и effective доступ, включая protected subtree. Здесь никакая SMB политика не менялась.

**Rollback:** до публикации protected payload допустимо вернуть только прежний UID того же pinned inode, если mount/tuple и receipts/runtime ещё соответствуют сохранённому pre-state; GID/mode/descendants остаются прежними. После публикации автоматический возврат UID1001 недопустим: он вновь открывает namespace владельцу1001. Тогда rollback требует отдельно принятого прекращения protected использования и settlement его exact resources, после чего повторной проверки исходного inode. Не удалять чужие packages/data. SMB changes, если владелец отдельно примет их, имеют собственный сохранённый pre-state и rollback; их нельзя скрыть внутри bundle cleanup. Persistence owner/guard и SMB access после штатного remount/reboot проверяются ROOT отдельно, здесь таких испытаний нет.

Подробный прежний контракт: [storage preflight](C:/Projects/RAZVILKA/worktrees/sol-research/docs/delivery-2026-10-03/handoffs/RESEARCH_ENTWARE_STORAGE_PREFLIGHT_RU.md). GID0 guard не требует; root-owned `/opt/lib` не защищает имя `lib`, пока родитель принадлежит1001.

## 2. Достижимое evidence полного backend coverage

Найдены опубликованные vendor sources: SDK pin `1d58c10c46e270d6876836e5455fa4e9b786ad1e` (ветка5.01), kernel tag4.9.337-181-2 → `7b6c9477d429217042117fbfa3d2e9894a087607`. [SDK kernel selection](https://github.com/keenetic/keenetic-sdk/blob/1d58c10c46e270d6876836e5455fa4e9b786ad1e/include/kernel-defaults.mk#L8) указывает этот tag; [localversion](https://github.com/keenetic/kernel-49/blob/7b6c9477d429217042117fbfa3d2e9894a087607/localversion-ndm) содержит `-ndm-5`. Это **кандидат для review**, не attestation работающего Netcraze: совпавшего suffix недостаточно, требуются точные model/build/image/component provenance.

| Часть evidence | Проверяемый путь | Что ещё удерживает приёмку |
|---|---|---|
| Registered classic IPv4/IPv6 | Complete bounded EOF чтение `/proc/net/ip_tables_names` и `ip6_tables_names` до/после exact rows всех зарегистрированных tables в том же boot/netns | Missing/permission/malformed/truncated/change → Unknown. Custom table: поддержанный read либо отказ; fixed five не доказывает полноту |
| Native nft всех families | Reviewed GETGEN A → UNSPEC GETTABLE complete dump → весь classic batch → GETGEN B, stable full generation, kernel peer и ACK/DONE/framing | Только complete zero-table даёт Empty; любая table отказывает. Ошибка/недоступный GET не превращается в Empty/Unsupported |
| nft действительно выключен сборкой | Окончательный matching kernel config с NF_TABLES=n, проверенный running image и module/provider provenance, либо отдельно reviewed exact vendor absence profile | Uname, default config, отсутствие CLI/модуля и EINVAL/EOPNOTSUPP сами этот путь не закрывают; current reader не имеет error→absence fallback |

В pinned vendor [x_tables.c:1274](https://github.com/keenetic/kernel-49/blob/7b6c9477d429217042117fbfa3d2e9894a087607/net/netfilter/x_tables.c#L1274) names reader обходит namespace-specific `net->xt.tables[af]` под family mutex; [создание proc entry](https://github.com/keenetic/kernel-49/blob/7b6c9477d429217042117fbfa3d2e9894a087607/net/netfilter/x_tables.c#L1572) привязано к `net->proc_net`. Это inventory текущих зарегистрированных tables, без доказательства отсутствия compiled/unloaded providers. Повтор names не делает multi-table rules атомарными и не исключает external-writer ABA; остаются принятые platform writer assumptions и fresh checks на existing effect boundaries. Отсутствующую `security` нельзя пропускать из-за ошибки `-S`: нужен положительный active-table coverage contract, review consumer поведения и отдельных required mutation capabilities. Нынешний fixed-five guard сохраняется.

Vendor [GETTABLE dump](https://github.com/keenetic/kernel-49/blob/7b6c9477d429217042117fbfa3d2e9894a087607/net/netfilter/nf_tables_api.c#L456) при UNSPEC обходит все зарегистрированные nft families; [GETGEN](https://github.com/keenetic/kernel-49/blob/7b6c9477d429217042117fbfa3d2e9894a087607/net/netfilter/nf_tables_api.c#L3858) возвращает full32-bit generation. Но [nfnetlink dispatcher](https://github.com/keenetic/kernel-49/blob/7b6c9477d429217042117fbfa3d2e9894a087607/net/netfilter/nfnetlink.c#L151) возвращает EINVAL как при отсутствии subsystem после autoload, так и при отсутствии callback/некоторых ошибках входа. Даже этот vendor source не превращает raw errno в absence proof. GET может вызвать `request_module`; userspace cancellation не доказывает жёсткий syscall deadline или отсутствие autoload.

**Не использовать базовый config как shortcut.** В [generic config:925](https://github.com/keenetic/keenetic-sdk/blob/1d58c10c46e270d6876836e5455fa4e9b786ad1e/target/linux/generic/config-4.9#L925) выключены NF_TABLES и XTABLES, а IPv4/IPv6 iptables также выключены ниже. Работающий router имеет iptables: этот файл очевидно не final evidence. [Configure:85–103](https://github.com/keenetic/keenetic-sdk/blob/1d58c10c46e270d6876836e5455fa4e9b786ad1e/include/kernel-defaults.mk#L85) соединяет target/config_KERNEL settings с package overrides. [SDK README](https://github.com/keenetic/keenetic-sdk/blob/1d58c10c46e270d6876836e5455fa4e9b786ad1e/README.md) начинает с сохранения собственного firmware image и точной версии для выбора branch. `unpack.sh` прочитан, но не предлагается как простой read-only extractor: он вызывает configure/build host tools. Применимость Keenetic SDK к конкретному Netcraze model/build пока не установлена.

Такой inventory закрывает только явно покрытые sources. Иные обязательные LAN backend/hook providers требуют своего positive coverage или сохраняют Unknown; nft Empty не удостоверяет legacy bridge/ARP, RPDB/routes, queue/process/flows. Shared reader и pure consumer predicates остаются одним существующим owner, без нового daemon/decoder/journal. `3e94a67` ограничивает RunBounded пятью table names; данные от ROOT не заменяют source-owner reviewed extension и native acceptance.

## 3. Точный следующий read-only probe для ROOT

Нужен **один связанный metadata/proc capture**, существующими проверенными инструментами, без установки пакетов, root filesystem изменений, module load, config dump с секретами, SMB writes или reboot:

1. Публичные model code, точный firmware build/date/component selection и Linux release; effective UID; boot ID из `/proc/sys/kernel/random/boot_id` и identities `/proc/self/ns/net`, `/proc/1/ns/net`. Не возвращать serial/CID/MAC/passwords. Если config опять отсутствует, фиксировать точный path/error; не повторять broad filesystem search.
2. Complete соответствующие records `/proc/self/mountinfo`; lstat/canonical stat `/`, `/opt`, `/opt/lib`, `/opt/sbin`, actual tools/libraries и существующих protected ancestors. Для directories вернуть device/inode, UID/GID, mode/type; для mount aliases — соответствующие `/tmp/mnt/<volume>` tuples и relative mount root. Никакого chown в этой пробе.
3. Nonsecret SMB share→directory mapping, anonymous/account policy, folder-control availability и effective permissions корня/protected/media folders. Отдельно установить, может ли SMB writer создавать/rename protected ancestors; POSIX UID по имени учётной записи не угадывать. Нет ACL tooling — явно unknown, не «ACL отсутствует». Protected payload/receipt/runtime presence вернуть как ограниченные identities/state, без содержимого private config.
4. Оба names files до/после capture: полный raw content до EOF и отдельный open/read error, не filtered grep и не silent head/truncation. Предлагаемые diagnostic limits: ≤8KiB и ≤64 names на family/read; excess означает отказ всей пробы. Снять fresh boot/netns в конце. Уже зарегистрированные rules читать лишь existing reviewed bounded collector; не пробовать absent tables ради autoload. Этого metadata capture ещё недостаточно для backend PASS.

После source/tool/storage review ROOT нужен отдельный native wire capture **уже проверенного** GET-only observer: exact request/response datagrams, peer/seq, ACK/DONE/full generation и endpoint/module state before/after. Эта стадия может вызвать kernel autoload, поэтому не входит в обещание «без module load» первой пробы. При EINVAL/EOPNOTSUPP результат остаётся Unknown; следующий необходимый input — matching final config/image provenance, а не повтор ошибочного запроса или mutating batch. Observer на роутере здесь не запускался и новый probe code не создавался.
