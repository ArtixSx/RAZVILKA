## Решения для финальной упаковки

1. **Номер утверждён: `0.20.0 > 0.19.3`.** Для сравнения номеров исключение не нужно. Переход файлов и состояния со старого0.19.3 требует отдельной проверки: его исполнитель не поддерживает новый протокол обновления. Готовится внешний установщик, сохраняющий состояние остановленных маршрутов; исходники и модельные тесты ещё не подтверждают успешную миграцию. Финальные VERSION, metadata и notes согласовать после проверки итогового кода. Перед публикацией проверить отсутствие нового тега `v0.20.0`.
2. Запрошены **три роутерные архитектуры**: ARM64, MIPS и MIPSel. Текущий workflow собирает и прикрепляет также AMD64 для Linux-стенда: четыре бинарника и 10 assets. Если выпуск должен содержать строго три бинарника, перед тегом нужен отдельный packaging change с проверкой состава архива, `SHA256SUMS`, attestations и upload list; AMD64 остаётся нужен для нативного transaction fixture. Само наличие стендового бинарника в прежних выпусках не является обнаруженной ошибкой установщика.

## Существующая процедура и архитектуры

- [Правила версий](../../VERSIONING_RU.md), [Release workflow](../../../.github/workflows/release.yml), [build.sh](../../../build.sh), [LAB](../../../LAB.md), [установка](../../INSTALL_RU.md).
- Тег `v*` запускает Release CI. Tag без `v` должен совпасть с VERSION без конечного `-dev` либо быть `<base>-rc.N`. Значения VERSION, fallback `app.Version`, UI version/cache keys должны согласоваться; это проверяет `internal/projectmeta`.
- Workflow задаёт version/commit/time/dirty, запускает полный `scripts/check.sh`, проверяет версию AMD64, пакует tar.gz/zip и алиас для bootstrap, проверяет staging на private files/links, создаёт attestations и **draft с `latest=false`**. Дефис означает prerelease. Используются `docs/releases/<version>.md`, иначе autogenerated notes.
- `install-entware.sh` делегирует `upgrade-entware.sh --apply`; bootstrap скачивает bundle и checksum из **одного** выбранного release, проверяет SHA-256/архив и передаёт выбор архитектуры его helper. `RAZVILKA_VERSION=v0.20.0` выбирает точный tag, `latest` — опубликованный Latest.

| Entware / uname | Go target / asset | Выбор установщика |
| --- | --- | --- |
| aarch64-k3.10 / `aarch64`, `arm64` | `arm64` / `razvilka-linux-arm64` | Прямой |
| mipssf-k3.4 / неоднозначное `mips` | `mips`, `GOMIPS=softfloat` / `razvilka-linux-mips` | ELF32, `EI_DATA=2` |
| mipselsf-k3.4 / неоднозначное `mips` | `mipsle`, `GOMIPS=softfloat` / `razvilka-linux-mipsle` | ELF32, `EI_DATA=1` |
| `mipsel`, `mipsle` | `mipsle` / `razvilka-linux-mipsle` | Прямой; `mipsel` — alias |
| x86_64 / `amd64` | `amd64` / `razvilka-linux-amd64` | Стенд, не роутерная архитектура |

При `uname=mips` читаются ровно шесть байтов `/proc/$$/exe` (fallback `/bin/sh`) через `dd bs=6 count=1` и совместимый с compact BusyBox `od -b`. Требуются ELF magic, класс 32 и полный dump с финальным счётчиком `0000006`. Неизвестный endian, ELF64, script, short/failed dump дают отказ до исполнения candidate. Явный `RAZVILKA_ARCH=mips|mipsle|mipsel|arm64` имеет приоритет. Не определять endian запуском скачанного бинарника.

Existing `scripts/test-installer-architecture.sh` проверяет оба endian, aliases/override, malformed/short headers, реальный host `od` на заданных байтах и обязательный checksum до candidate probes. `test-bootstrap.sh` проверяет передачу override. Cross-build не подтверждает физическую MIPS/MIPSel-приёмку.

## Команды финальной проверки (Root, позже)

Не запускались OPS. Выполнять из final clean checkout **после native/hour gates**, а не из OPS ветки. Push тега запускает workflow и создаёт draft; сам по себе не разрешает promotion.

```sh
REPO=ArtixSx/RAZVILKA
TAG='v0.20.0'
RELEASE_SHA='<final approved SHA>'
test -z "$(git status --porcelain)"
test "$(git rev-parse HEAD)" = "$RELEASE_SHA"
test "$(tr -d '\r\n' < VERSION)" = "${TAG#v}"
git ls-remote --tags origin "refs/tags/$TAG" "refs/tags/$TAG^{}"
# Только когда отсутствие тега и final SHA подтверждены:
git tag "$TAG" "$RELEASE_SHA"
git push origin "refs/tags/$TAG"
gh run list --repo "$REPO" --workflow release.yml --limit 5
gh release view "$TAG" --repo "$REPO" --json tagName,isDraft,isPrerelease,targetCommitish,assets,url
```

Скачать и проверить draft через authenticated CLI (download не запускает installer):

```sh
OUT="$PWD/.release-review-${TAG}"
mkdir -p "$OUT/dist"
gh release download "$TAG" --repo "$REPO" --dir "$OUT/dist" --pattern 'razvilka-linux-*'
gh release download "$TAG" --repo "$REPO" --dir "$OUT" --pattern SHA256SUMS --pattern 'RAZVILKA-*'
(cd "$OUT" && sha256sum -c SHA256SUMS &&
  sha256sum -c "RAZVILKA-${TAG#v}.SHA256SUMS" &&
  sha256sum -c RAZVILKA-entware.tar.gz.sha256)
gh attestation verify "$OUT/RAZVILKA-entware.tar.gz" --repo "$REPO"
# Также verify для каждого публикуемого binary и остальных attached artifacts.
tar -tzf "$OUT/RAZVILKA-entware.tar.gz"
# После точной router/hour acceptance и всех gates:
gh release edit "$TAG" --repo "$REPO" --draft=false --prerelease=false --latest
gh api "repos/$REPO/releases/latest" --jq '{id,tag_name,draft,prerelease,assets: [.assets[].name]}'
```

При смене packaging на строго три binaries сначала обновить workflow/attest/manifest; приведённые проверки читают фактический manifest. Во время подготовки ни tag push, ни promotion, ни удаления не выполнялись.
