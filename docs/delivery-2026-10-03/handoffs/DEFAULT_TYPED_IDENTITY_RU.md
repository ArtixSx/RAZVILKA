# DEFAULT: production shared LAN binding и typed retained identity

Отдельный finished implementation slice на принятой базе `4506a55` (`1a3fdd2` и accepted netidentity owner `70356411` уже включены). Ветка `sol/default-production-20261007`. Main/app/config, NFQ Spec/readiness/readback/collector и netidentity не редактируются. Реальные router/VM/native/GitHub операции здесь не выполняются.

## Callable startup API

`NewNetworkPolicyAdapter(ctx, NetworkPolicyAssemblyOptions)` возвращает concrete существующий `NetworkPolicyAdapter` для `Manager.Register` в ordinary `newDataplaneManagerWithNodes`. Конструктор не создаёт Manager, worker, execution journal или DNS/config/node migration. Он наблюдает concrete `*netidentity.Provider`; контекст должен иметь deadline, как требует provider. Полученная identity — binding, а не сохранённое permission. `adapter.NetworkIdentity()` возвращает detached metadata.

Options:

- `Provider *netidentity.Provider`: фактический trusted startup provider. Nil/zero/unknown не выдаёт adapter. Никакой exported fake observer, fallback по ENOENT или environment-profile selection здесь нет.
- `Binding *LANPolicyReceiptBinding`: существующий common mixed receipt, admitted Runner и точные IP/IPTables/IP6Tables; обязательны physical `Runtime.ScopeCheck`, ApplyGuard, CleanupGuard и RetireCheck. Descriptor/callbacks копируются, исходный binding больше не может их подменить. TransportCheck/ConsumerCheck сохраняются; их отсутствие по-прежнему отказывает там, где actual Verify требует corresponding consumer proof.
- `InventoryCheck(ctx, expected netidentity.Identity, allowedLAN *LANPolicyRuntimePlan)`: обязательный trusted owner callback. Для nonnil allowedLAN он должен подтвердить complete both-family registered classic coverage, complete native NFT coverage/отдельно принятый exact no-subsystem capture, отсутствие foreign reserved marks/priorities/chains и только exact independently receipted consumers этой LAN generation. Nil требует whole owned gate namespace absence, включая orphan generations; отсутствие owner файла и successful Deactivate не заменяют proof. Snapshot/RequireComplete alone не подтверждают ownership consumers. Этот callback должен потребить finished NFQ collector; success stubs недопустимы.

Физический ScopeCheck проверяет actual ingress birth/index/MAC, namespace и addresses against frozen typed LAN payload. ApplyGuard сохраняет existing review/control/capability/network admission. CleanupGuard сохраняет exact known receipt/control ownership независимо от forward WAN freshness. RetireCheck независимо подтверждает settled routing/filter/DNS/NFQ consumers до каждого delete. Callback не должен повторно вызывать blocking Manager operation или рекурсивно читать тот же receipt writer.

Каждая граница ScopeCheck/ApplyGuard/CleanupGuard/RetireCheck/InventoryCheck и actual Runner.Run/RunBounded проверяет full identity внутри concrete Provider.WithCurrent на одном OS thread, включая closing observation. Бюджет provider 2s ограничивает одну проверку/CLI, а не Apply/worker lifetime. Исходный admitted runner сохранён: identity не заменяет CORE admission at Cmd.Start. Исходная отмена и ошибки callbacks/CLI не нормализуются в PASS.

## Durable metadata

Новый factory пишет LAN owner Schema2 с `network_identity` и всеми пятью canonical fields. Его reader отказывает Schema1, old strings, missing/mixed/foreign identity и changed boot/inode/profile. Untyped прежний adapter также не принимает Schema2. Автоматической migration/adoption и новой cleanup authority из owner metadata нет. Общие receipt Apply/Inspect/Promote/Remove, generation semantics, exclusion MAC/source gates, foreign refusal и LAN-last order сохранены.

Existing Manager resource scope захватывает binding от SAME зарегистрированного gate, проверяет fresh identity при opening и после original review guard. NFQ reservation сохраняет её отдельно в `ExecutionNFQWSDefinition.NetworkIdentity` в SAME latest/transaction records; live matching требует исходную typed value. Deep clone не alias. Старый NFQ compiler пока принимает только proc inode: typed value должна точно совпасть с spec BootID и canonical `net:[inode]`. Reviewed singleton здесь **отказывается**, пока NFQ owner не завершит typed Spec/readiness/process/queue phase. Старую строку или receipt нельзя конвертировать в singleton.

У netidentity decoder строгий compact canonical wire form. `writeExecution` выбирает compact `json.Marshal` для records с typed identity; untyped формат остаётся прежним. Реальный write→read latest+transaction→CheckExecutionRecovery проверяется regression. Codec не ослаблен, aliases не добавлены.

## Следующий bounded active NFQ API: предложение для NFQ + CORE

Этот контракт обсуждается отдельно и **не реализован** данным slice. Current temporary assembly сохраняет caps 15s forward/5s cleanup, synchronous action и cleanup при возврате. Manager выдаёт её registrar только health/canary и закрывает scope после callback. Она не является ordinary Enable owner после Apply return.

1. **StartPrepared(requestCtx, same Manager reservation, frozen owner command)**. NFQ concrete owner проводит one-use READY/PERMIT/STARTED и actual queue/process proof в bounded activation phase. DEFAULT common issuer допускает capture только после actual ACK, same typed identity/LAN и durable process-pending → capture-ready. Неэкспортируемая живая prepared handle привязана ко всем восьми полям, original review/control и compiler effects; сериализованный Spec/binding её не заменяет. Отмена/unknown до transfer выполняет actual Stop/ECHILD/parent ACK и только existing-receipt cleanup; lost ACK остаётся fenced/no replay.
2. **CommitPrepared(requestCtx, exact prepared handle, accepted committed-plan guard)**. Нужна явная owner-approved передача к SAME Manager active resource после всех Prepare/Health и durable accepted config/plan publication. Оба existing execution records должны согласованно сохранять active definition, exact process session/typed identity/receipt reference и состояние transfer intent/ACK. DEFAULT scope.close отзывает request authority; только подтверждённый transferred owner продолжает жить. Нельзя просто сохранить старый review callback, продлить request context или запустить detached goroutine. Прерывание публикации без независимого ACK не превращается в active/unused.
3. **Observe(operationCtx, exact active binding)**. Новый operation context проверяет actual same process/queue, typed provider, protected files, shared receipt и accepted committed-plan/control revision. Fresh committed guard supplied by CORE читает actual Store/control, а не cancelled HTTP/request context. Observed active state не выдаёт следующий mutation grant. Same active owner нужен bounded Health/Commit/reconcile; foreign/missing/drift отказывает.
4. **Stop(operationCtx, exact active handle/binding)**. Только existing Manager Stop/retirement/rollback operation gate допускает owner signal/join. NFQ first доказывает same child inactivity/ECHILD/parent ACK; DEFAULT затем удаляет только known common receipt effects и independently settles removed in both existing execution records. LAN RetireCheck последним подтверждает всех consumers. Unknown signal/join/ACK/receipt сохраняет fence/retained definitions, без adoption/retry запуска.

После successful Commit отмена исходного request/возврат Apply не останавливает active runtime. Отмена до Commit требует Abort/known cleanup. Panel lifetime — отдельный explicit trusted startup context, который CORE создаёт/передаёт и закрывает через bounded existing shutdown/join; он не является сохранённым grant. Command's current immutable 15s lifetime нельзя просто растянуть на 8min request или panel: NFQ должен отдельно определить reviewed command schema/activation deadline и protected active-lifetime owner. Не нужен новый scheduler.

DEFAULT следующий resource phase должен хранить/передавать owner ACK, а не разрешать terminal `State=prepared`. Чистый metadata validator подтверждает shape; cold/restart active grant требует fresh concrete owner observation, не чтения `active=true`. При пропавшем live owner cold helper остаётся read-only/fenced и не реконструирует запуск из argv/старых strings. Concrete names/signatures и момент transfer относительно app CAS/Manager finishCommit должны быть приняты NFQ+CORE перед implementation.
