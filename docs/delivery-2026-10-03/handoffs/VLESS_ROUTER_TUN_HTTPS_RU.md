# Router-origin HTTPS через owned TUN — VLESS → CORE

`proxy_node_router_http*.go` содержит private transport `probeNodeRouterHTTPS`, предназначенный для production NodeTUN verifier из research checkpoint `477d411`. Это один настоящий TCP4 HTTPS request с назначенного router TUN IPv4 source, public literal destination и исходного service URL. Результат имеет origin `router-owned-tun`; он не является LAN observation, egress witness или разрешением Commit.

Linux transport проверяет up/nonloopback interface, exact source address и ifindex до запроса, непосредственно до и после `SO_BINDTODEVICE`, затем после service response. Socket binding требует успешного set и matching kernel get. Actual socket local source и remote destination:443 проверяются после connect. TLS использует исходные Host/SNI и обычную certificate verification; redirect, proxy environment, DNS dial, повторная попытка и alternate source отсутствуют.

Общий бюджет 10 секунд, dial/TLS по 4 секунды, response headers 6 секунд и 16 KiB. Service acceptance требует frozen full catalog predicate: exact ServiceID/URL, selected Probe и все status/content-type/JSON/schema/body expectations. URL-only reconstruction и callback boolean не дают semantic authority. Reader берёт bounded 32 KiB sample с lookahead и честным truncation; existing `probecheck.Evaluate` принимает только VerdictPass. Result связывает ServiceID/ProbeID/PredicateHash с ответом. Cancellation закрывает socket и завершает pending dial перед возвратом. Non-Linux production возвращает unavailable. Private per-call options существуют только для local TLS/OS fixtures и не экспортируются.

Перед вызовом и после него владелец verifier обязан проверить текущие runtime/config/manifest/control/network/generation identities, frozen service predicate в reviewed intent, назначенный TunnelCIDR и exact TUN ifindex. CORE typed NodeTransitLease должен дать краткий exact source /32 + oif + pinned destination /32 selector в уже owned TUN table, общий allocator, central parser/readback, durable intent и recovery в существующем Manager journal. Caller проверяет backend remote-socket isolation и return path/rp_filter capability. Закрытие sockets и exact lease removal/absence обязаны завершиться до успешной проверки или Commit. Unknown cleanup удерживает transaction fence.

Обычный Apply может получить RouterTUNService evidence после фактической native acceptance этой вертикали. LANFlowObserved/LANServiceObserved остаются unknown без настоящего LAN client flow и same-service witness. Exported LAN HTTPS helper из `76a3cd0` остаётся отдельной optional acceptance возможностью.

Private `newProxyServicePredicate(full catalog.Service)` проверяет catalog shape, выбранный unique ProbeURL, предварительные bounds и глубоко копирует caller arrays/provenance. Hash включает full catalog service и выбранный Probe. При непустом Probes отсутствие/неоднозначность selected URL отвергается; пустой Probes явно сохраняет существующий catalog web default, включая YouTube204. Frozen predicate никогда не выводится из одного URL или HTTP DTO.

Local TLS fixtures проверяют exact source/device/pin, set/get refusal, ifindex/address drift, invalid input before work, actual socket mismatch, original TLS hostname, semantic refusal, bounded body, proxy/redirect refusal, cancellation во время dial/TLS/body и non-Linux unavailable. После P2 исправления full-predicate tests включают ложный login/soft-block HTTP200 при обязательном BodyContains, content-type mismatch, invalid/missing/truncated JSON, полный JSON ровно32KiB, YouTube200/204, известную block page, missing/ambiguous/oversize/tampered predicate и caller mutation. Root `Test(NodeRouter|ProxyServicePredicate)` count3 PASS0.211s; автор Windows vet RC0; Linux compile/vet всего dataplane с новым native helper RC0. Native kernel/TUN/network здесь не запускались; normal registration, reviewed frozen service predicate, typed lease/recovery и committed health consumer пока требуют CORE/DEFAULT integration.

## Opt-in actual TUN component fixture

`RAZVILKA_XRAY_ROUTER_HTTPS_NATIVE=1` поверх существующего `RAZVILKA_XRAY_TUN_NATIVE=1` добавляет проверку к `TestNativeScopedXrayTUN` после реального Activate/Health/Commit A. Потребуются прежние pinned absolute Xray/Sing-box binaries. Новый helper проверяет root-owned private fixture root, router role и self netns != PID1, current owned runtime/manifest/policy receipt, actual source/ifindex и read-only rp_filter capability. Он имеет бюджет30s и отдельный cleanup8s; existing fixture deadlines увеличены на40s только при новом флаге.

В специально созданном router namespace helper применяет test-owned exact source /32 + oif + destination /32 → actual owned table tuple. Numeric readback/collision/route-get и ACK-only exact deletion/absence проверяются до возврата и продолжения lifecycle. Pending/unknown запрещает Deactivate; final namespace reaper остаётся владельцем teardown. Это временный механизм теста, а не production typed lease/journal/recovery.

Positive использует actual OS assignment, production checked bind/dial/TLS и только local CA roots. Frozen catalog требует JSON fields/content type/body marker controlled exit; result ServiceID/ProbeID/PredicateHash и body SHA/bytes сравниваются с реальным ответом controlled server. Дополнительный HTTP200 по тому же URL/source/oif/pin с невозможным обязательным marker обязан получить semantic отказ. Wrong ifindex/unassigned source/failing bind дают отказ; actual TUN link/address replacement здесь не тестируется. No NodeTUNObservation/LAN proof synthesis.

Linux amd64 compile-only RC0 (4.048s), Linux vet RC0 (1.005s), diff check RC0. Native запуск этого расширения пока ожидается от координатора. Даже успешный native component run не заменяет ordinary cold Apply, sealed production lease/recovery и normal registration.
