# CORE: retained self-update startup fence and matching consumer foundation

03–04.10.2026, `sol/core-20261003`. Один исполнитель; только sol-core. Новый common policy addition receipt модуль передан VLESS, CORE его не начинал. Эта порция **не installable D11 completion**: production OPS provider ещё отсутствует, поэтому `-self-update-schema` честно возвращает **0**, manual/scheduled/helper application installation отказывается до handoff effects. Legacy `RunInstallerHelper` из main больше не вызывается. Component schema2 и остальные ранее принятые component APIs сохраняются.

## Реально подключено

`main` читает retained file/helper journals **до** NormalizeLegacyStagePermissions, private restore, Load/create defaults/token и runtime recovery. По pending/corrupt state обычные CLI mutation modes отклоняются; daemon запускает ограниченную recovery-панель только из существующих config/token/credentials. Недостающие settings не подменяются defaults. Частные Stores, collectors, scheduler, node/network/USQUE recovery не стартуют. Повреждённые журналы и файлы не удаляются и не исправляются. Если recovery config/token нельзя прочитать безопасно, bootstrap прекращается с сохранением файлов.

Explicit roots: `-self-update-installation`, `-self-update-file-state`, `-self-update-helper-state`; env `RAZVILKA_SELF_UPDATE_INSTALLATION`, `RAZVILKA_SELF_UPDATE_FILE_STATE`, `RAZVILKA_SELF_UPDATE_HELPER_STATE`. Только абсолютные non-filesystem-root пути, без surrounding whitespace. Defaults `/opt`, `/opt/var/lib/razvilka/self-update-files`, `/opt/var/lib/razvilka/self-update`; config/dataplane relocation их не переносит. Private CLI/helper игнорирует эти публичные env overrides и использует fixed production roots.

Dynamic operation guard закрывает обычные Enter/Exclusive после появления pending/corrupt journal. GET `/api/v1/self-update/recovery` остаётся bounded/read-only/authenticated. POST требует strict JSON `transaction_id`, `action`, `expected_revision`, `confirm=REPAIR_SELF_UPDATE_TRANSACTION`, auth/Origin/CSRF, exact exclusive matching admission; не заимствует живой installer lease и не обходит component/private/network fences. Guard повторно проверяет Store revision/Stop/SafeMode перед и после наблюдений. Credential changes и обычная cancellation сохранённого helper при pending закрыты. Healthcheck распознаёт `SELF_UPDATE_RECOVERY_REQUIRED` как retained fence/exit76, сохраняя recovery-панель.

`SelfUpdateFiles.Action` реально вызывает OPS `selfupdatejournal.Prepare/Install/Restore/Execute/ResolveUnknown/Accept`, не печатает capability вместо consumer. Prepare требует полный фиксированный набор шести файлов и SHA staged migrated config до первого journal write. Любой other/duplicate/missing target отвергается. Journal обеспечивает old/new image hashing, durable file progress и отказ от third image. CORE дополнительно ограничивает порядок четырёх command names; команды одноразовые. Unknown command только trusted ResolveUnknown, без run/replay. Accept требует finished corresponding start command и independent Live. После terminal journal вызывается Finish; matching повтор при exact pending helper ID завершает только Finish, без file/command/live-acceptance replay. Finish сам обязан снова проверить independent live/image integrity.

CLI `self-update-files current` только читает fixed roots; `self-update-files <action> <jobID> <expected_revision>` использует тот же consumer и independent readonly fences; `self-update-helper <jobID>` использует новый `RunHelper`, без unsafe legacy fallback. RunHelper принимает только новый handoff: prepare/install/stop-old/start-candidate/accept-live; лишь known independent candidate live failure после confirmed start может перейти в stop-candidate/restore/start-rollback/accept-rollback. Unknown/crash не auto-resume. Терминальный разрыв helper settlement не вызывает rollback принятой file transaction.

## OPS provider: точный нейтральный контракт

Владелец OPS реализует concrete constructor в `internal/updatecheck` без импорта app. CORE подключит его в `nativeSelfUpdateFileAdapter()` и только после native evidence включит capability1.

```go
Inspect(context.Context, string /* retained file transaction ID */) error
Ready(context.Context, string /* new reviewed job ID */) error
Review(context.Context, string) (uint64 /* fixed revision */, string /* staged migrated config SHA256 */, []selfupdatejournal.File, error)
Authority(context.Context, string, uint64) error
Quiescence(context.Context, string) error
Run(context.Context, string, string /* fixed command name */) error
Observe(context.Context, string, string /* unknown fixed command */) error
Live(context.Context, string, bool /* rollback */) error
Startup(context.Context, string, int /* exact helper PID */) error
Finish(context.Context, string, bool /* rollback */) error
```

`Inspect` — новое уточнение: bounded readonly verification retained terminal images/schema/path/current/helper bindings, без ожидания runtime recovery и любых effects. Используется на ordinary startup/admission и перед новым Prepare; parser-only terminal успех не освобождает gate. Exact installed hashes/modes обязательны во время pending replacement и terminal helper-settlement gap (`Finish`); после полного settlement обычные reviewed config edits законны и не должны навечно сравниваться с SHA прежнего release image. Без provider даже terminal file receipt остаётся fenced. Обычный terminal inspect имеет 3s budget; provider обязан соблюдать ctx. Missing current с orphan preparation/image entries или unsafe writer marker даёт retained fence без deletion. `Review` замораживает exact helper job/release/deployment/CAS и config migration в **stage** до Prepare; после Prepare нельзя вычислить новый SHA из произвольного live файла. Возвращает immutable review и для recovery. `Authority` сверяет exact helper/file ID, boot identity, revision, Stop/SafeMode и направление old/new config при каждом эффекте. `Startup` подтверждает actual supervised helper/process/executable identity и соответствующую start command; просто PID alive не разрешает normal startup. `Quiescence/Observe` основаны на retained durable supervision и kernel wait/reaped evidence; historical unknown без него закрыт. `Live` — настоящее независимое подтверждение приложения и применённых routes. `Finish` выполняется после terminal file journal, с самостоятельной повторной integrity/live проверкой, затем durable helper receipt settlement.

## Блокеры capability1 — не скрывать

1. OPS provider/migration/supervised actual helper consumer пока нет. `nativeSelfUpdateFileAdapter()` возвращает nil. Здесь tested provider явно simulated; никакой production live/supervision PASS не заявлен. Нужны ordinary manual + scheduled + native helper + independent rollback/recovery acceptance с retained journals.
2. OPS library Execute допускает command только после Install/Restore; текущий порядок устанавливает frozen files под exclusive installer lease, затем записывает stop-old/start-candidate. Если production требует stop **до** первого replacement, OPS должен расширить journaled phase/order. Нельзя вызвать legacy unjournaled stop и объявить его покрытым ledger. Полный native consumer до согласования не включать.
3. Ограниченная recovery-панель не подключает обычный `/service-control/runtime` Stop: он сохраняет config и тем самым создаст third image. Dynamic gate в полном app сохраняет отдельный Stop scope, но этим нельзя обосновать Stop в interrupted file bootstrap. Конкретный следующий контракт для OPS опубликован в `CORE_SELF_UPDATE_STOP_CONTRACT_RU.md`: common CORE ledger вне config, revocation202 без installer lease borrowing, action-sensitive bounded rollback authority, independent exact cleanup, retained Stop на restart, никаких unknown→stopped-success. Это не финальное выключение Stop: module/consumer реализуются следующей согласованной порцией. Сейчас Stop здесь unavailable, не PASS.
4. Independent private journal reader признаёт только canonical checksummed idle metadata и никогда не восстанавливает images. Scope syntax/checksum проверяются; exact expected target-scope binding пока остаётся последующей проверкой owning Coordinator. Перед capability1 нужен owner-provided readonly scope/lease admission без Store migration/auto-recovery, иначе foreign-scope idle и concurrent restore не дают полного доказательства. Mutable/private directories остаются отдельным restore protocol, не file journal.
5. OPS retained-handoff lease должен освобождаться при abandoned `requires-review` и proven helper tree quiescence, чтобы matching repair живого старого app был достижим. Нынешний RetainHandoff освобождает только terminal+dead helper или process shutdown; HTTP намеренно не заимствует живой lease. Historical helper-only repair без supervision остаётся fenced.
