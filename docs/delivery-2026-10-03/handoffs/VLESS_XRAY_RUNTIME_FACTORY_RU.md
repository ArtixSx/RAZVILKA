# Xray runtime factory и обычная проверка сервиса

## Граница checkpoint

Код consumer/factory компилируется самостоятельно. Это готовая порция для CORE/DEFAULT insertion, а не утверждение, что `main` уже регистрирует factory или Manager уже выдаёт transient resource. До их подключения реальная операция отказывает; отсутствие issuer/review/predicate не заменяется разрешающим callback.

CORE insertion: `app.NewXrayNodeRuntime(app.NodeRuntimeFactoryOptions{Configs, Nodes, StateRoot, FreshProfile})` возвращает `*dataplane.ProxyTunnelAdapter`. Factory использует `Nodes.MaterializeXray`, точный engine-specific service record, logical catalog ID и актуальный network profile. Generic Xray adapter заменяется scoped экземпляром только при наличии private NodeStore. Установка бинарников, runner/process admission и регистрация в Manager остаются у CORE. `NodeTUNProbe` factory не создаёт.

DEFAULT insertion: guarded Manager operation устанавливает private `nodeTransitRegistrarKey{}` / `nodeTransitRegistrar`; каждый attempt получает отдельный private root. `register(ctx,spec,root,digest)` durably записывает typed resource **до** receipt/kernel effects в существующем execution ledger. Повторный cleanup callback проверяет то же зарегистрированное intent. `settle` разрешён после removed schema2 receipt и fresh exact absence. Cleanup получает отдельную recovery authority через `cleanupGuard`; отменённый review не возобновляется. Recovery реконструирует команды через `CompileNodeTransit`, а не из JSON argv. Committed/background health также требует нового зарегистрированного attempt root; committed policy receipt не переиспользуется для temporary grant.

Optional `settleUnused` закрывает только metadata resource при доказанном **живой функцией** отказе registration/early preflight до shared receipt/effect entry. Private one-shot token принадлежит той же lease; `VerifyUnused` проверяет root SameFile, fresh source/boot/ifindex, отсутствие receipt/permanent lock до и после numeric обеих семей, presence0. Fresh lease, read-only absence, crash или любой shared backend/intent/ACK error не создают этот token. При missing callback/ошибке resource остаётся retained; kernel command не выполняется.

Actual Manager readback ABI объявлен в VLESS-owned `node_transit_readback.go`: private `networkPolicyTransitReadbackKey`, callback `(ctx,spec,root,digest,mode) error` и modes prepared/removed/unused. Consumer устанавливает callback **до issuer**; он начинает работать только после возврата issuer и привязки фактически выданного root и созданной lease. Prepared подтверждает owner identity перед durable register, без усыновления kernel tuple. Removed независимо читает schema2 removed receipt и numeric обеих семей. Unused требует исходный private typed error и публикацию успешного `VerifyUnused` после всех завершающих проверок; claim привязан к той же lease/spec/root/digest, монотонный возраст не более 10s, только один раз. Manager сначала сопоставляет существующий prepared record, затем вызывает unused readback и сохраняет metadata-only settlement. Ошибка сохранения сохраняет fence, повторить claim нельзя. Четырёхаргументный `settleUnused` остаётся прежним; proof не является DTO и не сохраняется на диск.

`nodeTransitRuntimeFor(ctx,spec)` возвращает actual owner Runner/IP и read-only guards для независимой реконструкции Manager. Register остаётся nil; Manager обязан подключить callback проверки существующей записи и сам связать PlanID/Digest с immutable Execution. Boot, live launch/config/manifest, source/ifindex, profile и текущая candidate либо committed policy generation проверяются повторно. Generation directory и receipt ID могут различаться после restoration; receipt связывается с binding.ReceiptID. Receipt readers открывают только существующие anchored marker/document, используют общий trusted state/compiler loader, сверяют исходный/загруженный/завершающий snapshot и никогда не создают missing lock. Независимый mirror guard вызывает только owner readback, избегая рекурсии через Manager cleanupGuard.

## Обычный service/override путь

Stage требует sealed `Route.ProbeService` через `FrozenProbeService`, exact resolved node, client scope и materialized destination allowlist. Health сначала проверяет owned live process/config/manifest, launcher receipt, boot, owned interface/ifindex, actual assigned `TunnelCIDR` address и candidate/committed policy generation. Все свежие IPv4 service pins должны уже входить в materialized IP scope; расширение через DNS требует нового transaction.

Temporary rule задаёт exact assigned source `/32`, `oif`, destination `/32` и существующую owned table. Центральный NodeTransit registry использует отдельные slots после общего shared range, без WG canary coordinates. Add/delete используют существующий schema2 receipt и mandatory registration/guards; чужой или неизвестный tuple не усыновляется.

Router transport выполняет literal TCP4:443 с original verified TLS host/SNI и checked `SO_BINDTODEVICE`. Full frozen selected catalog predicate проверяет status/content type/body/JSON. Runtime, manifest, source/index, policy generation, lease/readback и backend isolation проверяются вокруг socket operation. Effective strict `rp_filter` отказывает; sysctls не меняются. Backend IP/owned fd tuples должны быть disjoint с service pin/source; Unix и explicit `NETLINK_ROUTE` control sockets классифицируются отдельно, неизвестный socket inode отказывает. Все proc/kernel reads bounded до parsing/allocation.

Socket закрывается и join завершается до cleanup; exact rule удаляется и absence подтверждается до успешного Health/Commit. Batch: 30s, один probe за раз, каждый HTTPS transport до 10s. Частичный batch не даёт общий PASS. Runtime/forwarding/router service proof не создаёт LAN selected/control/egress observation.

`NetworkPolicyRole=default` намеренно не превращается в catalog service. Полный Xray DEFAULT требует отдельной согласованной transport/source/IPv6/UDP acceptance; этот путь пока отказывает. Обычный catalog service/override использует full semantic predicate. Optional actual LAN producer остаётся отдельным путём.

## Локальная проверка

Новые factory/NodeTransit/USQUE/D10/router/readback/inactivity fixtures проходят без native/network запусков. Финальный полный dataplane: PASS, 111.355s; общий целевой selector dataplane/app: PASS 21.619s / 0.123s. Readback regression отдельно: PASS 1.208s, включая обе семьи, исходный успешный one-shot proof, независимый mirror, missing/corrupt marker с неизменным деревом, loaded-document ABA и независимые directory/receipt ID. Предыдущий полный app получил один внешний consumer scope failure `TestEncryptedPrivateBackupRestoresSensitiveConfigIntoDraftOnly` (fixture ожидает один engine file, фактически warp-wg и wireguard); CORE получил exact metadata reproduction и выпустил отдельный isolation fix, его принятие/merge здесь ещё ожидается. Остальные целевые новые app tests проходят. Windows и Linux package vet: RC0; Linux binaries компилируются, здесь не исполняются.

Coordinator-reported native48 проверил отдельный real Router HTTPS component, exact temporary cleanup, selected/control TUN, fresh adapter, sidecar restart и B→A rollback. Это acceptance component fixture, ещё не acceptance нового Manager-issued production NodeTransit/main factory пути.
