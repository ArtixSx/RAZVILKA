# RAZVILKA — исправление контракта списков и исключений
Дата: 07.10.2026.

Это адресное исправление прежней ошибочной трактовки «весь интернет», а не новый master-plan. Порядок D00–D14, назначенные роли и фактически достигнутый прогресс сохраняются. Процент готовности здесь не переоценивается. Код не менялся, тесты приложения не запускались.

Номера ниже проверены по текстовым файлам полной поставки от 03.10.2026. Они относятся к физическим строкам исходного Markdown до внесения изменений, а не к номерам строк поисковой выдачи. В более новой рабочей копии искать по заголовку и точной старой фразе. Не заменять текущие документы целиком старой копией: это может потерять отчёты и статусы агентов.

## 1. Единый исправленный контракт

RAZVILKA применяет обходы только к активному списку сервисов, доменов и поддержанных IP/CIDR-правил, по смыслу user list. Список действует на выбранные домашние сети без обязательного назначения каждого сервиса каждому устройству. Исключённые устройства и ресурсы из действующего списка исключений сервисов не обрабатываются обходами RAZVILKA. Список исключений объединяет отдельно хранимые ручные записи и разрешённый обновляемый каталог российских ресурсов. Несовпавший трафик использует обычную политику роутера. Пустой активный список не создаёт обходов. Общее подключение может обслуживать несколько активных записей, но не становится туннелем для остального интернета. Нужны общий исполнитель и согласованный DNS; защиту неподдержанного исполнения нельзя удалять вместо реализации.

Заменить его на «Замысел продукта: обход по активному списку на домашней сети» с контрактом раздела 1 этого уточнения.

В действующих копиях `GLOBAL_POLICY_SPEC_RU.md`, `ALL_INTERNET_EXECUTOR_RU.md`, `START_FOR_CLAUDE_CODEX_RU.md`, `ASTRA_COORDINATOR_V2_2_RU.md`, таблице задач, критериях приёмки и карточках агентов сверить смысловые формулировки:

| Устарело | Новое требование |
|---|---|
| Неизвестный сайт / прямой IP всегда получает общий обход | Без совпадения с активным правилом — базовая политика. Прямой IP может обходиться лишь по действующему разрешённому IP/CIDR-правилу. |
| Ноль сервисов сохраняет общий туннель всего интернета | Ноль активных правил — нет перехвата пользовательского трафика обходами RAZVILKA. |

| Исключение — только отсутствие карточки / мониторинга | Исключение обязательно ограничивает реальный маршрут, NFQWS2 и связанный service DNS. |
| Новый найденный сервис сразу получает общий VPN | До разрешённой активации записи — базовая политика. Auto-discovery не отменяет список исключений. |
| Весь интернет не зависит от наличия выбранных сервисов | Обход зависит от активных include-правил, а не от числа загруженных определений каталога. |

Не делать глобальную замену слова `default` в исходниках: там могут быть корректные значения fallback, профиля по умолчанию и маршрутов peer. Не переименовывать существующие пути только из-за старого названия папки. Поставить в исторических спецификациях явную отметку о замене продуктового контракта; журналы выполненных проверок не переписывать задним числом.

Разрешённый переход к базовой политике после отказа обхода и существующие интерфейсные свойства не означают разрешения full-tunnel. Профиль WG с AllowedIPs=0/0 также не является разрешением включить весь LAN.

Согласованное изменение исключения должно быть одной понятной пользовательской операцией, а не новым «режимом защиты изменений». Открытие страницы само не меняет сеть. Автоматика в уже разрешённых пределах не требует повторных подтверждений каждого шага.

## 4. Обязательные проверяемые результаты

1. Ресурс в активном списке, устройство участвует, исключений нет — используется разрешённый обход.
2. Ресурс отсутствует в активном списке — базовая политика.
3. Активный список пуст — перехвата через обходы нет.
4. Российский сервис одновременно попал в положительный импорт и в действующее RU-исключение — без обхода.
5. Ручное исключение домена/сервиса побеждает широкий положительный список и закреплённый VLESS.
6. Исключённая PS5 или устройство умного дома обращается даже к включённому YouTube — никакого NFQWS2, туннеля или service DNS RAZVILKA.
7. Удаление/отключение записи возвращает базовую политику, но не стирает другое действующее положительное правило на тот же ресурс.
8. Ресурс исключён во время проверки кандидата — старое разрешение Apply не применяется.
9. Перезапуск, обновление источников и автоматическое восстановление не отменяют принятые исключения.
10. Недоступный/пустой/повреждённый ответ источника RU-исключений не очищает последний принятый снимок и ручные записи.
11. Auto-discovery/auto-hostlist не предлагают повторно и не активируют исключённый ресурс. Сигналы исключённых устройств не запускают обходные проверки от их имени.
12. Сопоставление точных доменов, поддоменов, IDN, CNAME и адресов согласовано; пример `example.com` не включает `notexample.com` или `example.com.evil.test`.
13. Новый A/AAAA известного сервиса не создаёт вечное адресное правило: учесть срок, семейство адресов, источник и исключения.
14. Общий CDN-IP у активного и исключённого домена не приводит к перехвату исключённого сервиса. При недостатке возможностей — отказ спорного плана и понятная причина, не молчаливое расширение.
15. Добавление исключения при уже открытых TCP/UDP-сессиях имеет проверяемый переход; не показывать окончательное применение раньше него и не делать глобальный flush conntrack.
16. Все исполняемые обходы соблюдают одинаковое решение: NFQWS2, Xray, Sing-box, WG/AWG, WARP/USQUE и применимые дополнительные backend. Кандидатная проверка не выдаётся за клиентскую.
17. Изолированный отказ обхода затрагивает только соответствующий активный трафик согласно fallback-политике; обычные и исключённые ресурсы остаются под базовой политикой роутера.
18. Предлагаемые и сохранённые в библиотеке сервисы не входят в активный список до предусмотренной активации; обновление библиотеки не изменяет этот факт.

Это новые/уточнённые ожидаемые результаты, а не выполненные здесь тесты. Актуальные результаты агенты записывают с commit, командой, exit code и границами проверки. Не обнулять всю прежнюю приёмку: повторить затронутые сценарии на объединённом коде.
