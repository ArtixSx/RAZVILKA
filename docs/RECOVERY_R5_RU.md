> Исторический документ конкретного этапа. Версии, команды и состояние функций
> ниже относятся к тому этапу. Сейчас используйте [план](ROADMAP.md),

База выпуска: v0.18.1-rc.2, commit c6859b07316d07de3dc1fa243484a96078c5782b.
Рабочая VERSION: 0.18.2-dev. R5 — имя локального кандидата, не опубликованный релиз.

Восстановлены исходники A1/R3 из переданных ранее архивов, добавлен полный frontend R4.2.
Сохранённые node_check_fetch.go / node_cleanup.go R4 интегрированы с действующими
HTTP handlers, NodeStore, exact-checker и общей admission-блокировкой. Недостающий
консервативный фильтр очистки восстановлен по контракту, а не взят из неизвестной
прежней рабочей копии. Сетевые права и private stores не заменены демонстрацией.

## Исправлено

- Сопоставление протоколов NodeStore с политикой: `VLESS` больше не отклоняется
  из-за сравнения с `vless`. Неизвестные протоколы всё ещё запрещены.
- Кворум отказов использует реальные типизированные verdict/stage checker,
  а не ожидает отсутствующий `FAIL`. INCONCLUSIVE не запускает failover.
- Проверки ограничены контекстом сервиса, маршрута, времени и текущей сети;
  готовый резерв перед переключением перепроверяется. Успех не переносится на другой сервис.
- Снятие ещё не применённого сервиса очищает его собственный черновик без
  применения чужих ожидающих правок. Автоматическое обслуживание уступает место
  готовой к выполнению сервисной задаче.
- Получение подписки и последовательные точные проверки обслуживает одна задача
  Go-приложения. Закрытие HTTP-запроса не отменяет её; отмена требует ID текущей задачи.
- Массовое удаление имеет preview, generation guard, проверку ссылок и частичный итог.
  Защищены назначения, группы, pin, suspended routes, автономные резервы и планы отката.
  Старый DELETE отдельного узла также использует эти защиты.
- «Нерабочий» для очистки — два свежих разнесённых transport/egress отказа при
  пригодном независимом контроле; не отдельный отказ сайта, не ошибка DNS/исполнителя.
- GitHub-импорт сверяет переданный отпечаток предпросмотра до изменения определения.
- Встроен сайт R4.2: отдельная главная, сетка сервисов, AI-категория с индивидуальными
  результатами, инспектор, реальные кнопки fetch/check/delete и проверки обходов.
- Обновлена идентичность кэша frontend. Обновлены старые тесты для нового смысла
  выбора просроченного узла (его можно выбрать для удаления, но нельзя проверить/применить).

## Обязательные границы

Компиляция, unit/race, HTTP и браузерные тесты не подтверждают аппаратную работу
роутера или доступность публичных узлов. Результаты этого запуска поставляются
в отдельном VALIDATION_R5_RU.md с командами, кодами завершения и контрольными суммами.
Не объявлять stable и не заменять единственную рабочую установку до HIL.

Ночная автоматическая установка приложения/движков НЕ реализована. Окна A1
позволяют check/prepare, а не install. Нужны подписанный совместимый manifest,
комплект binary/config/dependency/schema rollback и испытание отказа без UI.
Не разрешать install изменением одного enum и не использовать общий opkg upgrade.

Автоматическая установка отсутствующего движка, полное нативное владение NFQWS2,
динамический Smart DNS, новые VMess/Trojan/XHTTP/UDP/IPv6 сценарии остаются отдельными
направлениями. Действующий checker поддерживает VLESS/HY2/TUIC/SS для веб-сценария.
Подбор использует готовые компоненты. Истёкшие результаты не становятся PASS от fetch.

Не завершены все origin-retention/GC/огромные подписки, лёгкое наблюдение вместо
каждого глубокого теста и crash-reconciliation разрыва config commit/sidecar receipt.
При неясном состоянии сохраняется review/Safe Mode, а не неограниченное разрешение.
Обновление источника не означает гарантированно независимый резерв или бесшовность сессий.
