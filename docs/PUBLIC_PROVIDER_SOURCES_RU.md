# Публичные источники резервных обходов — план

Запрос пользователя от 4 сентября 2026. Это будущая интеграция, не включённый
автопилот и не обещание доступности всех ключей.

## Первые кандидаты

- [VLESS Checker](https://tiagorrg.github.io/vless-checker/) — публичный список
  VLESS; страница заявляет обновление каждые 30 минут.
- [Goida VPN Configs](https://avencores.github.io/goida-vpn-site/) — подписки с
  несколькими протоколами; страница заявляет обновление каждые 9 минут.

Сверено 4 сентября 2026. Частота, протоколы и адреса выгрузок могут изменяться.
Заявление сайта об обновлении не является доказательством работоспособности
узла из сети пользователя. Не копируем UI/скрипты этих сайтов и не включаем их
аналитику. Перед встроенным шаблоном проверить условия использования выгрузки.

## Как это должно выглядеть для пользователя

«Другие обходы не работают» → «Найти резервный узел» → один раз включить
выбранный публичный источник → получить кандидатов и проверить из своей сети →
назначить проверенный узел/группу конкретному сервису.

В Lite — краткий статус «Проверяем / Доступен для Telegram / Устарел / Не подошёл»;
подробные причины и данные источника в Pro. Не выдавать TCP ping или успешный
импорт за работающий Telegram. Для Telegram отдельно обозначать, что проверено:
веб-сайт, сеть DC или клиентский сценарий. Успех веб-сайта не доказывает звонки.

## Порядок разработки и критерии

1. **N0.2:** безопасный частичный импорт. Реализован локально; один XHTTP или
   повреждённый ключ не мешает остальным. Отказ не подменяется другим транспортом.
2. **N1:** NodeStore с идентичностью узла, private credentials, provenance,
   временем получения и карантином. Подписка не может задавать DNS, firewall,
   inbounds, внешние API или системные команды. Новые узлы выключены.
3. **Exact checker:** ограниченная очередь с отменой и лимитами CPU/трафика;
   реальный handshake → проверенный выход → конкретный сервис, без direct fallback.
   Ошибки TLS не обходятся. Проверки только публичных адресов, с SSRF/rebinding
   защитой. Результат привязан к узлу, сети, сервису и сроку действия.
4. **Привязка сервиса:** выбирать точный узел или проверенную группу, показывать
   фактический маршрут. Активация проходит snapshot/canary/rollback. Проверка
   кандидата сама не меняет работающий NFQWS2/WARP/собственный сервер.
5. **Source adapters:** выключенные по умолчанию шаблоны этих двух источников,
   фиксированный parser/API-format, HTTPS, лимиты размера/числа записей/времени,
   redirect allowlist и защита publicfetch. Не произвольный обход HTML/ссылок.
6. **Автообновление по согласию:** отдельные настройки «Обновлять список» и
   «Проверять доступность». Conditional GET, TTL, jitter, backoff, cooldown,
   ограниченная параллельность, остановка и ручное обновление. Не опрашивать
   сайт с частотой UI refresh; `304` не продлевает здоровье узлов.
7. **Безопасное устаревание:** сохранить последний корректный список при ошибке
   источника; показать дату и статус stale. Пропавшие узлы не удалять из работающих
   привязок автоматически и не считать здоровыми бессрочно. Изменение ключа или
   endpoint сбрасывает health. Retry карантина — отдельный ограниченный процесс.
8. **Автоматическая замена:** отдельный последующий gate и opt-in в выбранной
   группе сервиса. Только свежие exact-service доказательства, hysteresis,
   минимальное время стабильности, лимит переключений и LKG rollback.
   Общий AUTO не получает право скрыто выбрать публичный прокси.

## Риски и границы

Публичный сервер может быть недоступным, перегруженным или недоверенным; его
оператор видит сетевые метаданные и незашифрованный прикладной трафик. Не отправлять
через тесты пароли, cookie, личные данные и приватные маршруты. Проверка показывает
результат на конкретный момент, а не обещает безопасность сервера.

Текущие выборочные parser-тесты работают только по opt-in, не сохраняют ключи
в Git и не подключаются к прокси. Скачивание списка не является отправкой
пользовательского трафика через него. Live-проверка и автоматика требуют отдельных
тестов, в том числе на роутере, прежде чем попадут в стабильный релиз.
