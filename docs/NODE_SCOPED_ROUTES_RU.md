# N1.4 — привязка проверенных узлов к сервисам

N1.4 подключает приватный NodeStore к рабочему адаптеру Sing-box. Импортированная
ссылка сама по себе по-прежнему не становится маршрутом. В выборе конкретного
сервиса появляются только узлы, для которых последняя точная проверка этого же
сервиса успешно завершилась в текущем профиле сети и ещё не истекла.

## Контракт выбора

- `sing-box:node-<id>` означает один конкретный узел. Базовый вариант
  `sing-box` или неизвестный суффикс не подтверждают существование такого узла.
- Доказательство ограничено тройкой «узел + сервис + профиль сети». Проверка
  Telegram не разрешает использовать узел для YouTube.
- Учитывается только самый новый подходящий результат. Новый отказ немедленно
  отзывает старый `PASS`; старое доказательство не может быть восстановлено из
  истории.
- Отключённый, просроченный или утративший provenance узел не материализуется.

## Группы и последний рабочий узел

Страница «Узлы» позволяет создать группу в одном из двух режимов:

- **Только выбранный узел** — сервис работает только через основной узел.
- **Автоматический резерв** — сохраняется узел из последнего зафиксированного
  рабочего плана. Пока его точное доказательство действительно, задержка других
  узлов не вызывает переключений. После подтверждённого отказа выбирается
  проверенный основной узел, затем доступный узел с наименьшей измеренной
  задержкой; равенство разрешается стабильным ID.

Изменение или удаление назначенной группы запрещено. Сначала сервису нужно
назначить другой маршрут и применить его. Удаление узла, входящего в группу или
напрямую назначенного сервису, также запрещено.

## Материализация и защита от зацикливания

Перед транзакцией выбранная группа разрешается в точный `node-id`. Приватные
credentials извлекаются только внутри NodeStore и передаются локальному
dataplane-адаптеру; HTTP API, публичный план и журнал их не содержат. Sing-box
получает минимальную конфигурацию только с нужными outbound и назначенными
доменами/IP. Остальной трафик закрывается правилом `block`.

Публичные адреса серверов узлов превращаются в точные `/32` или `/128` исключения
с более высоким приоритетом и таблицей `main`. Поэтому соединение Sing-box с
собственным сервером не попадает обратно в тот же туннель. Неопределимый,
локальный или непубличный endpoint блокирует подготовку плана.

## Транзакция и откат

Материализация выполняется после snapshot и до native validation/canary. Затем
используется общий порядок `stage → validate → isolated canary → activate →
health → commit`. При любой ошибке рабочий runtime и policy восстанавливаются из
снимка, а зафиксированный план продолжает указывать на последний рабочий узел.
Черновик назначения сохраняется для исправления пользователем.

## Подтверждено автоматически

- exact node/service/network/TTL selector и отзыв старого PASS новым отказом;
- manual/fallback group, стабильный выбор и переход после утраты proof;
- запрет удаления членов группы;
- приватная детерминированная конфигурация и конфликт владельцев назначения;
- endpoint-исключение раньше tunnel policy;
- API групп без изменения рабочего маршрута и без раскрытия credentials;
- schema 1–3 читаются без фоновой записи, schema 4 хранит группы и участвует в
  зашифрованном backup/restore.

Аппаратная проверка N1.4 на Keenetic, включая реальное переключение двух узлов и
откат после отказа canary, остаётся отдельным gate перед стабильным релизом.
