# RAZVILKA v0.11.0 — план реализации и испытаний

Статус: планируется. Версия выпускается только после выполнения обязательного
объёма, прохождения автоматических тестов и аппаратной проверки на тестовом
Keenetic/Netcraze.

## Цель релиза

Сделать RAZVILKA лёгким локальным центром управления, который устанавливается
одной командой, позволяет выбрать нужные сервисы, устанавливает обходы по
требованию, безопасно подбирает стратегии NFQWS2 и показывает реальные ресурсы
и трафик роутера.

Основной интерфейс — «Центр управления», первый запуск — простой мастер,
расширенные возможности — отдельный экспертный режим Strategy Lab.

## Зафиксированные продуктовые решения

- Базовая установка содержит UI, API, каталог, диагностику, транзакционный
  координатор и менеджер компонентов, но не устанавливает все обходы заранее.
- NFQWS2, usque/WARP, sing-box, Xray, AmneziaWG и следующие интеграции
  устанавливаются из раздела «Обходы» по выбору пользователя.
- WARP/usque также устанавливается по требованию. В базовый пакет входят только
  manifest, preflight и код безопасной установки/настройки.
- Первый мастер предлагает четыре варианта: «Только интерфейс», «NFQWS2»,
  «NFQWS2 + WARP» и «Выбрать вручную».
- Установленный z2k до миграции считается внешним владельцем NFQUEUE. RAZVILKA
  не запускает поверх него второй NFQWS2 и не удаляет z2k автоматически.
- Идеи z2k переосмысливаются в архитектуре RAZVILKA. Его скрипты, fake payloads
  и телеметрия не копируются в проект без отдельной проверки лицензии и
  происхождения.
- Для входа исследуется адаптер учётных записей Keenetic Web UI. Пароль SSH не
  переиспользуется. На неподдерживаемых прошивках остаётся локальная учётная
  запись RAZVILKA и recovery key.
- Весь интерфейс работает локально, без CDN и обязательной внешней телеметрии.

- [ ] Добавить переключение «Простой / Экспертный режим».
- [ ] Сделать раздел «Обходы» вместо списка предустановленных компонентов.
- [ ] Сделать Strategy Lab отдельным экспертным разделом.

- [ ] Добавить локальные иконки, пустые состояния, понятные ошибки и ссылки на

- [ ] Проверить адаптивность от 320 px до настольной ширины, светлую и тёмную

### 2. Установка одной командой и консоль `razvilka`

- [ ] Одна команда устанавливает только базовый control plane и печатает URL
      первого входа.
- [ ] Preflight проверяет Entware, архитектуру, прошивку, netfilter/NFQUEUE,
      TUN, свободные RAM/flash, DNS, время и доступность источников.
- [ ] Установщик показывает короткие этапы и понятную причину остановки.
- [ ] Повторный запуск выполняет обновление/ремонт, а не дублирует файлы и
      init-скрипты.
- [ ] Добавить команды `razvilka status`, `doctor`, `components`, `update`,
      `backup`, `rollback` и `uninstall`.
- [ ] Сохранять предыдущую версию и автоматически откатывать неудачное
      обновление.
- [ ] Проверять checksum/signature release-артефактов до запуска.

### 3. Менеджер обходов по требованию

- [ ] Показывать состояния: доступен, устанавливается, установлен, настроен,
      активен, ошибка, доступно обновление и внешнее управление.
- [ ] Реализовать `plan → download → verify → snapshot → install → validate →
      health → commit-or-rollback`.
- [ ] Реализовать установку, обновление и удаление NFQWS2.
- [ ] Реализовать установку, обновление и удаление usque/WARP MASQUE.
- [ ] Подключить существующие адаптеры WARP-WG, sing-box, Xray и AmneziaWG к
      тому же контракту компонентов.
- [ ] Не разрешать удаление активного компонента без отключения зависимых

- [ ] Не менять файлы, процессы и правила внешнего владельца.
- [ ] Добавить уведомление вида `1.1.0 → 1.2.0` и отдельную кнопку обновления.

### 9. Вход и безопасность

- [ ] Исследовать NDM/Keenetic challenge-response и поддерживаемые версии

- [ ] Реализовать адаптер входа через учётную запись Keenetic Web UI, если API

- [ ] Оставить локальную учётную запись и recovery key как совместимый fallback.
- [ ] Не использовать и не сохранять пароль SSH в UI.
- [ ] Сохранить LAN bind, SameSite cookies, CSRF/origin checks, rate limiting,

- [ ] Не включать внешнюю телеметрию по умолчанию.
- [ ] Диагностический экспорт должен удалять токены, ключи, пароли, приватные
      endpoints и персональные данные.

## План реализации

1. **Контракты и данные** — component manifest, resource/traffic schema,
   Strategy Lab evidence и z2k import preview.
2. **Backend** — component lifecycle, samplers, Strategy Lab, migration и новые
   API с unit/integration тестами.
3. **Установщик и CLI** — UI-only install, preflight, команды, upgrade и
   rollback.
4. **Новый UI** — общий каркас, мастер, «Обходы», Strategy Lab, ресурсы и
   трафик.
5. **Лабораторные тесты** — чистая Entware-среда, fake runtimes, ошибки сети,
   конфликты и crash recovery.
6. **Аппаратные тесты** — тестовый Keenetic с установленным z2k, затем чистая
   конфигурация после контролируемой миграции.
7. **Release gate** — документация, changelog, артефакты, checksums, rollback и
   повторный полный smoke-test установленного релиза.

## Критерии выпуска

`v0.11.0` можно тегировать, если одновременно выполнено следующее:

- все обязательные пункты выше завершены или явно перенесены из обязательного
  scope до начала release candidate;
- автоматические тесты и cross-build зелёные;
- UI-only install, upgrade, rollback и uninstall проверены на роутере;
- NFQWS2 Strategy Lab дал воспроизводимый результат и пережил reboot;
- WARP устанавливается по требованию и не теряет live-профиль при неудаче;
- z2k и standalone NFQWS2 никогда не владеют NFQUEUE одновременно;
- показатели ресурсов и трафика подтверждены системными счётчиками;
- ни один UI-экран не выдаёт desired/planned состояние за фактически
  применённый маршрут;
- backup и откат к предыдущей версии проверены перед публикацией;
- README, руководство установки, CHANGELOG, THIRD_PARTY и troubleshooting
  соответствуют фактическому поведению релиза.

После прохождения gate выпускаются подписанные артефакты `v0.11.0`. Небольшие
совместимые исправления этой ветки получают версии `0.11.1`, `0.11.2`, `0.11.3`; следующий
крупный функциональный этап — `0.12.0`.
