# PR-1.1 — старые форматы и приватный backup

Продолжение 31 августа 2026 года. Локально, без регистрации, push/release и
изменений рабочего роутера. API и UI нового Provider ещё не подключены.

## На чём основаны адаптеры

Проверены исходники с фиксированными commit, а не случайные конфиги из сети:

- [USQUE config](https://github.com/Diniboy1123/usque/blob/6aa03fc97d12848dce34eedbd187fb1077b5d1ea/config/config.go)
  и [сохранение после регистрации](https://github.com/Diniboy1123/usque/blob/6aa03fc97d12848dce34eedbd187fb1077b5d1ea/cmd/register.go).
  Формат содержит EC private key в DER/base64, PEM peer public key,
  endpoint IPv4/IPv6/H2 и отдельные назначенные адреса `ipv4`/`ipv6`.
- [wgcf config](https://github.com/ViRb3/wgcf/blob/b0ffa9659a06f5ddefc4660f61f7d2d6f4db3348/config/config.go)
  и [запись account](https://github.com/ViRb3/wgcf/blob/b0ffa9659a06f5ddefc4660f61f7d2d6f4db3348/cmd/register/register.go).
  В account используются четыре строки: device ID, access token, private key
  WireGuard и license key.

Это сведения о формате, не доказательство действительности аккаунта или
совместимости любой сторонней сборки с этими версиями.

## Реализация

- Добавлен импорт `wgcf-account`: только плоские строковые поля выгрузки wgcf,
  одинарные/двойные кавычки и комментарии. Таблицы, escapes, multiline,
  повторные/неизвестные поля и redaction-заглушки отклоняются. Это намеренно
  ограниченный адаптер, не универсальный TOML-парсер.
- USQUE с известной структурой получает `format=usque-v1`: разбираются EC-ключи
  P-256, соответствие семейств endpoint/assigned IP, считается fingerprint
  локального публичного ключа. Неизвестный/неподдержанный вариант остаётся
  `opaque-archive`, без заявленной пригодности для транспорта. Старые копии
  schema 1 не становятся нечитабельными из-за более строгой проверки.
- Дубликаты JSON и неоднозначный регистр известных полей не дают типизированный
  результат. Все импортированные копии остаются `imported-unverified`:
  ни fingerprint, ни распознавание формата не подтверждают handshake/egress.
- Добавлены синтетические воспроизводимые fixtures для полей upstream;
  тестовые ключи никогда не регистрировались. Реальные ключи пользователя
  при разработке не читались.
- Provider использует существующий парольный AES-GCM envelope приватного
  backup. В открытом виде наружу возвращается только public DTO; метод Store
  экспорта возвращает ciphertext. Файл самого локального хранилища, как и
  раньше, защищён правами, а не шифрованием от root.
- Restore объединяет копии одной атомарной записью. Существующие записи не
  удаляются; одинаковый ID с другими данными блокирует всю операцию. Проверки
  пароля, целостности, схемы, лимитов и writer lock выполняются до commit.
- Расширение `provider_snapshots` находится только в приватном payload и
  отсутствует в JSON старых payload без Provider. Старый общий импорт роутера
  явно отклоняет архив с Provider, пока нет согласованной полной транзакции.
  Нельзя сообщать об успешном восстановлении, молча пропустив аккаунты.
- Размер криптографических полей проверяется до base64-декодирования/KDF.

## Ограничения и продолжение

1. Пока нет автоматического чтения/миграции `/opt/etc/usque` или wgcf-файлов.
   Store принимает только переданные байты и владеет своей копией, не runtime.
2. Новый backup/restore доступен как внутренний контракт. Далее нужны
   аутентифицированные API, UI preview и интеграция общего recovery.
3. Неизвестный `.import.lock` не удаляется автоматически. Восстановление после
   аварийно прерванного writer требует отдельного решения с доказанным владельцем.
4. Парольный KDF имеет ограниченное число итераций; отмена проверяется до и
   после вычисления, не в каждой итерации. При интеграции API нужен отдельный
   глобальный лимит параллельных backup/restore на маломощных роутерах.
5. Transport candidates и регистрационные DNS/API evidence ещё не подключены.
   Следующий регистратор разрабатывается только через mock API.
6. Максимальный backup — существующий лимит приватного payload (8 МиБ).
   Если сериализованная совокупность копий не помещается, экспорт отказывает,
   не создаёт усечённый архив. Для больших коллекций понадобится выбор записей.

## Проверки

Тесты: известные/неизвестные форматы, порты/семейства IP, невалидные ключи,
дубликаты, redaction, шифрованный round-trip, идемпотентный restore, сохранение
существующих записей, неверный пароль, конфликт ID, повреждённый контент,
посторонний router payload, writer lock, отмена и переполнение capacity.
Полный общий импорт также проверяет запрет молчаливого пропуска Provider.

После последних изменений прошли `go test ./... -timeout=90s` и
`go vet ./...`. Fuzz-проверка `FuzzParseImport`: 79 409 запусков без падений.
Все пакеты и provider test binaries скомпилированы для Linux arm64, mips и
mipsle (MIPS softfloat). Эти бинарники на целевых устройствах не запускались.

Linux/race и аппаратная проверка по-прежнему отдельные gates; локальная
кросс-компиляция не объявляется подтверждением работающего WARP.
