# RAZVILKA R3 — перестройка локального интерфейса

Дата: 2026-09-08. База: предоставленный `RAZVILKA_UI2_SOURCE.zip`, исходники `0.18.2-dev` (A1/UI2 поверх опубликованного rc.2 `c6859b07316d07de3dc1fa243484a96078c5782b`). R3 — обозначение локального UI-этапа, не новый GitHub-релиз.

## Почему это не очередная перекраска

В UI2 длинная навигация выставляла все движки на первый план, а слева и справа на главной повторялись сервисы. В R3 изменено размещение функций: семь основных направлений, контекстные вкладки, одно представление сервиса с фактическим маршрутом, отдельные сценарии «посмотреть», «добавить», «настроить».

| Основной раздел | Вложенные представления |
|---|---|
| Обзор | Состояние выбранных сервисов; Автопилот |
| Сервисы | Мои/все/нужна проверка; политики и резерв |
| Подключения | Узлы; каталог источников; подписки; текущие соединения |
| Обходы | Шесть компонентов; редактор; NFQWS2 Lab; DNS/Smart DNS; проверки |
| Устройства | Клиенты, имена, группы и область политик |
| События | История действий; диагностика с ресурсами/графиком трафика |
| Настройки | Общие настройки; мастер; обновления; источники доменных списков |

Сохранены 20 существующих `view-*` и шесть контекстов редактора. 695 исходных DOM ID сохранены для совместимости обработчиков. Это не обещание 20 заново переписанных backend-функций. Старые формы и API не вырезаны.

## Главная

Одна кнопка «Добавить сервис», сводка свежих подтверждений, единые карточки сервисов, блок требующих внимания, краткие ресурсы, окно обслуживания и последние события. Удалён второй видимый дубликат списка маршрутов. Трафик/история ресурсов перенесены в диагностику, а не удалены.

AI — одна раскрываемая категория по метаданным каталога. ChatGPT, Claude, Gemini, Perplexity и пользовательский сервис с `category=AI` остаются самостоятельными сервисами. Нет синтетического маршрута `ai`. Разные маршруты обозначаются явно. Состав группы не расширяет разрешённый трафик. Новые участники каталога остаются выключенными; массовое включение в этом этапе не реализовано.

## Карточка и инспектор сервиса

Показываются выбранность, текущий путь, результат проверки и состояние очереди. Сохранённое намерение управления теперь видно даже до изменения исходного draft/applied: сервис не исчезает из «Моих», пока backend подбирает путь. Это UI-проекция (`selectedView`), не мутация сетевой конфигурации.

Нажатие открывает боковую панель с маршрутом, областью устройств, составом доменов и действиями. Проверка, настройки, передача Автопилоту, пауза и очередь удаления используют прежний серверный контракт. Пауза не выдаётся за снятие маршрута. HTTP 202/успешный приём запроса не выдаётся за применение.

В «Сервисах» список выбран по умолчанию; доступны карточки. Поиск охватывает название и домен, раскрывает соответствующую AI-группу. Фокус/раскрытие сохраняются при перерисовке. Все подробные индивидуальные формы доступны в раскрытии, не загружают основной список.

## Подключения и обходы

Сохранены импорт ссылок, выбор узлов, фильтры, группы и существующий путь проверки/применения. Исправлена фильтрация протоколов: сначала фильтр, потом пагинация. Каталог источников не является подтверждением доступности его серверов.

Каждый движок имеет вход из общей страницы обходов, свой заголовок, назначение, версию и раздельные ступени: установка, процесс, маршруты, проверка сервиса. Все исходные формы конфигураций/файлов/импорта/проверки сохранены. Это улучшение представления существующих возможностей, не завершение нативного NFQWS2 или USQUE lifecycle.

## Визуальная система

Светлая тема по умолчанию, тёмная по кнопке. Системные шрифты; исходный логотип/favicon и SVG-иконки сохранены, добавлен собственный символ группы AI. Без CDN и внешних шрифтов.

Один скомпилированный `interface.css` строится из `interface-compat.css` и `interface-shell.css`. В совместимом слое 675 статических цветовых/background-деклараций прежних стилей переведены на общие токены: исправлена нечитаемость старых тёмных блоков в светлой теме. Это переходный слой, а не окончательное удаление старого CSS. Новые страницы используют собственные `ui3-*` компоненты. Старые исходные CSS оставлены для отката/совместимости, но главная их отдельно не загружает.

Все загружаемые JS получили одинаковый cache key `0.18.2-ui3`. Мобильное меню не перекрыто невидимой подложкой; закрытая панель не получает ввод. Добавлена компактная нижняя навигация. Диагностика и формы проверены на ширинах 360/768/1440 px.

## Исправления поведения и достоверности

1. `console-autonomy.js`: после `409 RESTORE_OPERATION_BUSY` повтор сохраняет исходную редакцию авторизации. Выход/401 отзывает уже ожидающий retry; не происходит повторной записи под новой сессией.
2. Новый инспектор отменяет запросы при завершении сессии и не принимает поздний ответ в новое состояние. Таймаут мутации 20 секунд сообщает неопределённый результат, а не автоматически повторяет запись.
3. `service-dashboard-ui.js`: PASS требует корректного `checked_at`, не находящегося в будущем, и непросроченного срока; пропущенная или будущая дата больше не даёт зелёный результат.
4. `console-autonomy.js`: строка runtime `healthy/applied` не повышает свежесть сервисной проверки. Сводка пользуется общим TTL-aware представлением.
5. `interface-model.js`: выбранность отделена от применения. Принятый сервис отображается «Ожидает настройки», удаляемый — «Удаление в очереди».
6. Добавление пользовательского сервиса немедленно обновляет общий каталог; выбранная категория передаётся существующему API и не ограничивается демонстрационными именами.

## Реальные контракты, не новые обходящие API

- Общие сервисы/состояние/узлы/компоненты — существующие GET API и state.
- Новый custom-сервис — `/api/v1/custom-services`, существующая schema.
- Передача управления/пауза — `POST /api/v1/autonomy/services`, конкретный ID, `expected_revision`, `confirm=MANAGE_SERVICE`, область из сохранённых defaults или прежнего назначения.
- Снятие управления — `DELETE /api/v1/autonomy/services/{id}`, `confirm=REMOVE_SERVICE`, очередь, сохранение определения по умолчанию.
- Проверка и подробное применение — существующие service-control/checker/route UI handlers.
- Изменения мастера — `/api/v1/autonomy`, существующий A1 контракт; missing API не заменяется демо-успехом.

Не добавлялись браузерные таймеры переключения сети, второй NodeStore, новый checker, отдельный installer или новый механизм Apply.

## Разграничение production и предпросмотра

`cmd/razvilka/web` содержит настоящие обработчики API. В нём нет `__demoData`, подмены `window.fetch` или фиктивного PASS.

`RAZVILKA_R3_PREVIEW.html` — отдельная сборка того же DOM/контроллеров с подставными ответами, уведомлением и версией PREVIEW. Искусственные даты проверок нормализуются только в preview. Его изменения живут в памяти и пропадают при перезагрузке. Тестовый адаптер возвращает отказ для реального применения/установки и неоднозначные результаты сетевых проверок; он не реализует туннели. Этот HTML нельзя устанавливать вместо production.

## Что остаётся техническим долгом

- Общий старый `app.js` всё ещё крупный; он не переписан ради внешнего вида. Следующий этап — пофункциональное извлечение с контрактными тестами.
- Часть старых home-targets сохранена в скрытом compatibility-контейнере, пока старые обработчики на них ссылаются. Удалять вместе с зависимостями, не стирать произвольно ID.
- Совместимый CSS содержит старые правила, переопределённые новой темой; 345409 байт текущего compiled CSS до сжатия. После снятия старых зависимостей потребуется поэтапная очистка.
- Браузерный UI не доказывает LAN-путь, здоровье движка или завершённость AUTO2–AUTO4.
- Go backend A1 оставлен без сетевых изменений: не скомпилирован полностью в этом окружении. Дополнен только тест embedded assets.
- Установка обновлений ночью, отсутствующих движков, нативные advanced-функции, UDP/IPv6 сценарии и аппаратная приёмка вынесены в `CODEX_HANDOFF_R3_RU.md`.
