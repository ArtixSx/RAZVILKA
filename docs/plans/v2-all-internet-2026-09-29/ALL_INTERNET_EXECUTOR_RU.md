# Исполнитель «всего интернета»: проект решения

**Статус:** предложение для согласования владельцем (29.09.2026). Ничего из этого
документа пока не реализовано и не выпущено. Основание: главная задумка владельца
и контракт [GLOBAL_POLICY_SPEC_RU.md](GLOBAL_POLICY_SPEC_RU.md).

## Задумка владельца

> Установил RAZVILKA → выбрал нужные сервисы, исключил устройства и сайты, которым
> обход не нужен, разрешил подходящие способы подключения → дальше программа сама
> организует доступ ко всему интернету для остальных устройств: получает и проверяет
> кандидатов, применяет подключения, следит за работой, переключает резервы и
> восстанавливается.

## Что есть и чего не хватает

| Часть | Сейчас | Нужно |
|---|---|---|
| Сервисы и их маршруты | Есть: домены/CIDR сервиса → NFQWS2 или туннель, правила `ip rule` по адресу назначения и устройству | Сохранить как «индивидуальные сервисы» поверх общего пути |
| Исключения сайтов | Есть для NFQWS2 (`exclude.list`, вкладка «Исключения») | Общие исключения для туннелей: сайт → напрямую |
| Исключения устройств | NFQWS2 — через политику Keenetic; туннели — только область в карточке сервиса | Общий список «вся сеть, кроме…» для всех обходов |
| Общий путь | Модель есть (NetworkPolicy schema 2, `DefaultRoute`), исполнитель отказывает (`NETWORK_POLICY_EXECUTOR_REQUIRED`) | Исполнитель: весь прочий трафик участвующих устройств → проверенный туннель |
| Автопилот | Для сервисов: кандидаты, проверка, резервы, переключение, восстановление | Та же логика для цели «общий путь» (F01/F02) |
| Защита | Транзакция с откатом при сбое health | Сторож после применения: пропал интернет → вернуть прежнее (как WayHop) |

## Архитектурное решение: метки, а не селекторы `ip rule` по источнику

Правило «от исключённого устройства → основная таблица» перебивает политики доступа
Keenetic для этого устройства. Правила «все, кроме» через дополнения CIDR умножают
число правил сверх лимита. Поэтому общий путь строится на метках (как WayHop на
Keenetic, но без переписывания основной таблицы роутера):

1. Собственная цепочка `mangle PREROUTING` только для входящего трафика
   согласованных LAN-интерфейсов. Трафик роутера (OUTPUT) не перехватывается.
2. Порядок внутри цепочки повторяет раздел 4 контракта:
   - исключённые устройства (MAC/адреса из реестра устройств) → `RETURN`;
   - служебное и локальное (адреса роутера, частные сети, мультикаст) → `RETURN`;
   - сайты «без обхода» (ipset из списков и адресной книги DNS) → `RETURN`;
   - российские адреса (ipset по геобазе, если включено) → `RETURN`;
   - иначе метка общего пути (`MARK --set-xmark 0x…/маска RAZVILKA`).
3. `ip rule fwmark <метка>/<маска> lookup <таблица туннеля>` на приоритете после
   правил индивидуальных сервисов: сервис со своим маршрутом по-прежнему выигрывает.
4. В таблице туннеля — маршрут по умолчанию в интерфейс туннеля и `throw` для
   локальных сетей; адрес сервера туннеля уже исключается существующим механизмом.
5. Метки и маска выделяются из свободного пространства с проверкой чужих правил
   (nfqws2 использует `0x40000000`, `0x20000000`; Keenetic — свои метки политик).

Для NFQWS2 общий путь не нужен: он уже обрабатывает автосписок и списки сервисов.
Если туннель недоступен, работает выбранная политика отказа (раздел 12 контракта):
пропускать напрямую либо блокировать управляемый трафик.

## Этапы

1. **Исключения устройств и сайтов для туннелей через метки.** Цепочка
   классификации и ipset, пока без общего пути: те же исключения применяются к
   правилам сервисов на всю сеть. Проверка: исключённое устройство идёт напрямую,
   остальные — через сервисный туннель; чужие правила Keenetic не тронуты.
2. **Общий путь за явным согласием.** Мастер: выбор способов, политика отказа,
   область устройств. Цель `default` в плане dataplane (не поддельный сервис 0/0),
   канарейка, readback, откат. Сторож после применения: нет интернета ~45 с →
   возврат прежнего плана.
3. **Автопилот для общей цели.** Кандидаты из разрешённых источников, проверка
   общего доступа (несколько эталонных сайтов, DNS, UDP), резервы, переключение по
   подтверждённому отказу, восстановление после перезагрузки и смены WAN.
4. **DNS без утечек и российские исключения.** Общий резолвер для участвующих
   устройств, адресная книга (домен → адреса с TTL) для исключений сайтов,
   геобаза RU.

Каждый этап — отдельный выпуск с HIL на роутере владельца и явным разрешением
перед включением общего пути.

## Решения владельца (29.09.2026)

1. **Полный отказ:** пропускать трафик напрямую. Если все туннели недоступны,
   трафик идёт обычным WAN, панель показывает деградацию.
2. **Российские и прочие сайты без обхода — только списком.** Автоматической
   геобазы нет; пользователи дополняют список своими сайтами (вкладка
   «Исключения»).
3. **Все пути:** общий путь может использовать любой разрешённый исполнитель
   (узлы из подписок, WARP, свой WireGuard/AmneziaWG, Xray…) через один
   интерфейс, который расширяется в будущем.
