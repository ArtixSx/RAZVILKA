# ALL-INTERNET: контракт общей политики V2

**Статус:** предлагаемая семантика, не существующий JSON API. Обязательный результат — последнее уточнение владельца. Конкретные имена типов допускается адаптировать к текущему коду без второго manager/реестра.

## 1. Главная формула

`Участвующий домашний клиент → системная безопасность → исключения → подходящий индивидуальный сервис → общий путь для всего остального интернета`.

Выбранные сервисы НЕ являются allowlist охвата. Ноль сервисов допустим. Новый сайт без записи в каталоге обслуживается default. Невыбранный известный сервис тоже обслуживается default, если не совпало исключение.

## 2. Четыре разных объекта

| Объект | Назначение | Что не означает |
|---|---|---|
| Membership | Segment/interface/device identity, exclusions | Не разрешает все новые VLAN/guests |
| Default policy | Путь и резервы для всего unmatched трафика | Не гарантирует доступность каждого сайта |
| Service override | Отдельные path/DNS/health/failure constraints | Не ограничивает весь остальной интернет |
| Site exception | BASE или явный override RU в точной области | Не отключает firewall/parental control |

Происхождение определения сайта хранится отдельно от его выбора пользователем. Не вводить поддельный сервис «весь интернет» с CIDR 0/0 в обычном каталоге: существующие validators и semantic IDs не должны использоваться вопреки контракту.

## 3. Предлагаемое состояние

В существующей модели нужны:
- версия схемы и ревизия общей политики;
- список согласованных home segment IDs, исключённых device IDs/CIDRs, правило для новых устройств;
- default intent Auto/pin, допустимые executors/profile refs/sources/trust, требуемая coverage;
- applied default: конкретные executor/version/config/profile/DNS identities, не строка Auto;
- independent service override revisions и runtime references;
- catalog/exceptions revisions/digests, rules exact/suffix/ip/cidr;
- global и per-service failure policy; Stop/Pause authority;
- observation generation и timestamps отдельно от идентичности неизменной конфигурации;
- очередь target_kind=default/service с idempotency key и полномочиями;
- ограниченные default/service LKG/reserves и independent evidence.

Не хранить секреты в этой модели. References разрешаются через существующие закрытые хранилища.

## 4. Приоритет решений

Protected/local/admin/bootstrap трафик классифицируется до обычных интернет-правил, с сохранением существующей безопасности роутера. Исключение не создаёт firewall ACCEPT.

Внутри internet policy:
1. Устройство вне согласованной области либо исключено → BASE.
2. Явный обязательный site DIRECT → BASE.
3. Явный BYPASS overriding automatic RU → соответствующий допустимый path/override/default.
4. Российское автоисключение → BASE.
5. Совпало service override И его client scope → service path.
6. Иначе → default path.

Противоположные mandatory ручные правила → конфликт изменения, не случайный приоритет. Обычное добавление сервиса не является BYPASS override российского исключения.

**Ключевая регрессия:** если сервис настроен только для клиента A, то клиент B, который всё ещё участвует в общей политике, использует общий путь для того же сайта. `SERVICE_SCOPE_MISMATCH` не должен возвращать BASE до общих исключений/default в новом режиме.

## 5. Семантика пользовательских действий

| Действие | Итог |
|---|---|
| Добавить сервис для отдельного управления | Создать override/monitoring и разрешённую серверную задачу; остальное не меняется |
| Удалить индивидуальную настройку | Вернуть default; не отключить интернет этому сервису |
| Убрать сервис из наблюдения | Прекратить его специальные проверки, не удалить общий маршрут |
| Без обхода для сайта | Создать явное site exception |
| Исключить устройство | Вывести его из всех собственных bypass/DNS механизмов |
| Пауза автопилота | Не делать новые автоматические переключения; сохранить применённое по policy |
| Stop | Явно согласованное снятие own runtime или блок managed traffic; не смешивать с Pause |
| Выключить весь продукт | Сохранить настройки; безопасно снять own ресурсы согласно выбранному действию |

Обычная обратимая операция — одна кнопка с job status и возможностью отмены намерения, не много последовательных подтверждений. Уже применённое сетевое действие отменяется транзакционным возвратом, а не просто отменой HTTP.

## 6. Покрытие протоколов и адресов

«Весь интернет» — полный охват политики, не ложное утверждение, что каждый executor переносит все L3-протоколы.

Для TCP4/TCP6/UDP4/UDP6/QUIC/ICMP и иных классов хранить capability и конечное решение. Совместимый общий путь может быть одним IP-туннелем либо объявленной составной схемой. На первом этапе не строить сложную комбинацию ради формального checkbox: определить поддержанный набор и честные остальные outcomes.

Неизвестный домен, ECH, DoH внутри приложения, прямой IP или непопавший в каталог UDP-пакет не становится DIRECT автоматически. Неподдержанный класс — другой разрешённый путь, явно согласованный base либо scoped block с причиной. Не отключать IPv6 всей сети из-за одного профиля.

NFQWS2 — обработка подходящего трафика, Smart DNS — resolver/gateway для подходящих имён. Они не подменяют универсальное туннелирование; могут быть сервисной ветвью либо частью проверенной композиции. WARP/WG/AWG/Xray/USQUE используются по действительным capabilities.

## 7. DNS и ограничения классификации

Общий resolver для управляемых клиентов, service-specific resolver override и базовый resolver исключённых клиентов — независимые роли. Query route и data route фиксируются раздельно. Локальный ответ связывается с A/AAAA/CNAME/TTL и точным сценарием соединения; original Host/SNI/TLS сохраняются.

Вести AddressLedger с references и сроками. Один IP может обслуживать несколько имён. В L3-only пути нельзя точечно разделить два противоречивых доменных правила на том же IP без дополнительного достоверного discriminant. Не молча исключать весь CDN. Можно выбрать проверенный domain-aware executor либо показать ограничение и отвергнуть опасное новое правило.

Sniffing/FakeIP/перехват DNS — опциональные, проверяемые механизмы. Не подменять TLS и не требовать MITM. Unresolved domain всегда имеет default disposition, но точность site override в таком случае не гарантируется. Клиентский cache/existing connections переходят через bounded convergence; вечный PASS не продлевается.

## 8. Устройства и топология

Согласованный сегмент — граница общей власти. NewDevices=inherit означает новых клиентов этого сегмента, не всех новых интерфейсов. Guest/VPN/WAN исключены до явного добавления. Не менять доступ между VLAN.

Исключения привязываются к стабильному device ID и подтверждённым MAC/address bindings. DHCP и IPv6 privacy addresses учитываются; неизвестный новый MAC нельзя назвать старым устройством. Пропажа отрицательной identity не даёт право catch-all захвату: ограничить затронутую область/использовать последнее безопасное состояние и сообщить uncertainty. Это не причина убить панель или unrelated сервисы.

## 9. Dataplane и bootstrap

RAZVILKA владеет своими chains/tables/marks/ports/NFQUEUE/runtime. Номера выделяются из фактически безопасного пространства с проверкой чужих политик. Не переписывать глобальную main default route только потому, что UI выбран «весь интернет».

Ограничить перехват согласованными forwarded LAN клиентами. Router-originated control traffic имеет отдельную политику. Endpoint recursion исключается через корректный базовый WAN/штатную policy, а не обязательно жёсткую main table. Endpoint DNS refresh обновляет исключение и маршрут согласованно.

Не включать auto_route/auto_redirect исполнителя параллельно с независимыми собственными rules. Делегирование допустимо, только если оно учтено в одном manifest, rollback и readback. Проверять fwmark, connmark, rp_filter, NAT, return path, MSS/PMTU и offload на целевой платформе; не менять глобальные sysctl вслепую.

## 10. Жизненный цикл общего пути

Минимальные состояния: not_configured, preparing, probing, applying, active_with_evidence, monitoring, recovering, degraded, blocked_by_policy, paused, stopped, unknown.

Принять intent → capabilities → deps → isolated probe → повторная проверка permissions/revisions → stage → exact scoped rules → readback → traffic probes → commit. Новая реплика задачи возвращает прежний job, не запускает Apply снова. Если ответ утерян, клиент читает результат по ID.

Endpoint/probe success, активный process, kernel route simulation и физический клиентский поток имеют разные виды доказательств. Для Auto возможны предусмотренные локальные сетевые пробы после первоначальной HIL-валидации платформы; не требовать физического ручного клика при каждом failover и не называть локальный canary новым physical-client proof.

## 11. Отказ и переключение

Default и сервисы имеют независимые health/reserves, но общие runtime dependencies. Падение default требует его восстановления, не массового переписывания исправных service overrides. Падение одного сервиса чинится локально. При отказе общего engine координировать один repair всех зависимых targets.

A→B probe PASS→B apply FAIL→safe rollback→C допускается только при атрибутированной ошибке и подтверждённой очистке. Safe rollback не обязан воскресить мёртвый A. Unknown execution → reconcile прежде нового mutating action. Cleanup/journal uncertainty не маскируется успехом.

Существующие flows: выбрать проверяемую политику drain/reconnect, затрагивать только свои потоки. TCP/UDP continuity не обещать при смене egress; измерять краткий разрыв и корректное повторное соединение. Не глобальный conntrack flush.

## 12. Политика полного отказа

Однократный выбор в мастере:
- **сохранить обычный доступ**: разрешённый base при исчерпании рабочих резервов, с заметным degraded статусом;
- **не выпускать управляемый трафик без выбранного обхода**: scoped block до восстановления, исключения и management остаются.

Значение не выводится из доступности произвольного ping. Пользовательское согласие на base при outage не отменяет более строгий pin/service privacy constraint. До первого принятия политики новый общий режим не активен; не угадывать желание пользователя.

После аварийного снятия ресурсов либо рестарта исход policy сохраняется. Safe Mode не даёт автоматики право тайно снять запрет или расширить trust. Владельцу доступны диагностика и безопасные разрешённые действия даже при неизвестном runtime.

## 13. Миграция

Legacy selected_services сохраняется после update. Новый мастер сразу ориентирован на весь интернет, но активация только после однократного согласия на scope/trust/failure policy. Миграция сохраняет site/device pins, user lists, staged changes, secrets и предыдущую конфигурацию для downgrade.

Обновить serializers/strict decoders/backup/restore/schema check/UI forms/queue payload fingerprint вместе. Не сохранять новые поля под старой schema, если старый rollback decoder их отвергнет. Не активировать отсутствующий default автоматически по одному enum all_except.

## 14. Что обязано пройти до общего default в выпуске

Новый незнакомый сайт; ноль сервисов; прямой IP; невыбранный российский сервис; ручной direct/override; service scope miss; удаление override; два физических клиента; encrypted DNS/unknown identity; independent default/service failures; sessions; WAN/reboot; отказ источников; policy revoke; no implicit base; management/bootstrap safety.

Проверки перечислены с ID в ACCEPTANCE_MATRIX.json и связаны с задачами. Все здесь — ожидаемые результаты, не новые выполненные тесты.
