# Автоматизация способов обхода: VLESS, WARP, умный DNS

**Дата:** 30.09.2026. **Основание:** просьба владельца «как можно больше
автоматизации»: автопилот сам получает кандидатов, проверяет их для каждого
сервиса, применяет лучший, следит и переключает резервы. Дополнительно —
автоматический WARP и DNS-шлюзы вроде Xbox DNS.

## Лестница способов

Для каждого сервиса автопилот пробует способы от дешёвого к дорогому и
принимает только тот, что прошёл проверку **этого** сервиса (его сценарий,
его домены), через транзакцию с откатом:

| Шаг | Способ | Когда помогает | Чего не делает |
|---|---|---|---|
| 1 | NFQWS2 | DPI, замедление, блокировка по SNI | Не помогает при блокировке IP |
| 2 | Умный DNS (шлюз) | Сервис сам не пускает пользователей из РФ: ИИ, Spotify, Xbox, JetBrains | Не помогает против блокировок РКН; шлюз видит имя сайта |
| 3 | WARP (WireGuard → MASQUE) | Блокировка IP, UDP, игры | Cloudflare могут резать отдельные адреса — нужен подбор точки входа |
| 4 | Узлы VLESS/Hysteria2 из подписок | Почти всё | Узлы живут недолго — нужен постоянный подбор |

После применения — наблюдение: подтверждённый отказ (не одна неудачная
проверка) → следующий проверенный резерв; все резервы отказали → свежие
кандидаты из разрешённых источников. Решения владельца о полном отказе
(пропускать напрямую) действуют и здесь.

## Исследование (29–30.09.2026)

**z2k, игровой WARP** (изучен по резервной копии на роутере владельца):
- свой демон на Go: регистрация устройства (через ретранслятор, если API
  Cloudflare недоступен), транспорт WireGuard с запасным MASQUE-h2,
  интерфейс, NAT, проверка живости и переподключение;
- направление трафика только в `PREROUTING` для клиентов LAN, никогда в
  `OUTPUT`; метка только `--set-xmark` с маской, чтобы не затирать метки Keenetic;
- списки игр (Steam, Riot, Battle.net, EA, Ubisoft и др.) как ipset, отдельно —
  устройства целиком;
- **пассивное наблюдение DNS**: копии ответов DNS через `NFLOG` (без вердикта,
  не может сломать DNS) → адреса доменов из списков попадают во временные
  наборы по каждому клиенту. Это даёт маршрутизацию по доменам без подмены DNS;
- подбор точки входа WARP из пулов `/24` (источник — warpscout), каждая точка
  обязана пройти настоящее рукопожатие и проверку внутри туннеля;
- самовосстановление каждые 25 с, при неготовом туннеле маршрут снимается
  (отказ открытый).

**Xbox DNS** (проверено с роутера владельца 29.09.2026): серверы
`111.88.96.50/.51` и новые `111.88.96.54/.55` отдают для `chatgpt.com`,
`gemini.google.com`, `claude.ai`, `open.spotify.com` адреса своего шлюза
`87.228.47.198–203`; Cloudflare DNS отдаёт исходные адреса. Шифрованный
доступ: DoH `https://xbox-dns.ru/dns-query`, DoT `xbox-dns.ru`. Адреса
серверов меняются — ссылаться на DoH и перепроверять.

**WARP и DNS вместе** (поиск 30.09.2026: Хабр «Чебурнет 2026», форумы
Cloudflare и Keenetic): WARP в обёртке AmneziaWG (мусорные пакеты против DPI)
в России работает, но выходит в интернет с российского адреса Cloudflare.
Поэтому он помогает с ресурсами, заблокированными у нас по IP или протоколу
(Telegram, Discord, Instagram, игры по UDP), и не помогает с сервисами, которые
сами не пускают пользователей из России (ChatGPT, Gemini, Claude, Spotify) —
для них нужен умный DNS-шлюз. Обычный DNS провайдеры перехватывают и
подменяют, поэтому и шлюз, и основной резолвер — только через DoH/DoT
(Keenetic владельца уже ходит к Cloudflare по DoT/DoH). Отсюда связка для
автопилота: WARP для заблокированных, DNS-шлюз для гео-блокированных,
шифрованный DNS для всех; выбор по результату проверки каждого сервиса.

**Уже есть в RAZVILKA:** встроенный генератор WARP (регистрация, подбор точек
входа, журнал их здоровья, политика ротации), адаптеры WARP·WireGuard и
WARP·MASQUE; поставщики DNS, включая шлюзы Xbox DNS, Comss, GeoHide, malw (в
режиме «лаборатория»); сравнение DNS для сервиса с проверкой самого сервиса;
DNS для одного устройства. Не хватает оркестрации: автопилот этими способами
сам не пользуется.

## Этапы

1. **0.19.2 (готово в ветке):** освобождение каталога узлов от просроченных
   кандидатов подписок (иначе после заполнения 512 записей импорт вставал
   навсегда); автоматическое принятие обновлений сервиса из каталога
   сообщества; выбор основного и резервных узлов по стабильности; главная
   показывает, что не работает и что проверяется.
2. **Умный DNS как способ автопилота.** Проверка: имена сервиса через шлюз
   (DoH) → проверка сервиса, привязанная к адресу шлюза. Применение: записи
   «DNS-сервер для домена» в DNS-прокси Keenetic только для доменов сервиса,
   с манифестом владения, чтением обратно и откатом; позже — через общий
   резолвер LAN (этап 4 «всего интернета»). Только для сервисов с отметкой
   «гео-блокировка со стороны сервиса». Разрешение владельца — один флажок
   «Умный DNS» в правилах автопилота с пояснением, что шлюз видит имя сайта.
3. **WARP без ручных шагов.** Флажок «WARP» в правилах автопилота включает
   один раз принятие условий Cloudflare (действие владельца), затем автопилот
   сам: регистрирует устройство, собирает профиль, подбирает точку входа,
   при отказе WireGuard переходит на MASQUE, включает существующую политику
   ротации и предлагает WARP сервисам как проверяемый способ.
4. **«Весь интернет»** — по [ALL_INTERNET_EXECUTOR_RU.md](ALL_INTERNET_EXECUTOR_RU.md).
5. **Адресная книга DNS** по образцу z2k: пассивные копии ответов DNS через
   `NFLOG` → адреса доменов для туннелей и исключений сайтов без подмены DNS.
   Нужна и для «сайтов без обхода» во «всём интернете».

## Проверка автоматикой

- Каждый способ проверяется сценарием сервиса, а не общим «интернет есть».
- Неопределённый результат не считается ни успехом, ни отказом.
- Результаты копятся в истории узла/способа; стабильность за сутки влияет на
  выбор основного и порядок резервов.
- Переключение только по подтверждённому отказу и с лимитом в час.
- Панель показывает для каждого сервиса: работает / проверяется / подбирается
  / не работает, текущий способ и последнее действие автопилота.
