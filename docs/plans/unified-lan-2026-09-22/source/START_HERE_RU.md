**Сверка: 22 сентября 2026. База исходников: `c3722365dcbcee8e1c5e5909aabbbf907e457a22`, версия 0.18.10.**

Это комплект исходных изменений, проверок и плана продолжения. Это **не установочный выпуск**, не архив готовых бинарников и не подтверждение полной автоматизации на роутере. GitHub и роутер при подготовке не изменялись.

## Что читать и применять

Единственное действующее задание — `CODEX_TASK_RU.md`. Детали — `docs/MASTER_PLAN_RU.md`, `docs/UX_CONTRACT_RU.md`, `docs/CATALOG_SOURCES_RU.md`. Отчёт — `docs/TEST_REPORT_RU.md`. Сверка прежних планов — `docs/PLAN_CROSSWALK_RU.md`.

**Не применять по очереди старые установщики Stage 1 и Stage 2.** Их архивы сохранены только для происхождения в `reference/original_archives/`. Активный установщик исходников — `apply_unified.py`: он собирает оба этапа и исправления совместимости в одну конечную версию.

На отдельной рабочей ветке с сохранённым пользовательским diff:

```sh
python /путь/к/комплекту/apply_unified.py --repo /путь/к/RAZVILKA --check --diff
# Только после просмотра:
python /путь/к/комплекту/apply_unified.py --repo /путь/к/RAZVILKA --apply
```

По умолчанию скрипт ничего не записывает. Он сверяет контрольные суммы комплекта, локально получает исходные blobs через `git show`, проверяет базу/предка HEAD, точное содержимое затронутых файлов, уникальность якорей, синтаксис итогового JS, основной HTML и сборный CSS. Нужны Python 3.10+, Node и локальная Git-история проверенной базы. Скрипт не скачивает зависимости и не вызывает команды роутера.

Распознаются точные состояния: исходная база, ранее наложенный Stage 1, Stage 2, оба этапа, конечная версия. Повторное применение конечного состояния не должно создавать изменения. Неизвестный diff в затрагиваемом файле или другая версия приложения блокируют перенос. Не использовать `reset --hard` и не откатывать новые изменения ради совпадения хеша: адаптировать патч вручную с теми же проверками. Незатронутые пользовательские файлы не изменяются.

**В этом окружении перенос на полном checkout не выполнялся.** Код скрипта и известные строки переноса проверены отдельно, но первый реальный preflight и полный CI обязательны в Codex. Проверка всего checkout — не формальность после компонентных тестов.

## Что изменяется сейчас

Исходные улучшения загрузки/подтверждений Stage 1 и структуры страниц Stage 2 объединены. Добавлены исправления общей сборки CSS и версий ресурсов, включение новых тестов в CI, доступность неприменённых изменений, актуализация открытой карточки целиком, устойчивое освобождение UI-блокировки при исключениях, согласование старых состояний задач с общей паузой, менее навязчивая диагностика доступности панели.

`candidate/catalogadapter/` — отдельно проверенный Go-кандидат адаптера Geo-Aggregator. Он **не копируется установщиком в production**: это чистые парсеры полученных байтов без HTTP, прав и применения сети. Codex должен интегрировать их по контракту из `docs/CATALOG_SOURCES_RU.md`, не подключать альтернативного владельца маршрутов и не подменять им существующий API каталога вслепую.

## Как повторить доступные проверки

```sh
python run_checks.py --browser
# Без браузерного окружения:
python run_checks.py
```

Компонентный стенд: Python, Node, локальный Go; браузерная часть требует установленного Playwright и Chromium `/usr/bin/chromium`. Загрузки и установка этих инструментов скриптом не выполняются. Go 1.23 используется только для независимого стенда; **production go.mod/toolchain проекта не понижать**. В проверенной базе указаны Go 1.26.0 / toolchain go1.26.5.

`results/current/summary.json` — последний полный местный прогон. `results/baseline_*` — повтор прежних тестов до исправлений. `results/earlier-attempt` — зафиксированная исправленная ошибка промежуточного прогона; её не путать с состоянием конечных исходников. Генерируемые результаты не входят в контрольные суммы неизменяемых входов: повтор тестов не ломает preflight.

Дальше выполнить полный существующий CI на изолированном Linux-стенде, настоящие HTTP/auth/store integration, сборку точного выпуска, затем согласованные аппаратные тесты. Полный перечень незакрытых уровней и сценариев — в отчёте.
