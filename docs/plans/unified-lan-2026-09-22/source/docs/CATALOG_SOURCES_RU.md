# Источники сервисов: Hydra и правильная интеграция

## Что проверено

Hydra **Launcher** действительно использует внешние download sources: JSON-данные сопоставляют игры с загрузками. Это пример отделения программы от обновляемого каталога, но не источник доменов/IP для RAZVILKA. Официальные документы: https://docs.hydralauncher.gg/documentation/11/download-sources-11 и https://github.com/hydralauncher/hydra/wiki/FAQ . Полное тело страницы документации было недоступно для извлечения, а её Markdown endpoint вернул 404; базовое назначение sources подтверждается официальным описанием/FAQ. Формат игровых загрузок не копируется и не запускается.

Для сетевой задачи найден Hydra**Route**: Neo/HRweb поддерживает импорт из Geo-Aggregator, GeoIP/GeoSite и внешних списков. Проверенный ref HydraRoute: `984ec135dbc3e9fb54e0c8c63a0e2fd829538772`, README `Neo/README.md`: https://github.com/Ground-Zerro/HydraRoute/blob/984ec135dbc3e9fb54e0c8c63a0e2fd829538772/Neo/README.md . Сам HydraRoute не должен устанавливаться внутрь RAZVILKA или становиться вторым владельцем правил.

Geo-Aggregator — самостоятельный агрегатор. Проверенный ref: `7d9696419648a99bfa4d4d8ccb725d092622b3c7`. В README снимка 21 сентября заявлены **19 дружественных категорий и 312 записей сервисов**; полный индекс содержит намного больше тегов (1747 в метаданных снимка). Это не 312 испытанных обходов: среди записей есть укрупнённые группы, платформы и технические категории. Категории/названия/иконки curated, их не получают просто из названия txt.

https://github.com/Ground-Zerro/Geo-Aggregator/blob/7d9696419648a99bfa4d4d8ccb725d092622b3c7/README.md

## Как устроено получение

1. `db/catalog.json`: версия, generated, base, категории и записи `{id,name,cat,icon?,src}`. Это дружественный индекс выбора.
2. `db/database.json`: полный индекс тегов и фактических путей. Не угадывать папку по названию сервиса.
3. `source<N>/<tag>.txt`: собственно набор правил/адресов. Подгружать лениво для выбранного сервиса или фонового обновления уже используемого, не все списки при открытии главной.
4. `.gz` — способ передачи, не право снять лимит распакованного размера. В transport нужны отдельные compressed/uncompressed/time bounds.

Для source2/telegram.txt в проверенном ref получены **12 CIDR и 21 домен в одном файле**. Направить этот URL только в `DomainsURL` — значит потерять сетевую часть; только в `CIDRsURL` — потерять домены. Источник также включает смежные ресурсы экосистемы, поэтому не следует объявлять его точной копией официального IP-списка Telegram.

https://github.com/Ground-Zerro/Geo-Aggregator/blob/7d9696419648a99bfa4d4d8ccb725d092622b3c7/source2/telegram.txt

Upstream агрегирует Loyalsoldier, V2Fly, Runetfreedom, itdoginfo, antifilter.download и b4geoip. Использовать каждый набор с происхождением и собственными ограничениями. Наличие нескольких источников не означает независимость: один может быть производным другого.

## Почему нельзя заменить одну ссылку в RAZVILKA

В текущем `internal/community/community.go` Registry принимает 1..128 записей, отдельные DomainsURL/CIDRsURL, preview с памятью до десяти минут, предел 2000 доменов и 2000 сетей. Include дерево имеет отдельные пределы: depth 8, 64 файла, 8MiB total. Эти ограничения защищают роутер, не отменять их ради числа карточек.

Существующие понятия надо развести:

| Сущность | Содержание | Что НЕ следует из наличия |
|---|---|---|
| Библиотека сервисов | Название, категория, источник состава, доступные сценарии | Сервис включён |
| Принятое определение сервиса | Нормализованные exact/suffix/CIDR, версия/digest | Конкретный обход работает |
| Подключение/узел | VLESS/SS/HY2/TUIC/туннельный профиль | Все сайты доступны через него |
| Рецепт NFQWS2 | Совместимые параметры и доверенные ресурсы | Можно выполнять произвольный Lua/shell |
| Применённый маршрут | Зафиксированные устройства/исполнитель/путь/версия определения | Есть свежий service/client proof |

Большой внешний индекс не становится целиком Config.Services. Лимит отображаемой библиотеки, выбранных определений, рабочих правил, одновременных проверок и живых туннелей задаётся отдельно. Индекс можно показывать страницами, выбранные определения кэшировать постоянно. Автовключение всех 312 исключено.

## Семантика правил — обязательная граница

В README HydraRoute отмечено, что Domain и Full из GeoSite при их импорте обрабатываются как домен с поддоменами. В агрегаторе есть нормализация с удалением префиксов. Поэтому flattened .txt **не доказывает** сохранение первоначального exact/suffix различия. Не называть его точным зеркалом V2Fly, не приписывать утраченную семантику восстановленной.

В нашем кандидате:

- `full:example.com` — exact; `domain:example.com` — suffix;
- bare domain получает явно заданную семантику адаптера, записываемую в provenance/semantic digest;
- CIDR — отдельный тип, IPv4/IPv6 не теряются;
- regexp/keyword/include/Clash-строки/hosts-файлы не угадываются и не режутся до первого похожего домена;
- неподдержанная строка отклоняет кандидат целиком, прежнее принятое определение не заменяется неполной частью.

Это консервативный старт. Для V2Fly typed origin сделать отдельный адаптер с include limits и сохранением types. Если нынешний catalog.Service или исполнитель умеет только suffix-массив, exact-правило нельзя молча туда записать. Сначала расширить типизированную модель и пути materialize/test/apply, либо явно отказать в неподдержанном типе.

## Реализованный кандидат

`candidate/catalogadapter/adapter.go` — собственная реализация по прочитанной схеме, без копирования upstream кода или полного датасета. Стандартная библиотека Go, независимые тесты. Он проверяет JSON structure/duplicate keys/depth/size, IDs/category refs, pinned repo+commit, источник `sourceN/*.txt`, имена, mixed domains/CIDR и лимиты строк/числа правил. Текст читается Scanner, а не разбивается сразу на миллион строк; лимит строк ограничивает и пустые/дублированные записи.

URL получается из доверенных repo/ref и проверенного `src`; чужой `base`, абсолютный URL, traversal/encoded path отклоняются. Удалённая иконка не становится HTML/SVG в интерфейсе. Source digest и semantic digest различаются; один и тот же raw body при exact/suffix не даёт одинаковое определение.

**Не реализовано в кандидате:** получение всего live feed, HTTP redirects/DNS-rebinding/TLS, gzip decoding, подпись издателя, ETag/TTL cache, каталог в Store, native exact support, лицензированный bundled seed, real UI/API import, проверка сайта и применение сети. Эти функции остаются у существующих компонентов и должны быть интегрированы ниже. Нового daemon или второго БД-каталога не создавать.

## План интеграции с существующим backend

**C1 — source adapter.** Расширить существующий community/catalog provider layer, а не подменять весь Registry другим JSON. Результат чистого parse не активен. Stable key `provider_id + upstream_id`; canonical service ID и alias map отдельные. Не склеивать X/x-twitter или разные провайдеры по приблизительно совпавшему friendly name. Не перезаписывать пользовательский `custom-*` автоматически.

**C2 — единый pinned snapshot.** Получить разрешённую ревизию каталога; index и выбранные txt читать из одного commit. Хранить digest фактических bytes и normalized digest с типами. Проверить generated/clock, trust identity, ограничения скачивания. Нельзя index из commit A соединить с txt из плавающего main B. Работу с HTTPS и IP-проверками делегировать проверенному publicfetch; allowlist host сам по себе не решает redirects/DNS rebinding. Проверить каждый redirect и фактический dial IP, не выполнять shell с пользовательским URL.

**C3 — local-first.** Небольшая встроенная библиотека для first run плюс атомарные постоянные снимки текущего и предыдущего принятого состава. Ошибка/пустая выдача/304 без тела не очищает старые данные. Выбор сервиса и поиск не ждут источник. Новый источник/пакет обрабатывается очередью с бюджетами, stale отображается с возрастом, provider failure не ломает остальные providers и страницу.

**C4 — import by snapshot.** Карточка preview выдаёт immutable snapshot_id, digest и отличие от существующего определения. Применять именно его без дополнительного fetch после клика. Проверить CIDR overlap, shared domains, permissions, RAM/firewall budget. Raw external record не может задавать route, service enabled, device scope, probe arbitrary URL или credentials. Probe берётся из отдельного доверенного сценария, не из первого попавшегося домена. Unknown-service можно сохранить без выдуманного PASS.

**C5 — автономное обновление.** Пользователь заранее разрешает автоматическое обновление выбранного сервиса от определённого поставщика в ограниченных пределах. Обновление названия/иконки не требует нового диалога. Обновление допустимого состава аннулирует прежний proof, проверяется/применяется через общую транзакцию. Смена источника, агрегирование до «все соцсети», расширение до большой CDN/новых категорий устройств или неограниченное добавление CIDR выходят за такие права — один понятный review с diff. Не требовать подтверждение для каждой безвредной метки, но и не считать разрешение на один сервис доверием ко всем будущим данным URL.

**C6 — UX.** «Сервисы → Добавить сервис» показывает встроенные и дополнительные определения с понятными категориями. Фильтры по источнику — дополнительные. «Источники списков сайтов» и «Источники подключений» разделены. 18+/sensitive из metadata сохраняются и по умолчанию скрыты из общего каталога, без массового выбора. Поиск по названию/домену/alias локальный, а не GitHub API на каждый ввод.

**C7 — лицензии/публикация.** README Geo-Aggregator указывает GPL-3.0. До включения переработанной базы в выпускаемый bundled seed оформить происхождение и применимые условия каждого набора в THIRD_PARTY, не подставлять MIT для чужих данных. Этот пакет не переносит полный датасет; способ распространения production-данных требует отдельной проверки. Checksum не является подписью издателя; GitHub не источник автоматического доверия ко всему коду.

## Обязательные случаи

Полный реальный catalog.json на выбранном ref; mixed Telegram; недоступна только CIDR-часть; 312 metadata entries при малом числе selected; 404/429/304; отсутствующий/испорченный persistent snapshot; огромный распакованный ответ; duplicate JSON keys; traversal/redirect/private dial IP; full/suffix round-trip; unsupported regexp; stale/future dates; pinned A/B mismatch; конфликт alias/canonical/custom; offline restart; обновление только названия; крупное расширение scope; отозванный источник; full-probe unavailable; shared domain двух сервисов; отсутствие UI-reload и доказательств работы только по факту import.
