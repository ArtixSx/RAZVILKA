# Единая структура интерфейса

## Основной сценарий

Вход → один мастер → выбор сервисов и устройств → явное разрешение типов автоматической работы → система готовит и поддерживает выбранное. В повседневной работе пользователь видит результаты, а не проходит мастер и review после каждого клика.

Главная — диспетчер состояния, не второй каталог и не демонстрация архитектуры KEEP/CHECK/RESERVE. Первый блок: «Автопилот включён / на паузе / нужна настройка / ограничен / состояние неизвестно», короткая причина и **одно** основное действие. Доступность сервисов показывается независимо: работающий автопилот не означает успешный доступ. Обычная выполняющаяся проверка не считается просьбой вмешаться.

Сервисы — ваш список по умолчанию. Одна кнопка «Добавить сервис» открывает библиотеку; оттуда доступны «Свой сайт» и «Загрузить список». GitHub — происхождение данных в деталях источника, не название обязательного навыка пользователя. AI — только визуальная группа, без общей галочки PASS или нового route ID. Работает + есть несохранённое/неприменённое изменение — допустимое сочетание разных состояний.

Подключения — собственные ключи, серверы и подписки на серверы. «Источники подключений» не смешиваются со «Списками сайтов». Выбор источника сервера не включает его автоматически для всех сервисов. Резерв показывает основной плюс запасные; не создавать отдельный туннель для каждого сохранённого запасного профиля.

Устройства — где действует обход. Не требовать знания CIDR для обычного выбора: имя, адрес, группа; точный scope — в деталях. Неизвестное устройство и пустой список — разные состояния. «Все устройства» никогда не вытекает из пустого/непрочитанного массива.

События — что программа сделала и почему, а не raw networking log. 202 значит «Принято», не «Выполнено». Ошибка операции и результат её последующего readback показываются раздельно. Доступны активное задание, шаг, время, следующий повтор, причина отмены и исход очистки, без секретов.

Настройки — заметные карточки «Автопилот», «Способы обхода», «Обновления», «Проблемы с подключением». Остальные инструменты сгруппированы по задачам. Старые deep links сохраняются, в глубине страницы есть возврат. Поиск со словами «только телевизор», «запасной сервер», «проверять реже» полезен как дополнение, но не заменяет названия и расположение действий.

## Модель действий и подтверждений

| Действие | Интерфейс | Сервер |
|---|---|---|
| Переход, фильтр, раскрытие карточки, сортировка | Без подтверждений | Без изменения сети/конфигурации |
| Проверка одного сервиса | Один явный клик, результат в той же карточке | Существующее ограниченное задание, не Apply |
| Изменение частоты в ранее разрешённых пределах | Короткая форма, без повторного полного мастера | CAS/revision, запись desired, валидация |
| Включение уже разрешённого сервиса | Ясное действие, очередь и прогресс | Идемпотентное задание, разрешённый scope, preflight/apply/verify |
| Новый источник, транспорт, расширение области, снятие Safe Mode | Одно содержательное согласование нового объёма | Явно сохранённая политика; старое согласие не переносится на новые поля |
| Удаление определения/ключа, восстановление backup, опасная системная операция | Один конкретный диалог с последствиями | Проверка references, журнал/rollback, отсутствие затрагивания чужих ресурсов |
| Неопределённый исход POST | Не предлагать повторить тот же Apply вслепую | Найти исходный job по idempotency key и фактическому checkpoint |

Не удалять серверные guards ради снижения числа кликов. Автосохранение — не бесконтрольный Apply по каждому символу. Для текстового поля: локальный черновик, debounce, CAS, состояние «Сохранено / ожидает / ошибка»; при конфликте другой вкладки — не перетирать новое. Ключи не помещать в localStorage, маску секрета не сохранять как новый ключ. Отмена формы до отправки и отмена принятого сетевого задания имеют разные последствия.

## Закончить после текущего патча

Короткие формы «Интервал проверки», «Устройства сервиса», «Резерв», «Расписание обслуживания» должны открываться непосредственно, а не переводить пользователя в четыре шага мастера. На момент комплекта это ещё не готово. Не декларировать полную переработку Подключений/Устройств/Событий только по изменению основных пунктов меню.

После настоящих HTTP snapshots убрать двойной service-editor: перенести нужные контролы в одну карточку, сохранить все backend actions и способы задать ручной pin. Сначала перевести тесты поведения, затем убрать старые DOM anchors; не прятать второй интерфейс бесконечно в compatibility CSS.

При занятости разрешать навигацию и читать согласованные безопасные снимки; блокировать только конфликтующую мутацию. GET /devices ранее выполнял discovery с записью, поэтому нельзя разрешить все GET в обход operationgate. Snapshot должен быть in-memory/read-only, иметь revision и age; никогда не считать cache текущим подтверждением состояния сети.

Проверять клавиатуру, Escape, возврат focus, aria-live без постоянного чтения секунд, скрытые controls не остаются focusable. Размеры 360/390/768/1440/1920 и обе темы — обязательная полная приёмка; в текущем стенде проверены только указанные в отчёте размеры, не весь этот список.
