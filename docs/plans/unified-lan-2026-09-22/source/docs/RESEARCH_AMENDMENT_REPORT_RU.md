# Отчёт об исследовательском дополнении

Дата: 22.09.2026. Основа: `RAZVILKA_CODEX_UNIFIED_DNS_2026-09-22.zip`.

## Что изменено

Добавлен реестр из 31 первичного источника: официальная/авторская документация,
сайты операторов, конкретный код генератора и датированные пользовательские
наблюдения. Отдельно перечислены недоступные источники, не используемые для выводов.

Подготовлены 21 предложение и 48 EXP-сценариев, все в исходном planned-статусе.
Добавлены контракт жизненного цикла WARP, сравнительная матрица серверов/роутеров,
разбор NFQWS2/offload, USQUE HTTP/2/native/hooks и уточнение AWG совместимости.
Обновлены основные точки входа Codex, master-plan и feature-status. Ранний DNS D1
не перенесён в конец работ.

Не добавлены новые рабочие профили, endpoint-пулы, исполняемые рецепты, private keys,
регистрации WARP и автоматические сетевые изменения. Все прежние patch/overlay,
кандидат парсера, скрипты применения и журналы остаются побайтово прежними.
Исторические README/планы в reference намеренно не переписаны.

## Что проверено в этой сессии

Проверка входного ZIP, существующего checksum-inventory, связности новой JSON-матрицы,
идентификаторов источников и сценариев, сохранности прежнего кода/журналов и итогового
архива. Применена также существующая функция `verify_package` общего установщика.
Результаты записаны отдельно в `results/research_validation.json`.

Эти проверки подтверждают сохранность и внутреннюю согласованность комплекта.
Они не доказывают производительность сети, исправность endpoint или выполнение
перечисленных EXP-сценариев. Старые тестовые журналы не являются новым прогоном.

## Что не выполнялось

Полный checkout/build/CI RAZVILKA; настоящий HTTP integration; запуск native engines;
измерения роутера/VPS/двух клиентов; длительные испытания; регистрация/enrollment,
генерация пользовательских ключей на сторонних сайтах и массовые пробы endpoint.
Исполняемое окружение не получило полноценный сетевой доступ к исходникам; доступный
GitHub connector использован для чтения точной базы и конкретных файлов.

Форумные наблюдения не объявляются подтверждённым диагнозом пользовательского роутера.
В частности, selective PPE workaround должен пройти испытание на соответствующей
модели, а клиентские AWG-параметры — проверку wire-совместимости.

## Воспроизведение проверки комплекта

```sh
python tools/validate_research_bundle.py
```

Проверка только локальных файлов и описаний; не читает учётные данные и не вызывает
роутер, API провайдера, opkg или git. Результат можно сохранить через `--report` в новый
файл внутри `results/`. Заново применять старые вложенные архивы не требуется.

SHA256 обеспечивает контроль целостности, но не является цифровой подписью издателя.
Полный CI и hardware-приёмка выполняются в Codex на известной версии и согласованном
стенде перед выпуском.
