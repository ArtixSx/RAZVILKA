# Матрица сравнения серверных и роутерных исполнений

**Предложение для испытаний, не рейтинг производительности.** Дата исследования: 22.09.2026. У пользователя не запрошены и не измерены конкретный VPS, ASN, маршрут провайдера и нагрузка. Поэтому модель сервера, страну и гарантированные Мбит/с здесь не назначаем. Протоколы и ограничения сверены по E18–E29, аппаратные идеи — по E12–E17.

## Кандидаты

| Условия и цель | Что сравнивать | Условие допуска |
|---|---|---|
| Нужна базовая серверная TCP-схема | Существующий рабочий клиент/сервер и VLESS + RAW/TCP + REALITY/Vision на совместимой версии | Поддержка поля/flow обеими сторонами, корректные peer параметры, доступность целевого сервиса |
| Требуется HTTP-тракт через свой reverse proxy/CDN | XHTTP в режиме, поддерживаемом обеими сторонами и промежуточными узлами | Допустимость использования CDN, лимиты запросов/потоков, фактические H1/H2/H3 участки; не просто открытый порт |
| UDP пригоден, CPU/память достаточны | Hysteria 2 и сохранённый TCP fallback; отдельно параметры congestion | Точный bandwidth по измерению, отсутствие ресурсного голодания и проверка под нагрузкой |
| Собственный сервер туннеля | WireGuard/AWG точной версии и совместимый клиент | Peer-required параметры согласованы; миграция и возврат не удаляют пользователей без отдельного плана |
| UDP/MASQUE нестабилен | USQUE H3 и отдельный H2-кандидат | Правильный endpoint/pin, передача данных; нельзя менять только номер порта |
| На VPS не работает отдельный сервис | Прямой выход VPS и разрешённый дополнительный выход для этого сервиса | Маршрут SSH/admin/update остаётся восстановимым; DNS resolution location известен |
| Слабый роутер | Прежний proxy+sidecar, USQUE native, при готовности HEV | Сравнение идентичного назначения, MTU, TCP/UDP, CPU/RSS/FD; не добавлять два конкурирующих владельца |
| Пользователь просит конкретную страну | Проверенные собственные/разрешённые выходы с соответствующим service result | Не обещать выбор страны сменой WARP ingress или геометкой источника |

Совместимый sing-box как основной proxy core остаётся допустимым. Название Xray/USQUE/Mihomo не является основанием заменить уже работающий путь. 3x-ui на VPS — возможный внешний инструмент управления владельца; это не компонент для установки внутрь RAZVILKA. Доступ к панели, SSH и контейнерному runtime не выводить публично ради удобства проверки.

## Что измерять

Для каждого прогона записать commit/build hash, версии клиента и сервера, реальные architecture/kernel/capabilities, используемую сеть и время, scopes и безопасные идентификаторы. Сохранять результаты не вместе с приватным URI профиля, а со ссылкой на локальный защищённый материал.

Разделить время handshake, первый байт, устойчивую скорость в обе стороны, latency/jitter под параллельной нагрузкой, reconnect после простоя/смены сети и время автоматического восстановления. Также измерить CPU по ядрам, RSS, файловые дескрипторы, UDP drops, ошибки процесса, нагрузку на интерфейс и запись во flash.

Сначала baseline без искусственного ухудшения. Затем собственный контролируемый сервер: ограниченные loss/latency/MTU/перерывы. Не проводить нагрузочные эксперименты на случайном публичном сервере или бесплатной чужой подписке. Точные лимиты трафика/времени задать до начала, при дефиците ресурса отменять исследование, сохраняя рабочий путь.

Менять по одному фактору: core, transport, DNS, MTU, congestion или endpoint. Чередовать A/B в сопоставимом временном окне, повторять; не объявлять редкий лучший прогон обычной скоростью. Не сравнивать native без шифрования с полноценным прокси и не менять одновременно страну/провайдера/клиента.

## Что не включать автоматически из «ускоряющих» инструкций

Не выполнять пакет sysctl без проверки текущих значений и доказанного эффекта. Linux TCP BBR/CUBIC применяется к конкретному TCP пути, а не внутреннему QUIC congestion. Буферный максимум ядра, фактический socket buffer и QUIC receive window — разные параметры. Недоступная kernel capability должна давать корректное ограничение, не фатальный старт всей панели.

Не выключать IPv6, QUIC, DNSSEC, фильтрацию безопасности или аппаратное ускорение для всей сети только ради одного теста. Изолированный диагностический контроль с заранее известной областью и возвратом отличается от production-настройки. Локальная подмена клиентского протокола может скрыть проблему вместо её устранения.

Не включать одновременно автоматическую маршрутизацию sing-box, постороннего менеджера и RAZVILKA. Реестр owned ports/marks/tables/queue должен обнаружить коллизию ещё на планировании. Auto-redirect, работающий на современном OpenWrt, не переносится как готовый совет в legacy iptables/ядро Keenetic.

Не отключать проверку TLS/REALITY/server identity, не подставлять непроверенный SNI и не копировать случайный fake blob как доверенный код. XHTTP/Reality/AWG — набор контрактов версий, а не магические названия обхода.

## Результат, который нужен продукту

После испытаний пользователь не выбирает десятки технических переключателей. Исполнитель получает профиль возможностей и ограниченный набор проверенных стартовых параметров; автопилот учитывает его ресурсную стоимость и поддержанные сценарии. Если экономный вариант не поддерживает UDP, UI сообщает это до выбора для голосовой связи. Если H2 работает, а H3 нет, программа сохраняет проверенный H2 без требования каждый раз вручную открывать вкладку.

Окончательные default-параметры принимаются только по собственным измерениям на поддержанной платформе. Все предложенные комбинации в этом дополнении пока имеют статус candidates / planned.
