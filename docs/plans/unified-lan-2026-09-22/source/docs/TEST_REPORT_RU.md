# Фактические проверки единого пакета

Проверены существующие ZIP, pinned исходники через GitHub connector, изменённые компоненты, модели, установка исходного патча и браузерный стенд. **Полного локального checkout нет: DNS-загрузка GitHub из исполняемого контейнера не удалась.** Не выполнялись полный `go test ./...` проекта, интеграция настоящего HTTP App, сборка релиза и аппаратные испытания.

## Последний прогон

`python run_checks.py --browser` завершил все выполняемые наборы успешно. После последнего ограничения строк кандидат каталога отдельно повторно прошёл race/vet и fuzz. Конечные результаты — `results/current/`, браузер — `results/unified-browser.json`, fuzz — `results/catalog-fuzz.log`.

| Область | Что реально выполнено |
|---|---|
| Общая модель UI | 31 успешный тестовый случай, плюс воспроизведение старого дефекта attention на прежней модели |
| Исходные изменения Stage 1 | 52 компонентных JavaScript-проверки повторены с конечным heartbeat |
| Установщик исходников | 24 unit/synthetic filesystem теста: пути, symlinks, неизвестный diff, reapply, mode, откат записи, якоря/wiring |
| Браузер | 38 сценариев Chromium: частичный DOM стенда, реальные изменённые функции, вспомогательный layout и callbacks симулированы |
| Memory availability / Gate | 9 Go test functions, 6 подслучаев; три прогона `-race` в отдельном модуле; vet |
| Кандидат каталога | `go test -race -count=2` + vet: 10 Test-функций и Fuzz seed; проверки JSON/paths/types/лимитов/неполного результата; подробные subtests в JSON log |
| Fuzz кандидата | Отдельный ограниченный запуск 3 секунды, без найденного падения. Не доказательство отсутствия всех ошибок |
| Синтаксис | Node проверил конечные изменённые JS-компоненты и новые тестовые файлы |

Среда: Go 1.23.2 linux/amd64, Node 22.16.0, Python 3.13.5, локальный Chromium (версия записана в browser JSON). Go1.23 служит только изолированным стендом стандартной библиотеки. Production-база требует Go1.26/toolchain1.26.5, её требования не изменены.

Прежние Stage1/Stage2 тесты до новых исправлений тоже повторно проходили. Это не означает, что весь проект был совместим: их узкий объём не покрывал single stylesheet/version query, старые UI composition contracts, свежее содержимое всего инспектора и все renderer-exception границы. Эти пробелы разобраны в AUDIT_FIXES.

## Чего результаты не доказывают

Не было полного source merge на реальном дереве, компиляции итогового App, full-repo scripts/check.sh, настоящей аутентифицированной HTTP интеграции, проверок на ARM64/MIPS/MIPSel, работающего Geo-Aggregator live fetch/cache/API, реальных VLESS/NFQWS2/USQUE/Mihomo/HEV процессов, client traffic, перезагрузки роутера и soak 24/72h. Новые тесты в overlay/internal/app и integration-oriented scripts нужно выполнить в checkout. Не считать наличие этого файла результатом его запуска.

Структура реального HTML проверяется самим source applier до записи при первом применении в Codex. Сейчас проверены известные шаблоны/якоря и отдельные модели, а не полный 182KB HTML со всем production CSS. Скриншоты в results — **компонентный стенд с демонстрационными данными**, не рабочая панель пользователя.

9/15/44 и другие Go-счётчики нельзя складывать без учёта parent/subtest и повторов `-count`: JSON содержит отдельные события родительской функции, каждого подслучая и каждой попытки. Аналогично 104/20/86/30 старых acceptance cases остаются требованиями, не выполненными тестами.

## Следующая приёмка

На актуальном checkout: baseline CI → проверенный перенос и полная сборка CSS → current full CI → реальные HTTP/auth/store integration → controlled native engines → точный artifact/router HIL → soak. Для каждого слоя сохранить commit, artifact SHA, platform/firmware, command exit, raw redacted evidence. Функция, которая работает только на моках, не переводится в production-ready.
