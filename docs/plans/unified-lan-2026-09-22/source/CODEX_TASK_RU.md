# Задание Codex: принять единый пакет, закончить управляемость и автономность

Работай в актуальном `ArtixSx/RAZVILKA`, сохрани более новые исправления и пользовательский diff. Прочитай применимые AGENTS.md. Не создавай RAZVILKA2, второй сетевой демон, второй автопилот или новую панель поверх прежних трёх слоёв.

## Исходная проверка

1. Сними `git status --short`, HEAD, VERSION, go.mod. База комплекта — `c3722365...`, 0.18.10. Сверь актуальное дерево; не понижай инструментарий ради нашего локального стенда.
2. Прочитай START_HERE, отчёт и master plan. Сверь committed-планы `docs/plans/automation-2026-09-20/` и `docs/plans/catalog-resilience-2026-09-20/`. Их уже выполненные в 0.18.9 исправления не повторяй как новые задачи.
3. Запусти исходный полный CI на отдельном Linux-стенде до переноса. Не запускай разрушительные HIL на живом роутере без отдельного разрешения и способа восстановления доступа.
4. Выполни `apply_unified.py --check --diff`. При несовпадении не обходи проверки. Перенеси содержательные изменения на текущую базу вручную и запиши различия.
5. Прими изменения в исходники. Не применяй старые вложенные ZIP отдельно. Собери CSS штатным `scripts/build-interface.mjs`, проверь, что его вывод совпадает с итоговым interface.css.

## Первый законченный результат

Полный CI после переноса, настоящий authenticated браузер→HTTP backend, один известный сетевой путь. Панель должна оставаться понятной и доступной при долгой операции и ошибке одного раздела. Повторить все новые тесты на настоящих функциях checkout и добавить HTTP-тест `panel/availability` через общий Security.Middleware: анонимный запрос не получает защищённые сведения, busy/fenced не дают право мутации, Stop/cancel не снимают защиту журнала.

Убедись, что служебная проверка не публикует stale service-PASS; прямой ответ панели не подтверждает доступ через обход. Никаких обходов авторизации, TLS, namespace/ownership, revision, network epoch, rollback или config review под предлогом удобства.

Новая модель навигации: Главная, Сервисы, Подключения, Устройства, События, Настройки. Автопилот и его реальное состояние — первый блок главной. Способы обхода доступны из видимой карточки в настройках; технические страницы сохраняются. Один экран сервиса вместо двух конкурирующих редакторов. Штатные действия не требуют поиска названия внутреннего модуля. Кнопка проверки не переносит в лабораторию.

После этого выполнить этапы U1–U8, E1 и ранний D1 из MASTER_PLAN с завершённой приёмкой каждого. Не ограничиться применением интерфейсного патча и не объявлять полную автоматизацию готовой.

## E1. Все домашние устройства, исключения и российский direct-каталог

Прочитай `docs/LAN_EXCLUSIONS_RU.md` и 40 LE-сценариев в
`docs/LAN_EXCLUSIONS_ACCEPTANCE.json`. Это новый запрос пользователя и дополнение
основной политики, не разрешение включить весь LAN у существующих установок.

Раздели `lan_except` (клиенты выбранного home-сегмента) и `all_except` (широкий
выбор трафика). Основной предлагаемый режим: lan_except + выбранные сервисы.
При обновлении сохранить прежний scope; all-except требует отдельного согласия.
Исключённое устройство не попадает в NFQUEUE/TUN/proxy и сервисный Smart DNS.
Ручное обязательное direct сильнее авто; явный bypass override сильнее auto-RU,
но не сильнее исключённого устройства. Противоположные mandatory правила не
разрешать случайным порядком. Не изменять чужие политики прошивки/VPN.

В интерфейсе использовать существующие Устройства/Сервисы и сводку главной:
«Все домашние устройства, кроме…», «Исключения», «Российские сервисы без обхода».
Повторное прохождение мастера и подтверждение каждой новой записи не нужны
для уже согласованного типа обновлений. Смена области и новое разрешение direct
должны быть видимыми. Экспорт WARP/DNS не включает этот режим скрыто.

V2Fly category-ru включает tld-ru, поэтому это не узкий список компаний.
Основной RU-профиль собирать из проверяемых per-service правил; весь .ru/.рф/.su
— отдельный режим. GeoIP RU выключен по умолчанию. Не схлопывать shared CDN IP
в direct и сохранять exact/suffix. Per-client DNS views обязательны для
исключений Smart DNS. Если идентичность назначения недоступна, не подменять её
догадкой; применение конфликтующей комбинации не должно выключать всю панель.

E1 проектируется с U1/U2/D1 до production-широкого охвата. Распространить модель
на clone/storage/backup/review/Apply/observer/failover, не добавлять второй
контроллер. Патчи существующего комплекта не реализуют E1. Все LE-кейсы planned.

## DNS/Smart DNS — обязательная ранняя вертикаль D1

Прочитай `docs/DNS_SMARTDNS_PRIORITY_RU.md`. Проверен текущий код
`dnscontrol/provider_metadata.go`: Xbox/другие Smart DNS закрыты для автопилота и
разрешены только для лаборатории. Не выдавай существующий UI-пункт за работающий
обход. После U1/U2 доведи exact DNS+service probe, scoped executor, transactional
Apply/readback/rollback и разрешённый fallback. Не жди интеграции новых движков.

DNS выбирать как часть комбинации для сервиса, а Smart DNS учитывать как шлюз
с отдельным доверием, не как обычный свободно заменяемый resolver. Пользователь
не должен менять глобальный DNS или подтверждать каждый retry. Не снимать
`AllowedForAutoPilot=false` без завершённого исполнения и тестов; не включать
service Smart DNS для регистрации WARP/USQUE и обновлений автоматически.
Проверить 24 DNSP-сценария, оставляя непроверенные уровни в исходном статусе.

## Каталог как в Hydra — отдельная обязательная работа

Hydra Launcher: источники загрузок игр; формат и механизм — идея, данные не годятся для маршрутизации. HydraRoute: релевантен Geo-Aggregator, где есть дружественный `catalog.json`, полный `database.json`, mixed domain/CIDR `.txt`. Не копируй все 312 записей в прежний Registry с лимитом 128 и не увеличивай без разбора все лимиты.

Подключи чистый кандидат `candidate/catalogadapter` к существующим community/catalog/publicfetch только после проверки на полном реальном pinned snapshot. Библиотека/источники/включённые сервисы/применённые маршруты — разные сущности. Полные правила из одного pinned commit, поддержанные типы, digest+provenance, bounded storage и локальное открытие каталога без GitHub. Данные новой версии не заменяют применённый список молча. Точность exact/suffix/CIDR должна сохраняться до каждого исполнителя; при неподдержанном типе — отказ/показ причины, не расширение правила.

## Критерий полной автономности

Закрытый браузер; A перестаёт передавать трафик; B проходит изолированную пробу, но не проходит применение; безопасный откат завершён; C применяется и проверяется новым клиентским соединением; позже разрешённый источник приносит D, резерв пополняется. Параллельный сервис и второй исключённый физический клиент не меняются. При ошибке общего движка B не объявляется неисправным; при неуспешном rollback следующий кандидат не активируется.

Запиши результаты по каждому уровню: unit/component, real-HTTP integration, native engine, hardware, soak. Не складывай 104+20+86+30 прежних сценариев в число якобы пройденных тестов. Обнови docs/CURRENT_STATUS_RU.md только фактическими результатами с ревизией, SHA бинарника, платформой, командами и ограничениями. Непройденные аппаратные шаги оформить как конкретную приёмку, а не менять все статусы на PASS.


## Исследование внешних источников — уточнения к реализации

Не пропускай `docs/EXTERNAL_RESEARCH_RU.md`. Это дополнение текущих U/D этапов,
а не разрешение добавить новый самостоятельный контроллер. R01–R21 привязаны к
конкретным областям кода и EXP-001…048. Все EXP сейчас planned.

Закрой R01/R03/R04/R08/R18 как инварианты при разработке: scope не расширяется,
экспорт не регистрирует новый аккаунт, неизвестный ответ не запускает вторую
регистрацию, hook не владеет маршрутами, DNS не заменяет selected на all.
R02 — аппаратная гипотеза: вначале воспроизвести видимость потока и определить
capabilities, а не копировать PPE/connskip/retrans числа с чужой модели.

Развить генератор по WARP_LIFECYCLE: transport-specific endpoint/pin, immutable
materialization, readback и rollback; DNS/MTU/экспорт не меняют identity аккаунта.
Перед original-USQUE migration закрепить commit и сравнить возможности/ABI
нужной архитектуры. H2 и native — реальные испытанные исполнения; L4 не выдавать
за UDP-capable путь. Не включать insecure, глобальный DNS или default route
из чужого примерного hook. Не выполнять внешние генераторы или регистрацию
на чужих аккаунтах ради тестов без отдельного разрешения.

Серверные профили — кандидаты для controlled VPS, не «лучший сервер» по названию
протокола. Разделить kernel TCP congestion, QUIC congestion, socket buffers и
TUN MTU. Точные значения default принимаются только после собственных измерений.
NTC.party/4PDA в этот раз не дали достаточного доступного материала; не приписывать
им нечитанные рекомендации. Полный отчёт RAZVILKA и router HIL здесь не запускались.
