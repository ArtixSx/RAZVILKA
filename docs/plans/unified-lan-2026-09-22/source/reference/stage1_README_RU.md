# RAZVILKA: первый пакет упрощения интерфейса и план автономности

**База:** `c3722365dcbcee8e1c5e5909aabbbf907e457a22`, версия исходников `0.18.10`.
**Подготовлено:** 21 сентября 2026 года.
**Статус:** исходный патч для проверки и продолжения в Codex. Не готовый релиз, не установщик для роутера и не заявление о завершённой полной автоматизации.

## Что уже сделано

В `changes/edits.json` находятся 16 точных замен в шести существующих файлах. В `overlay/` — новые исходники и тесты. Применение к полному checkout нужно выполнить и проверить в Codex: здесь запускались изменённые функции и новые компоненты, но не весь репозиторий.

Изменения первого пакета:

1. Общий `/api/v1/status` и проверка активности перестают быть обязательным барьером перед чтением остальных разделов. Сохраняются четыре параллельных чтения, старые корректные данные и защита от запоздалых ответов.
2. Переключение страницы выполняется до необязательной отрисовки. Ошибка блока статуса или другого необязательного блока не должна удерживать пользователя на прежней странице. Черновики не удаляются.
3. Добавлен авторизованный `/api/v1/panel/availability`. Он читает только короткое состояние допуска операций в памяти, а не конфигурации, файловые журналы, DNS, сетевые правила или внешние процессы. Ответ панели не означает, что обходы работают.
4. Добавлен компактный индикатор связи с панелью. Он не перекрывает навигацию, делает только GET-запросы, различает занятость, недоступность и необходимость восстановления журнала. Проверка ограничена тремя секундами; при ошибках используются задержки с увеличением до минуты.
5. Общий диалог получает одного владельца. Второе одновременное действие не получает согласие от первого; Escape и выход из аккаунта не подтверждают операцию.
6. Повторное сохранение мастера в пределах прежних разрешений больше не требует повторной галочки. Новые источники, протоколы, транспорты, устройства, расширение режима обновления и снятие Safe Mode требуют согласования. Редактирование после согласия делает старое согласие недействительным.
7. Убрано повторное модальное подтверждение у явно выбранного импорта совместимых z2k-стратегий в непроверенные кандидаты. Применение стратегий к трафику этим не разрешается; зависимости от работающего z2k не добавляются.

## Что это пока НЕ исправляет

Занятые или защищённые серверные хранилища не открываются для произвольного чтения. Если все обычные API отклоняются общим допуском, новые данные настроек ещё не появятся: доступны оболочка, предыдущие данные и новый индикатор. Для полноценного чтения во время применения нужен следующий этап — отдельная неизменяемая модель отображения.

Не реализованы этим пакетом: сохранение любых форм автоматически, все сетевые операции как фоновые задания, автоматическое восстановление `event-drain`, полный переход A → ошибка применения B → откат → C, новый подбор NFQWS2-стратегий, автоматическая установка всех зависимостей и автоматическая установка обновлений. Подробные задания на них находятся в плане.

Падение самого процесса, OOM, недоступный `/opt` или остановленный HTTP-сервер невозможно исправить одной браузерной обработкой ошибки. Это отдельные сценарии запуска и надзора.

## Как передать в Codex

Откройте полный репозиторий и передайте весь этот каталог вместе с `CODEX_START_RU.md`.

На отдельной рабочей ветке, при отсутствии параллельного редактирования:

```sh
python3 /путь/к/пакету/apply_changes.py --repo /путь/к/RAZVILKA --check
python3 /путь/к/пакету/apply_changes.py --repo /путь/к/RAZVILKA --diff
python3 /путь/к/пакету/apply_changes.py --repo /путь/к/RAZVILKA --apply
```

По умолчанию скрипт только проверяет. Он сверяет HEAD, Git blob каждого изменяемого файла и единственность всех замен. При более новой ветке, чужих изменениях, частично применённом патче, совпадении имени нового файла с другим содержимым или симлинках скрипт отказывается продолжать. **Не сбрасывать новую main ради применения пакета:** перенести изменения вручную на свежую базу.

Проверка выполняется для всего набора до записи. При обычной ошибке записи уже сделанные записи откатываются. Это не файловая транзакция, защищённая от отключения питания посередине: используйте отдельную Git-ветку и проверьте `git diff` после любого прерывания. Скрипт не запускает команды на роутере, ничего не устанавливает, не делает commit/push и не изменяет настройки Git.

После применения в полном checkout:

```sh
gofmt -w internal/app/operations.go internal/app/panel_availability_test.go internal/operationgate/snapshot*.go internal/panelhealth/*.go
node scripts/test-ux-stage1.mjs
node scripts/test-panel-loading-ui.mjs
node scripts/test-project-log-ui.mjs
go test ./...
go test -race ./...
go vet ./...
```

Использовать toolchain из `go.mod` репозитория. Локальный тестовый модуль этого пакета не заменяет Go/toolchain основного проекта.

Полный список UI-проверок и команд сборки взять из действующего CI проекта. Нельзя считать три перечисленных JavaScript-скрипта заменой всему CI.

**Граница:** JS-тесты использовали извлечённые функции, Go — изолированный модуль с точным исходным `Gate`, браузер — реальные функции и native dialog на стенде с подменёнными API-ответами. Это не полная сборка, не тест реальной панели со всеми её скриптами и не аппаратная приёмка.

```sh
python3 run_local_tests.py
```

Для воспроизведения нужны Python, Node, Go с поддержкой `-race`, Python Playwright и Chromium. В репозитории применять изменения скриптом выше; `run_local_tests.py` сам проект не изменяет.
