# RAZVILKA — понятный интерфейс, Stage 2

**Пакет исходных изменений для передачи Codex. Это не установленная панель и не готовый релиз.**

База: `ArtixSx/RAZVILKA`, `main`, `c3722365dcbcee8e1c5e5909aabbbf907e457a22`, версия исходников `0.18.10`. Подготовлено 21 сентября 2026 года.

## Что меняется

Главная начинается с состояния автопилота. Вместо нескольких равнозначных входов в «Главную/Автопилот» — один основной экран. На нём видно, что происходит, какие сервисы подтверждены и где действительно нужно участие человека. Обычная текущая проверка сама по себе не попадает в список проблем.

В «Сервисах» разделены ваш список и каталог для добавления. У карточки одно основное действие. Добавление при уже настроенной политике использует существующий `interfaceManage`, без нового сетевого API; проверка использует существующий `serviceDashboardStart('check', ...)` и больше не отправляет человека в ручную лабораторию. Статусы применения и доступа остаются разными.

В основном меню шесть разделов: **Главная, Сервисы, Подключения, Устройства, События, Настройки**. NFQWS2, WARP и другие инструменты не удалены: они находятся в «Настройки → Способы обхода». Старые адреса страниц сохраняются. Техническая страница автопилота становится страницей подробностей в настройках, а не второй главной.

Настройки открываются понятными карточками задач. Поиск остаётся дополнительным инструментом, а не обязательным способом узнать термин внутри проекта.

## Что находится в пакете

- `changes/manifest.json`: 18 правил преобразования исходников, включая необязательное удаление старого пункта мобильного меню.
- `changes/interface-functions.js`: 15 новых/заменяемых функций действующего `interface.js`.
- `changes/interface-model.js`: обновлённая чистая модель представления. Исходный оригинал в тестах проверен по Git blob SHA.
- HTML-фрагменты для существующих страниц и стили для существующей единой темы.
- `apply_changes.py`: проверка базы, вывод diff и применение к checkout. Меняет пять файлов интерфейса, пересобирая CSS тем же объединением, что использует проект.
- `tests/`, `results/`: компонентные тесты, браузерный стенд и результаты.
- `docs/UX_SPEC_AND_HANDOFF_RU.md`: подробное устройство интерфейса и продолжение работ.
- `docs/ACCEPTANCE_MATRIX.json`: дальнейшие проверки настоящей панели; они не помечены пройденными.
- `prerequisite/`: неизменённый предыдущий архив Stage 1. Он сохраняет задачи устойчивости панели и полной автоматизации.

## Границы выполнения

В этой сессии прочитан код через GitHub-коннектор. Полный checkout в исполняемой среде получить не удалось: сетевое обращение git не разрешилось. Оба предоставленных shared-чата Codex также не открылись. Их содержимое не использовалось как будто оно было прочитано.

Выполнены **45 проверок модели и изменённых JavaScript-функций**, **14 тестов скрипта применения** и **29 браузерных сценариев**. Браузерный стенд использует изменённые функции, но вспомогательную разметку, стили и ответы контроллеров имитирует. Это **не полная исходная панель**, не проверка реального API и не аппаратная приёмка. Полный запуск патчера на настоящем checkout, все прежние тесты проекта, Go-сборка и проверка роутера остаются для Codex. Backend в Stage 2 не меняется.

GitHub, ветки и работающий роутер этой работой не изменены.

## Применение в рабочей копии разработчика

Сначала прочитайте `CODEX_START_RU.md`. Работайте на отдельной ветке, без параллельного редактирования тех же файлов.

```sh
python /path/to/RAZVILKA_UI_STAGE2/apply_changes.py --repo /path/to/RAZVILKA --check --diff
python /path/to/RAZVILKA_UI_STAGE2/apply_changes.py --repo /path/to/RAZVILKA --apply
```

По умолчанию скрипт ничего не записывает. Он сверяет HEAD и полные Git blob SHA входных файлов, затем проверяет уникальность якорей и синтаксис целых получившихся JavaScript-файлов через Node. Новую версию исходника нельзя перезаписать «похожим» старым патчем. При несовпадении перенесите изменения вручную на актуальный код; **не выполняйте reset или force**.

Две вставки Stage 1 в `index.html` распознаются и сохраняются. Порядок на точной базе: Stage 1 → Stage 2 → общая проверка → коммит. Если Stage 1 уже закоммичен или HEAD продвинулся, нужен осознанный перенос на эту ревизию, а не сброс коммита. Повторный запуск Stage 2 на уже изменённых файлах безопасно отказывается, а не пытается менять их снова.

Патчер не запускает маршруты, не меняет разрешения, не устанавливает зависимости и не делает commit/push. Запись отдельных файлов атомарна, при обычной ошибке записи выполняется откат записанных файлов. Это не обещание транзакционности всего checkout при отключении питания.

## Повторение локальных тестов

```sh
python run_tests.py
python run_tests.py --browser
```

Браузерным тестам нужны Python Playwright и Chromium. Загрузка зависимостей самим пакетом не производится. После интеграции можно проверить функции уже из checkout:

```sh
RAZVILKA_CHECKOUT=/path/to/RAZVILKA node tests/test_taskflow.cjs
```

Это всё ещё компонентные тесты, а не замена полной панели. Затем обязательны штатные проверки проекта, `node scripts/build-interface.mjs --check`, весь Go-набор с toolchain из `go.mod` и реальный браузерный прогон.
