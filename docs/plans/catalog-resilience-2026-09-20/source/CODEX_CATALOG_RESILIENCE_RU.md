# RAZVILKA: устойчивое получение определений сервисов

Дата проверки: 20 сентября 2026. Проверенная ревизия main:
`245e78a63038d287465337fbd6c2c4ebd7edbf3c`.

Это дополнение к общему заданию на автономность, а не новый выпуск программы.
Производственный код, GitHub и роутер этим комплектом не изменены. Ни один
приёмочный сценарий ниже не объявляется выполненным тестом приложения.

## 1. Что действительно установлено

На скриншоте поиск находит «Telegram · домены и сети», но получение состава
справа завершается ошибкой. Это различие между локальным поиском метаданных
и сетевой загрузкой определения, не доказательство недоступности всего GitHub.

В текущей ревизии `configs/community-catalog.json` Telegram использует:

- domains_url: `https://raw.githubusercontent.com/v2fly/domain-list-community/master/data/telegram`;
- cidrs_url: `https://core.telegram.org/resources/cidr.txt`;
- provider: `V2Fly + Telegram`;
- probe_url: `https://telegram.org/`.

`internal/community/community.go`, `Manager.Search` ищет по локальному registry.
`Manager.Preview` сначала получает дерево доменов, затем CIDR. Ошибка любой части
возвращает пустой Preview и ошибку; успешно полученные домены не показываются.
У Entry один DomainsURL и один CIDRsURL; списка альтернатив нет.
Общий срок Preview — 25 секунд, HTTP client — 20 секунд; дерево включает до
64 файлов с глубиной до 8, суммарно до 8 МиБ. Успешный preview кешируется в памяти
на 10 минут. При явном refresh кеш не используется как резерв в случае отказа.
Загрузчик принимает только HTTP 200 и не реализует здесь ETag/304/cooldown.
Разрешённые source-hosts сейчас raw.githubusercontent.com и core.telegram.org.
Добавление произвольной CDN-ссылки в JSON само по себе не внедрит новый транспорт.

`docs/CURRENT_STATUS_RU.md` уже фиксирует прежний timeout core.telegram.org при
HTTP 200 Raw GitHub. Для нового кадра конкретная ошибка DNS/TLS/HTTP неизвестна:
не называть именно этот прошлый timeout доказанным текущим инцидентом.
В текущей внешней проверке официальный cidr.txt был доступен; это не проверка
пути с роутера пользователя и не обещание его доступности оттуда.

## 2. Проверенные альтернативы и важное различие составов

| Источник | Файл / тип | Как использовать |
|---|---|---|
| V2Fly/domain-list-community | data/telegram; простой список доменов | Сохранить как исходный доменный источник. Telegram-файл получен, 21 запись. Включает связанные ресурсы экосистемы; не выдавать за минимальный набор только мессенджера. |
| Telegram | resources/cidr.txt; 14 IPv4/IPv6 строк | Первичный источник официального снимка сетей. Загружать при сборке каталога и по разрешённому расписанию, не делать обязательным успешный запрос при каждом клике. |
| Loyalsoldier/geoip | release/text/telegram.txt; 12 строк | Кандидат альтернативных IP-данных, НЕ точное зеркало текущего официального файла. |
| MetaCubeX/meta-rules-dat | meta/geo/geoip/telegram.list; 12 строк | Текстовый альтернативный IP-набор. Совпадает по покрытию с полученным Loyalsoldier, не является независимым голосом достоверности. |
| MetaCubeX/meta-rules-dat | meta/geo/geosite/telegram.list; 21 строка с `+.` | Материал для адаптера формата. Текущий доменный parser не следует считать совместимым без теста семантики. |
| blackmatrix7/ios_rule_script | rule/Clash/Telegram/Telegram.list | Дополнительный источник определений с DOMAIN, DOMAIN-SUFFIX, KEYWORD, CIDR, ASN, PROCESS-NAME. Не прямое зеркало и не готовый импорт в текущую схему. |

Для полученных снимков выполнено локальное сравнение покрытия CIDR (не сетевой
тест): 14 официальных строк после объединения соседних сетей дают 11 префиксов.
Loyalsoldier/MetaCubeX содержат то же покрытие плюс `95.161.64.0/20`.
12 строк вместо 14 НЕ означают потерю двух сетей; но дополнительный /20 —
реальное расширение. Нельзя подменить им официальный источник и продолжать
показывать «официальные сети Telegram» без указания происхождения и проверки diff.

У blackmatrix7 есть более широкие сети, например `91.108.0.0/16`, `2a0a:f280::/29`,
и правила дополнительных клиентов. Объединение всех источников будет расширением
охвата, а не просто повышением отказоустойчивости. Дата заголовка полученного
файла — 2025-09-10; она не доказывает актуальность всего содержимого сегодня.

## 3. Решение: локальная библиотека + обновляемый каталог + зеркала

Основное правило: каталог выбора должен открываться без внешней сети. Обновление
каталога не должно быть обязательной частью открытия диалога.

На чистой установке активный/выбранный набор по-прежнему только штатный NFQWS2.
Telegram, AI, Netflix и другие определения могут лежать в НЕАКТИВНОЙ локальной
библиотеке. Они не добавляются в «Мои сервисы», не включаются и не получают
маршруты до выбора пользователя. Не возвращать прежние 16 активных defaults.

Предлагаемая архитектура, ещё не текущий API:

1. Сборка/публикация получает проверенные первичные файлы и фиксирует ревизии.
2. До роутера уже доезжает нормализованный согласованный снимок, включая раскрытые
   include и нужные IPv4/IPv6 CIDR. Не заставлять каждую установку обходить десятки
   GitHub include-файлов на каждый клик.
3. Снимок входит в подписанную поставку/каталог, со сведениями о версиях парсеров,
   происхождении, составе, лицензиях, sha256, времени получения и допустимом возрасте.
4. При наличии разрешения роутер фоново обновляет библиотеку; при отказе показывает
   последнюю принятую или встроенную версию с её настоящей датой и состоянием.
5. Preview — всегда именно один сохранённый снимок. Import не обращается заново
   к плавающему upstream и не импортирует другую редакцию по старому подтверждению.
6. Изменения уже добавленного сервиса — отдельный diff и политика обновления:
   preview нового каталога не расширяет действующую область автоматически.

### Два разных вида резервирования

**Транспортное зеркало:** одни и те же байты одной ревизии из Raw GitHub,
контролируемого GitHub Release/Pages или jsDelivr. Для каждого зеркала проверяется
ожидаемый digest из доверенного manifest. CDN не считается отдельным поставщиком
содержимого. Cache freshness, retries и denylist сохраняются.

**Альтернативный поставщик:** V2Fly, MetaCubeX, Loyalsoldier или blackmatrix.
Может иметь другой состав и формат. Нужны адаптер, семантическое сравнение,
происхождение и согласование расширения. Не выбирать случайно самый длинный список.

Приоритет быстрого отображения: текущая локальная версия -> встроенный снимок
(с возрастом и ограничениями). Обновление сети идёт параллельно. Не задерживать
диалог сначала на всех внешних тайм-аутах. Устаревшая копия не получает новую
дату происхождения от факта локального чтения и не даёт фиктивный service PASS.

## 4. Модель данных и атомарность

Ввести версионированное определение логического сервиса и компоненты данных:

- стабильный service_id;
- definition_revision и digest нормализованного состава;
- coverage: domain / IPv4 / IPv6 / известные дополнительные сценарии;
- required_components для каждого поддержанного сценария;
- component_sources: origin, revision, format, raw_digest, normalized_digest;
- статусы частей: available / cached / stale / missing / rejected;
- provider_id и mirrors (только эквивалентные артефакты);
- fetched_at, checked_at, origin_age, expiry; не путать их с health соединений;
- parser_version; зафиксированная политика exact/suffix;
- diff added/removed и старый совместимый снимок.

Конкретные названия полей выбрать под текущую модель проекта. Это не разрешение
сломать schema=1: нужен совместимый reader/migration и явный отказ неизвестной
версии, backup и rollback. Старые пользовательские Entry сохраняются.

Постоянный cache хранить отдельно от пользовательского CustomServices и
AppliedServices, ограничить суммарные байты/версии. Запись через существующий
ownedfs/restorejournal и CAS. Не принимать symlink/чужие владельцы. Согласованный
снимок домены+сети публикуется атомарно; не смешивать половины разных релизов.

Отпечаток подтверждения должен охватывать не только текст, но также service_id,
coverage, происхождение и выбранную fallback-редакцию. Между preview/import
смена источника либо состава требует нового review. Обновление метаданных
загрузки без изменения byte/destination identity отдельно от изменения полномочий.

## 5. Отказы частей определения

Не возвращать пустую карточку, если список доменов загружен, а сети — нет.
Показывать отдельные компоненты и их состояния. Но не объявлять неполный набор
полноценным Telegram и не разрешать автоматический маршрут для неизвестного охвата.

Полный сценарий Telegram: требуемые домены и сети получены из согласованного
снимка, либо сохранён прежний полный снимок с допустимым возрастом. Если такого
снимка нет, можно предложить ОТДЕЛЬНОЕ действие «Добавить только доменную часть».
Это иной явно показанный охват без утверждения о сообщениях/медиа/звонках. Оно не
должно заменить уже существующее полное определение. Пользовательский выбор
частичного варианта не устанавливает fresh service evidence.

Если часть optional, её отсутствие не должно блокировать просмотр. Политика
обязательности зависит от сценария, не от удобства сокрытия ошибки. Все ipv6
ограничения показывать отдельно. Прямые P2P-звонки не обещать закрыть одним
официальным CIDR-снимком без проверки.

## 6. Загрузчик и новые форматы

Использовать существующий publicfetch и служебную политику сети. Не делать
bootstrap зависимым от ещё не установленного Telegram/VLESS-маршрута. Если прямой
служебный доступ запрещён, использовать только другой разрешённый management path
или локальные данные; не обходить согласие пользователя.

Ограничить время отдельной попытки и всего job; план не должен тратить весь budget
на первый источник, не оставляя возможности fallback. Числовые лимиты подобрать
под тесты слабых MIPS. Сохранить лимиты байтов/строк/include depth/concurrency,
таймауты, cancellation, ETag/304 с действительным cache, Retry-After и jitter.
Опустевший/HTML/повреждённый ответ не заменяет рабочий cache. 304 без тела в cache
не является успехом. Более старый/подменённый manifest отклоняется.

Не расширять allowedHosts на «любой сайт»: отдельный allowlist точных зеркал,
проверка TLS, redirects и DNS rebinding для каждого запроса. Не отключать TLS и
не передавать токены/куки RAZVILKA провайдерам. Не использовать неизвестные GitHub
прокси с собственными mutable списками в качестве доверенного каталога.

Форматы: V2Fly, plain CIDR, Meta domain-list `+.`, при необходимости Clash classical.
Сохранять exact DOMAIN/full: отдельно от suffix DOMAIN-SUFFIX/domain:. Не стирать
префикс exact и превращать запись в suffix. PROCESS-NAME у LAN-трафика роутера
нельзя считать поддержанным. ASN/KEYWORD/regexp требуют отдельного исполнителя
или явного списка skipped/unsupported. Не делать незаметный ASN -> огромный CIDR
или regexp -> приблизительный домен. All-required importer обязан отклонить
непредставимый обязательный охват, partial — показать отличие и запросить согласие.

## 7. Интерфейс

Переименовать «Каталог сервисов GitHub» в «Каталог сервисов». GitHub — источник
доставки, не назначение диалога. Левый список и правая карточка читаются локально.
Кнопка «Обновить определение» запускает явную фоновую задачу, а не очищает карточку.

Карточка показывает: редакция; домены/IPv4/IPv6; источник каждой части; возраст;
использованная резервная копия; причины пропуска; diff; возможность безопасного
импорта текущего снимка. При ошибке: «IP-список Telegram не получен: timeout» плюс
локальный проверенный состав, если он есть. Не показывать просто «GitHub не работает».

Обновление данных не должно сбрасывать текст поиска, выбор сервиса, ручной ввод или
несохранённые настройки. Epoch/serial/abort обязательны на switch/logout/close.
Поздний ответ Telegram не перезаписывает открытую карточку другого сервиса.
Не заменять обещанную кнопку реальной операции ссылкой на вкладку.

## 9. Приёмка (все пункты запланированы, не выполнены здесь)

T01. Холодная установка без интернета: библиотека отображается, но только штатный
     NFQWS2 выбран; Telegram/AI не включены автоматически.
T02. Домены Telegram HTTP200, core.telegram.org timeout: карточка не пропадает;
     с подходящим полным snapshot разрешён осознанный импорт именно этого snapshot.
T03. То же без сети в cache: показывается partial, полный scope не выдаётся.
T04. Raw GitHub недоступен: разрешённое точное зеркало с правильным hash принято.
T05. То же зеркало с другими байтами: reject, рабочий snapshot не заменён.
T06. Все зеркала недоступны: сохранённый состав виден; loop загрузок не возникает.
T07. Альтернативный CIDR добавляет 95.161.64.0/20: реальный diff и происхождение,
     не тихая подмена «официального» источника.
T08. Перегруппировка 14 официальных строк в 11 равных по охвату не считается
     потерей сетей; строки и семантическое покрытие сравниваются раздельно.
T09. Restart, corrupted cache, cache из будущего, expired metadata: политика
     последовательно применена; не обновляются фиктивно возраст и health.
T10. Invalid TLS, HTML200, truncation, oversized line, private DNS/redirect:
     не сохраняется правдоподобный неполный snapshot как полный.
T11. Include циклы/глубина/число/суммарные байты ограничены; все части закреплены
     одной source revision; timeout оставляет данные старой версии.
T12. ETag304 без cache, 429/503 Retry-After, перезапуск в cooldown: корректные повторы.
T13. DOMAIN exact и DOMAIN-SUFFIX не смешаны; `+.` корректен; unsupported regex,
     KEYWORD/ASN/process отображаются и не получают ложного покрытия.
T14. Preview новой редакции, обновление источника, import по старому digest:
     старое подтверждение не применяет новые данные.
T15. Partial domains не заменяет существующий полный Telegram; stable service_id
     не создаёт дубликаты только из-за смены зеркала.
T16. Смена карточки/закрытие/logout/cancel в запросе: поздний ответ не пишет state.
T17. Рабочие DNS/маршруты/ключи и чужие устройства неизменны от просмотра каталога.
T18. Сохранённые пользовательские источники и определения переживают обновление
     поставки; не перезаписываются «исправленным defaults».
T19. Воспроизвести fixture domains200+CIDRtimeout в unit/API и настоящем
     authenticated browser->HTTP, затем на сети пользователя с раздельными логами.
T20. Полный test/race/vet/JS/build gate; отчёт с commit, фактическими кодами и
     отдельно аппаратными/внешними пробами. Test runner != роутер.
