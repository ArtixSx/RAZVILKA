# PR-1.1 — явное копирование старого профиля с роутера

31 августа 2026. Локальный блок `0.18.1-dev`. Без публикации, SSH, изменения
рабочего роутера, регистрации Cloudflare и запуска транспортов.

## Что изменено

В «Настройки → Копии аккаунтов Cloudflare» добавлен блок «Скопировать профиль
с роутера». Пользователь выбирает известное расположение, проверяет структуру
файла и одним подтверждением сохраняет отдельную копию. Файл не переносится
физически и не удаляется. Его runtime не останавливается и не передаётся под
управление нового Provider.

Список содержит разрешённые расположения, а не результаты поиска или признак
работоспособности. При старте/загрузке списка файлы не читаются. Проверяется
только выбранный файл. Неподдержанный архивный USQUE остаётся архивом, а не
работающим транспортом. Скопированные данные имеют прежние честные статусы
`copied-snapshot` / `imported-unverified` и входят в отдельный зашифрованный
архив аккаунтов, реализованный предыдущим блоком.

## Источники и изоляция

Стандартная Linux-установка с config `/opt/etc/razvilka/config.json`:

| ID | Источник |
|---|---|
| `warp-profile` | `warp/wgcf-profile.conf` рядом с config |
| `wgcf-account` | `wgcf-account.toml` в выбранном каталоге `-warp-state` |
| `usque-session` | `/opt/etc/usque/session.conf` |
| `usque-config` | `/opt/etc/usque/config.json` |
| `usque-state` | `/opt/var/lib/usque/config.json` |
| `wireguard-profile` | `/opt/etc/wireguard/warp.conf` |

Для отдельного config доступны только профиль рядом с ним и явно выбранный
нестандартный каталог состояния WARP. Производственные пути USQUE/внешнего
WireGuard и стандартный WARP state не наследуются неявно. Это привязка к
расположению config, не универсальная sandbox для всех старых managers.

Источники задаются при старте в Go, максимум восемь. HTTP не принимает пути,
URL, команды, glob или новые источники. Другие расположения можно импортировать
как файл с компьютера через прежний безопасный сценарий; их автоматический
поиск/сканирование не добавлен.

## Защита чтения и сохранения

- Корневой каталог источника открывается через anchored `ownedfs.Root`.
  Отвергаются symlink самого файла/открываемого каталога, каталоги вместо
  файлов, отсутствующие, пустые и слишком большие файлы (более 256 КиБ).
- На Linux финальный open использует `O_NOFOLLOW|O_NONBLOCK`: подмена файла
  FIFO между проверкой и открытием не должна ждать появления писателя.
  После открытия требуется обычный файл с той же файловой идентичностью.
- До/после чтения сверяются идентичность, размер и время изменения; байты
  ограничены, затем проходят типизированный parser USQUE/wgcf/WireGuard.
- Preview возвращает только публичную модель и digest, связанный с ID источника,
  типом и содержимым. Copy повторяет чтение; другой источник или изменившееся
  содержимое не проходит старое подтверждение. Это receipt содержимого, не
  серверный журнал согласия и не доказательство владения аккаунтом Cloudflare.
- Сохраняется снимок прочитанных байтов. Внешний процесс не блокируется: он может
  изменить свой профиль после чтения. Мигратор не обещает заморозить внешний
  runtime и не использует этот снимок для активации.
- Прежний `ImportSnapshot` обеспечивает атомарность, лимит 32 и идемпотентность.
  Те же байты/тип возвращают прежний ID; новые создают новую копию. Неизвестный
  writer lock не удаляется. Сбой не обнуляет существующее хранилище.
- Код мигратора не пишет, не переименовывает и не меняет права исходного файла.
  ОС при чтении может обновить atime; содержимое/mtime/права код не меняет.

## API и UI

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/cloudflare/legacy/sources` | Только метаданные разрешённых расположений |
| POST | `/api/v1/cloudflare/legacy/preview` | `source_id`, чтение и публичный review без записи |
| POST | `/api/v1/cloudflare/legacy/copy` | `source_id`, `review_digest`, `confirm=COPY_LEGACY_ACCOUNT` |

Для всех методов требуется вход администратора, включая initial setup и nil
gate. POST защищены Origin/JSON; все ответы no-store. Тело ограничено 2 КиБ,
неизвестные/повторные поля, другой регистр и лишний JSON отклоняются.
Чтение/копирование делят общий лимит операций копий Cloudflare: без очереди,
при занятости — `429`. GET метаданных не читает файлы и не удерживает этот лимит.
В ответах и audit нет ключей, исходных байтов или локального пути.

UI хранит только ID/digest. Смена источника, отмена, ошибка, уход с экрана,
закрытие раздела и выход отменяют подготовленное подтверждение. Поздние ответы
не восстанавливают старую кнопку. При неясном результате из-за обрыва связи
предлагается обновить список; повторное копирование идемпотентно.

## Проверено и что остаётся

- Go: три формата, preview без записи, повторный copy, сохранность исходных
  байтов/идентичности/mtime/прав, изменённый файл, неизвестный источник, лимит,
  директория, symlink, чужая блокировка, отмена; изоляция candidate config.
- API: закрытый доступ/Origin/JSON, строгий input, no-store, busy,
  неизменность config, отсутствие приватного input в журнале.
- JS: preview/copy, одно подтверждение, reset/ошибка, поздние ответы на всех
  этапах, несовпадение источника в preview, отсутствие автоматического чтения.
- Полные Go test/vet и JS regressions прошли локально. Все Go-пакеты и provider
  tests собраны для Linux arm64/mips/mipsle, включая Linux-only FIFO test.
- В браузере проверен отдельный раздел с синтетическим файлом и реальными
  обработчиками API: preview → copy → list, исходный SHA-256 сохранён;
  отсутствующий источник даёт понятное сообщение. Узкая ширина — 390 px.

Это не запуск Linux-only тестов или аппаратная проверка. До стабильного релиза
нужны Linux/race, Entware/HIL, FIFO/path replacement проверки на Linux и
reboot/power-loss. [Crash-recovery writer нового протокола](CLOUDFLARE_WRITER_RECOVERY_RU.md)
добавлен следующим локальным блоком без удаления чужих lock. Полный ownership
работающих транспортов и общая транзакция router+provider backup ещё не завершены.
PR-1.2 продолжать с локальными ключами/mock registrar, без live registration.
