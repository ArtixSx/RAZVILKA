# PR-0.3 — изоляция проверок и безопасная очистка

Локальная разработка после `v0.18.1-rc.1`, 31 августа 2026.
Роутер и рабочие маршруты не изменялись. Это не подтверждение работы внешних узлов.

## Исправлено

- Проверка ID процесса ошибочно запрещала буквы `x` и цифру `0` из-за
  неверной записи нулевого символа. Это затрагивало запуск Sing-box и Xray
  настоящим контроллером; fake-контроллеры в старых тестах не ловили дефект.
- Временное резервирование TCP-порта для NFQWS2 привязано к `127.0.0.1`.
  Пробный прокси сохраняет только управляемый loopback inbound; Xray API
  удаляется из пробной копии так же, как дополнительные сервисы Sing-box.
  Дополнительно убраны Xray metrics и импортированные пути логов. Прокси-canary
  отклоняет Sing-box endpoints, требующие отдельного адаптера интерфейсов;
  проверка такого профиля не должна неявно создавать системный туннель.
- SOCKS readiness читает ровно два байта приветствия и закрывает соединение
  при отмене. Разделение ответа на TCP-пакеты больше не даёт ложную ошибку.
- Диагностические команды ограничены временем, размером вывода и ожиданием
  унаследованных дочерними процессами каналов. Усечённый вывод не считается
  успешным свидетельством. Быстрый inventory по-прежнему использует `/proc`.
- Рекурсивная очистка кандидатных файлов использует открытый `os.Root`,
  запрещает удаление самого корня, выход через `..` и символические ссылки.
  Подмена имени каталога после открытия не перенаправляет удаление в новый каталог.
- PID, log и config управляемого процесса должны лежать внутри его каталога.
  Записи, переименования и очистка PID/receipt привязаны к открытому каталогу.
  Атомарные записи dataplane также выполняются через эту границу.

## Проверки и границы

Добавлены тесты корректных/опасных ID, путей за пределами каталога, symlink,
подмены корня, отмены canary, разделённого SOCKS-ответа, зависшего процесса,
переполненного вывода и незакрытых каналов. Полный локальный набор Go-тестов
прошёл; новые целевые тесты также прошли после финальных правок.

Это защита перечисленных операций, не полноценная песочница запуска стороннего
ядра и не аудит всех файловых операций проекта. Точные PID-generation проверки
для остановки старых процессов и аппаратная fault-injection матрица остаются
отдельной работой. Нельзя объявлять внешний профиль рабочим только по запуску.
