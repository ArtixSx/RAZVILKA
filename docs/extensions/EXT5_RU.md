# EXT5 — Mihomo, HevSocks5Tunnel и переносимые стратегии

Версия кандидата: **0.18.2-repair.5**. Исходная база UPDATE4:
`98b37263aa6446679c88f5e222f94e39e2e27eb6`.

Это локальная разработка для передачи Codex, не опубликованный стабильный релиз.
Новые сетевые исполнители не включены по умолчанию и не устанавливаются автоматически.
Сохранены прежние шесть базовых NFQWS2-групп, индивидуальные сервисы, WARP,
импорт источников, VLESS bulk, обслуживание UPDATE4 и все защитные ограничения.

## Сделано

### Mihomo
В «Обходы» добавлен локальный конфигуратор. Ссылка, файл или статический JSON/YAML
проходят уже имеющийся parser providerprofile. Строится один выбранный outbound:
VLESS TCP/TLS/Reality/WS/gRPC, Hysteria2, TUIC v5, Shadowsocks — только в поддержанном
проектом подмножестве. Новые параметры XHTTP, плагины и другие неописанные возможности
не объявляются поддержанными лишь потому, что они есть в актуальном Mihomo.

Конфигурация — YAML с loopback SOCKS, одним статическим proxy и MATCH к нему.
DNS/TUN/sniffer/geo-auto-update и controller не включены. Исходные подписки,
правила, чужие listeners и системные операции не переносятся. Это НЕ конвертер
любого полного Mihomo-конфига и НЕ новая активная маршрутизация.

Предпросмотр не возвращает Config/UUID/password. Экспорт возвращает файл с ключом
только при совпадении SHA256 с повторно построенным профилем. Файл не сохраняется
в рабочий router runtime. Закрытие диалога/выход очищают ввод; нет localStorage
секретов, внешнего конфигуратора, iframe, online-конвертации или автоотправки ключа.
`native_validated`, `service_verified`, `live_applied` остаются false.

### HEV
Добавлен генератор JSON, совместимого с YAML upstream 2.17.1. Поддержаны только
IPv4, локальный SOCKS, принадлежащее RAZVILKA имя TUN, MTU 1280–1500, лимит
32–4096 сессий. IP-подсеть /24–/30, адрес должен быть частным host-адресом.
Скрипты, mapdns, pid-daemon, фиктивные ICMP-ответы отсутствуют.

`dataplane.NewProxyTunnelAdapterWithHev()` — **программная экспериментальная точка**
для USQUE/Sing-box/Xray с существующим SOCKS→TUN путём. Формирование, валидация,
аргументы процесса и rollback snapshot учитывают выбранный sidecar. Старый snapshot
без поля kind означает Sing-box; смена backend при удерживаемом runtime запрещена.
Действующий constructor, порты, маршруты и способ по умолчанию не изменены.

Нативного dry-run HEV не выдумываем: проверяется точный сгенерированный файл.
Настоящее создание TUN/health/UDP/rollback требует отдельного стенда. HEV-бинарник
не получен, не поставляется, не запущен. Отдельной CLI-галочки/выбора в мастере пока
нет: нельзя дать пользователю ложное подтверждение работоспособности.

### Стратегии
«Обходы → Пакеты стратегий» и «Лаборатория NFQWS2 → Импорт и обмен» используют
один диалог и один StrategyLab. Импорт additive: существующие кандидаты, нативные
проверки, Evidence и Selections сохраняются. Изменённые параметры — новый ID,
старый вариант не удаляется. Тот же ID не теряет проверку при повторном импорте.

Пакет: schema 1, ID/sequence/time/compatibility и 1–64 записи pool/name/arguments.
Максимум 256 КиБ, 512 кандидатов после импорта, 128 receipt-источников. Сохраняются
sequence+SHA256. Старшая ранее принятая версия не заменяется младшей; та же sequence
с другим digest отклоняется. Запись кандидатов и highwater выполняется вместе
через descriptor/CAS механизм restorejournal. Внешняя параллельная запись блокирует
дальнейшие записи старого экземпляра до повторного открытия. Память не показывает
успешный несохранённый импорт.

Поддерживается узкое data-only подмножество --filter/--payload/--lua-desync и --new.
Нет shell, lua-init, qnum, путей файлов и чужих runtime-настроек. Только известные
функции и ссылки на локальные blobs. Даже принятые параметры требуют установленного
NFQWS2 --dry-run, независимой локальной пробы и штатного применения. Это формат
обмена кандидатов, а не разрешение облаку исполнять произвольный Lua.

Встроенные примеры: TCP circular и QUIC fake из закреплённого nfqws2-keenetic
`c77226bd384e047a3d97e3ab6f0ad8b46fc3c967`. Не заявления об их работе на вашей сети.
UDP/Discord voice не копируется через неточную адаптацию неподдержанных параметров.
Примеры загружаются только по кнопке, не автоимпортируются при старте.

Личные пакеты принимаются только явным действием. Подписанные дополнительно
проверяются Ed25519, с разделением домена подписи и точным payload. Ключи издателя
поступают не из самого пакета, а из заданного владельцем `-strategy-pack-keys` JSON.
Подписанный пакет не получает право Apply. Онлайн-получения и статистики нет.

При экспорте нет истории испытаний, сервисов пользователя, устройств, VPN-ключей
или журналов. **Имя и SNI в параметрах остаются**, их надо проверить перед передачей.
Отправка никуда не выполняется. Все ручные `AddCandidate` старого expert-режима
остаются: непереносимую стратегию можно сохранить локально, но не экспортировать
через безопасный формат.

### Офлайн-инструмент издателя
`cmd/strategy-pack` не является службой и не устанавливается в init. Пример:

```sh
# На компьютере издателя, НЕ на роутерах подписчиков; файлы должны быть новыми.
go run ./cmd/strategy-pack -mode keygen -key-id community \
  -private /secure/private.json -public /secure/public.json
go run ./cmd/strategy-pack -mode sign -key-id community \
  -private /secure/private.json -in reviewed-pack.json -out signed-pack.json
go run ./cmd/strategy-pack -mode verify -public /secure/public.json -in signed-pack.json
# На роутер можно передать только public.json с корректными правами и явным доверием.
```
Файлы создаются с 0600 и O_EXCL; существующий ключ/пакет не перезаписывается.
Приватный ключ не включён в source, fixture или поставку. Подпись обеспечивает
происхождение относительно явно выбранного владельцем ключа, не универсальное доверие.

## Что не готово

Mihomo native -t/managed process/NodeStore compilation/scoped apply/health, HEV
package+CLI opt-in+платформенное испытание, seamless sidecar migration, реальная
оценка скорости/ресурсов, исходный USQUE update/H2 regression не реализованы здесь.

Нет серверного ingest, telemetry, подписанного online feed, автоматического
обновления стратегий или его подключения к Autopilot. Пакеты добавляются вручную.
Нет runtime-активации стратегии сразу после импорта.

Highwater сохраняется в текущем файле StrategyLab. Старое приложение UPDATE4 может
не понимать receipt-поля и удалить их при перезаписи: **обратная миграция старой
версии должна сохранять полный снимок**. Это не полноценная TUF-система отзыва,
откатозащиты резервных копий или доверенного времени. Эти задачи нужны до unattended feed.

Все ранее незакрытые UPDATE4 задачи сохраняются: автоматическая установка с полным
rollback, fair/resumable selected batch, per-domain TTL/endpoints, доставка AWG,
сквозное восстановление реального VLESS, 24–72 часа аппаратной приёмки.
