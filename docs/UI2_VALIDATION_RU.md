## Что означает «проверено»

Предпросмотр исполняет те же контроллеры и DOM, но подставляет API в памяти браузера.
Он проверяет интерфейс и формат запросов, а не сетевую доступность публичных серверов.
Снимки native-responses получены чтением реально запущенного опубликованного rc.2 на Linux
amd64 с изолированными файлами и Safe Mode. Никакие Apply, регистрации WARP, изменения
firewall, установки компонентов и настройки реального роутера этим запуском не выполнялись.
Тест cold-start использует эти формы ответов; в копии для передачи нормализованы локальные
пути. В нём отсутствующий A1 возвращает 404, а пустой каталог не заполняется выдуманными узлами.

Вывод старого исполняемого файла не является подтверждением нового Go-кода A1.
Существующие 22 regression scripts — количество скриптов, а не сумма всех их внутренних тестов.
Не заявляются WCAG-сертификация, проверка всех браузеров или производительность на MIPS.

## Воспроизведение браузерных тестов

В папке `validation`:

```sh
python -m pip install -r requirements.txt
python -m playwright install chromium
python scripts/test_ui2.py
python scripts/test_failures.py
```

Можно задать `CHROMIUM_PATH` для установленного Chromium. В `reports` будут JSON-результаты.
`tests` содержит только тестовый транспорт и нормализованные снимки. В производственный
каталог `web` они не входят. Открытие HTML и тесты не дают права менять роутер.

Исходные API regression scripts запускаются в распакованном проекте:

```sh
for f in scripts/test-*.mjs; do node "$f" || exit 1; done
```

При наличии требуемого Go toolchain следующие обязательные ворота перед выпуском:
`go test ./...`, `go test -race ./...`, `go vet ./...`, штатная сборка, проверка точного
артефакта и изолированный аппаратный прогон. Ни один из этих Go/HIL этапов не заменён
успешными браузерными тестами.
