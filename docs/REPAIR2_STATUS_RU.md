# RAZVILKA 0.18.2-repair.2 — единый тестовый кандидат

Дата: 16 сентября 2026. База: опубликованный тег v0.18.2-rc.6,
commit `cea4b6fec8a3fc807556a045c1c6446fa8932c9d`.
Это локальная исходная доработка, не объявление нового стабильного релиза.
Точная итоговая ревизия, коды команд и контрольные суммы находятся в отчёте поставки рядом с архивом.
Предыдущие отчёты DC1/AWG/rc.5/rc.6 остаются историей своих сборок.

## Реализовано

### Первый запуск

Новый `configs/service-catalog.json` содержит только 278 доменов штатного
`nfqws2-keenetic/user.list`, сгруппированных в YouTube, Discord, Roblox,
Speedtest/Ookla, вход Riot Games и общие CDN. Список закреплён за исходной ревизией,
не скачивается и не исполняется при открытии панели.

Последний шаг мастера показывает исходный состав и SHA review. Одной записью
политики сохраняются разрешения на базовый NFQWS2 и отдельно выбранные дополнительные
определения. Другие приложения не подключаются по умолчанию. Дополнения можно
импортировать до завершения мастера, затем явно отметить; наличие в каталоге не
означает согласие на применение. VLESS-подписка не обязательна для локального NFQWS2.

До успешной проверки и транзакции статус — ожидание, а не работа. Отсутствующий
NFQWS2 не заменяется скрытно другим обходом. Существующие desired/applied/suspended
назначения, ручные политики и изменённые определения не перезаписываются.

**Обновление не очищает существующий пользовательский каталог.** Штатный установщик
сохраняет его. Правило «только NFQWS2 по умолчанию» относится к чистой установке.
На старой системе лишние записи убираются отдельным согласованным действием,
после снятия их маршрутов; при обновлении рабочий Telegram не исчезает.

### Добавление сервисов

Согласован контракт `import_guard=source-sha256`. Импорт требует SHA показанного
preview. Отсутствующий, просроченный либо подменённый состав не импортируется.
Исправление не отключает контроль источника ради зелёной кнопки.

Есть GitHub-файл (не корень репозитория), локальный файл либо вставленный текст.
Форматы: домены и публичные CIDR. Для вставленного текста действует 256 КиБ,
для сетевой загрузки — существующие ограничения безопасного fetch/walker.
HTTPS-проба необязательна: определение без неё допустимо, но не получает service PASS.
Произвольный shell, HTML, VLESS-ключи и конфиги VPN не исполняются как сервисный список.
Пользовательский URL принимается только для поддержанного GitHub-host/file; разрешения
на запросы не расширяются на локальную сеть. Обновление списка не меняет маршруты.

### WARP и установка

Единственный WARP-конфигуратор расположен в «Обходы → WARP · WireGuard».
AmneziaWG содержит собственный профиль и проверку совместимости, старый переход
к WARP открывает его каноническую страницу. Второй обработчик/хранилище не создаётся.

Зависимые флаги автоконтроля приводят черновик политики в непротиворечивое состояние.
Выбор автоприменения включает подготовку и саму политику, но **не принятие условий
Cloudflare**. Выключение политики снимает зависимые действия. Порог отказов выше
числа назначенных WARP-сервисов объясняется, а не уменьшается тайно.

Кнопка установки использует план выбранного компонента и существующее подтверждение.
Установленный компонент не переустанавливается; внешнее владение не захватывается.
Если AWG-модуль этой модели/ядра нельзя установить штатно, показывается причина;
это не выдаётся за успешно добавленную поддержку модуля.
Уведомление о черновике одного движка не остаётся указанием в другом; глобальные
ошибки rollback/владения не скрываются этим правилом.

### Автопилот и обслуживание

Обслуживание check/prepare получило место перед обычной сервисной работой
существующего автономного цикла. Оно не ждёт, пока список требующих проверки
сервисов опустеет. Общий reconciler/operation gate остаётся единственным владельцем.

Неуспешный read/check/prepare не закрывает всё окно: до трёх попыток, с паузой.
Успех сохраняется; существующая pending-подготовка опрашивается, а не создаётся повторно.
Промежуточный retry-счётчик хранится в памяти, успешные оконные receipts — на диске.
Это безопасный повтор проверки/подготовки, **не новая политика регистрации аккаунтов
и не автоматическая установка обновлений**.

При некоторых корректно возвращённых INCONCLUSIVE (transport/egress/service/service_ip)
worker теперь может подготовить ограниченный разрешённый резерв вместо раннего
возврата до его проверки. Это **не право применить резерв при любой неопределённости**.
Ошибки cleanup/identity/runtime, отмена, неустановленная сеть и ошибки checker
по-прежнему блокируют опасные действия. Реальное подтверждённое падение узла и
восстановление собственного процесса используют прежние transaction/rollback guards.

Общий deadline и отмена checker больше не называются доказанным изменением WAN.
Итоговая попытка получает типизированный код, не положительное доказательство.

### Все VLESS

Интегрирован отдельный all-vless scope, независимый от страницы и UI-фильтров.
Одна серверная очередь фиксирует текущие допустимые ID. Узлы проверяются по одному;
между завершёнными проверками и cleanup допускается восстановление. Scope не растёт
при новом импорте. Очередь переживает закрытие браузера, но **не reboot процесса**.

Массовое удаление: preview+review hash, повторная проверка текущего использования,
сохранение активных/приостановленных/group/pinned/reserve/recovery узлов и один CAS
для допустимой подвыборки. Другие протоколы не удаляются. Подписки не отключаются
и могут вернуть локально удалённые записи.

## Ограничения

1. На этом этапе не запускались реальные WARP/AWG/VLESS/NFQWS2, регистрации Cloudflare,
   LAN-трафик, WAN reconnect, перезагрузка Keenetic и 24–72 часа наблюдения.
2. Улучшен all-vless batch. Старый обычный selected/service batch до 64 узлов ещё
   удерживает admission на всю партию. Унификацию очередей и durable resume доделать.
3. Резервные проверки при INCONCLUSIVE не заменяют расследование аппаратного инцидента.
   У неподтверждённого checker нет автоматического разрешения переключать узел.
4. Ночное обслуживание — check/prepare. Полный подписанный канал, безопасная
   unattended установка приложения/движков и rollback компонентов остаются отдельными этапами.
5. Live DNS для сервиса, точная пара DNS+маршрут, TTL/cache convergence и применение
   в области клиентов не завершены; предохранитель DNS_LIVE_ADAPTER_UNAVAILABLE сохранён.
6. Каталог сообщества — офлайн-модель. Сетевой ingest, регулярная публикация, отправка
   статистики по opt-in и production ключи здесь не создавались.
7. AWG31 требует совместимой утилиты и загруженного модуля. Автоустановки .ko по
   неподтверждённой архитектуре или через wget|sh нет.
8. GitHub-источник может оказаться недоступен в сети пользователя. Исправление API
   позволяет корректно обработать результат, но не гарантирует доступ к внешнему сайту.
9. Все имена и числа в standalone preview относятся к тестовому состоянию.
   Этот HTML не подключается к роутеру; запись и проверки в нём запрещены.
