# Повторное внешнее исследование: что использовано и что оставлено на испытания

30.09.2026. Источники и уровень чтения — `SOURCES.json`. Не выполнялся построчный аудит всех перечисленных проектов, не проверялись публичные узлы/регистрации. Код чужих контроллеров не копировался в runtime RAZVILKA; реализации новых helpers написаны локально под существующие контракты.

## Использовано в подготовленном коде

**WireGuard, официальная документация.** Keepalive не обязан присутствовать. Проверка должна сама инициировать разрешённый трафик, а не ждать появления handshake бесконечно. Это реализовано в helper WG/AWG; отдельные HTTP/data/handshake результаты не смешиваются.

**keenetic-entware-extras, `api-utils.lua`.** Изучены single-producer status cache и stale fallback. Перенесён принцип, не Lua: в каталоге RAZVILKA одна загрузка, параллельные читатели используют LKG, ошибки получают cooldown. Чужая проверка JSON по первому символу не скопирована; используются строгий parser и ограниченный checkpoint. Проект содержит и более широкий DNS/geo-split controller — он не устанавливается.

**keenetic-entware-extras, `net-check/scripts/lib/batch.sh`.** Полезен fallback MemAvailable→MemFree и мысль об адаптации партий. В этой поставке перенесён только консервативный fallback: +1 к партии и router-load thresholds не копируются. Общий ресурсный scheduler остаётся задачей, защита OOM не ослаблена.

**SmartDNS, документация кэша.** Полезно сохранять checkpoint не только при штатном выходе и различать устаревший ответ и свежесть. В RAZVILKA применено к публичному каталогу: snapshot после принятой загрузки, оригинальное время, bounded staleness, не service proof. Это не внедрение SmartDNS как дополнительного демона и не продление DNS TTL.

**Mender / RAUC, модель обновлений.** Установка, запуск и принятие новой версии — разные стадии; при незавершённом исходе нельзя просто начать ещё одну mutation. Использовано для typed outcomes, fail-stop batch, pending intent. Полноценные RAUC slots/Mender daemon не добавлены, а общий durable component journal и удержание old-working ещё предстоят.

## Полезные новые находки для следующего этапа

**HEV.** Upstream явно допускает локальные ICMP Echo replies. Поэтому ping через TUN может подтвердить локальную эмуляцию, а не достижимость удалённого сервера. В матрицу приёмки внесён отрицательный тест «удалённый выход отсутствует, local ping отвечает». Уменьшение stack/TCP buffers/session count может помочь малой памяти, но требует измерений.

**Mihomo MASQUE.** Документация различает `quic`, `h2`, `h3-l4proxy`; последний сейчас не поддерживает UDP. MASQUE private/public keys описаны как ECDSA, а не обычные WG keys. Есть remote-dns-resolve; при его включении путь DNS меняется. Это полезно для версиизависимого общего Cloudflare exporter, но нельзя объявить любой генератор WG/MASQUE взаимозаменяемым.

**USQUE.** Native TUN создаёт интерфейс, а маршруты остаются внешней задачей. L4-режим и полноценный IP tunnel не равнозначны. H2 использует отдельные endpoint-поля/server identity; reconnect hooks не гарантируют cleanup при окончательном падении процесса. Нужны supervisor, generation и существующий coordinator, не shell hooks как второй сетевой владелец.

**Mihomo providers / sing-box URLTest.** Lazy checks, timeout, idle interval и tolerance полезны для дешёвого резерва. Но fastest-node/url-test не равен нашему «сохранить рабочий LKG и переключить при отказе»; interrupt-existing-connections отдельно влияет на живые flows. Не заменять автопилот группой минимального ping.

**mwan3, реальный `mwan3track` openwrt-24.10.** Прочитаны состояния connecting/disconnecting/online/offline и привязка проверки к source/interface/family. Это образец более точного failure state machine. LD_PRELOAD/fwmark/hotplug OpenWrt не переносится на Keenetic вслепую. Страница OpenWrt wiki требовала проверку браузера; вместо неё прочитан исходный скрипт.

**Xray / AmneziaWG.** Актуальные документы — основание для versioned compiler fixtures, а не обещание, что установленный бинарник поддерживает все перечисленные поля. Не смешивать версии модуля, CLI и wire format. Не менять работающую схему sidecar только из-за нового пункта документации.

**z2k / Tachyon / WayHop.** Повторно просмотрены описания стратегий, восстановления и capabilities. У WayHop описание fallback не следует автоматически читать как строгое приоритетное резервирование; у Tachyon богатый README не заменяет проверку пути. Их интеграция не включена как зависимость. Следующее углубление: точный strategy trial и resource ownership, а не копирование универсальных списков.

**CyberPortal.** Страница генератора описывает несколько форматов, но это заявление сервиса. API регистрации/выдачи ключей не вызывался; размещённый код не приравнен к похожему public fork. Результат внешнего генератора допустим только как недоверенный кандидат с явно принятым доверием. Новые accounts или endpoint scans здесь не создавались.

**quic-go.** GSO, PMTU и буферы зависят от ядра/transport. Оптимизация Linux VPS не является настройкой старого Keenetic. Проводить узкий A/B-test, не вставлять глобальные sysctl в установщик.

## Сообщения пользователей: только генераторы тестовых гипотез

При поиске встретились обсуждение кэширования SmartDNS и сообщение о загрузке CPU после reboot mwan3. Они не использованы как доказательство ошибки RAZVILKA или всей upstream-версии. Полезный результат — тесты первой cache miss/expiry и reboot/reconnect с ограниченным числом workers. Эти случаи здесь не воспроизведены на соответствующих проектах.

## Не перепроверено глубоко в этой итерации

Podkop, Nikki/Momo, HomeProxy, OpenClash, dae, mosdns, XKeen, keen-pbr, остальные WARP-генераторы и публичные VLESS feeds остаются в прежнем радаре V2. Нельзя называть их исходники заново полностью проверенными. Для следующего аудита нужны конкретная ветка, файл, лицензия, идея, риск и собственный тест. Личные/публичные серверы по спискам не сканировались.

## Вывод

Наиболее полезное сейчас — не ещё десяток способов обхода. Это одинаковая семантика Apply, независимые типы доказательств, проверяемая ошибка, долговечный LKG-кэш и запрет повторных изменений при неизвестном исходе. Несколько этих решений уже подготовлены в коде; сложные live dataplane и обновления не объявлены готовыми раньше испытаний.
