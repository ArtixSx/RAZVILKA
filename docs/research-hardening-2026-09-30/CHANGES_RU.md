# Что подготовлено в исходниках

Все изменения привязаны к 0.19.3 / `8177834`. Это описание **подготовленного кода**, а не утверждение о принятой новой версии.

## 1. Единые идентификаторы автономных маршрутов

Добавлен `internal/routekind`: семь локальных исполнителей возвращаются свежим списком; проверка точного ID не зависит от изменяемой экспортированной slice. Валидация PreferredRoutes и callback `ApplyAutonomyRouteWithRollback` используют один registry. Сохранён отдельный строгий путь `sing-box:node-*`. `auto`, `direct`, произвольные suffix, ошибочные и неизвестные строки не разрешены как произвольный исполнитель.

Остаются без ослабления CAS ревизии, SafeMode/Stopped/manual, сохранение соседних сервисов, нормализация scope, undo и NodeStore proof. Добавлены полный repo-тест сохранения/reload/undo каждого исполнителя и изолированные проверки точного callback с моделью Store. Полный runtime lifecycle этим не завершён.

## 2. Canary обычного WG и AWG

`internal/tunnelcheck` отделяет инициирующий разрешённый запрос, handshake и сервисный результат. Обычный WG/AWG начинает с URL своего сервиса через источник временного туннеля; не нуждается в Cloudflare и не меняет Keepalive. Проверка WARP сохраняет свой обязательный provider trace. Ошибка сайта при состоявшемся handshake не называется ошибкой handshake и не запускает бессмысленную смену WARP-портов.

`wg_canary_checks.go` подключён вместо прежнего цикла в общем адаптере. Маршруты с Sources не пропускаются в изолированной пробе, а сами Sources остаются в плане для отдельного live scope. Повторяющийся URL не порождает повторный одинаковый HTTP-запрос в этой пробе. Это оптимизация одинакового generic-web probe, не объединение разных сценариев сервиса.

Добавлены холодный peer без keepalive, scoped-only план, ошибки/отмена/таймаут, несколько URL и контроль WARP. Общий интерфейс пока требует IPv4-адреса как раньше; dual-stack HIL и точная привязка пакета остаются отдельными задачами.

## 3. Типизированные результаты обновления

`components.UpdateFailure` различает отказ до package mutation, проверенный rollback и неподтверждённый rollback. Causes сохраняются через errors.Is, отображение не используется как управляющий протокол. Нераспознанная ошибка после входа в изменяющий код консервативно остаётся неизвестным исходом.

`maintenancebatch` останавливает следующие изменения при неизвестности или невозможности сохранить результат; частичный отказ не закрывает окно как выполненное. Один общий пакет (например wireguard-tools под двумя карточками) не обновляется повторно в одном списке. Отмена, окно, права и конфигурационная ревизия проверяются на каждом шаге.

## 4. Полномочия и сохранённое намерение обслуживания

Новый App-адаптер сохраняет `components = pending:<id>` в существующей Maintenance-map до начала действия. Метка остаётся после неизвестного исхода/падения и препятствует новому автоматическому batch и передаче приложения установщику. Пакетный журнал на диске, pin предыдущей рабочей версии, зависимостей и полный recovery после питания всё ещё не реализованы.

Safe Mode, Stop, manual, незавершённый черновик, закрывшееся окно, изменившаяся политика/ревизия запрещают новую автоматическую package mutation. Повторная проверка выполняется после подготовки непосредственно перед вызовом обновления. Это не снимает изоляцию общей очереди.

## 5. Новая найденная ошибка: receipt сам не проходит декодирование

В исходной 0.19.3 `runAutoInstall` записывает Maintenance[`application-install`]. `decodeAutonomy` разрешает только `application` и `components`, максимум два элемента; `persistAutonomyLocked` вызывает этот декодер перед записью. В итоге собственная попытка автоустановки может не пройти сохранение и заблокировать автоматику **до** handoff.

Подготовлена ограниченная запись `application = install-attempt:<version>` без нового ключа. Она не смешивается с завершённым окном. При явном отказе до handoff прежняя запись восстанавливается; unknown handoff сохраняется. Чтение каталога или завершение check-окна не стирает неизвестную попытку. Точная защита по hash артефакта и поколениям installer остаётся дальнейшей задачей.

## 6. Каталог после перезапуска и при нескольких вкладках

Добавлен `catalogsnapshot`: ограниченный envelope публичного индекса с origin, schema, исходным временем и SHA-256. Digest обнаруживает повреждение, **не является подписью издателя**. Перед использованием вновь выполняется geoEntries/source validation.

Manager.Load восстанавливает сохранённый индекс рядом с собственным registry. Запись использует существующий ownedfs, `0600`, atomic rename и sync directory. Старый индекс не очищается при ошибке загрузки. После перезапуска timestamp не обновляется искусственно. Для offline browsing принимается индекс не старше 30 дней; это не продление route/service proof.

На экземпляр менеджера действует одна in-flight загрузка; параллельный читатель с LKG не ждёт чужой fetch. Ошибка даёт минутный cooldown вместо запросов на каждом нажатии. Первый запрос обновления сам всё ещё может ждать сеть — полноценное фоновое обновление и подключение cache-status к панели оставлены Codex. Добавлены repo-тесты restart/offline/corrupt/singleflight и изолированные тесты envelope.

## 7. DNS отмена и старые ядра

DNS-повторы сохраняют прежние три попытки и отсутствие повторов NXDOMAIN, но теперь отменённый контекст возвращается именно как отмена и не превращает поздний успех в PASS.

StrategyLab на ядре без MemAvailable использует консервативный MemFree. Явный MemAvailable=0 не подменяется fallback. Прежние пороги защиты RAM/load не снижены. Это исправление учёта памяти, **не законченный адаптивный планировщик всех фоновых операций**.

## Что намеренно не менялось

NFQWS2-only не переосмыслен скрыто как preferred; не изменены согласия и доверие к публичным источникам; не перезаписаны пользовательские конфиги и ключи; не подключены внешние контроллеры; не включены непроверенные runtime/global-policy возможности. Версия проекта не повышена до вымышленного release.
