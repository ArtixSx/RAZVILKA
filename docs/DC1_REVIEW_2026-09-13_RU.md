# Проверка и исправления DC1 — 13 сентября 2026

База: полный пользовательский архив DC1, commit `9bdfa04bc8e37fa2cc9f497037c3e5e086ce55e7`, версия `0.18.2-dev`. Работа выполнена в отдельной ветке, с сохранением исходной истории. Это исправленный кандидат для тестирования; аппаратная приёмка не завершена.

## Исправления

| Область | Ошибка и результат |
| --- | --- |
| Автопилот | Изолированный тест удалённого узла мог скрыть остановку собственного туннеля. Теперь проверяется применённый процесс и его область; восстановление того же узла проходит общую транзакцию с откатом. |
| Очередь | Долгая предыдущая задача могла отнять весь срок следующей проверки. Каждая получает свой бюджет в момент запуска, в пределах общего срока. |
| AmneziaWG | Между этапами проверки повторно проверяются профиль, настройки, сервис, возможности исполнителя, сеть и отмена. Проверенная CLI должна совпадать с запускаемой CLI, включая явный override. |
| DNS | IP-адрес больше не принимается как публичное DNS-имя. Проверяются настоящий DNS wire-ответ и NODATA, конфигурация до каждого запроса, отмена, сессия и неизменность сервиса. Ошибки API имеют правильные статусы и не раскрывают внутренние сообщения. |
| DNS-интерфейс | Поздний результат после отмены, выхода или смены редакции настроек не показывается как актуальный. Метаданные пользовательского DNS сохраняются при перечитывании. |
| Каталоги | Неоднозначные JSON-поля с разным регистром, дубли и отсутствующие обязательные значения отклоняются в подписанных рекомендациях и keys-json подписках. |
| Вход | Старый ответ 401 больше не завершает новый сеанс. После входа очищается старое уведомление, запросы прежнего сеанса отменяются, повтор старого изменения запрещён. |
| Обновление | Без единственной корректной SHA256-записи бинарник даже не запускается для предварительной проверки. Исправлен старый путь сборщика CSS. |

## Интерфейс

- Тёмная тема при первом открытии и недоступном хранилище браузера. Явный выбор светлой темы сохраняется; оформление применяется до загрузки CSS.
- Заметные вкладки «Главная» и «Автопилот» с пояснениями, единая навигация и существующие контроллеры.
- Главная с разными акцентами для доступности и Автопилота, более читаемыми заголовками и понятным первым запуском.
- Пустой каталог предлагает открыть все сервисы и действительно очищает поиск/категорию. Ожидающее отключение действующих маршрутов не выдаётся за первый запуск.
- Индикаторы нагрузки и распределения маршрутов работают с действующей строгой CSP. Нулевое значение не выглядит полной полосой; отсутствующая память/CPU не выдаётся за ноль.
- Более выразительные карточки, видимый фокус клавиатуры, адаптация к телефону, доступное имя кнопки поиска и поддержка уменьшенного движения.
- Сохранены русские названия стран, группы сервисов, редакторы обходов и браузер подключений. Отрисовка не создаёт сетевых проверок и не меняет маршруты.

## Проверка

На Go 1.26.5 выполнены `go mod verify`, полный `go test -count=1 ./...`, полный `go test -race -count=1 ./...`, `go vet ./...`, gofmt и проверка diff. Windows race использует локальную Zig CLI и системную библиотеку синхронизации; это не проверка ядра роутера.

Выполнены 29 JavaScript-наборов, синтаксис 22 производственных JS-файлов и воспроизводимость CSS. Добавлены исполняемые асинхронные регрессии авторизации, DNS-отмены и устаревших ответов, тесты темы, CSP-индикаторов и первого запуска. Проверки установщика дополнены отсутствующими/повторными/неверными checksum-записями.

Интерфейс проверяется на настоящем локальном Go-сервере с отдельной тестовой учётной записью и Safe Mode. Он использует реальный API, а не демонстрационный `PREVIEW.html` из архива. Итог проверки Linux CI, кросс-сборок и состав архивов записываются в отчёт поставки рядом с архивами. Полный платформенный сценарий: `scripts/check.sh` в Ubuntu CI.

## Что ещё требует разработки и аппаратной проверки

1. **DC2: один сквозной сервисный тест.** DNS-ответ → точный публичный IP → выбранный обход → исходное имя SNI/Host → TLS → конкретный сценарий сервиса. Различать региональный отказ, ограничение частоты и отсутствие ответа. Сохранять TTL, сеть, редакции профиля и сервиса вместе с результатом.
2. **DC3: применение DNS только в нужной области.** Общая транзакция DNS и маршрута, фактическое чтение применённого состояния, отсутствие утечек на другие устройства и откат. До этого несистемный live DNS остаётся закрыт с `DNS_LIVE_ADAPTER_UNAVAILABLE`.
3. **DC4: подбор пары DNS + обход.** Проверять сначала последний рабочий вариант, ограничивать число проб и расход ресурсов, учитывать повторный подтверждённый отказ. Не менять узел лишь из-за DNS-таймаута.
4. **Коллективный каталог.** Пока это офлайн библиотека рекомендаций. Нужны постоянная защита sequence+digest от отката, загрузчик, ротация ключей, сервер приёма и отдельное добровольное согласие на отправку результатов. Облачная отправка не включена.
5. **Роутер и обновления.** Проверить реальный AWG 3.1, восстановление WARP, отказ текущего узла и переход на резерв, закрытый браузер, перезагрузку, слабую память и 24–72 часа работы. Проверить миграцию и откат всех новых autonomy/DNS данных между версиями. Плановая проверка/подготовка обновления не равна автоматической установке.

Ни DNS-ответ, ни работа процесса, ни сборка для архитектуры отдельно не доказывают доступность всех функций сервиса на роутере. Исторические отчёты rc.2/A1/AWG31 сохраняются как сведения о своих версиях, а не результаты этой проверки.
