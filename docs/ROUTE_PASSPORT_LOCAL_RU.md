# Локальный паспорт пути — продолжение PR-0.2

Дата: 30 августа 2026 года. База: `7104fd7`, цикл `0.18.1-dev`.
Статус: локальная разработка; стабильный релиз и рабочий роутер не заменялись.

## Исправленная проблема

Успешный HTTP-ответ через локальный SOCKS раньше сам повышал результат до
`route-confirmed`. При этом профиль мог выбрать DIRECT, порт мог принадлежать
другому процессу, а файл конфигурации — отличаться от использованного при запуске.

Теперь наблюдение ответа и подтверждение выбранного пути разделены. Если
сервис ответил, но путь не доказан, результат — `INCONCLUSIVE`, уровень
`runtime`, подпись «Путь не подтверждён». HTTP-код и факты ответа сохраняются.
Это не равнозначно утверждению, что сервис или профиль не работает.

## Что реализовано

- При управляемом запуске Sing-box, Xray или USQUE создаётся запись
  `engine.pid.identity.json` с правами `0600`. В ней: PID, boot ID, время старта
  процесса в тактах ядра, путь исполняемого файла и SHA-256 аргументов/конфига.
  Ключи, токены, пароли и содержимое конфига в запись не включаются.
- Хеш конфигурации снимается до запуска и сверяется после него. Проверка
  никогда не «усыновляет» сторонний процесс, создавая запись задним числом.
- До и после запроса сверяются запись запуска, текущий процесс, точные
  аргументы, конфигурация и принадлежность IPv4 loopback-порта процессу по
  inode сокета. Пространство сети должно совпадать с процессом проверки.
- Паспорт меняется при перезапуске, смене конфигурации или слушающего сокета.
  При остановке запись аннулируется. Rollback, запускающий сохранённый профиль,
  создаёт новую запись; старое подтверждение процесса не восстанавливается.
- Проверяется статический выход: Sing-box `route.final` либо первый outbound;
  Xray — первый outbound при отсутствии routing rules. Неиспользуемая запись
  DIRECT допустима, выбранный DIRECT/freedom — не подтверждение обхода.
- Отсутствие паспорта, изменение процесса или неоднозначный профиль отзывают
  старое успешное свидетельство в Smart Route, не изменяя рабочие маршруты.
- SOCKS greeting, authentication, CONNECT и чтение адреса имеют общий timeout
  и реагируют на отмену. Ошибка запуска управляемого процесса завершает только
  созданный этим вызовом дочерний процесс и освобождает его ресурсы.
- Проверки подписей UI добавлены в `scripts/check.sh`, включая запрет зелёного
  результата при наличии `route_proof_error`.

## Границы поддержки

Подтверждаются статические профили одного удалённого выхода без управляющего
API, дополнительных routing rules и цепочек. Управляемый USQUE проверяется как
фиксированный MASQUE-runtime с соответствующей записью запуска.

Сторонние/ранее запущенные процессы без записи, URLTest/selector-пулы, detour,
Xray balancer и другие сложные схемы остаются **доступными для проверки связи**,
но пока не получают точного подтверждения выбранного пути. Их настройки не
переписываются, импорт не запрещается, автоматического перезапуска нет.
Для однозначного теста можно использовать отдельный профиль одного узла.

Отдельный native USQUE, WARP WireGuard, AmneziaWG и NFQWS2 сохраняют собственные
проверки интерфейса/маршрута/очереди; этот паспорт их не заменяет.

## Чего паспорт не доказывает

Это локальное свидетельство при доверии к управляемому runtime, а не наблюдение
пакетов на удалённом сервере. Пока не исключаются независимо перехват трафика
внешними правилами, изменение поведения runtime извне или резолвинг адреса
самого прокси в другой узел. Нельзя объявлять доказанными remote egress,
отсутствие любых direct leak, воспроизведение YouTube, MTProto и звонки Telegram.

Равенство внешнего IP не считается утечкой: для NFQWS2 оно нормально.
Конфигурация пула не доказывает, какой её узел реально обслужил запрос.
Candidate canary по-прежнему требует дальнейшей унификации с независимым
подтверждением пути; эта работа не объявляет его полноценным route passport.

## Проверки и следующий gate

Fixtures покрывают смену boot ID, повторное использование PID, изменённый
конфиг/argv, чужой inode, конфликт порта, чужое пространство сети, DIRECT,
локальный relay, routing rules, selector/urltest, цепочки, отсутствие записи,
сохранение фактов HTTP при отзыве proof и отзыв старого успеха автопилота.
Отмена/timeout тестируются на каждой фазе SOCKS-handshake.

Локально прошли полный `go test ./...`, `go vet ./...`, проверка синтаксиса
JavaScript и исполняемые проверки подписей UI. Собраны Linux ARM64, MIPS и
MIPSel; Linux-only тестовые бинарники ARM64 также скомпилированы. Race detector
в этой Windows-среде с `CGO_ENABLED=0` не запускался; он остаётся в общем CI.

Linux-only тесты работают с реальным `/proc`, временным loopback-портом и
отдельным тестовым дочерним процессом. Они не запускают реальные обходы и не
меняют маршруты. Их выполнение в Linux CI и на оборудовании — отдельный gate;
кросс-компиляция сама по себе не является выполнением этих тестов.

Далее: выполнить Linux-проверки, затем аппаратный canary без замены рабочего
baseline; подтвердить конкретный узел пула и удалённый путь независимым
контролем. Публиковать только после общей стабильной проверки.

## Основания для трактовки конфигурации

Семантика выбора выхода сверена с официальной документацией:
[Sing-box Route](https://sing-box.sagernet.org/configuration/route/),
[Sing-box Dial Fields](https://sing-box.sagernet.org/configuration/shared/dial/),
[Xray Routing](https://xtls.github.io/en/config/routing.html).
Поддержка ограничена указанным подмножеством; неизвестные схемы не угадываются.
