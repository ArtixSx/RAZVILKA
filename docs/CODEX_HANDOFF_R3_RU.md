# RAZVILKA — точное продолжение для Codex после R3

Дата: 2026-09-08. Начинать с фактически поставленных исходников, а не с повторного исполнения старой очереди R18.

## 0. Где находится работа и что считать базой

`RAZVILKA_R3_SOURCE.zip` содержит целый проект **A1 + UI2 + R3** с VERSION `0.18.2-dev`. Патч `RAZVILKA_R3_FROM_UI2.patch` содержит только разницу R3 относительно приложенного UI2. Он не применяется напрямую к чистому rc.2 и не включает заново A1.

Опубликованный rc.2 основан на `c6859b07316d07de3dc1fa243484a96078c5782b`. Проверенный main на момент работы совпадал с ним. Локальный R3 не публиковался. Если использовать текущий удалённый main, сначала сделать delta-аудит и сохранить все новые пользовательские изменения. Не перезаписывать repository архивом поверх неизвестного dirty tree.

R3 изменяет интерфейс/его tests и исправляет клиентские ошибки состояния и авторизации. **Новый Go-runtime в этом этапе не реализован.** Наличие в архиве A1 не означает, что он прошёл компиляцию и HIL. Полный тест остановился до компиляции: нужен Go >=1.26.0, pinned toolchain 1.26.5; доступен 1.23.2. Проверки standalone-пакетов и embedded-assets не являются обходом этого gate.

Главный сценарий не изменился: «установил → прошёл мастер → добавляет/убирает любые сервисы». Вкладки движков остаются для контроля и тонкой настройки; они не должны требовать ежедневного обслуживания человеком.

## 1. Уже сделано — не начинать заново

Сохранять NodeStore, точный checker, source fetcher, транзакционный manager, backup/restore, ручной updater, управление устройствами и отдельные source/device/node/service сущности.

В R3 есть семь основных разделов, двадцать сохранённых представлений, шесть editor-context, AI-аккордеон, поиск/фильтры/list/cards, инспектор конкретного сервиса, выбранность queued-намерения, общий TTL-aware health и строгий auth epoch на retry. Сохранены 695 наследуемых DOM ID. Не возвращать двадцать пунктов в основной sidebar и второй дублирующий список маршрутов на главную.

Политика на сервис и проверка на сервис остаются индивидуальными. AI — категория UI, не новый общий route. Не связывать здоровье Claude с ChatGPT и не заставлять все AI использовать один VLESS.

## 2. Неподлежащие нарушению ограничения

- Один реальный владелец процесса/интерфейса/NFQUEUE/mark/table/rule; чужое состояние только наблюдать до явного принятия под управление.
- Все сетевые изменения проходят существующий snapshot/stage/validate/canary/activate/health/commit/rollback с повторным CAS/consent/network/proof gate.
- Ручное действие и удаление сервиса отзывают устаревшее автоматическое право на commit.
- Никакого `opkg upgrade` всех пакетов, shell из remote-конфига, отключения TLS, записи чужих каталогов или второго z2k runtime.
- Внешняя недоступность не оправдывает ложный PASS, бессрочное продление proof, обход trust или расширение scope до всего LAN.
- Секреты только в существующем приватном хранилище. Не выводить полный URI/UUID/token в обычном DTO/DOM/журнале/support bundle. Только существующее явное reveal/export.
- Артефакт для роутера не публиковать как stable до проверок точного SHA/бинарника. Наличие UI/compile не подтверждает UDP, IPv6 или пользователя на LAN.
- Прежний рабочий NFQWS2/YouTube и посторонние маршруты защищены. Нельзя одновременно менять NFQWS2, DNS и WAN ради одного эксперимента.

## 3. Первый PR: BUILD-A1-R3 — полная компиляция и интеграция

Это ближайший gate, не ещё один UI rewrite.

На отдельном Linux-стенде установить требуемый Go 1.26.5, C compiler для race и Node. Не снижать `go.mod`, версии зависимостей и production-компилятор ради зелёного теста. Читать AGENTS.md, если он появился в рабочем репозитории.

```sh

node --version
git status --short
node scripts/build-interface.mjs --check
for f in scripts/test-*.mjs; do node "$f" || exit 1; done
go test ./...
go test -race ./...

sh scripts/check.sh
```

Последний скрипт также выполняет сборку и тесты Entware; запускать на изолированном стенде, не на действующем роутере. Любые недостающие системные инструменты документировать, не маскировать PASS.

Особенно проверить `internal/app/autonomy_api_test.go`, `internal/config/autonomy_route_test.go`, `internal/app/autonomy_worker.go`, `autonomy_store.go`, `autonomy_services.go`, `autonomy_maintenance.go`, `reconciler.go`. Runtime A1 не проходил полную проверку типов ранее. Исправлять конкретные ошибки небольшим diff; не считать их заранее известными только по этому документу.

**Приёмка:** весь проект test/race/vet, четыре target-сборки; локальный запуск нового (не rc.2) amd64 с отдельными путями, loopback и Safe Mode; GET/load/login/CAS/custom-service/API 404/409/401; реальный HTTP-сервер отдаёт R3 и корректные CSP/cache headers. Browser fixtures — дополнение, не замена этого теста. Старые файлы/конфигурации читаются и не импортируют новые разрешения из backup автоматически.

## 4. PR AUTO-INTEGRATION — завершить существующий цикл A1

Точки: `internal/app/autonomy_worker.go`, `autonomy_services.go`, `autonomy_store.go`, `autonomy_api.go`, `internal/autonomy/decision.go`, `internal/config/autonomy_route.go`.

В A1 уже присутствуют обход готовых способов, ограниченная выборка узлов, резерв, budget, удаление в очереди и последующее применение через Dataplane. Не добавлять независимый orchestrator. Но эти пути ещё не прошли интеграцию/HIL.

Обязательные сценарии:

1. Новый **произвольный** custom-сервис после мастера наследует разрешённые defaults. Принятое намерение видно pending, следующий round выполняет реальную проверку и применение. Никаких проверок на имена chatgpt/telegram.
2. Неизвестный/неподдержанный сценарий не получает service-ready по одному `GET /`. Веб, API, видео, UDP и семейства адресов разделены.
3. Failed current path подтверждается отдельно от `INCONCLUSIVE` и общей недоступности WAN/DNS/probe-provider.
4. Один текущий путь + целевой резерв. Рабочий не вытесняется меньшей задержкой. `ReserveTarget` в A1 включает основной узел; не добавлять лишний процесс по неверной трактовке числа.
5. Manual/pin/disable/delete/cancel/restore между probe и commit запрещают устаревшую mutation. Отмена сохраняет lease до фактического завершения cleanup.
6. A1 sidecar receipt и config commit имеют отдельные точки записи. Восстановить/согласовать исход, если процесс умер между ними. Не «разрешать всё», убрав requires-review.
7. Удаление A не останавливает shared engine/node для B. Нельзя пропускать deleting-задачу из-за `Enabled=false`; проверить все комбинации в реальном round.
8. Текущая `Definition`/`DraftFingerprint` защита не должна требовать нового согласия после собственного безопасного изменения при каждом round. Но расширение scope/trust/настоящая внешняя правка должны требовать пересмотра.
9. События повторяются/объединяются, budget и pin переживают restart; доказательства здоровья не восстанавливаются как свежие из журнала.

**Приёмка:** два своих контролируемых узла, два сервиса с разными политиками, чужой контрольный клиент. Полный automated A→B, rollback A при ошибке B, поиск разрешённого нового C при исчерпании резерва. Браузер закрыт, никаких ручных повторных Apply.

В `autonomyRound` maintenance вызывается после захвата `Operations.Exclusive` и до обработки сервиса. Проверка компонентов имеет timeout 90 секунд. Проверить приоритет восстановления/отмены и длительность блокировки на медленном источнике; не объявлять это уже измеренной аварией. Разделять подготовку и сетевую активацию можно только при сохранении общего admission/ownership контракта.

## 5. PR ACTIVE-HEALTH / RESOURCE — не запускать тяжёлый checker постоянно

Точки: `autonomy_worker.go` сейчас вызывает `checkAndRecordNode` для активного узла, `internal/dataplane/nodecheck.go`, `internal/probecheck`, `internal/systemprobe`, `internal/evidence`, общий operationgate/reconciler.

Отделить лёгкое наблюдение действующего runtime от глубокой проверки нового outbound. Не плодить Xray/Sing-box по одному процессу на сервис и не дублировать одной подписке расписание на каждого участника.

Разделить transport evidence и сервисный proof. Разрешить повторное использование transport-сигнала в корректном контексте, но не успеха приложения другого сервиса. Проверять фактический LAN-путь и наблюдаемые собственные правила/counters, когда поддержано; loopback-canary одного роутера не выдавать за все устройства.

Глобальный resource governor: память/процессы/FD/CPU/tmp/disk/write budget, cancellation, priority и overload. При overload откладывать discovery, не уничтожать рабочий LKG. Ожидание ресурса не считать сетевым FAIL.

**Приёмка:** sequential/shortlist на слабом MIPSel, десятки сервисов не создают десятки cores, пустой traffic не считается отказом, глобальный WAN fault не запускает массовые перезапуски, рост RSS/FD/goroutines ограничен в soak.

## 6. PR FEED-LIFECYCLE — регулярное пополнение без потери активного пути

Точки: `internal/providerfeed`, `internal/nodestore` (originFresh/routeCheckUsable), `internal/publicfetch`, `internal/app/reconciler.go`.

В rc.2/A1 уже существуют лимиты и периодические загрузки. Не убирать ограничения ради огромного файла. Нужны capped streaming/disk-backed snapshot, ротация выборки по всему каталогу, стабильная идентичность полного effective outbound и сохранение разных ключей на одном host:port.

Приоритет интервала: явная настройка → поддержанные метаданные подписки → проверенный пресет → bounded default. Cron издателя является подсказкой публикации, а не точной гарантией: `*/9` и `*/17` не равны непрерывным периодам. Таймзона/пограничные минуты/Retry-After/backoff/jitter, задержка публикации и ETag304 требуют тестов. Remote metadata не может назначить частоту без минимума/максимума. Не исполнять код сайта/сборщика.

Три раздельных слоя: fetched snapshot, разрешённый резерв, committed material. Source 404/503/пустая/битая/резко усохшая выдача сохраняют LKG. Временное отсутствие origin, явный revoke, истечение полномочий и запрет доверия различаются. Старый active material сохранять только в пределах согласованной grace/failure политики, не обновлять ReceivedAt/ExpiresAt ради обхода защиты. `304` не продлевает health.

Требуется надёжный bootstrap/download path вне нового ещё неработающего туннеля. Одно зеркало не считать независимым оператором; резерв по разным источникам/IP/ASN — признаки разнообразия, не гарантия.

**Приёмка:** источник на 3–5MiB с пределами, compressed bomb, одно malformed/unsupported URI, redirects/private IP/rebinding/TLS mismatch, источник пропал при рабочем A, отзыв A, пустой catalog, восстановление C; активный сервис не рвётся просто от sync.

## 7. PR UPDATE-TRUST / AUTO-INSTALL — ночная установка ещё НЕ сделана

A1 `autonomy_maintenance.go` выполняет только `check/prepare` и записывает slot до попытки. Он не является готовым unattended-installer. В `internal/autonomy/policy.go` `install` намеренно запрещён. Нельзя просто разрешить строку install и вызвать opkg.

Переиспользовать реальные `internal/app/self_update.go`, `internal/updatecheck/updater.go`, `internal/components`, штатный helper/installer/rollback (точные функции сверить в текущем дереве). Отдельные небольшие PR:

**U-TRUST:** проверяемый подписанный manifest с root trust, допустимые версии, architecture/ABI, dependencies, schemas, hashes, expiry, channel и отзывом. Сохранить attestation/SBOM при наличии; checksum не равен подписи. Trust bootstrap должен существовать до первого фонового executable fetch.

**U-STAGE:** immutable candidate artifacts, место на диске, владельцы/симлинки, отдельные candidate пути, полная конфигурация и совместимость native validator. Активный binary не заменяется на этапе скачивания.

**U-INSTALL:** окна приложения и движков независимы; local IANA/DST, перенос через полночь, пропущенное окно, clockjump, пользовательская активность, аварийный резерв. Обновлять компоненты последовательно. Не перезапускать все движки одновременно. Отсутствующие компоненты ставить только по заранее выданному install-on-demand согласию и capabilities.

**U-RECOVER:** комплект отката содержит binary/config/dependencies/schema, а не один файл. Внешний helper/supervisor возвращает LKG, даже если новая UI/основной процесс не стартовали. Неудачная версия в карантине; не ставить её повторно каждую ночь. Для credentials/remote enrollment отдельная reconciliation: удалённую регистрацию нельзя откатить простым file restore.

**Приёмка:** правильная/подменённая/просроченная подпись, потеря питания в каждой фазе, процесс не стартует, здоровье сервисов ухудшилось, несовместимая schema/dependency, мало RAM/диска, чужие права, reboot и откат без панели. Согласованное время не является автоматическим согласием на обновление всех сторонних приложений роутера.

## 8. Native NFQWS2, USQUE, WARP и DNS — сохранить отдельные gate

**NFQWS2:** `internal/dataplane/nfqws2.go`, `internal/strategylab`, compiler/lists/owner contracts. Полные typed recipes, версии Lua/assets, NFQueue lease, однопроцессное ownership, scoped test, WAN/NDM restoration, baseline YouTube, no-z2k-dependency. Имеющиеся editor-fields не доказывают завершённую нативную подсистему.

**USQUE/WARP:** `internal/cloudflareprovider`, dataplane/adapters, components. Собственная pinned сборка и совместимость; раздельные WG/MASQUE credentials; обязательный server pin аутентификации MASQUE, не механическое удаление `InsecureSkipVerify` при наличии корректного custom verifier. Process/listener/handshake/egress/service — разные состояния. Reconnect сначала, повторная регистрация только при credential-причине и бюджете. Сравнение native TUN с текущей связкой на одном железе; язык реализации не служит доказательством экономии памяти.

**DNS/SmartDNS:** `internal/dnscontrol`, compiler/dataplane/publicfetch. Resolver ≠ gateway. Нельзя отправлять весь AI-каталог через SmartDNS по одному веб-тесту. Динамические назначения по TTL/CNAME/семейству IP, bootstrap/control-plane исключения и ясные конфликты. При missing scope запрещён переход на вся LAN. Локальный DNSobserver — отдельное согласие и отсутствие внешнего журнала.

**Новые протоколы:** current exact-checker VLESS/HY2/TUIC/SS не подтверждает VMess/Trojan/XHTTP. Расширять parser→native config validation→isolated exactchecker→routebinding→HIL как целый путь. Unsupported никогда не превращается в TCP автоматически. UDP calls/stream/API отдельные безопасные probes; никакого платного API вызова с user secrets без согласия.

## 9. UI следующего этапа — не возвращать старый dashboard

R3 сохраняет старые редакторы намеренно. Следующий шаг не третий UI сверху, а пофункциональное извлечение крупного app.js и удаление ненужного compatibility-layer по тестам. Сначала api/state/service/browser, затем инженерные формы. Идентификаторы695 — временный regressionguard, не вечная архитектурная цель.

Существующие файлы:
- `interface-model.js`: чистая UI-модель, никаких сетевых прав.
- `interface.js`: page composition, inspector, safe API actions.
- `interface-shell.css`: общие токены и компоненты.
- `interface-compat.css`: нормализованный слой прежних CSS.
- `console-autonomy.js`: существующий A1 wizard/forms/auth epoch.
- `service-dashboard-ui.js`: общий display-proof; не создавать третий isHealthy.

**Batch AI/actions — ещё не реализованы.** Группировкаread-only плюс отдельные действия сейчас честнее небезопасного `Promise.all`. Для batch нужен серверный состав serviceIDs/revisions/scope, частичный результат каждого, явная отмена, сохранение pins/trust. Новые future-каталожные участники не получают согласие от старого «выбрать всё». Не объединять прикладные proof/active/LKG.

Следующие UI-проверки: Firefox/WebKit, экранный диктор, клавиатурный фокус и Tab внутри диалога, контраст WCAG 4.5 для обычного текста, масштаб 200–400%, reduced motion, длительно открытая панель, локальный HTTPS/CSP и загрузка после рестарта. Сейчас проверен Chromium; полная доступность во всех браузерах не заявляется.

## 10. Минимальный аппаратный выпускной протокол

Использовать тестовый роутер, не домашний baseline. Зафиксировать модель, прошивку, архитектуру, WAN, commit и hash бинарника, поддерживаемый сценарий. Внешние аккаунты и ключи — предоставленные владельцем тестовые; в публичный отчёт не включать.

1. Сохранить snapshot и проверить обычный интернет, панель и исключённого контрольного клиента.
2. Чистая установка, мастер, два произвольных сервиса и два контролируемых узла. Закрыть браузер.
3. Проверить реальные LAN-запросы: точный узел, DNS, семейство IP и counters. Исключённый клиент остаётся на прежнем пути.
4. Оборвать A и подтвердить B. Сломать B после активации и доказать rollback. Получить C из разрешённой подписки.
5. Проверить ошибку/пустой ответ источника, ETag, revoke и TTL, общий WAN/DNS fault и отсутствие массового переключения.
6. Reboot, поздний WAN, поток NDM-событий, потеря питания в каждой фазе: нет оставленных процессов, правил, интерфейсов. Ручное изменение во время probe отзывает устаревшее право.
7. Удалить сервис во время sync/probe/apply: общие объекты остальных сервисов остаются.
8. Ночное обновление с намеренно неудачным бинарником, зависимостью и схемой; восстановление без панели.
9. 24–72 часа: RSS, FD, goroutines, CPU, записи на диск, фоновый трафик, время восстановления и ложные переключения.
10. Отдельно MIPS/MIPSel, IPv6 и UDP в рамках заявленных функций. Кросс-компиляция не заменяет аппаратный результат.

Численные SLO определить по реальному базовому прогону. «Без единого обрыва при отказе любого узла» не обещать. Когда пригодных разрешённых путей нет, соблюдаются terminal policy и ограниченный повтор; показана точная причина.

```text
Не менять рабочий роутер, DNS/firewall/credentials и не публиковать stable
без отдельной аппаратной приёмки.
Сохрани R3: семь главных разделов, один сервисный список, AI только UI-category,
индивидуальные proof/routes, source trust, старые экспертные формы,
auth-epoch retry fence и queued-intent display. Никаких fake PASS или demo fetch
в production, второго checker/apply/NodeStore и обязательного z2k.
После первого зелёного gate отчитайся точными командами/exit codes/SHA;
следующий отдельный PR — AUTO-INTEGRATION, затем resource/feed lifecycle.
Обновления install только через signed compatible staged package+полныйrollback,
не простое разрешение режима install или opkg upgrade.
В финале каждого PR разделяй implemented / tests / build / HIL / release.
```

## 12. Критерий завершения

Обычный пользователь один раз дал понятные ограниченные разрешения, добавляет/убирает сервисы, больше не ищет ежедневные ключи и не редактирует движки. Система действительно делает это при закрытом браузере на проверенном роутере. Отказ источника/процесса/обновления не выдаётся за успех, не расширяет доверие и не ломает чужой интернет. R3 приближает UX к этому состоянию, но один интерфейс не закрывает эти системные критерии.
