# RAZVILKA v0.18.2-rc.5

Предварительный выпуск с исправлением пустых настроек и медленной загрузки
сервисов при большой подписке. Стабильный канал остаётся на `v0.18.0`.

## Исправления

- Список маршрутов читает хранилище узлов один раз за запрос вместо повторного
  чтения для каждого узла. На роутере с 344 узлами старый запрос сервисов
  не завершался за 90 секунд. Проверки актуальности, сети и работоспособности
  узлов сохраняются; ручная группа требует пригодности выбранного узла.
- Разделы панели показывают данные по мере получения. Медленный запрос больше
  не задерживает все настройки. Чтение ограничено по времени, ошибки получают
  повторную попытку, а ранее загруженные сведения сохраняются с отметкой.
- Отсутствие ответа больше не показывается как отсутствие установленного
  компонента или нулевой список сервисов. У редактора есть выход из ошибки
  загрузки и действие «Перечитать».
- Многострочные стратегии NFQWS2 читаются и редактируются целиком. Изменение
  параметров заменяет полное значение присваивания; неподдерживаемый синтаксис не
  переписывается через простой редактор.
- Для создания, смены и восстановления пароля убрана минимальная длина.
  Допускается любой непустой пароль до 256 байт UTF-8; пробелы сохраняются.
  Установленный пароль и настройки при обновлении сохраняются.

## Установка

В проверенном `scripts/bootstrap.sh`:

```sh
RAZVILKA_VERSION=v0.18.2-rc.5 sh bootstrap.sh
```

[Инструкция](https://github.com/ArtixSx/RAZVILKA#установка).
Панель использует LAN-адрес роутера и порт **8787**.

## Проверка выпуска

Точный commit `3cabc9df9811d9ba0e8032de2f7c083e3a48dfea` прошёл
[Release CI](https://github.com/ArtixSx/RAZVILKA/actions/runs/34808235192)
и [CI тега](https://github.com/ArtixSx/RAZVILKA/actions/runs/34808235262):
Go tests/race/vet, 30 наборов JavaScript-проверок, сборки Linux arm64, mipsle,
mips и amd64, а также изолированные проверки установщика.
Контрольные суммы официальных файлов и подтверждение происхождения сборки проверены.

Официальный ARM64-бинарник с SHA-256
`ebc2fec5831975763bd6591e326fb78973831d748f7aedac44bdd2e3b02152b6`
проверен на Netcraze. Установка и штатный перезапуск приложения сохранили
учётную запись и настройки; действующий runtime восстановлен и подтверждён.
В реальном браузере проверены вход, 16 сервисов и полные настройки NFQWS2:
6 файлов, 15 понятных полей, 16 строк `NFQWS_ARGS`. Исходный файл настроек
остался побайтно неизменным. Список сервисов загружен за 1,39 секунды вместо
прежнего тайм-аута 90 секунд. Все 25 статических файлов совпали с тегом.
Два свежих клиентских HTTPS-запроса Telegram вернули HTTP 200 через TUN,
с приростом RX/TX и без изменения правил.

[Точный отчёт и ограничения rc.5](https://github.com/ArtixSx/RAZVILKA/blob/main/docs/releases/0.18.2-rc.5-validation.md)
также доступны в `VALIDATION_RU.md` на странице этого выпуска.

Аппаратная проверка выполнена на одном ARM64-роутере. Сборки MIPS/MIPSle и
amd64 не заменяют проверку на соответствующем устройстве. Реальная
перезагрузка роутера, WAN reconnect, физический второй клиент, IPv6 HTTPS,
малый объём памяти, полный набор аварийных сценариев и 24–72 часа автономной
работы требуют отдельных результатов. Проверка формы NFQWS2 не означает
применения новой стратегии; результаты rc.4 сохраняются как история.

## Результат продолженной проверки

После успешной установки, перезапуска и проверки веб-доступа обнаружена потеря
собственной цепочки RAZVILKA в таблице `filter`: процессы, TUN и правила `nat`
сохранились, но новые клиентские соединения перестали проходить. Панель верно
показала отсутствие подтверждённого runtime. Автоматическое восстановление
такого случая в rc.5 отсутствует; исправление готовится в rc.6.
Первоначальные успешные проверки не означают, что этот сценарий устойчивости закрыт.
