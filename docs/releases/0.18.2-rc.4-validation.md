# Проверка v0.18.2-rc.4 — 14 сентября 2026 года

Проверен опубликованный commit `200363e771e53428d99c3c6bcdf591afc9debcf3` на Netcraze 6614,
aarch64, Entware. [CI исходников](https://github.com/ArtixSx/RAZVILKA/actions/runs/34786226722) и [Release CI](https://github.com/ArtixSx/RAZVILKA/actions/runs/34786226725)
завершились успешно. Проверены четыре Linux-бинарника, SHA256SUMS и четыре
payload внутри Entware-архива; его происхождение подтверждено
`gh attestation verify`.

## Аппаратный результат

- Обновление через SSH и отдельный перезапуск приложения завершились.
  Применённый маршрут к сохранённому узлу восстановлен; пароль, настройки
  сервиса и область устройств сохранились. Версия, commit и SHA256 совпали.
- Обычные свежие HTTPS-соединения выбранного ПК к `telegram.org` и
  `web.telegram.org` прошли через TUN: проверены точные соединения,
  RTCACHE/интерфейсы и прирост RX/TX (37131/3208 байт).
  HTTP 200 получен без локального прокси.
- Отдельный новый TCP-поток получил тестовую пакетную марку `0xffffaaa`.
  Зафиксировано срабатывание точного MARK-правила и фактический путь этого
  соединения через TUN, HTTPS 200 и прирост RX/TX
  (29320/1860 байт).
  Временное правило удалено. Значение conntrack mark не использовалось
  как замена доказательства пакетной марки.
- Для другого адреса LAN проверен только запрос маршрута: он указывал
  обычный путь. Физический второй клиент не участвовал.
- Наблюдались один процесс панели и один её сокет на 8787; панели на
  8788/8789 не обнаружены. Присутствовали процессы NFQWS2 и USQUE.
- Основной HTML и 25 ресурсов интерфейса совпали с исходниками
  выпуска; кэш и CSP проверены. DNS-сравнение получило A/AAAA для
  `chatgpt.com` через Cloudflare DoH без применения DNS и без заявления
  о проверенном доступе к самому ChatGPT.
- Приватный финальный снимок проверен по SHA256 и содержимому квитанции.
  Удалены только два предусмотренных cleanup-планом объекта — временный
  каталог обновления и прежняя копия отката. Их отсутствие подтверждено;
  сохранена одна текущая копия отката, защищённые файлы и сторонние процессы.

## Ограничения

Аппаратная проверка относится только к этому Netcraze aarch64. MIPS/MIPSel
и amd64 собраны; аппаратная матрица этим не закрыта. Не выполнялись
перезагрузка самого роутера, физический второй клиент, WAN reconnect,
IPv6 HTTPS, голосовые звонки и 24–72 часа непрерывной работы.

Проверена миграция применённого маршрута сохранённого узла. Старые маршруты
других адаптеров вне этого сценария могут требовать просмотра и явного
применения новой схемы; при отказе возможен штатный откат к прежнему снимку.
Все прежние конфигурации автоматически мигрировавшими не объявляются.
Полный цикл обновления кнопкой панели на железе отдельно не подтверждён.

У rc.3 обычный TUN-путь работал, но контролируемая маркированная проверка
выявила конфликт приоритетов. rc.4 прошёл оба указанных выше сценария;
это не обещание совместимости с любой сторонней политикой или ACL.
DNS + обход + сервис и автоматический выбор пары остаются DC2–DC4.
Публичный отчёт не содержит профилей, учётных данных или приватных копий.
