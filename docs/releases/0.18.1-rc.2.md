# RAZVILKA 0.18.1-rc.2 — понятное управление, браузер подключений и проверки по таймеру

Предварительный выпуск для общего тестирования на Keenetic/Netcraze с Entware.
Он объединяет браузер VLESS, подписки, группы резервных подключений и новое
управление сервисами. Выпуск помечен **Pre-release** и не заменяет стабильную
[0.18.0](https://github.com/ArtixSx/RAZVILKA/releases/tag/v0.18.0).

## Что изменилось в интерфейсе

1. **Автопилот и ручная настройка.** Общий режим сохраняется на роутере;
   защитный Safe Mode управляется отдельно.
2. **Версия приложения.** Индикатор показывает установленную версию и
   результат проверки обновлений, открывает подготовку официального пакета.
3. **Включение и остановка.** Нижний переключатель управляет собственными
   маршрутами RAZVILKA, сохраняя параметры сервисов и устройств.
4. **Один вход в каталог.** На главной осталась одна основная кнопка перехода
   к сервисам.
5. **Поиск по сайту.** Список можно развернуть и найти сервис по введённому
   адресу сайта.
6. **Отдельные «Обходы».** Запущенные компоненты находятся в начале списка;
   дополнительные разделы навигации сворачиваются.
7. **Стартовая страница «Главная».** Названия разделов приведены к единому виду.
8. **Показатели с переходами.** Карточки показателей открывают связанные страницы.
9. **Понятные действия.** Основные кнопки получили короткие подписи,
   технические сведения вынесены в подробности.
10. **Версии обходов.** Рядом с названием видны установленная версия и
    подтверждённое доступное обновление.
11. **Компактные сервисы.** Раскрывающиеся карточки показывают выбранный и
    применённый маршрут, устройства, задержку и доступность. Добавлены ручная
    проверка, ограниченный подбор и сохраняемый таймер проверок на роутере.

Браузер подключений содержит поиск, фильтры, карточки стран и транспорта,
отдельные TCP- и сервисные проверки. Подписки можно получать из публичных
источников или по собственному HTTPS-адресу и обновлять по расписанию.
Таймер работает на роутере при закрытой странице браузера.

## Применение и автоматическая замена

Низкая TCP-задержка не подтверждает доступ к сервису. Перед применением
проверяются конкретное подключение, внешний выход и ответ сервиса с проверкой
TLS. Неоднозначный результат остаётся **INCONCLUSIVE**: рекомендация не выдаётся.

Автопилот использует сохранённые разрешения. Автоматическая замена ограничена
явно применённой резервной группой Sing-box, разрешёнными узлами и выбранными
устройствами. Обновление подписки не включает маршрут и не добавляет новые
узлы в разрешённый резерв автоматически. Ручной подбор предлагает результат;
применение требует отдельного действия.

Исправлены сохранение посторонних черновиков при применении маршрута сервиса,
проверка просмотренного плана перед записью, отзыв устаревших результатов
после изменения сети и восстановление собственного runtime. Определение
запущенного обхода больше не принимает краткую команду проверки версии за
работающий процесс.

Исправлен выбор бинарника на MIPS: неоднозначный `uname -m = mips` больше не
считается признаком big-endian. Установщик определяет BE/LE по ELF32 текущей
оболочки; если определить архитектуру нельзя, он отказывает до запуска
бинарника. Сохранён явный выбор через разрешённые значения `RAZVILKA_ARCH`.
Прошли 18 сценариев проверки определения архитектуры с подставными данными;
это не аппаратная приёмка MIPS.

Приватные подписки и нативное состояние WARP входят в зашифрованную резервную
копию. Создание WARP-аккаунта не считается подтверждением рабочего туннеля.
Установка и откат проверяют совместимость приватного формата до замены файла
приложения.

## Обновление приложения из панели

Кнопка версии позволяет подготовить и затем явно установить подходящий
**стабильный** официальный релиз. Проверяются архитектура, версия, идентичность
релиза, SHA256 и состав архива. Установка использует штатный установщик с
резервной копией, проверкой запуска и откатом. Проверка целостности не выдаётся
за проверку подписи или происхождения сборки.

Тестовый экземпляр с отдельными путями не обновляет production. Более старый
стабильный выпуск не заменяет новую тестовую сборку. Нестандартные владельцы,
права или символические ссылки в путях установки блокируют автообновление с
объяснением причины. Сам установщик основной версии через эту кнопку в
аппаратной приёмке rc.2 **не запускался**.

## Что проверено

Перед подготовкой выпуска локально прошли полный `go test` и Windows
`go test -race` — **47 пакетов**, `go vet` и **21 проверка интерфейса**.
Полный Linux Release CI для релизного тега является отдельным этапом проверки;
локальные результаты его не заменяют.

На итоговом ARM64-кандидате исходного кода этого выпуска проверены:

- сохранение общего режима и отказ запросу с устаревшей редакцией настроек;
- два запуска таймера с интервалом 60 секунд при закрытой странице браузера;
- ручная проверка и ограниченный подбор, без применения неоднозначного результата;
- восемь параллельных проверок состояния обходов без ложного статуса запуска;
- навигация, поиск сайтов, версии компонентов и окно обновления;
- отказ тестового экземпляра обновлять основную установку;
- три Linux-теста завершения временных процессов и отказа от записи через
  подменённый путь, без запуска production-установщика.

Свежая проверка сохранённого VLESS-узла дала **INCONCLUSIVE**. Применённые
маршруты оставались пустыми. Прежний HTTP 200 Telegram на отдельной сборке
ядра не считается аппаратным подтверждением этого выпуска.

## Ограничения тестового выпуска

- Переход между двумя реально рабочими узлами **A → B**, рабочий резерв WARP,
  перезагрузка роутера, WAN disconnect и непрерывная приёмка **24–72 часа**
  не подтверждены для rc.2.
- MIPS и MIPSel собираются, но аппаратного запуска на этих архитектурах нет.
- TCP- и веб-проверки не подтверждают звонки, UDP, MTProto или видеопоток.
  IPv6 HTTPS, малый объём памяти и аварийное отключение питания требуют
  отдельной аппаратной проверки.
- Публичные узлы могут перестать работать в любой момент. Страна в имени —
  метка источника, а не измеренное местоположение выхода.
- Если после обновления текущая сеть требует новой проверки маршрута,
  установщик может отказать и выполнить откат; готовность не предполагается
  по одному факту запуска процесса.

## Файлы и установка rc.2

| Архитектура | Бинарный файл | Аппаратная приёмка |
|---|---|---|
| aarch64 / arm64 | `razvilka-linux-arm64` | Проверки управления на одном Netcraze; границы указаны выше |
| mips | `razvilka-linux-mips` | Softfloat; аппаратная приёмка открыта |
| mipsel / mipsle | `razvilka-linux-mipsle` | Softfloat; аппаратная приёмка открыта |
| amd64 | `razvilka-linux-amd64` | Совместимые Entware/Linux-системы; не вариант для Keenetic |

Архивы `RAZVILKA-0.18.1-rc.2-entware.tar.gz` и
`RAZVILKA-0.18.1-rc.2-entware.zip` содержат установщик, инструкции и все четыре
архитектуры. В выпуск входят контрольные суммы архивов и `SHA256SUMS`
для бинарных файлов (`dist/SHA256SUMS` внутри архива); GitHub Actions формирует
provenance сборки.

Скачайте архив именно этого предварительного выпуска и распакуйте его.
В его каталоге сначала выполните:

```sh
sh scripts/upgrade-entware.sh --dry-run
```

После успешной проверки:

```sh
sh scripts/upgrade-entware.sh --apply
```

Сохраните напечатанный путь резервной копии. Обычная команда bootstrap из
README устанавливает latest stable, поэтому не используется для выбора rc.2.
Для старого бинарника с несовместимым приватным форматом произвольный downgrade
может быть отклонён; используйте штатный откат к сохранённому снимку.

При сообщении об ошибке укажите архитектуру, прошивку, версию приложения,
ожидаемое действие и полученный результат. Ключи подключений, пароли и приватные
резервные копии в публичный отчёт не включайте.
