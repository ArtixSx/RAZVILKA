# USQUE: отдельная проверка DNS-кандидата

Дата: 4 сентября 2026 года. Локальная разработка, ещё не стабильный релиз.

## Возможность

В USQUE Doctor появился раскрываемый блок «Проверить другой DNS без применения».
Пользователь выбирает разрешённый профиль и получает результаты запросов A/AAAA
для имени API регистрации Cloudflare. Рабочий DNS, привязки сервисов,
черновики и сохранённые результаты обычного DNS-теста не меняются.

Запрос ограничен 30 секундами, четырьмя одновременными endpoint и проверкой
соответствия ответа вопросу/CNAME-цепочке. Частные адреса, повреждённые ответы,
FlashStart и trusted-local профили не допускаются. Отмена не превращается в
успех. В отчёт не попадают точные IP из ответа. Повторное нажатие кнопки во время
проверки не запускает второй запрос; после ошибки управление доступно снова.

Один успешный транспорт означает только возможность разрешить имя. Неудачи
других транспортов остаются видны. Отсутствие ответа одного семейства не
выдаётся за подтверждение dual-stack.

## Проверки

- Полный `go test ./...`, `go vet ./...`, форматирование Go и проверка JavaScript
  прошли локально на Windows.
- Поведенческий тест интерфейса проверяет двойное нажатие, восстановление кнопок
  и экранирование полученных строк.
- Keenetic ARM64: изолированный тестовый бинарник проверил реальные ответы
  `quad9-unfiltered` для `api.cloudflareclient.com`:

| Endpoint | Результат DNS | Семейства ответов |
|---|---|---|
| UDP, первый | Успех | IPv4 + IPv6 |
| TCP, первый | Успех | Только IPv6 |
| UDP, второй | Успех | IPv4 + IPv6 |
| TCP, второй | Успех | Только IPv4 |
| DoT | Успех | Только IPv6 |
| DoH | Неуспех: неожиданный HTTP-ответ | Не подтверждены |

Это один сетевой замер, а не гарантия доступности провайдера. Причина отказа
DoH и отсутствующих семейств в этом прогоне не установлена.

На том же ARM64 прошли проверки повреждённых ответов, отмены запроса,
неизменности состояния и запрета непубличных адресов. Тестовый файл удалён.
После проверки RAZVILKA по-прежнему сообщала версию `0.18.0`, healthy и PID
`28953`, совпадающий с состоянием до теста. Службы не перезапускались, новая
сессия Cloudflare не создавалась.

SHA-256 тестового бинарника:
`49a0bb16a1d6913b22c000ecaa3f566e4809b2bea68bc9bece612a667c7e84db`.

## Следующий этап

Отдельный HTTPS/TLS-canary должен обращаться именно к адресам выбранного
DNS-кандидата, сохранять проверку имени сертификата, запрещать переключение
на системный DNS и не регистрировать аккаунт. Затем нужны проверка новой
сессии и реальный сервисный тест. Ни DNS-ответ, ни `warp=on` отдельно не
подтверждают работу Telegram.

Изменение `/etc/resolv.conf`, NFQWS2-кандидат, автоматическая регистрация и
применение маршрутов не входят в этот блок. Linux/race и MIPS/MIPSel остаются
обязательными отдельными проверками перед выпуском стабильной версии.
