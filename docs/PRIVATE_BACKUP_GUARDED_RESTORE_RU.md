# Приватный архив: защищённый откат импорта

Локальный блок 31 августа 2026 года, подготовка общей транзакции PR-1.1.
Это исправление существующего импорта черновиков, **не** завершение общего
восстановления router+Cloudflare и не новая опубликованная версия.

## Что исправлено

Раньше при ошибке импорта возвращались заранее прочитанные снимки каталогов,
маршрутов и устройств целиком. Между чтением снимка и откатом пользователь
или другая операция могли изменить настройки. Такой откат мог затереть правку.
Кроме того, ошибки возврата уже записанных файлов обходов игнорировались.

Теперь каждый из первых трёх шагов захватывает состояние до/после своей записи
под блокировкой соответствующего хранилища и возвращает защищённую отмену:

1. Пользовательский каталог сервисов.
2. Метаданные устройств, если хранилище доступно.
3. Черновик маршрутов сервисов.
4. Файлы черновиков обходов — последним шагом, с собственным откатом пакета.

При ошибке отменяются только завершённые шаги, в обратном порядке. Если текущее
состояние уже отличается от записанного импортом, отмена этого шага отказывается
перезаписывать его. Остальные отмены всё равно выполняются. Изменение маршрута,
применение настроек, переключение Safe Mode, правка каталога или новая информация
об устройстве не должны теряться из-за старого снимка этой операции.

Успешная отмена повторно ничего не записывает. Если запись отмены не удалась,
состояние в памяти соответствует состоянию после импорта; попытка отмены остаётся
повторяемой внутри того же процесса. Автоматических повторов импорта нет.
Снимки каталога отдельно копируют вложенные ожидания проверок: изменение
переданных или полученных списков не меняет сохранённый снимок через общие ссылки.

Архив с устройствами отклоняется до записи, если их хранилище недоступно.
Раньше этот раздел мог быть молча пропущен. Архив с `ProviderSnapshots`
по-прежнему отклоняется: отдельный Cloudflare archive API остаётся независимым.

## Понятный результат ошибки

Ошибки этапа записи/отката возвращаются без исходных приватных данных и путей:

| Код API | Значение |
|---|---|
| `PRIVATE_BACKUP_IMPORT_ROLLED_BACK` | Импорт не завершён; изменения этой операции отменены |
| `PRIVATE_BACKUP_RECOVERY_REQUIRED` | Импорт не завершён; часть отмен не удалась или обнаружена более новая правка |

`phase` — фиксированное имя этапа, не текст из архива. `live_applied=false`
относится к этой операции импорта, а не гарантирует отсутствие других
параллельных действий. Рабочие маршруты импорт сам не применяет.

После ошибки панель очищает пароль и подготовленный архив, отключает повторное
подтверждение и предлагает проверить черновики. Потеря связи не объявляется
успешным откатом. Если сервер подтвердил импорт, но обновление панели не удалось,
UI сообщает именно об этом, а не о неудачном импорте.

Отмена запроса проверяется перед каждым этапом. Уже начатая файловая запись
завершается; отмена до следующего этапа запускает компенсацию. После успешного
последнего этапа позднее отключение клиента не отменяет завершённый импорт:
пользователь должен обновить панель, чтобы узнать результат.

## Проверки

- Отказ каждого шага: порядок компенсаций, отсутствие следующих записей.
- Отказ самой отмены: оставшиеся компенсации выполняются, результат неполный.
- Каталог/маршруты/устройства: успешный возврат, повтор отмены, ошибка записи,
  более новая правка; отдельно сохранение discovery-метаданных устройств.
- Файлы: отказ создания каталога/записи, возврата старого файла или удаления
  нового; ошибка отката больше не скрывается.
- HTTP-импорт настоящего зашифрованного тестового архива: искусственный отказ
  staging, возврат сохранённых настроек, `no-store`, отсутствие приватного пути
  в ответе. Тесты используют временные каталоги, не роутер.
- UI: успешный/неполный откат, потеря связи, ошибка обновления после успеха,
  успешный импорт и отмена; старый preview нельзя отправить повторно.
- Полный `go test ./... -count=1 -timeout=90s`, `go vet ./...`, синтаксис `app.js`
  и пять JS-наборов прошли. Целевые regression-тесты прошли пять повторов.
- Все Go-пакеты и тестовые бинарники App/config/customservices/devices/engineconfig
  собраны для Linux arm64/mips/mipsle; локально эти бинарники не выполнялись.

## Ограничения и продолжение

Это компенсация **внутри работающего процесса**, а не глобальная атомарная
транзакция. Проверки защищают изменения через те же экземпляры менеджеров;
они не являются межпроцессной блокировкой и не обнаруживают произвольное внешнее
редактирование файлов. Между этапами может быть видно промежуточное состояние.
После сбоя процесса нет журнала, который восстановил бы весь импорт при старте.
Правки до начала конкретного шага не защищены устаревшим preview: контракт
повторной проверки общего плана ещё предстоит доработать.

В файловом staging нет отмены успешно завершённого пакета для последующего
этапа. Поэтому добавлять после него сохранение аккаунтов пока нельзя.
Общий экспорт/импорт ещё не объединяет Provider state, не восстанавливает
`EngineOrder` и не меняет пароли панели. Публичный импорт профиля в этом блоке
не переведён на новый порядок компенсаций.

Следующее: согласовать владение всеми изменяемыми хранилищами, durable-журнал
и startup recovery до открытия изменяющих API, затем подключить общий архив
router+provider с проверками сбоев в каждой точке фиксации. Не снимать текущий
запрет на `ProviderSnapshots` раньше этих условий.

Linux/race, Entware shell regression, браузерная визуальная проверка,
роутер и отключение питания в этом блоке не проверялись. GitHub и рабочие
настройки сети не менялись.
