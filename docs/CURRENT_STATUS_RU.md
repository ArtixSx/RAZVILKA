## Последняя проверка

- Ошибка восстановления устранена на настоящем роутере. Проверка процессов
  ошибочно требовала завершающий NUL в `/proc/PID/cmdline`; системный nginx
  не имел такого байта. Исправлен разбор аргументов без потери последнего
  байта и без исключений для конкретного процесса. Ограничения размера,
  проверки исполняемого файла, ядра и управляемых процессов сохранены.
- Четыре пути установленного NFQWS2 имели владельца UID/GID 1001:1001.
  После резервной копии владелец исправлен на root; содержимое файлов и
  права доступа не менялись. Проверка владения в коде не ослаблена.
- Офлайн-завершение старой операции после настоящей перезагрузки прошло
  успешно за 70,19 с. История и доказательства сохранены, приватные метаданные
  прежнего процесса перемещены штатным механизмом. Это подтверждение его
  отсутствия после перезагрузки, а не успешный откат старой операции.
- Исправлен следующий запуск: завершённое восстановление распознаётся по
  связанным архиву, журналу публикации, контрольным суммам и свидетельству
  проверки. Старый committed plan больше не запускается автоматически.
  Повреждённые или неполные доказательства сохраняют блокировку.
- Независимое ревью исправления старта не выявило блокирующих замечаний.
  Копия настоящего успешно закрытого журнала проверена в отдельном Linux
  chroot: два запуска Recover и Refresh не меняют историю и не вызывают
  команды управления сетью. Это тест метаданных, не аппаратная проверка.
- На роутере rc.31 прошла 12 проверок настроек и совместимости состояний.
  Панель запустилась, блокировка восстановления снята штатно, без ручной
  правки config или журналов. Настройки и семь выбранных сервисов сохранены.
- Старый VLESS для Telegram не подтвердил выход. Проверены восемь резервных
  узлов из существующего каталога: три подтвердили выход и доступ к Telegram,
  пять дали неопределённый результат. Один прошедший узел применён обычным
  API с проверкой плана и прежним охватом. Задание завершилось успешно;
  runtime — committed, live_active=true, Safe Mode выключен.
- С домашнего ПК через шлюз 192.168.1.1 получен HTTPS 200 для telegram.org,
  web.telegram.org и t.me; одновременно росли счётчики туннеля rz-sing.
  Проверка повторена после перезапуска панели. Это проверка веб-доступа
  Telegram, не отправки сообщений, звонков или часового теста клиента.
- Штатный API выключения/включения прошёл полный цикл: Stop за 21,48 с,
  Resume за 50,25 с. Отдельно проверен перезапуск процесса панели: остановка
  за 1,17 с, успешный запуск за 14,52 с. После старта автоматическое
  восстановление повторно проверило маршруты и вернуло live_active=true,
  node_recovery=recovered. Сторонний интерфейс nwg0 сохранён.
- Визуальная проверка новой сборки через браузерный инструмент не выполнена:
  доступ к вкладке был отклонён его политикой. Результаты выше получены
  через реальные API, SSH и HTTPS-запросы с ПК.

Полный Linux610 `scripts/check.sh` на исходниках `99dd3387` завершился с RC 0:
Go 1.26.5, обычные и race-тесты всех пакетов, vet, UI, shell, AArch64/AMD64
и установочный стенд. Дополнительно прошли целевые проверки восстановления,
NFQWS2, сетевой идентичности и воспроизведение исходного журнала роутера.
Отдельный replay611 успешно проверил настоящий журнал после восстановления;
добавление этого теста не меняет установленный код приложения. Установочный
стенд не заменяет чистую установку опубликованного пакета на настоящий роутер
и отдельную проверку будущего обновления 0.20.0.

До релиза остаются сквозная приёмка списков/DNS/исключений, независимость
сервисов, автоматическая замена VLESS со скачиванием нового резерва,
аппаратная приёмка WG/AWG/WARP, будущие обновления и часовой тест Telegram.
Native596 с управляемым NFQWS2 остаётся неуспешным: настоящее уведомление об
изменении основного маршрута прервало Apply, завершение отката не подтвердилось.
Обычный успешный Apply не заменяет эту отдельную проверку. Повторять её нужно
со свежим наблюдением сети, сохраняя проверки сетевой идентичности.
MIPS/MIPSel и публикация следуют после завершения функциональной приёмки.

По уточнению владельца от 11.10.2026 **0.20.0 — новая база для чистой
установки**. Обновление с 0.19.3 и более старых выпусков не требуется и не
блокирует выпуск. Проверяем обновления с 0.20.0 на более высокие версии:
вручную и автоматически по расписанию, с сохранением настроек, проверкой
нового запуска и возвратом при ошибке. Незавершённые старые журналы не
считаются успешно перенесёнными; старые данные перед очисткой сохраняются
отдельно. Исторические отчёты о попытках миграции оставлены как результаты
проверок, а не как действующее требование.

Владелец уточнил охват: **обход только по активному списку** сайтов, сервисов
и поддержанных IP-правил. Остальной интернет использует обычную политику роутера.
Исключения устройств, ручные исключения ресурсов и принятый российский список
имеют приоритет над положительными назначениями. Пустой список не перехватывает
трафик. [Полный контракт](delivery-2026-10-03/LIST_MODE_CORRECTION_RU.md).

Сверка кода выявила прежние предположения об общем маршруте и недостаточный
приоритет исключений. Исправления распределены между CORE, DEFAULT, NET, NFQWS,
VLESS, OPS и UI с сохранением ранее реализованных движков, очереди, журналов,
проверок доступа и отката. Новые отрицательные сценарии пока не объявлены
пройденными: [критерии](delivery-2026-10-03/LIST_MODE_ACCEPTANCE.json).

Актуальная приёмка этапов находится в
[TASKS.json](delivery-2026-10-03/TASKS.json), точные результаты и ограничения —
в [VALIDATION_RU.md](delivery-2026-10-03/VALIDATION_RU.md). Полный план,
сквозная работа списков и исключений и часовая проверка Telegram через VLESS

После публикации выполняются очистка старого проекта на флешке роутера,
чистая установка опубликованного 0.20.0 и проверка его работы. Entware и
посторонние файлы не входят в очистку проекта.

## История исходной интеграции

Работа ведётся в отдельной ветке `review/delivery-2026-10-03`.
Сохранённая копия `current` не перезаписана. До импорта сделан отдельный коммит
`cc63c03` с двенадцатью файлами локальных исправлений проверки подключений.

Контрольные суммы всех 1134 файлов входящего проекта сверены с manifest.
Перенесён единый diff поставки, без повторного применения H00/IM.
Конфликт в `internal/dataplane/nodecheck.go` разрешён объединением выбора
успешного IP с локальной изоляцией параллельных проверок. Пригодность узла
по-прежнему требует подтверждения пути и сервиса.

`VERSION=0.19.3` и production `go.mod` сохранены. Это невыпущенная рабочая
копия. Полные Linux-прогоны `64a2d46`, `5c24dac` и финальный `ba18bc9`
прошли. D00 завершён. Изменения UI, VLESS
и обновлений подготовили три ассистента в отдельных ветках.

На роутере удалены 92 старых временных элемента RAZVILKA после проверенной
резервной копии на ПК. Установленная версия и настройки сохранены. Бинарник
новой копии проверен на AArch64 командами версии и проверки входных файлов.
Туннели и новый сетевой исполнитель этой проверкой не подтверждены.
Публикации на GitHub и замены действующей установки не было.

Следующий checkpoint включает per-node Xray, изоляцию WireGuard, именованные
WG-профили и endpoint pins, persistent component journal и ограничение
операций при незавершённом обновлении. Native Linux-проверки Xray TLS/REALITY,
WG IPv4/IPv6 и сохранения чужих маршрутов прошли на `367ef14`.
Полный Linux gate `check-linux-06` этой базы также прошёл, RC 0, включая
обычные/race тесты, vet, UI, четыре cross-build и установочный цикл.
Matching recovery на уровне приложения, same-peer WG/LKG и полный LAN/DNS
executor остаются открытыми; этот checkpoint не предназначен для установки
как готовый релиз.

По новому поручению владельца разработка передаётся пяти чатам модели
`gpt-6.1-sol`: CORE, VLESS, NET, OPS и UI. Координатор принимает изменения,
проверяет код, выполняет общий Linux gate и управляет единственным
live-окном на VM/роутере. Задания и границы файлов:
[SOL_HANDOFF_RU.md](delivery-2026-10-03/SOL_HANDOFF_RU.md).
