# Текущий статус — кандидат 0.20.0

> Черновик до итоговой приёмки. Выпуск ещё не опубликован; окончательная
> готовность, полная аппаратная проверка и часовое наблюдение не заявлены.

**0.20.0 — чистая новая база.** Ставится начисто, без переноса настроек
0.19.x и старее. Обновления 0.20+ идут только из панели: с журналом,
снимком настроек и откатом при подтверждённом сбое. Неизвестный исход
требует проверки журнала.

## Возможности кандидата 0.20.0

**Основной режим — вся сеть.** Обход действует только для включённых
сервисов, всё остальное идёт обычным маршрутом роутера.

| Что | Как |
| --- | --- |
| Сервисы, заданные доменами (YouTube, Discord и др.) | NFQWS2: имя сайта проверяется в каждом соединении |
| Telegram | сервис «Telegram · через VPN или прокси» из каталога — только официальные IP-сети Telegram, через узел VLESS, WireGuard или WARP |
| Сайты без обхода | «Исключения → Сайты без обхода»: NFQWS2 не обрабатывает эти сайты, адреса и сервисы (домен — вместе с поддоменами). Если исключённый адрес или сервис попадает в маршрут через VPN или прокси, применение останавливается с объяснением. Домен из списка маршрут по IP не различает — для него исключите IP-адрес. Исключения действуют во всех профилях nfqws2: управляемый блок в конце nfqws2.conf ставит перед профилями владельца профили без обработки для исключённых имён и адресов (nfqws2 выбирает первый подходящий профиль и выбирает заново, когда имя сайта становится известно). Профили владельца и списки пакета не меняются; при остановке блок снимается |
| Устройства без обхода | для NFQWS2 — политика доступа Keenetic («Исключения → Настройки исключений NFQWS2»); для VPN и прокси — выбор устройств в карточке сервиса |
| Автопилот | проверяет сервисы, держит резерв узлов, возвращает рабочий путь; недоступный выбор объясняет, а не повторяет бесконечно |

**Защита от перехвата чужих сайтов.** Сервис, заданный доменами, нельзя
направить через VPN или прокси по IP: на одном IP работают посторонние сайты.
Такое применение останавливается с причиной `DOMAIN_FLOW_AUTHORITY_REQUIRED`.
Если исключённый адрес попадает в IP-сети сервиса, идущего через VPN или
прокси, применение останавливается с причиной `SITE_EXCLUSION_CONFLICT`.

**Экспериментально — режим «Домашняя сеть»** (обход только для выбранных
устройств): пока один сервис с IP-диапазонами и только Netcraze Ultra
(NC-1812) с прошивкой 5.01.C.6.0-1.

## Состояние приёмки

- Linux-прогон `scripts/check.sh` для ревизии `22a96a79` завершён успешно:
  Go-тесты, race, vet, интерфейс, shell и установочный стенд. Для этого прогона
  выбран ARM64; служебный стенд также собирает AMD64. Итоговые MIPS/MIPSel
  проверяются отдельно в конце подготовки. Этот прогон не подтверждает
  последующие изменения исходников; для них фиксируются отдельные результаты.
- Локальные проверки Windows и интерфейса относятся к проверенным ревизиям;
  они не заменяют полный Linux-прогон и реальные сетевые испытания.
- На Netcraze Ultra (NC-1812), ARM64, KeeneticOS 5.01.C.6.0-1 установлен
  начисто тестовый кандидат `0.20.0-rc.47` из ревизии `22a96a79`.
  Контрольная сумма бинарника и содержимое основных файлов интерфейса
  проверены по сборке. Приёмка продолжается.

### Приёмка на роутере

Итоговые исходная ревизия, контрольные суммы комплекта, результаты сетевых
сценариев и часового наблюдения будут указаны после проверки окончательного
кандидата. Установка панели и импорт узлов сами по себе не подтверждают доступ
к Telegram или работу всех способов подключения.

На `0.20.0-rc.47` отдельные проверки NFQWS2 подтвердили HTTP-ответ и путь
запроса для YouTube, Discord, Roblox, Riot Games, Speedtest и общего списка.
Временные правила после проверок удалены; существующий VPN роутера сохранён.
Автопилот затем применил все шесть назначений. С ПК отдельно подтверждены
HTTPS-ответы Discord и исключённых Госуслуг; ограниченное наблюдение пакетов
показало путь через LAN и WAN без изменения чужого VPN. Это не доказывает
отсутствие обработки DPI для исключённого сайта: проверка поведения исключений
и длительный прогон остаются незавершёнными.

Исправлен запуск профилей VLESS Reality без явно заданного fingerprint:
Sing-box получает согласованный uTLS-параметр, а применение требует новой
проверки именно такого профиля. Реальный Sing-box принимает конфигурации,
которые ранее отклонял. Два профиля из источника «Игорёк» подтвердили Telegram
через точный VLESS-путь: проверены HTTPS-имя и официальный IP с исходным TLS SNI.
Они используют один сервер и не считаются независимыми резервами. Применение
этого пути к трафику ПК, MTProto, независимый резерв, автоматическое переключение
и часовой сетевой тест ещё не подтверждены.

Обновление источников по сохранённому расписанию наблюдалось на роутере:
новые узлы поступили в каталог и очередь проверки; ответ HTTP 304 не выдан
за новый снимок. Импорт не означает работоспособность подключений. Обнаружен
и исправляется дефект приоритета очереди, из-за которого готовый проверенный
узел мог долго ждать за неработающими кандидатами.

Проверки логики интерфейса проходят. Полный просмотр окончательной сборки
в браузере, включая все страницы, кнопки и узкий экран, остаётся отдельным
незавершённым условием публикации.

## Известные ограничения

- MIPS и MIPSel собираются, но на физических роутерах не проверялись.
- Установка и обновление пакета USQUE запрещены, если его автоматические
  адреса `172.16.1.100–172.16.1.200` пересекаются с адресами или сетями локальных
  интерфейсов. Запрет действует и для адреса уже работающего штатного USQUE:
  по одному адресу нельзя подтвердить владельца интерфейса. Отказ
  `USQUE_PACKAGE_ADDRESS_CONFLICT` требует проверки настроек пакета; установка
  не должна обходить эту защиту.
- Исключение устройств своей меткой соединения (без политики Keenetic) — после 0.20.0.
- Два DPI-исполнителя с переключением (идея d2k/z2k) — после 0.20.0,
  см. [архитектурную записку](DUAL_DPI_ARCHITECTURE_RU.md).
- «Настроено», «маршрут применён» и «сервис доступен» — разные проверки:
  запущенный процесс сам по себе не доказывает работу обхода.
