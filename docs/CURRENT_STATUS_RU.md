# Текущий статус RAZVILKA

## 0.18.15: панель не блокируется фоновой работой, обновление без подтверждённых маршрутов

После 0.18.14 на роутере не удавалось обновиться и установить обход. Установщик
откатывал 0.18.14 на шаге 7 («applied node recovery requires review»): маршруты
после восстановления ждали новой проверки подключений. Панель в это время
отвечала «Сейчас выполняется другая операция»: раунд автопилота держит
исключительный допуск во время проверки сервиса, а запросы панели получали
отказ сразу, не называя причину.

Теперь действия пользователя ждут до 20 секунд и прерывают фоновую автоматику,
включая просмотр плана установки обхода. Отказ и индикатор панели называют
выполняемую операцию. Установщик требует подтверждённых маршрутов, только если
они были подтверждены предыдущей версией. Разделение подготовки автопилота
и исключительного допуска остаётся задачей ветки 02.

Точный пакет 0.18.15 из GitHub установлен на AArch64 установщиком без ручных
шагов. Маршруты после установки ещё не подтверждены: их нужно проверить
и применить в панели.

## 0.18.14: восстановление после сбоя отката и снижение фоновой нагрузки — история

После ручного обновления `nfqws2-keenetic` смена init-скрипта не позволила
подтвердить откат следующей транзакции. Журнал маршрутов остался заблокированным,
а при каждом запуске проверка готовности получала 503, и служба завершала процесс.
На AArch64-роутере RAZVILKA была недоступна около 28 часов после перезагрузки.
Теперь такая блокировка оставляет процесс работать и называет свою причину.
Добавлены явные команды принятия init-скрипта обновлённого пакета и закрытия
неповторяемого отката с проверенным отключением собственных процессов и правил.

Обе команды применены на роутере сборкой из этой ветки. Журнал перешёл
в `rolled-back` с неподтверждённым откатом, затем 0.18.13 запустилась
и прошла проверку готовности. Состояние `network-stale` требует новых проверок
подключений; Safe Mode оставлен включённым до решения пользователя.

Профиль CPU на роутере показал основную фоновую нагрузку: каждый раунд
согласования дважды заново проверял все сохранённые подключения (528 КБ).
В простое без открытой панели нагрузка снизилась примерно с 7,9 до 2,4 %
одного ядра (замер сборки с профилировщиком), RSS — с 30 до 25 МБ.
История показателей больше не перезаписывается на USB-накопитель каждые
5 минут. Точный пакет 0.18.14 установщиком GitHub ещё не устанавливался.

**Ещё не завершены:** единые LAN-исключения в исполняемых правилах, весь набор
длительных действий общей очереди, автоматический подбор NFQWS2 для медиа,
полный жизненный цикл DNS и компонентов, установка обновлений без участия
пользователя и длительные 24/72-часовые испытания. Обновление используемого
NFQWS2 из панели по-прежнему требует сначала снять его маршруты; резервные
копии обновлений не удаляются автоматически. Сборка MIPS/MIPSel не заменяет
проверку на физических роутерах этих архитектур. Полный план не объявлен выполненным.

## 0.18.13: очередь, восстановление и обновление панели — история

Общее обновление и кнопка «Обновить состояние» теперь повторно получают
состояние автопилота; данные обновляются и при возвращении на главную.
На отдельном локальном экземпляре проверены сбой запроса и восстановление
после нажатия кнопки. На роутере подтверждены запрос и обновление карточки.
Несохранённые поля и защита от поздних ответов после выхода сохранены.

Проверена очередная часть [единого плана](plans/unified-lan-2026-09-22/README.md).
Проверки сервисов и подключений, применение просмотренного узла, DNS и Stop/Resume
используют постоянную очередь. Сохраняются ревизия, курсор, отмена и результат
очистки. Stop получает высший приоритет; обслуживание постепенно повышает свой
приоритет и выполняется после безопасного завершения текущей операции.

При занятом исполнителе панель читает защищённые снимки настроек, компонентов,
автопилота, журнала и показателей. Возраст данных виден; сохранённые сведения
не означают работоспособный маршрут. При первом входе такой снимок разрешает
отправить только Stop с проверкой ревизии на сервере.

DNS для явно выбранных клиентов и доменов поддерживает проверку, общий откат,
остановку, возобновление и восстановление. Приёмка на одном AArch64-роутере
и одном физическом ПК включает UDP/TCP DNS; это не испытание всей домашней
сети, двух клиентов или каждого транспорта. Подробные результаты по точным
ревизиям приведены в [журнале выполнения](plans/unified-lan-2026-09-22/EXECUTION_RU.md).

Точный пакет 0.18.13 из GitHub установлен на AArch64: установщик завершился
успешно, восстановление сохранённого маршрута подтверждено. Очистка журнала
после выхода проверена в 0.18.12 и остаётся покрыта регрессионными тестами.
Настройки и ожидающие изменения сохранены. Публичное подключение не сразу
прошло повторную проверку после перезапуска; затем маршруты восстановились.
Длительная стабильность этим не доказана.

## Исправления панели и первый этап автоматики 0.18.9

Исправлен запуск обновлений состояния после входа через сохранённую сессию:
общий переключатель больше не остаётся без данных из-за скрытой формы входа.
Он останавливает и возобновляет ранее применённые маршруты; панель остаётся
доступной. Перед возобновлением проверяются сохранённые подключения. В безопасном
режиме запуск требует разрешения в настройках. Кнопка «Лог» показывает причины
отказов и последние действия.

Аппаратная проверка также обнаружила слишком короткий двухсекундный лимит:
маршрут передавал клиентский трафик, но полная проверка его сетевых правил
обрывалась. Проверка собственного процесса и всех правил сохранена; её лимит
увеличен до восьми секунд отдельно от проверки свежести сети. Отмена запроса
учитывается, а таймаут и другие причины неподтверждённого состояния видны в логе.

В карточках обходов появились проверка версий, установленная и доступная версии,
установка и удаление. Ошибка обновления каталога больше не скрывает установленный
компонент. Отдельно учитываются работающий процесс, внешний владелец, зависимости
и устаревшие данные. USQUE и Xray используют Sing-box как сетевую зависимость;
его нельзя удалить или обновить под выбранным либо действующим маршрутом.

На роутере найден загрузчик Entware без HTTPS, мешавший обновлению каталогов
NFQWS2 и WARP. Установлен `wget-ssl`, обновление всех подключённых каталогов прошло.
Установщик теперь исправляет этот случай и повторно проверяет результат.
Из 35 источников сервисов недоступен был IP-список Telegram на `core.telegram.org`.
Он заменён на каталог Loyalsoldier в GitHub с явным указанием происхождения:
там объединены официальный список и данные ASN. Частичная загрузка доменов без
обязательного IP-списка не считается успешным импортом.

Автопилот теперь может перейти к следующему резерву после свежего подтверждённого
отказа кандидата в пределах установленного лимита. Неопределённый результат,
потеря наблюдения сети, ошибка очистки или применения останавливают раунд.
Полный сценарий «успешная проба B → отказ применения B → откат → применение C»
этим изменением **не закрыт**.

[Новый план из 15 этапов](plans/automation-2026-09-20/README.md) сверён с текущим
кодом. Его 104 сценария сохраняют статус запланированных; локальные проверки
отдельных исправлений не подменяют аппаратную приёмку всей матрицы.
Проверки версий и подготовка архива по расписанию существуют. Полностью
автоматическая установка обновлений приложения и компонентов остаётся отдельной
незавершённой работой; настройка расписания не выдаётся за её реализацию.

Точные файлы 0.18.9 собраны из `78be7ef62db23b736db34dd5dc777d5a91997638`.
Прошли полный локальный набор Go-проверок, проверки интерфейса, три запуска CI
и [сборка выпуска](https://github.com/ArtixSx/RAZVILKA/actions/runs/35478011260).
У всех десяти файлов проверены размеры, SHA256 и манифесты; у архива — также
происхождение из подписанного задания GitHub. Формат бинарников проверен для
ARM64, MIPS, MIPSel и тестового AMD64.

На Netcraze с ARM64 установлен именно этот выпуск. Настройки, учётная запись
и восемь подключений сохранены. На точном архиве прошли изолированные проверки
подготовки Entware, удаления, установки, повторного обновления, отката и отказов.
Все 35 источников каталога сервисов получили успешный предварительный просмотр;
Telegram загрузил 21 домен и 12 сетей. Обновление каталогов компонентов прошло.
Цикл установки и удаления `wgcf` проверен на кандидате того же исходного кода,
без создания аккаунта или туннеля.

Выключение и повторное включение выполнены кнопкой в браузере. После включения
переключатель показал «Проект включён»; после перезагрузки страницы сохранённая
сессия снова получила состояние. Три настоящих HTTPS-запроса к Discord прошли
с одного компьютера через собственные правила и TUN, что подтверждено счётчиками.
Маршрут ограничен этим компьютером. Запрос маршрута для другого исходного адреса
обошёл TUN; это не заменяет испытание на втором физическом клиенте.
Для этого сервиса включена проверка каждые пять минут. Первый запуск по таймеру
завершился успешно, сервер сохранил время следующей проверки. Это проверка
доступности, а не подтверждение полной автоматической установки и восстановления.

После выключения собственные процессы, TUN и правила убраны, основная таблица
маршрутов, policy rules и IPv6 firewall сохранились. В IPv4 firewall отдельно
отмечено изменение адреса и порта в постороннем правиле Cloud службы прошивки;
побайтовое совпадение всего firewall не заявляется. Семь временных каталогов
испытаний удалены, резервные копии сохранены.

**Открытая проблема:** наблюдатель сети иногда теряет непрерывность наблюдения
на этапе `event-drain`. Трафик может продолжать идти, но прежнее подтверждение
маршрута становится недействительным. Переключатель остаётся включённым,
показывает «Нужна проверка», а лог объясняет причину. Точная причина сброса
и устойчивое автоматическое восстановление после него ещё не подтверждены.
Это отдельная задача нового плана, не исправленная увеличением лимита проверки.

| Применение дополнительного узла C | Сервисный PASS, маршрут применён; три HTTPS 200, +6 пакетов, TUN RX 580632 / TX 18208 байт |
| Остановка после A/C и откат B | Все девять проверок очистки прошли в каждом случае: исходные маршруты, policy rules и IPv4/IPv6 firewall восстановлены, собственных процессов, TUN и слушателей нет |

Из двух дополнительно проверенных публичных узлов первый не прошёл проверку
выхода, второй (C) подтвердил сервис и клиентский трафик. Ранее полученный PASS
узла B не заменил проверку непосредственно при применении: при отказе внешнего
пути изменения откатились, проверки не ослаблялись. A и C применялись отдельно,
с остановкой между ними; непрерывное переключение A → C на кандидате не проверялось.

Перезагрузки роутера не было. Сравнение firewall исключает изменяемые счётчики.
Эти результаты относятся к кандидату; точные файлы выпуска проверяются отдельно.

## Исправления восстановления

Подтверждён дефект планировщика восстановления: после смены состояния оставалась
старая задержка узла B — шесть попыток и следующий запуск примерно через 16 минут.
Исправлены двойное увеличение задержки, её сброс и пробуждение при новом
разрешённом состоянии восстановления. Перезапуск кандидата подтвердил
немедленную перепроверку и успешное восстановление с первой попытки.

Добавлены диагностика наблюдателя и ограниченный повтор прерванного чтения
netlink. Это не установленная причина прежних прерывистых сбросов наблюдателя;
она остаётся предметом расследования. Успешная проверка кандидата не доказывает,
что историческая причина сбросов устранена.

Пакет app, целевые тесты восстановления и vet прошли. Проверки наблюдателя
прошли на Windows; Linux ARM64 systemprobe на настоящем роутере, включая
чтение сетевого состояния без изменений: 43 PASS, два opt-in теста пропущены.
Общий CI кандидата 0.18.5 прошёл; результаты аппаратной проверки приведены выше.

## Сохранённые исправления EXT5

- Сервисные проверки читают ограниченный образец большого HTML-ответа, даже
  если сервер игнорирует Range. Проверки JSON и признаков блокировки сохранены.
- Допускается до восьми IPv4 CDN вместо четырёх; каждый адрес должен пройти
  проверку в пределах общего бюджета 45 секунд.
- Отказы этапа `service_ip` сохраняются; таймаут и отмена возвращают через API
  структурированный отрицательный отчёт без записи (`recorded:false`).
  Диагностика ограничена 240 символами без повреждения UTF-8.
- Исправлены загрузка панели, редактор NFQWS2, сохранение мастера и импорт
  файлов, подписи стратегий, очередь проверок и штатный автозапуск Sing-box.
