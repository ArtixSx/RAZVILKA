# Проверено в rc.128

Аппаратная проверка выполнена на Netcraze NC-1812 с Entware ARM64. Установщик, вход администратора и штатная остановка через панель прошли проверку. После испытания восстановлены четыре исходных каталога приложения, исходные сетевые правила и маршруты. Исключённый компьютер сохранил внешний адрес.

Встроенный и пользовательский Telegram Web имеют разные подписи в карточках, подробностях и списке автопилота. При выборе встроенного проверялся только он. На источнике VLESSforU первый узел вернул ошибку запроса за 7,064 с и переместился на последнюю из 32 позиций. Второй узел вернул HTTP 200 со страницей Telegram Web за 1,212 с. Он попал в резерв через 161,957 с после выбора сервиса. Время включает штатный интервал следующей проверки. Каждый новый пользователь проверяет текущую доступность узлов со своей сети.

Для области «домашняя сеть с исключённым компьютером» подтверждена проверка самим роутером. Рабочий маршрут устройств в этом опыте не менялся. Проверка Telegram Web не охватывает звонки, медиа и приложение Telegram. [Матрица](RUNTIME_SUPPORT_RU.md) · [Протокол приёмки](ROUTER_ACCEPTANCE_RU.md)

## Проверка веб-сервисов в тестовой сборке

У профиля «Discord · веб» появилась отдельная проверка загрузки веб-приложения через узел Xray. Профиль «Discord» сохраняет свой список доменов и стратегию NFQWS2. Успешная проверка с роутера позволяет сохранить узел в резерве. Чтобы подтвердить доступ из домашней сети, нужна загрузка страницы с ПК через применённый маршрут. Для этого в протокол приёмки добавлена браузерная проверка Telegram Web и Discord.

Сборку `0.20.0-rc.128.home.1` (`37ea81e`, ARM64) установили на NC-1812. С одного домашнего ПК в чистом Chrome 158 проверили появление форм входа.

| Путь с ПК | Telegram Web | Discord |
| --- | --- | --- |
| Обычная домашняя сеть до и после обновления | Тайм-аут | Тайм-аут |
| Явный диагностический прокси через проверенный узел Xray на роутере | Форма входа за 14,8 с | Форма входа за 4,8 с |

Для второй проверки прокси слушал только на локальном адресе роутера. Браузер подключался к нему через SSH. После проверки временный процесс завершили и закрытие порта проверили. При автоматическом режиме было применено 0 маршрутов. Доступ с ПК без настройки прокси остаётся открытой задачей.

Для Telegram Desktop отдельно проверили соединение с дата-центром DC2 по MTProto. На ПК в момент проверки девять соединений приложения ожидали ответа на установление TCP-соединения. На обычном подключении контрольный запрос к DC2 завершился по тайм-ауту за 3 секунды. Через временный прокси роутера и узел из резерва Telegram Web тот же дата-центр трижды вернул ответ с ожидаемым одноразовым значением. Проверка прошла без входа в аккаунт. Временный прокси закрыли. Доставку сообщений и работу настольного клиента в штатном режиме предстоит подтвердить после применения маршрута.
