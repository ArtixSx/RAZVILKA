## Более ранний аппаратный результат 8 сентября

До текущей объединённой сборки проверен отдельный снимок ARM64.
Из свежей ограниченной выборки Goida6 найден VLESS, который прошёл точную
проверку по имени и IPv4, затем штатное применение только к Telegram одного
ПК. После обоих сценариев восстановления получены новый процесс, новая сетевая
сессия и свежая проверка того же узла. Telegram вернул HTTP 200; контрольный
ПК не использовал этот маршрут, счётчики TUN выросли в обе стороны.

Исходные пользовательские черновики и пустой применённый маршрут восстановлены
через обычные API. Учётная запись кандидата, нативное состояние WARP,
посторонние черновики и глобальные файлы обходов сохранились. Проверка не
перезапускала основной роутер или его действующие внешние обходы.

Для этой сборки прошли `go test ./...` (47 пакетов), vet и целевые тесты
нового IP-контроля с настоящим Windows race detector. Более ранний снимок
6 сентября прошёл полный Windows `go test -race ./...` и native ARM64
проверки установки и владения. Новые проверки интерфейса/подписок не наследуют
эти результаты автоматически. Release CI итогового commit будет отдельным
подтверждением Linux tests/race и четырёх сборок.

Локальные первичные результаты: `candidate-recovery-restart-result.json`,
`candidate-recovery-cold-result.json`, `core-phase-20260908/restore-summary.json`.
Они хранятся в исключённой из публикации `.hil`; приватные профили и ключи
не входят в репозиторий или релиз.

## Ограничения общего теста

- Публичные узлы могут перестать работать после успешной проверки. Страна в
  имени/подписке — сведения издателя, пока выход не измерен отдельно.
- WARP WireGuard не подтвердил рабочий сервисный путь на проверенной сети.
  MASQUE дал смешанные успехи и ошибки при повторении. Надёжный резервный WARP
  сейчас не заявлен.
- ARM64 проверен на одном Netcraze. `mips` и `mipsel`/`mipsle` — сборки для
  самостоятельного аппаратного тестирования; amd64 — Linux-стенд.
- Реальная перезагрузка роутера, отключение питания, WAN reconnect, IPv6 HTTPS
  и нагрузка на малом объёме памяти остаются отдельными этапами приёмки.
- Автоматическое переключение допустимо только в выбранной пользователем
  группе и после свежей проверки. Обновление подписки не должно само включать
  маршрут или менять область устройств.
