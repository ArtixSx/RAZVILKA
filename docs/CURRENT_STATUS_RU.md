# Текущий статус RAZVILKA 0.18.4

Обновлено 19 сентября 2026 года. Ревизия **c7ea788** прошла полный CI и
аппаратные проверки локально собранного ARM64-бинарника из точного исходного
кода. **Итоговые файлы GitHub Release ещё требуют собственной проверки после
сборки тега.** Приведённые результаты не объявляют эту проверку завершённой.

## Исправления

- Сервисные проверки читают ограниченный образец большого HTML-ответа, даже
  если сервер игнорирует Range. Проверки JSON и признаков блокировки сохранены.
- Допускается до восьми IPv4 CDN вместо четырёх; каждый адрес должен пройти
  проверку в пределах общего бюджета 45 секунд.
- Отказы этапа `service_ip` сохраняются; таймаут и отмена возвращают через API
  структурированный отрицательный отчёт без записи (`recorded:false`).
  Диагностика ограничена 240 символами без повреждения UTF-8.
- Исправлены загрузка панели, редактор NFQWS2, сохранение мастера и импорт
  файлов, подписи стратегий, очередь проверок и штатный автозапуск Sing-box.

## Проверено на Netcraze ARM64

Использован **локально собранный бинарник c7ea788**, а не будущий файл GitHub Release.
Штатный установщик сохранил настройки, пять узлов и вход `admin`.

| Сценарий | Подтверждённый результат |
| --- | --- |
| Пять публичных VLESS-узлов | Два получили сервисный PASS Discord: проверены доменное имя и все пять адресов CDN |
| Маршрут A только для одного ПК | Три свежих HTTPS 200; собственные счётчики +7 пакетов, TUN RX 578171 / TX 16904 байт |
| Ручное переключение на B | Три HTTPS 200; +6 пакетов, RX 583684 / TX 19444 байт |
| Перезапуск приложения | Три HTTPS 200; +6 пакетов, RX 581384 / TX 18248 байт |
| Остановка собственных маршрутов и Safe Mode | Восстановлен исходный набор main routes, policy rules, IPv4/IPv6 firewall, исключая счётчики; управляемых Sing-box, TUN и слушателей не осталось |

Перезагрузки роутера не было. Синтетический запрос маршрута для адреса вне
выбранной области прошёл; физический второй клиент не испытывался.
Ручное A/B не является проверкой автоматического переключения при аварии.

Один сброс наблюдателя сделал прежнее подтверждение B неактуальным.
Восстановление A завершилось; повторная проверка B позволила переключение.
Событие не повторилось, причина сброса пока не установлена.

## Другие подтверждения

- `a5df27d`: полный Linux CI, 87 проверок реального изолированного HTTP-сервера,
  настольный и мобильный браузер, чистая установка панели и вход.

- Sing-box `1.13.3-2` установлен через API, с gVisor и `ENABLED=no`;

- После установки системных утилит снимки firewall, маршрутов и policy rules
  прочитаны успешно. Ранние ошибки отсутствующих утилит с кодом 127 исключены
  из успешных результатов.

## Что остаётся

1. Проверить attestation, контрольные суммы и аппаратные сценарии для точных
   итоговых файлов GitHub Release 0.18.4.
2. Автоматическое переключение с намеренным отказом основного узла, WAN reconnect,
   reboot, физический второй клиент и длительная работа.
3. Расследовать единичный сброс наблюдателя; проверить IPv6/UDP, MIPS/MIPSel
   и работу при ограниченной памяти.
4. Mihomo/HEV: нативный запуск и интеграция управляемых маршрутов. Сейчас доступны
   конфигураторы, а не готовые проверенные обходы.
5. Подписанные автоматические обновления с полным откатом, онлайн-пакеты стратегий
   и DNS для конкретного сервиса/устройства.

Загрузка CIDR Telegram отдельно остановилась по таймауту `core.telegram.org`;
Raw GitHub отвечал HTTP 200. Это не ошибка TLS и не опровержение проверки Discord.
