# Текущий статус RAZVILKA

Обновлено 19 сентября 2026 года. **Готовится выпуск 0.18.3 на основе EXT5;
публикация — после завершения проверок на роутере.** Сборка 0.18.2 осталась
неопубликованным черновиком после обнаружения ошибки проверки больших
HTML-ответов. Её Git-тег не переписывается. Пока стабильным выпуском остаётся
[v0.18.0](https://github.com/ArtixSx/RAZVILKA/releases/tag/v0.18.0).

## Возможности и исправления

- Мастер сервисов, устройств и разрешений Автопилота, проверки по расписанию,
  подписки и разрешённый резерв подключений.
- Каналы обновления приложения, подготовка архива и ручная установка.
- Режимы NFQWS2, импорт доменных списков и настройка компонентов обхода.
- Локальный экспорт подключения для Mihomo, экспериментальный профиль HEV
  и ручные пакеты стратегий NFQWS2.
- Исправления загрузки панели, редактора NFQWS2, сохранения настроек,
  выбора сервисов, сессии входа, импорта файлов и очереди проверок.
- Отключение штатного примерного сервера Sing-box после установки пакета.
- Для 0.18.3 исправляется ложный отказ при HTML-ответе больше 32 КиБ:
  ограничения проверки JSON и распознавание блокировок сохраняются.

## Что выявили реальные проверки VLESS

Проверены пять различных публичных узлов. **Четыре из пяти подтвердили протокол
и выход через узел; сервисного PASS нет ни у одного.** Три проверки Discord
завершились `response-body-invalid`: сервер проигнорировал Range и прислал
HTML больше 32 КиБ. Ещё одна проверка завершилась `request-failed`, один узел
не подтвердил выход (`node-egress-failed`).

Маршруты сервисов ещё не применялись. Успех протокола/выхода не выдаётся
за работающий сервис или подтверждённый клиентский маршрут.

Отдельно загрузка CIDR Telegram остановилась по таймауту
`core.telegram.org`; Raw GitHub вернул HTTP 200. Это не было ошибкой TLS.
Подробные результаты сохранены в приватных журналах без публикации ключей.

## Что остаётся проверить

После исправления чтения больших HTML-ответов нужны повторные сервисные
проверки и аппаратная приёмка точного бинарника 0.18.3. Результаты прежних
ревизий не переносятся на него автоматически.

Mihomo/HEV пока не являются готовыми управляемыми обходами. Ночная
автоматическая установка полного комплекта с откатом, онлайн-обновление
подписанных стратегий и DNS для конкретного сервиса/устройства остаются
отдельными задачами.

Применение маршрута, переключение VLESS A/B, WAN reconnect, reboot,
физический второй клиент, IPv6/UDP, малопамятные MIPS и длительная устойчивость
требуют отдельных подтверждений.

## Публикация

Удалены семь старых prerelease-записей: `0.18.1-rc.1`, `0.18.1-rc.2`
и `0.18.2-rc.2`–`rc.6`. Git-теги, история исходников и стабильные выпуски
сохранены. Тег 0.18.2 также остаётся историей неопубликованной сборки.

Для 0.18.3 готовятся архивы ARM64, MIPS, MIPSel и amd64 с контрольными суммами.
Описание содержит добавления и исправления; подробные результаты — в аудите.
Публикация будет отражена здесь после завершения проверки.
