# Текущий статус — кандидат 0.20.0

> База выпуска 0.20.0. Полная аппаратная проверка не заявлена.
> Владелец отложил часовой прогон; публикация допускается после контрольных
> проверок. Ограничения ниже сохраняются и для 0.20.0.

**0.20.0 — чистая новая база.** Ставится начисто, без переноса настроек
0.19.x и старее. Обновления 0.20+ идут только из панели: с журналом,
снимком настроек и откатом при подтверждённом сбое. Неизвестный исход
требует проверки журнала.

## Проверка 23 октября 2026 года

На Netcraze Ultra начисто установлен **0.20.0-rc.55**, ревизия
`6fb700b9677f40749eeb8098d23d9dcb00482b59`. SHA-256 бинарника:
`1de93d11388ea1b1d4e71eb02ca44647608f48a11718e463685a4ea587f6ed7e`.
Перед удалением сохранена закрытая резервная копия; старые данные перенесены
в отдельную папку. Сторонний VPN роутера остался включён.

- Через кнопку панели успешно установлена NFQWS2 1.3.1. Журнал подтвердил
  завершение установки, версия повторно прочитана. Компонент не запустился
  до настройки сервисов. Это закрывает прежний дефект первичной установки;
  обычное обновление существующего управляемого пакета пока блокируется.
- В Автопилоте выбраны шесть встроенных сервисов и четыре источника узлов.
  Автоматически загружены 72 узла; загрузка не подтверждает их доступность.
- Через каталог добавлен «Telegram · через VPN или прокси». Официальный
  источник был недоступен; после отдельного подтверждения использован
  явно обозначенный встроенный снимок от 20 октября: 14 сетей, без доменов.
- Проверено создание временного сервиса, отмена удаления и подтверждённое
  удаление. Остальные семь сервисов сохранились. На rc.55 открытый паспорт оставался виден после удаления. Исправление
  закрывает его только после свежего подтверждения удаления; проверено
  отдельно на Linux и включено в исходники выпуска.
- Кнопка «Лог» открывает одну панель и сохраняет текущую страницу. В логе
  отдельно показаны проверки Автопилота и ручная проверка каталога.
- Ускоренное чередование поиска первого VLESS прошло регрессионные тесты.
  Модель с семью сервисами получила три поисковых раунда вместо одного
  за шесть минут без остановки проверок остальных сервисов. Ускорение на
  настоящем роутере пока не подтверждено.

**Продолжается контрольная проверка.** Первый профиль NFQWS2 применился, но проверка
Discord получила тайм-аут TLS; выполнен подтверждённый откат. Следующая
попытка остановилась до изменения маршрутов при чтении сетевого состояния
роутера. Последующие применения Riot Games и Roblox завершились успешно,
включая проверку доступности. Ошибка чтения оказалась непостоянной;
добавлена диагностика конкретного этапа без вывода приватных данных.
Полный Linux-прогон исходного rc.55 выявил ошибку тестового сценария
повторной установки NFQWS2: новый менеджер маршрутов получил старый,
уже связанный менеджер компонентов. Исправлена только тестовая фикстура;
четыре native Linux-регрессии прошли без пропусков (коммит `611a4b90`).
Публикация требует успешного полного задания Release в GitHub Actions.
Последующие проверки отката первого Sing-box-подключения, диагностики
NFQWS2, удаления сервиса и интерфейса прошли на Linux (7 команд).
Успешного часа на окончательном кандидате нет.
ChatGPT/OpenAI исключён из текущих сетевых испытаний по просьбе владельца.

К выпуску требуются контрольные проверки и три сборки. Устойчивый VLESS,
независимый резерв и автоматическая замена, подробная приёмка исключений,
полный час и оставшиеся аппаратные сценарии передаются в работу над 0.20.x.
Прежние результаты ниже не заменяют эти проверки. Отсутствие длительной
приёмки нужно учитывать при установке.

## Известные ограничения

- Основной аппаратный стенд — Netcraze Ultra NC-1812, ARM64,
  KeeneticOS 5.01.C.6.0-1. MIPS/MIPSel собираются, но не проверялись
  на физических роутерах; управляемые маршруты на них недоступны.
- Основной режим — обход выбранных сервисов для всей сети. Режим отдельных
  устройств экспериментальный, ограничен точным профилем роутера и одним
  сервисом с IP-сетями. Исключения устройств NFQWS2 задаются политикой Keenetic.
- Доменные сервисы обслуживает NFQWS2. Прокси и VPN требуют определения
  сервиса IP-сетями: общие адреса CDN не перехватываются по одному домену.
- Обновление управляемого NFQWS2 блокируется до реализации сохранения
  рабочего профиля. Успешная первичная установка не отменяет этот запрет.
- USQUE не устанавливается при конфликте адресов 172.16.1.100–172.16.1.200
  с локальными интерфейсами/сетями. Нельзя обходить этот отказ вручную.
- Публичные VLESS нестабильны. В прежнем коротком тесте Telegram работал,
  затем 15-минутное наблюдение выявило сбои. Резерв и автоматическая замена
  требуют отдельной повторной приёмки. Результат загрузки подписки не равен
  результату проверки узлов.
- Подтверждение отсутствия первого неудачного Sing-box-подключения улучшено;
  неоднозначная ошибка ввода-вывода по-прежнему останавливает поиск.
  Защита восстановления не отключена ради продолжения перебора.
- Наличие интерфейса настройки WARP, WireGuard и AmneziaWG не означает,
  что все их сетевые сценарии приняты на этом стенде.

## Следующие исправления 0.20.x

1. Длительный прогон финального выпуска, доступность сервисов с ПК,
   независимые исключения сайтов/устройств и сохранение обычного интернета.
2. Стабильный VLESS для Telegram: полный цикл загрузки → проверка → применение
   → потеря узла → проверенный резерв; сравнение источников по фактическим
   результатам, а не числу импортированных ссылок.
3. Завершение обновления NFQWS2 с сохранением сайтов, исключений и остановки.
4. Приёмка установки, удаления, обновления 0.20.0 → следующая версия,
   отказов и отката на точных опубликованных артефактах.
5. Остальные движки, узкие экраны и физические MIPS/MIPSel-устройства.

Прошлые подробные протоколы сохранены в истории Git и локальной передаче
разработчика; они не считаются текущим результатом.
