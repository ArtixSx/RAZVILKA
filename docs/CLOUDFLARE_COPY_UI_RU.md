# PR-1.1 — пассивный импорт Cloudflare в API и UI

31 августа 2026 года. Продолжение локальной разработки `0.18.1-dev`, без
публикации, установки на роутер, регистрации или изменения рабочих обходов.

## Что доступно

В «Настройки» добавлен свёрнутый расширенный раздел **Копии аккаунтов
Cloudflare**. Он принимает существующий файл USQUE, wgcf-account или обычный
WARP/WireGuard-профиль с компьютера:

1. Выбрать формат и файл (UTF-8, до 256 КиБ).
2. Проверить структуру без записи на роутер.
3. Сохранить отдельную копию одним подтверждением.

Распознанная структура не означает действующий аккаунт, handshake или
работающий сервис. Неизвестный совместимый архив USQUE обозначается как
«Только архив · запуск не поддерживается». Исходник и рабочие настройки не
заменяются; повторный импорт тех же байтов возвращает прежнюю копию.

Этот раздел не предоставляет регистрацию, runtime export, активацию,
изменение DNS, выбор маршрутов или удаление существующих профилей.

## Контракт API

| Метод и путь | Результат |
|---|---|
| `GET /api/v1/cloudflare/accounts` | Публичные сведения о копиях и лимиты |
| `POST /api/v1/cloudflare/import/preview` | Разбор `source_kind` + `content`; запись не выполняется |
| `POST /api/v1/cloudflare/import` | Те же поля + `confirm=SAVE_ACCOUNT_COPY`; сохранение копии |

Все методы требуют администратора, включая GET до первичной настройки.
Отсутствующий security gate не открывает доступ. Действуют существующие
проверки Origin/JSON для POST. Все ответы, в том числе ошибки авторизации,
имеют `Cache-Control: no-store`.

Вход не принимает серверный путь, URL, название файла, команды, hooks или
настройки запуска. Повторные/неизвестные поля, неоднозначный регистр,
несколько JSON-документов, неподдерживаемый формат и превышение размера
отклоняются. Одновременно выполняется только одна операция этого API;
лишние запросы получают `429` + `Retry-After`, а не накапливаются в очереди.

Ответы содержат только публичный DTO. Тело запроса не попадает в журнал.
UI не выводит ключи, не кладёт содержимое в browser storage, очищает выбранный
файл/содержимое после сохранения или его ошибки, выхода, закрытия раздела и
перехода на другую вкладку. Поздний ответ не восстанавливает очищенные данные.
Это сокращение времени хранения ссылок на данные, не обещание физического
обнуления памяти JavaScript/Go.

## Локальное хранение и изоляция кандидатов

При обычном старте создаётся только каталог `cloudflare-private` рядом с
выбранным `config.json`. Для стандартной установки это
`/opt/etc/razvilka/cloudflare-private`. Параметр `-cloudflare-state` или
`RAZVILKA_CLOUDFLARE_STATE` задаёт другой путь явно.

Каталог создаётся с POSIX `0700`; файл копий — с `0600`. Существующий каталог
не получает новые права автоматически, повреждённое хранилище не обнуляется,
symlink отклоняется. Если открыть хранилище нельзя, новый раздел недоступен,
но запуск прежних обходов не блокируется. Preflight/check/healthcheck не
создают этот каталог. Изолированный кандидат с отдельным config получает
собственное хранилище, а не копии рабочей установки.

Секреты на диске защищены правами, не шифрованием от root. Передача по HTTP
не шифруется — интерфейс предупреждает использовать доверенную локальную
сеть. В следующем локальном блоке подключён отдельный encrypted backup/restore
к UI: [архив копий](CLOUDFLARE_COPY_BACKUP_RU.md). С общей резервной копией
настроек он пока не объединён; исходные файлы также сохраняйте отдельно.

## Проверено в этой итерации

- Go: закрытый доступ до setup/с nil gate, Origin/Content-Type, preview без
  файлов, импорт без изменения draft/live config, идемпотентность, отсутствие
  ключей и endpoint в ответах/журнале, некорректные/большие запросы, busy и
  отключённое хранилище; создание каталога рядом с config без перезаписи.
- JS: правильные статусы без ложного успеха, сохранение только после preview,
  очистка приватного кандидата после save/error/logout, защита от позднего
  ответа после навигации. Проверки добавлены в `scripts/check.sh`.
- Полный `go test ./... -timeout=90s`, `go vet ./...`, синтаксис двух JS-файлов,
  `test-probe-ui.mjs` и `test-cloudflare-ui.mjs` прошли.
- Все Go-пакеты собраны для Linux arm64/mips/mipsle; тесты App также
  скомпилированы для этих трёх архитектур. Это не выполнение на Linux.
- В браузере проверен новый раздел на изолированном loopback-стенде с
  вымышленным WireGuard-профилем и реальными обработчиками нового API:
  preview → save → list. На ширине 390 px переполнения нет; ошибок JS нет.
  Это не полный визуальный аудит всех вкладок и не аппаратный тест WARP.
