# Повторный аудит RAZVILKA и уточнение master-plan

Дата: 06.09.2026. Проверенная база:
`bd36e160af5eabd40c0a8bab77c2454d4e4fb06d`, версия `0.18.1-dev`.

Этот документ сохраняет состояние первого аудита. Последующая реализация
network epoch и испытания на роутере описаны в [отчёте NET1](NET1_2026-09-06_RU.md).

## Вывод

RAZVILKA уже содержит существенную основу: транзакционные адаптеры, NodeStore,
точную проверку узлов, привязки node/group, изолированные кандидаты, приватные
backup/restore, Source Hub и Lite/Pro. Наиболее полезный следующий шаг —
устранить ошибки доверия к результатам и завершить путь «узел → сервис».
Добавление новых движков не устраняет эти дефекты.

Это аудит выбранных критичных контуров и всех автоматических проверок,
доступных в окружении, а не доказательство отсутствия ошибок во всём проекте.
Новые изменения локальные; stable-релиз не создавался.

## Что остаётся исправить

1. **WAN identity / network epoch — приоритетный gate до расширения AUTO.**
   [DetectWANProfile](../internal/systemprobe/systemprobe.go) использует
   dev+gateway, а src — только без gateway; кэш — 10 секунд. `network-unknown`
   допускается checker, а [Node API](../internal/app/nodes.go) фиксирует профиль
   до проверки без повторной проверки после неё. При смене сети во время
   canary либо одинаковых dev/gateway старый proof может остаться применимым.
   Нужен epoch интерфейса/адресов/маршрутов/DNS, проверяемый перед запуском,
   записью proof и commit. Неизвестная сеть допускает диагностику, но не
   повторное использование PASS или AUTO. Эти изменения требуют отдельного
   согласованного изменения systemprobe, Store, checker и apply.
2. **N1.4 HIL:** две собственные ссылки, два сервиса, отказ/резерв, expired
   proof, WAN reconnect, отмена, cleanup failure, восстановление и откат.
3. **Завершённый интерфейс:** PR-NB1 через существующий preview/apply, затем
   opt-in subscriptions, bounded pagination и раздельные разрешения sync,
   check и switch. API проверки не равно готовому каталогу публичных серверов.
   Новый строгий импорт намеренно отклоняет неподдерживаемые HY2 Gecko/ECH/pin
   параметры. Полная совместимость расширенных YAML/JSON options не доказана;
   нужна дальнейшая version-specific матрица, а не молчаливое удаление полей.
4. **Native NFQWS2 и USQUE:** собственный lifecycle/lease, совместимость
   runtime, аппаратная приёмка. [ADR USQUE](ADR_NATIVE_USQUE_RU.md) закрепляет
   pinned upstream, раздельные WG/MASQUE credentials и mandatory server pin.
5. **Управляемое восстановление:** перед новым apply старый rollback-failed
   нужно сверять с журналом и реальным ownership; посторонние черновики нельзя
   незаметно включать в сервисное изменение. Это сценарий приёмки, не указание
   сбросить состояние действующего роутера во время аудита.

| [Control D source affinity](https://docs.controld.com/docs/ip-mismatch-between-dns-and-proxy) | Для этого провайдера разные DNS Source IP и Proxy Source IP нарушают redirect. Нужен отдельный диагноз и capability, а не общий вывод о любом Smart DNS. |

Разделы 48–49 плана уже подробно описывают ownership и scoped rollback.
Дополнительно Smart DNS должен учитывать client DoH и остаточный клиентский
кэш/соединения после отката. Это архитектурные выводы: DNS-правило роутера
распространяется на использующие его клиенты, а восстановление файла не
завершает автоматически все прежние соединения. У Control D поддержка IPv6
также зависит от [режима redirect](https://docs.controld.com/docs/default-rule).

Исследование источников подтверждает свойства реализаций, но не доступность
конкретного сервиса у российского провайдера. Для неё нужны exact-route HIL
на конкретной сети, клиенте, версии runtime и сервисе.

## Проверки

Первичный полный `go test ./...` и `go vet ./...` на исходной базе прошли.
JavaScript syntax, все девять имеющихся UI/supervision scripts и shell syntax
прошли после указания поставляемого POSIX shell. Первоначальный запуск
supervision без пути к shell завершился `sh ENOENT`; это ограничение PATH,
устранённое при повторной проверке, а не исправление кода приложения.

Окончательный прогон исправленного дерева: полный `go test ./...`,
`go vet ./...`, Go formatting и `git diff --check` прошли. Собраны Linux amd64,
arm64, mips и mipsle (оба MIPS — softfloat, CGO=0). Артефакты имеют отдельную
версию `0.18.1-dev+audit20260906` и `BuildDirty=true`; они не выдаются за stable.
Сборка подтверждает компилируемость, не работу движка на оборудовании.
Gate отсутствия runtime-зависимости от z2k проверен отдельно, включая
отсутствующий инструмент, grep с совпадением/без совпадений/с ошибкой.

`go test -race` не запустился: CGO=0, C compiler отсутствует. WSL Linux
не установлен; полный Entware regression требует Linux `ip` и
`start-stop-daemon`, отсутствующих в этом окружении. Эти gates не отмечены PASS.

Сетевые настройки, пакеты и аккаунты на роутере не менялись; живые публичные
прокси и регистрации не запускались. Публикация в GitHub и новый CI не выполнены.
