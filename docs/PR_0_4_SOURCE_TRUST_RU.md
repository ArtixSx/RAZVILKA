# PR-0.4 — безопасные источники и актуальность списков

Локальный этап `0.18.1-dev`, 31 августа 2026 года. Не опубликован и не
установлен на роутер. Продолжает Truth & Safety после `v0.18.1-rc.1`.

## Что изменилось

- Реестр источников понимает schema 2: уровень доверия, срок актуальности,
  предельное число записей, разрешённые адреса перенаправления и необязательный
  SHA256 исходного ответа. Старые schema 0/1 читаются без перезаписи файла.
- Общая граница `publicfetch` принимает только публичный HTTPS/443, проверяет
  TLS, не использует системный HTTP-прокси и не обращается к локальной сети.
  Все DNS-ответы проверяются до соединения; подключение идёт к уже проверенному
  IP без повторного разрешения имени. Смешанный public/private ответ запрещён.
- Перенаправления ограничены числом переходов и исходным либо явно разрешённым
  hostname. Понижение до HTTP, private IP и credentials запрещены; авторизация,
  Cookie и Referer не пересылаются. Для двух прежних Re-filter URL существует
  узкая совместимость с GitHub release CDN, не разрешение для любого GitHub URL.
- В реестре не принимаются query-параметры или userinfo: это публичные списки,
  не приватные подписки. Подписанные query на разрешённом CDN допустимы только
  во время перенаправления. В публичных данных и receipt сохраняется лишь origin,
  без пути/query. Произвольный секрет внутри пути автоматически распознать нельзя;
  приватные подписки сюда добавлять не следует.
- Время запроса, объём ответа, число записей и ожидание очереди ограничены.
  HTML, в том числе с ложным `text/plain`, не становится списком адресов.
- Список и его receipt фиксируются одним атомарным файлом `.cache.json`:
  нормализованные данные, два digest, происхождение, даты и сводка изменений.
  Ошибка загрузки сохраняет last-known-good. В карантине только ограниченная
  диагностическая запись, без тела ответа и секретных URL.
- TTL, digest и соответствие конфигурации проверяются после перезапуска и при
  построении новых планов. Просроченная копия сохраняется для диагностики, но
  не пополняет новый план. Старые `.lst` не получают выдуманное provenance:
  они явно помечаются как требующие сверки и не допускаются к автоматике.
- Автопилот не использует просроченный/непроверенный источник применяемого
  сервиса и не может вместе со сменой обхода менять его домены, сети, устройства,
  источники или адрес проверки. Обновление списка не активирует новые правила.
- UI показывает срок актуальности, сохранённую предыдущую копию и количество
  добавленных/удалённых записей. Это сравнение с предыдущей загрузкой, не diff
  относительно применённого маршрута. Технические сведения не означают «обход работает».
- Community-каталог использует ту же HTTPS/SSRF-границу; устаревший User-Agent
  с номером `0.10.0` заменён стабильным идентификатором компонента.
- Вся preview-операция community ограничена 25 секундами, дерево include —
  8 МиБ суммарно; сверх 2000 доменов обработка останавливается до следующих
  вложенных запросов. HTML и слишком длинная строка не дают частично успешный
  список. Сетевые заголовки ограничены 64 КиБ, соединения — двумя на hostname.

## Проверки

Автоматические тесты покрывают private/mixed DNS, pinning IP, запрет downgrade,
ограничение перенаправлений, отказ неподтверждённого TLS, отмену, redaction,
повреждение receipt, TTL, pin mismatch, лимит записей, LKG после перезапуска,
разницу списков и неизменность области маршрута при автопилоте. UI-проверки
исполняют настоящие функции отображения без браузерной имитации результата.

Локально прошли полный `go test ./...`, `go vet ./...`, проверка синтаксиса JS
и `scripts/test-probe-ui.mjs`. Собраны Linux arm64/mips/mipsle (MIPS softfloat),
скомпилирован Linux ARM64 dataplane test binary. Кросс-компиляция не является
выполнением Linux-тестов или проверкой на роутере.

Read-only проверка из среды разработки: Re-filter загружен через явно разрешённый
GitHub CDN, получено 81 056 доменов. Загрузка официального списка Telegram из этой
среды завершилась сетевой ошибкой; это не проверка Telegram через USQUE и не
основание ослаблять TLS. Ни рабочий DNS, ни firewall, ни маршруты не менялись.

## Оставшиеся границы

- Уровень доверия — метаданные конфигурации, не цифровая подпись автора.
  SHA256 receipt выявляет повреждение, но не защищает от владельца диска,
  который способен заменить одновременно данные и receipt.
- Формальные expected content types, подписанные реестры, Conditional GET,
  периодическое обновление с jitter и полный review адресного diff остаются
  следующими этапами Source/Proxy Hub. Сейчас показана краткая сводка количества.
- Это ещё не безопасный импорт публичных VLESS-подписок и не разрешение
  автоматически включать community-прокси.
- Новым изменениям нужны Linux CI/race и аппаратная проверка. Успешный CI
  опубликованного `rc.1` не распространяется на эти локальные изменения.
- Изоляция файлов не является песочницей стороннего runtime; процесс root
  с произвольным доступом к файловой системе не входит в эту модель защиты.
