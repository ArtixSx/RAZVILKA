# Как помочь RAZVILKA

Можно сообщить об ошибке, предложить улучшение, поправить документацию или код.
Для начала посмотрите [текущий статус](docs/CURRENT_STATUS_RU.md) и
[план](docs/ROADMAP.md): там отделены готовые функции от задач в работе.

## Сообщить об ошибке

Создайте [Issue](https://github.com/ArtixSx/RAZVILKA/issues) и кратко укажите:

- версию RAZVILKA, модель роутера и версию прошивки;
- что вы сделали, чего ожидали и что получилось;
- повторяется ли ошибка и как её воспроизвести;
- текст ошибки или снимок экрана без паролей, ключей и приватных ссылок.

В панели версия показана рядом с названием проекта. Через SSH её можно узнать
командой `/opt/bin/razvilka -version`. Для вопросов об уязвимостях используйте
[порядок сообщения о проблеме безопасности](SECURITY.md).

## Изменить документацию или код

Сделайте fork репозитория, создайте отдельную ветку и откройте Pull Request.
Опишите проблему, получившееся поведение и способ проверки. Для изменения
интерфейса полезен снимок экрана; для исправления ошибки — шаги воспроизведения.
Небольшое изменение с одной понятной целью проще проверить.

Карта проекта находится в [справочнике файлов](docs/FILES_RU.md). Документы
текущего состояния не должны выдавать запланированные возможности за готовые.
Лицензии и указания авторства сторонних данных сохраняются.

## Среда разработки

CI использует **Linux, Go 1.26.5 и Node.js 24**. Версия Go указана также в
[go.mod](go.mod). Полный набор проверок удобнее запускать в Linux или WSL;
для race-тестов нужен C-компилятор, для сборки — стандартные shell-утилиты
и `sha256sum`. Node.js нужен для проверок интерфейса, но не для работы
установленной панели на роутере.

Из корня репозитория:

```sh
go test ./...
go vet ./...
node scripts/build-interface.mjs --check
```

После изменения Go-кода примените `gofmt` к изменённым файлам.
Если меняли `interface-compat.css` или `interface-shell.css`, пересоберите
объединённый файл:

```sh
node scripts/build-interface.mjs
```

Перед отправкой изменения кода выполните полный набор:

```sh
./scripts/check.sh
```

Он проверяет форматирование, запускает Go-тесты, race detector, vet,
проверки shell и интерфейса, собирает четыре Linux-бинарника, сверяет суммы
и выполняет изолированную репетицию установки. Если Node.js отсутствует,
локальный скрипт пропускает его проверки; для результата, сопоставимого с CI,
он должен быть установлен. Одной успешной сборки недостаточно для утверждения,
что маршрут работает на физическом роутере.

## Изменения, влияющие на сеть

Для маршрутов, DNS, запуска компонентов и восстановления сохраните проверку
до применения, ограниченные таймауты, безопасный режим и понятный результат
отката. Проверяйте также отказ внешнего узла, отмену и ошибку очистки.
Интерфейс не должен передавать произвольные shell-команды.

Разделяйте результаты: модульный тест, изолированный запуск и проверка на
роутере подтверждают разные вещи. Не заменяйте проверку доступа к сервису
фактом запуска процесса. Не добавляйте реальные пароли, VLESS-ссылки, ключи,
cookie, резервные копии и приватные отчёты в коммит или приложенные файлы.

Правила подготовки выпуска описаны в [Версиях RAZVILKA](docs/VERSIONING_RU.md).
